# 智能体 — 综述

> - 设计状态：待讨论
> - 适用范围：智能体内部实现与观测、行动契约
> - 上级：[整体架构](../整体架构.md)

## 目标与边界

定义智能体实现：主体如何接收观测、形成记忆与内部模型、学习和决策，以及如何通过行动接口影响世界。具体学习算法、策略与控制结构均待讨论。

身体、生理、出生死亡及行动造成的世界后果归世界；内部记忆、信念、目标和策略归智能体。智能体通过明确的观测与行动契约接入，不依赖游戏平台界面或研究平台评分器。

## 拟定子模块

| 子模块 | 待讨论内容 |
| --- | --- |
| 感知与信息 | 世界观测的接收与内部处理；对接身体感知、采样、噪声、量化及信息边界 |

| 行动与控制 | 智能体意图、持续行动策略、执行反馈及控制接口；玩家输入适配由游戏平台负责 |

子模块尚未创建；讨论时分别建立 `设计.md` 与 `实现.md`。

## 设计进度与待决依赖

Python 为已接受的语言方向，具体学习算法、策略、部署和状态接口待讨论，新方案未实施。观测来源和行动后果需对接世界机制；身体视域及物理噪声不在智能体内重复定义。

候选保存方案：固定权重引用可取得且摘要匹配的模型产物，不必每个存档重复保存；影响未来的记忆等可变私有状态随方案保存。模型替换后的游戏续玩与研究闭环复现由各平台分别处理，接口尚未确认。

## 关联模块

研究使用时的主体定义及评价方向依据[研究综述](../研究理论/研究综述.md)，具体约束与验证方案由研究平台重新讨论。身体能力归[生命个体](../世界/生命个体/综述.md)；行动的世界后果由对应世界机制定义；输入界面归[表现层](../游戏平台/表现层/综述.md)。

游戏平台与研究平台分别选择、装配和驱动智能体；智能体自身的状态保存、推理预算、训练依赖及交付说明归本顶层。各平台如何协调世界状态与智能体状态，留待运行协议讨论。

决策推理的调度和性能写入相应子模块的实现文档；具体算法与执行策略待对应设计确定。
