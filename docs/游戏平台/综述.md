# 游戏平台 — 综述

> - 设计状态：讨论中
> - 适用范围：游戏装配、玩家体验与会话组织
> - 上级：[整体架构](../整体架构.md)

## 1. 职责与边界

装配世界、可选智能体与客户端，提供可玩的产品：玩家角色、玩法组合、输入、反馈、表现和游戏会话。

游戏平台具有自身的必备框架，模组管理器是其组成模块；框架与内容模组的边界见[整体架构](../整体架构.md#4-模块与装配边界)。

世界内状态与作用结果由世界机制定义；平台选择内容与配置并驱动接口，不在客户端另写世界规律。玩家输入适配属于本平台，NPC 认知与决策实现归智能体。

## 3. 当前方向与来源

- **玩法**：基因编辑形成感知与需求差异，关注个体、群体和跨代后果；探索、特殊生物发现、基因获取与跨群体互动仍是需求背景，见玩家行动综述。
- **地图**：先用全量运行的小地图验证核心玩法，大地图旅行及其他区域的简化组织见世界组织设计。有限地图不等于完整探索体验已经满足。
- **模组**：在必备框架之上，官方模组组成完整默认游戏；作者构建模组产物，玩家通过界面启用而无需编译。社区新算法无需研究证据，存档不因版本变化直接拒绝加载，详见模组管理设计。
- **时间反馈**：秒制读出与现实执行速率的感知锚点由表现层组织，具体显示与实时策略未定。

## 4. 依赖与后续工作

使用[世界](../世界/综述.md)提供的配置、推进和交互能力，按需接入[智能体](../智能体/综述.md)。跨库连接、组合存档与加载顺序还需接口设计，当前优先收束整体架构及模组接入。

本平台与[研究平台](../研究平台/综述.md)并列：游戏不依赖实验评分器，研究也不经游戏启动流程。共享工具或协议的复用需有明确接口，不通过读取私有状态连接。
