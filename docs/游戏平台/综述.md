# 游戏平台 — 综述

> - 设计状态：讨论中
> - 适用范围：游戏装配、玩家体验与会话组织
> - 上级：[整体架构](../整体架构.md)

## 1. 职责与边界

装配世界、可选智能体与客户端，提供可玩的产品：玩家角色、玩法组合、输入、反馈、表现和游戏会话。

游戏平台具有自身的必备框架，模组管理器是其组成模块；框架与内容模组的边界见[整体架构](../整体架构.md#4-模块与装配边界)。

世界内状态与作用结果由世界机制定义；平台选择内容与配置并驱动接口，不在客户端另写世界规律。玩家输入适配属于本平台，NPC 认知与决策实现归智能体。

## 2. 模块与进度

| 模块 | 负责内容 | 进度 |
| --- | --- | --- |
| [玩家行动](玩家行动/综述.md) | 玩家定位、玩法目标、指令和操作含义 | 讨论中；动机明确，具体玩法待定 |
| [表现层](表现层/综述.md) | 客户端视觉、音频、界面、输入与同步 | 讨论中；二维与 Godot 方向明确 |
| 世界组织 | 局部地图、大地图旅行与非详细区域 | [设计](世界组织/设计.md)：讨论中 · [实现](世界组织/实现.md)：未实施 |
| 模组管理 | 官方及社区模组装配、配置变化后的续玩 | [设计](模组管理/设计.md)：讨论中 · [实现](模组管理/实现.md)：未实施 |

当前客户端仅有启动场景，尚无可玩内容。组合会话与产品构建在开始讨论时再划分模块。

## 3. 当前方向与来源

玩法动机与验证问题归[玩家行动](玩家行动/综述.md)，地图规模与旅行组织归[世界组织](世界组织/设计.md)，官方／社区交付与续玩政策归[模组管理](模组管理/设计.md)，时间反馈与客户端同步归[表现层](表现层/综述.md)。这些文档分别维护规则，本综述只维护分工。

## 4. 依赖与后续工作

使用[世界](../世界/综述.md)提供的配置、推进和交互能力，按需接入[智能体](../智能体/综述.md)。跨库连接、组合存档与加载顺序还需接口设计，当前优先收束整体架构及模组接入。

本平台与[研究平台](../研究平台/综述.md)并列：游戏不依赖实验评分器，研究也不经游戏启动流程。共享工具或协议的复用需有明确接口，不通过读取私有状态连接。
