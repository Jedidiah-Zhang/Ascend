# 表现层 — 综述

> - 设计状态：讨论中
> - 适用范围：客户端视觉、界面、音频与同步的职责划分
> - 上级：[游戏平台](../综述.md)

## 目标与边界

定义世界运行结果如何被玩家感知，以及输入如何形成明确的操作请求。游戏二维表现方向已确定，具体画面表达、通信与显示频率的关系待讨论。

## 拟定子模块

| 子模块 | 待讨论内容 |
| --- | --- |
| 视觉表现 | 风格、相机、空间表达、渲染、动画与资产组织 |
| 界面与输入 | 操作流程、信息展示、反馈、设置与调试入口 |
| 音频表现 | 环境、交互、事件音效与音乐 |
| 客户端同步 | 通信协议、状态读取、加载、显示同步与响应预算 |

子模块尚未创建；讨论时分别建立 `设计.md` 与 `实现.md`。

## 设计进度与待决依赖

客户端采用 Godot，具体视觉、控件与协议仍待讨论，新架构尚未实施。需先明确玩家输入和可读状态接口，再确定同步粒度与反馈预算。

### 时间感知与现实锚定

已明确需要以秒制本地时间提供与现实时间对接的感知锚点。候选反馈包括当前本地时间、暂停状态和每现实秒实际推进的本地秒数；配置倍率与实际执行速率分开。实时对齐策略、加速倍率和显示方式仍待讨论，时间读出来自[时间系统](../../世界/世界框架/时间系统/设计.md)。

## 关联模块

操作含义来自[玩家行动](../玩家行动/综述.md)和主体接口；模型空间与时间含义来自[世界框架](../../世界/世界框架/综述.md)。显示、客户端缓存及游戏通信的实现细节留在本模块。研究者界面的流程、权限与工具由[研究平台](../../研究平台/综述.md)定义，不作为游戏界面的附属功能。
