# 世界组织 — 设计

> - 设计状态：讨论中
> - 适用范围：游戏局部地图、大地图旅行与模拟范围组织
> - 已确定范围：二维表现、有界局部地图全量运行、小地图优先验证
> - 尚未覆盖：旅行流程、非活动区域演化、同时活动地图数及 NPC 简化
> - 上级：[游戏平台](../综述.md) · [实现](实现.md)

## 1. 目标与职责

组织玩家活动区域、探索目的地与远程移动，在运行成本可控的条件下保留改造、生存及探索体验。调用世界空间与时间能力，不在平台重复实现世界规律。

本模块承接平台综述已有的地图组织讨论；具体生态、地图生成和身体移动机制仍归世界，玩家体验需求见[玩家行动](../玩家行动/综述.md)。

## 2. 概念与术语

| 概念 | 含义 |
| --- | --- |
| 局部地图 | 玩家可直接活动的有界详细运行区域 |
| 大地图 | 组织区域位置、目的地和远程移动的游戏层结构 |
| 非详细计算区域 | 由游戏组织简化演化的其他区域，不是局部空间内部裁剪出的计算窗口 |

## 3. 已确认方向

- 游戏采用二维平面表现与有界地图。详细活动地图使用世界的[全域计算能力](../../世界/世界框架/空间系统/设计.md#space-02-全域计算与读取分离)，相机与视野只影响读取及显示。
- 以“有界局部地图全量运行＋大地图远程移动”组织空间使用，其余区域以简化方式处理；大地图不以全域详细模拟为前提。接入阶段与细节仍待讨论。
- 先以规模受控的小地图验证核心玩法，不以远方近似演化或 NPC 简化策略作为首版前提。较小空间应能支持能力与需求差异产生有意义的选择和后果。

小地图用于验证，不代表已覆盖完整探索愿景。需分别检验“改造—行为—群体后果”与“探索—发现—获取新基因”；具体玩法判据由玩家行动模块维护。

## 4. 对外契约与配置

地图创建、进入、离开、保存、重新进入和旅行的接口尚未确定。目的地需要直接活动时接入相应局部地图；原地图离开后的演化与多个地图同时运行的关系仍待设计。

地图尺寸、环境分辨率、主体数和同时活动地图数由性能与玩法验证确定，当前无默认数值。生成、加载和演化的区别遵循空间设计，加载本身不补齐未演化历史。

## 5. 候选方案与取舍

非详细区域可采用统计、低频或低精度更新，目标是降低成本并保持玩家感知连贯、尽量接近详细模拟结果，不要求轨迹完全一致。尚未选择具体模型；近似组织在详细空间范围之外进行。

智能体技术未确定，不预设它能无损降低决策频率或切换简化策略。外部环境简化可能改变观测的频率、细节和语义，是否还能使用同一策略需按观测与行动契约验证。

先明确完整环境中的智能体接口与成本，再评估地图外个体、旅行队伍和非活动地图的低成本行为。如果效果不可接受，可调整活动地图数或远程行动规则；不承诺补出未模拟的详细行为历史。

## 6. 验收方向

已确认方向的检查：详细局部地图的演化覆盖不因相机或只读视野变化而改变；小地图验证应能展示能力和需求差异的后果。

后续方案确认后补充判据：往返区域的实体身份、已有状态、重要经历如何保持连贯；旅行消耗、时间与事件怎样交接；近似结果与详细结果的偏差在什么场景可接受。尚无具体阈值或实现证据。

## 7. 待决问题

| 问题 | 影响与阻塞范围 | 解决位置／时机 |
| --- | --- | --- |
| 地图规模及主体数量 | 阻塞性能预算和验证场景定值 | 核心机制与智能体成本明确后 |
| 旅行时间、消耗、事件与个体状态 | 阻塞大地图旅行实现，不阻塞局部地图验证 | 玩家行动及对应世界机制 |
| 非活动地图的演化和重新进入 | 阻塞区域切换方案 | 本模块、生成和保存能力 |
| 观测变化及 NPC 低成本策略 | 阻塞相关简化能力 | 智能体接口确定后 |
