# 研究平台 — 综述

> - 设计状态：讨论中
> - 适用范围：因果声明引擎、建模工作台、实验组织及研究适用性
> - 已确定范围：C++ 无界面核心与后续 Qt 工作台、模块公开量与方法、声明用途及验证边界、运行基底与函数机制的接入方向、小步联调计划
> - 尚未覆盖：持久化模型、跨语言与插件接口、实际访问核验、历史和随机细则、Qt 界面细节及具体研究验证协议
> - 上级：[整体架构](../整体架构.md)

## 1. 目标与边界

接入按研究规则声明的因果实验环境与可选智能体，提供研究配置、实验运行和证据管理。官方游戏世界只是可选的实验环境之一；研究者可以整体替换它，定义不具有空间、实体或玩法的因果系统。

[研究综述](../研究理论/研究综述.md)是项目作者亲自撰写的研究最高指导依据，原文保留。其他旧研究材料已[归档](../归档/研究理论/README.md)，其中的契约、形式化、协议及旧实现结论不直接作为新架构要求。后续从综述出发，重新讨论研究约束如何确立、如何对应实现及如何验证；本平台记录讨论结论与适用范围。

本平台以模块化声明与执行引擎接入因果环境，以轻量工作台提供浏览、编辑、检查和试运行。模块提供领域数据、方法及具体实现，引擎组织注册、引用、绑定、接口检查与执行。实验单位、分支、配对、观测协议和评价继续讨论；系统内作用的合法性及实际求值／演化由所选环境实现。实验不依赖智能体或游戏启动流程，也不以装配官方世界为前提。

## 3. 已明确的使用方向

### 自定义因果实验环境

研究者可按研究声明流程制作自己的因果系统，整体替换官方游戏世界；替换范围不限于世界内的机制或参数。只有变量、结构方程和外生随机量的非空间因果系统也属于接入目标，不应为了通过接口而虚构地图、身体或秒制时钟。

环境使用运行基底与机制函数组织生成过程；基底扩展、全局量和随机入口由 [ENV-01～05](实验环境与声明接入/设计.md#3-已确认规则)维护。具体声明格式、访问约束、干预与观测语义及求值方式仍待设计，不规定所有环境都采用固定步长或逐帧演化。

模块通过公开量与方法提供领域能力，声明的程序用途、语义说明和实现验证按 [ENV-07、08](实验环境与声明接入/设计.md#env-07-模块声明公开量与方法)分工。引擎消费有明确操作或检查用途的接口信息；领域含义可用文档说明，复杂约束可由模块代码检查，二者不自动成为实现正确性的证明。

研究准入按所选协议核验实际因果系统的声明、实现及验证证据，不以官方来源或是否具有游戏世界形式作为合格依据。审查须说明适用范围和已支持的研究保证；仅有可加载产物或声明元数据不构成合规证明，证据不足时不能授予相应资格。检查项、证据接口及自动化程度仍待协议对接确定。

模组作者负责构建可安装产物，使用者无需编译。研究侧的无界面装配继续独立于游戏菜单；共享包解析及加载能力的归属仍待确定。

### 引擎与因果建模工作台

工作台通过同一声明引擎浏览、编辑、检查和运行模型，模型文件及机制代码可脱离界面使用。首版范围、依赖视图与验证结果展示由 [WB-01～05](因果建模工作台/设计.md#3-已确认规则)维护，工具接口由 [ENV-06](实验环境与声明接入/设计.md#env-06-声明与执行能力独立于工作台)维护。

```text
因果建模工作台／无界面入口
              ↓
       声明与执行引擎
              ↓
   模型声明＋机制函数＋运行基底
```

上图表示逻辑使用关系。核心采用 C++，首个切片在 `kheker/native/` 中以独立静态库实现；后续工作台采用 Qt。共享包拆分、工作台进程边界及 Qt 界面方案待定。

### 使用世界库时的实验空间

选择世界库空间能力的实验使用有界空间及全域演化，相关规则由[空间系统](../世界/世界框架/空间系统/设计.md)维护。通过空间规模、环境分辨率和并行实例数控制成本；显示及只读观察范围不裁剪实验演化区域。非空间因果系统不因缺少几何空间而被拒绝接入。

验收时将核对实际模块组合的边界和更新计划，并在相同初态与输入等确定性条件下验证改变观察位置、范围或关闭显示不影响轨迹；这不表示每个机制每个步都必须更新。

### 使用世界时钟时的时间读出

使用[时间系统](../世界/世界框架/时间系统/设计.md)的实验，以其秒制本地时间及关系建立实验时间锚点。候选运行记录包括域身份、本地时刻、逻辑帧、相对倍率和现实耗时；配置倍率、模拟时长与吞吐率分开，不默认按现实速度运行。其他因果系统按自身声明解释求值顺序或模型时间，不强制映射成游戏逻辑帧。

现实时间采样属于运行测量；时间记录格式及协议帧号与本地秒数的对应仍待细化。

使用世界时间系统时，沿用 [TIME-03](../世界/世界框架/时间系统/设计.md#time-03-固定本地步长与步内阶段) 规定的基础固定步长，不由普通实验配置覆盖，也不将其列为世界语义声明项。

### 研究适用性与复现

依据[游戏模组政策](../游戏平台/模组管理/设计.md)，社区算法无需统一满足研究规范。本平台按具体协议检查所选模块的声明、可干预点、随机语义和验证证据；游戏加载成功不能作为满足研究要求的证据，单纯调用日志也不等于不透明算法内部的因果真值。

需要精确续跑的实验可锁定实现、配置、种子、模型、输入及摘要。改变机制或配置后按协议建立新身份或分支，不冒充原实验续跑。此策略不限制游戏按兼容路径继续原存档。

给定逐步输入的世界重放、重新运行智能体的闭环复现与统计重复性分开定义；固定版本和种子不是 GPU、多线程或任意算法位级复现的充分条件。具体保证随协议及实现证据确认。

## 4. 待决研究对接

已确认方向见各叶模块；下表维护跨模块的研究缺口。研究约束从综述重新讨论，不预先恢复旧契约条款。

| 对接项 | 当前关系／缺口 | 影响与解决时机 |
| --- | --- | --- |
| 综述到实现约束 | 哪些要求来自综述，哪些是为满足要求而提出的工程候选；如何确认和验证 | 优先讨论，作为后续状态与实体设计的研究输入 |
| 研究范围与适用条件 | 综述中的因果世界框架与通用因果实验环境接入能力如何对应 | 明确各项研究保证的适用环境，不自动把某类环境结构当作统一门槛 |
| 声明、实际执行与证据 | 具体输入输出映射、访问约束与验证方式尚未确立 | 阻塞新研究接入契约及资格认定 |
| 机制的数据来源 | 全局量读写、历史输入、机制记忆与随机请求的具体语义未定 | 影响运行条件及后续状态与实体设计 |
| 运行基底接入 | 公开量与方法的声明载体、绑定及模块校验接口待定 | 说明、程序检查及实现验证分工已明确；声明自动检查不保证基底实现正确 |
| 工具接口 | 模型目录、来源定位、编辑及诊断格式待定 | 引擎与工作台共同细化，检查规则保持单一来源 |
| 空间与时间的对接 | 世界库已有基础设计；与综述中的空间域、逻辑帧及帧内更新如何对应仍待核对 | 研究约束明确后核对，不从旧契约直接继承映射 |
| 完整状态、初态与随机条件 | 声明边界、平行轨迹条件与恢复要求待讨论 | 在状态与实体实现定稿前明确相关义务 |
| 干预、观测与评价 | 综述已给出概念与研究方向，具体执行和验收方案待讨论 | 随对应阶段细化，不沿用旧协议作为默认结论 |

引用旧材料仅用于追溯或比较；采用其中方案须重新确认其依据与适用范围。新讨论不得以旧实现已完成或旧验收通过代替研究论证。

## 5. 推进计划

首个原生接入契约与无界面执行切片已经落地，当前围绕第 1、2 步验证并细化接口；模型文件和研究执行协议仍待设计。按贡献指南先形成接口与测试，再实施；Qt 工作台在核心接口可用后接入。

| 顺序 | 工作 | 阶段完成条件 |
| --- | --- | --- |
| 1. 明确最小接入契约 | 以公开量与方法明确模块注册、数据／函数绑定、程序检查和模块校验入口，同时确定访问、目录及诊断需求 | 能区分说明与机器消费的信息；一个小模型的合法引用、调用方式与失败条件可明确表达 |
| 2. 实现无界面执行切片 | 完成加载、检查、函数执行与结果读取，使用不依赖官方世界的最小因果系统 | 能核对给定条件下的结果；错误引用或绑定有对应诊断；检查范围清楚 |
| 3. 接入轻量工作台 | 实现目录、声明及绑定编辑、依赖图、诊断与试运行，代码编辑复用现有工具 | 工作台与无界面入口共用检查和执行，编辑后的定义与视图一致 |
| 4. 扩展实验能力 | 随语义确认加入干预对比、历史与恢复、随机配对等能力，逐项补充验证 | 每项能力有明确条件与证据范围，工作台可呈现对应结果 |

第 2、3 步按可用接口交替推进。状态与实体设计在所需的研究侧访问、运行状态与恢复约束明确后恢复讨论，不以完整工作台交付为前提。各模块的实现文档记录实际代码和测量结果，本文不将计划写成完成状态。

非空间两变量示例已验证注册、调用和结果读取没有隐含绑定官方世界，见[当前落地情况](实验环境与声明接入/实现.md#3-当前落地情况)。干预、观测和研究证据核验仍需按适用协议补充，示例的独立初值运行不代表相应协议已经实现。

## 6. 关联模块

采用官方世界时，由[世界框架](../世界/世界框架/综述.md)定义演化、[运行支撑](../世界/运行支撑/综述.md)提供执行、记录与快照；[智能体](../智能体/综述.md)按需接入。通用研究接口不以世界专属状态与实体接口为唯一实现形式，复用范围与代码归属待定。

研究配置、推进、干预和真值读取不通过玩家视野或玩法事件反向获取；研究界面及权限独立设计，共享可视化仅在接口明确后复用。
