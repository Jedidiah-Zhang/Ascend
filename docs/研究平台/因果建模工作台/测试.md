# 因果建模工作台 — 测试

> - 测试状态：19 项会话用例与 12 项 Qt 交互用例在 Linux GCC Debug／Release 与 Clang ASan／UBSan 构建中全部通过；无界面 Qt 测试不替代真实桌面人工核对
> - 适用范围：无界面会话编排、类型适配、检查点分支比较、会话级记录重放与 Qt 界面交互
> - 上级：[研究平台](../综述.md) · [设计](设计.md) · [实现](实现.md)

## 1. 目的与范围

本文记录工作台首版自动化测试。会话用例覆盖状态与允许操作、配置草稿与运行身份、目录与检查、共同输入与记录、单步／有限步推进与停止、失败分类、检查点与分支干预、共同边界比较、状态字段视图与记录重放；界面用例覆盖窗口打开示例、命令到会话的映射、停止与继续、检查点与分支闭环、运行中关闭与截图证据。真实桌面下的布局、键盘操作与数值可读性人工核对、以及打包后的运行不在自动化范围内。

测试由两个程序组织：`ascend_session_tests`（无界面，19 项）与 `ascend_workbench_tests`（Qt，12 项）；命令行参数选择用例，CMake 把每个用例注册为一项 CTest。会话用例使用可复用确定性示例组件 `ascend::experiment_model`（含参考序列）与四个测试内模型（双输入、可分别触发输入与采样失败、实例化结果不确定、状态捕获可失败）；界面用例通过对象名驱动按钮、输入框与对话框，并在无界面平台（`QT_QPA_PLATFORM=offscreen`）下运行。注册清单见 [CMakeLists.txt](../../../testbench/workbench/CMakeLists.txt)。

## 2. 运行方式与验证环境

在仓库根目录执行：

```bash
cmake -S kheker/workbench -B build/workbench -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build/workbench --config Debug --parallel 4
ctest --test-dir build/workbench --build-config Debug --output-on-failure
```

也可以直接运行 `build/workbench/tests/ascend_session_tests <用例名>` 或 `build/workbench/tests/ascend_workbench_tests <用例名>`；界面用例由 CTest 注入 `QT_QPA_PLATFORM=offscreen`。会话测试不依赖 Qt，可通过 `-DASCEND_WORKBENCH_BUILD_GUI=OFF` 单独构建。测试通过编译期路径加载引擎核心、会话与示例语言资源。验证环境为 Linux x86-64，Qt 6.11.2（发行版共享库）：

| 日期与范围 | 工具链与配置 | 结果 |
| --- | --- | --- |
| 2026-09-30，会话编排首版与文本域接入（19 项：适配器、配置修订、运行控制、分支比较、失败分类、多输入与记录重放、文本回退、自主重放、部分输入记录与异常边界） | GCC 16.2.1 Debug | 19/19 通过 |
| 2026-09-30，同上 | GCC 16.2.1 Release | 19/19 通过 |
| 2026-09-30，同上 | Clang 22.1.8 RelWithDebInfo，AddressSanitizer＋UndefinedBehaviorSanitizer | 19/19 通过，无 sanitizer 报告 |
| 2026-09-30，Qt 界面首版与文案迁移（12 项交互用例） | GCC 16.2.1 Debug | 12/12 通过 |
| 2026-09-30，同上 | GCC 16.2.1 Release | 12/12 通过 |
| 2026-09-30，同上 | Clang 22.1.8 RelWithDebInfo，AddressSanitizer＋UndefinedBehaviorSanitizer | 12/12 通过，无 sanitizer 报告；修复了界面构造中的一处布局对象泄漏与未启动析构的会话资源泄漏 |

上限测量（`session.limits`，单分支 10000 步、10001 个采样与 10000 条输入记录，测量含进程启动与语言资源加载，非全程吞吐测量）：GCC 16.2.1 Release 用时约 0.02 秒、Debug 约 0.17 秒；进程峰值常驻内存约 24 MiB（两种配置）。界面侧上限测量（`workbench.runNThroughput`，一次运行到 10000 边界并生成 10001 行结果表格，离屏平台，含 Qt 运行时与界面侧轨迹副本）：GCC 16.2.1 Release 用时约 0.04 秒、Debug 约 0.22 秒；进程常驻内存约 90 MiB（两种配置相近）。时间轴全量视图绘制（同一用例，10000 边界、3 个信号、源序列，574×240 像素，密集区间按像素列聚合）：Release 约 1 毫秒、Debug 约 3 毫秒；绘制成本随像素数与序列数增长，不随边界数增长。停止响应测量（`workbench.stopDuringRun`，请求在运行开始后立即发出，从点击停止到界面恢复空闲）：GCC 16.2.1 Debug 与 Release 均约 5 毫秒（无界面平台，含事件调度，不代表机制调用本身的耗时）。测量仅覆盖目标示例，不代表其他模型的成本。界面响应与停止在无界面平台的交互用例中验证；真实桌面下的显示与交互人工核对结果待用户执行后记录。

独立工作台 CI 配置见 [workbench.yml](../../../.github/workflows/workbench.yml)：在 Linux 与 Windows 安装 Qt 6.8.3 后构建并运行同一测试集（引擎源码随工作台以子项目构建）。CI 配置本身不代表这些平台已在本地验证；平台覆盖结果以实际 CI 运行为准。

## 3. 用例

### session.adapter_int64

内建 64 位整数适配器：空文本、空白、小数、非数字与越界文本被拒绝并给出原因；上下界、显式正号与负零按精确值解析；显示与判等保持精确，超过 2^53 的曲线坐标标记为近似；未登记类型不提供查找结果。当前通过。它固定首版类型适配与编辑器精度边界。

### session.load_and_check

打开示例后处于可运行状态并建立运行编号 1；检查通过且报告包含工厂与装配、实验规格两类检查项；目录包含五个作用域路径，推进入口的说明按中文语言资源解析；实例视图包含 plant 与 input 的构造配置；输入与观测名与规格一致；构造时语言资源加载无诊断。当前通过。它是目录、检查与语言资源接入的首版证据。

### session.config_revision

相同配置不产生新修订；修改构造配置后草稿修订递增并标记陈旧，目录仍对应旧修订，旧运行继续按旧配置推进；应用重建产生新运行编号、轨迹与检查点重置，新配置在推进中生效；未登记实例给出诊断且不改变修订。当前通过。它对应场景 B 的“旧结果与新配置区分”要求。

### session.step_run_stop

相同配置与输入下逐一单步与运行 N 步得到相同轨迹；停止请求在步骤边界生效，返回实际完成步数并进入已停止，继续运行后与单步会话结果一致。当前通过。它对应运行控制、停止语义与“读取次数不影响演化”。

### session.checkpoint_branches

场景 A 主体：推进到边界 2 后建立检查点，可干预字段显示 x 的精确当前值；建立对照与干预（x := 10）分支后探索轨迹保留、分支起点分别为 `(2,1,0)` 与 `(10,1,0)`；同步推进到边界 5，对照为 `(5,4,6)`、干预为 `(13,12,22)`；同边界差值为 `(8,0,0)`、`(8,8,0)`、`(8,8,8)`、`(8,8,16)`；检查点在分支运行后不变，真值详情可见 x 的直接变化；分支模式拒绝新检查点；从检查点重建分支后轨迹回到起点并清空输入记录。当前通过。它是分支隔离、干预传播与比较的首版端到端证据。

### session.branch_order

交换分支创建顺序后各自结果不变；探索运行继续推进到边界 5 不改变检查点，分支从边界 2 恢复。当前通过。它对应“交换分支执行顺序仍得到相同结果”与“原实例继续运行不改变检查点”。

### session.intervention_errors

无状态容器、缺失字段、缺失模块、新值与现有值类型不一致、分支数量不为两个分别被拒绝；失败后会话保持源模式并可成功建立分支。当前通过。它固定 ENV-12 与首版分支数量约束下的会话级失败行为。

### session.partial_branch_failure

干预分支在推进中溢出：命令停止且保留两分支各自真实边界（对照 4、干预 3），失败状态禁止推进，比较只覆盖共同有效边界并把仅一方有的边界列入未配对；已记录采样逐边界核对，失败步骤的输入范围列入说明（结果状态为部分核对）；从检查点重建分支恢复可运行；样本序列下拉在分支建立后列出运行／对照／干预三条序列。当前通过。它对应“部分成功保留各自边界、只在共同有效边界比较”。

### session.failure_paths

示例模型溢出报 `x + a` 诊断并停留原边界、不追加采样；测试模型分别触发输入失败（边界不前进）与采样失败（推进已完成、边界前进、记录缺该边界采样），逐步事件类型与计数对应。当前通过。它对应场景 C 的“不误报边界完成／推进”与失败分类要求。

### session.record_inputs

两次运行中使用不同共同输入（1、1、2、2）：记录按驱动前边界与顺序保存实际值，轨迹反映实际输入（x 依次为 0、1、2、4、6）。当前通过。它是“不把计划输入当作实际执行记录”的证据。

### session.replay

场景 A 全流程重放通过并核对 8 个边界，重放不修改当前运行；观测依赖进程级计数、两次实例化结果不同的模型在首个边界报告不一致分支与字段；模板缺少已核对实现标识时检查与重建失败。当前通过。它是记录追溯与重放首版的主要证据。

### session.state_rules

空会话只允许打开；外部输入可选（未设置时按模块自身配置值推进，示例 a = 1）；检查不改变轨迹；失败状态禁止推进与检查点、允许检查与重建；输入类型不匹配与未知输入被拒绝。当前通过。它固定会话状态机与允许操作表。

### session.limits

单次步数 0 与超限被拒绝；一次运行到 10000 边界后继续推进被上限拒绝且边界不变。当前通过。它锁定首版步数与边界上限，测量结果见第 2 节。

### session.dual_input_replay

双输入规格（`a`、`b`）在同一驱动前边界上各记录一条输入：推进两边界后按记录重放，同一边界上的两项输入按顺序驱动后只推进一次，重放核对 3 个边界并通过。当前通过。它是多输入记录与重放按边界分组语义的回归。

### session.comparison_limits

对照与干预分支分别取 64 位下界与上界：起点差值超出 64 位时标注“差值超出 64 位”且不给出可比较结果，其余变量差值正常。当前通过。它覆盖差值的溢出与不可比较标注。

### session.localized_texts

不加载会话语言资源、语言为 `en` 时，检查项、检查范围与轨迹标签使用英文默认模板；加载 zh-CN 资源后同一批文本为中文，干预与对照的默认分支标签也按文本域给出。当前通过。它是会话层结构化文本与语言回退的证据。

### session.autonomous_replay

不设置任何输入自主推进 3 步后重放：无共同输入记录也逐边界核对全部 4 个采样，结果状态为完整（`complete`）且无未比较说明；先自主演化、随后驱动输入的混合记录同样逐边界核对全部 5 个采样。当前通过。它覆盖“重放不依赖输入记录决定推进次数”。

### session.partial_input_records

双输入步骤中 `a` 成功、`b` 失败：失败步骤不产生采样，但已成功驱动的 `a` 保留在共同输入记录中（边界 0、值 7）；重放核对已记录的采样。当前通过。它覆盖“逐输入记录实际执行结果”。

### session.exception_boundaries

状态捕获抛错时：创建检查点与建立分支的首次采样都转换为诊断返回，不逃出会话接口，运行状态、检查点与轨迹保留，恢复后可再次成功。当前通过。它覆盖会话接口的异常边界。

## 4. Qt 界面用例

界面用例通过对象名定位控件，点击按钮或编辑文本框驱动控制层，并在无界面平台下等待命令完成；断言读取窗口发布的状态与表格内容。

### workbench.windowLoadsExample

启动后自动打开示例：状态为可运行，模块树只含模块与公开符号（方法在前、斜体带括号，需求与连接不入树），需求与连接按模块分组非空，规格页签列出推进入口、输入与观测，结果表格有初值行，时间轴信号树列出观测且游标读数表非空，样本序列下拉列出运行序列；点击「检查」后检查表出现工厂与装配、实验规格等检查项；修改初态字段后模块树页签标注“目录陈旧”。当前通过。它是窗口到会话打开、检查命令映射、时间轴初始状态与目录陈旧标注的证据。

### workbench.stepAndVariableSwitch

世界按自身配置值（a = 1）单步：边界为 1、结果表格新增边界 1 行且观测为 `(1,0,0)`；在时间轴信号树切换显示信号后边界、行数与已显示的值不变。当前通过。它对应“命令映射”与“切换显示变量不改变演化结果”。

### workbench.stopDuringRun

请求运行 10000 步并请求停止：运行中切换标签页请求只读快照不会禁用停止按钮；窗口在超时内恢复空闲，状态为已停止、实际完成边界小于请求步数；继续单步后边界加一。当前通过。它验证停止按钮、停止在步骤边界生效、只读快照与运行命令的忙碌标记分离及控制层的状态管理。

### workbench.runNThroughput

单次运行到 10000 边界：边界与结果表格行数（10001 行）符合上限，记录耗时、常驻内存与时间轴全量视图绘制耗时；该用例同时是界面侧上限路径、大批量增量与波形密集绘制的回归。当前通过，测量结果见第 2 节。

### workbench.branchComparisonAndReplay

推进到边界 2、创建检查点，经分支对话框选择 `plant/state` 的 `x` 设为 `10`：出现探索、对照与干预三条序列，状态与干预页显示“由 2 改为 10”的干预位置与前值／新值；推进到边界 5 后结果表格显示对照 `(5,4,6)`、干预 `(13,12,22)`，共同边界差值行为 `8`、`8`、`16`；点击「重放」提示重放成功；点击「从检查点重建」后分支轨迹回到共同起点并可继续运行。当前通过。它是场景 A 经界面完整闭环的端到端证据。

### workbench.failedStateControls

通过初始配置表单把 `x` 改为 64 位上限并应用，提交输入后推进：会话进入失败状态，单步、检查点与分支按钮禁用，重建与重放可用，诊断列表出现记录；把配置修正为 0 并重建后恢复可运行、单步可用。当前通过。它对应场景 B、C 的界面状态限制、配置编辑命令映射与失败后重建路径。

### workbench.closeWhileRunning

运行 10000 步期间关闭窗口：关闭流程请求停止、等待当前操作返回并结束专属线程，窗口不再忙碌且不可见。当前通过。它覆盖关闭时的线程与对象生命周期。

### workbench.abandonedWorkbench

构造工作台但不启动即析构：控制层与会话资源被释放（消毒器构建下验证无泄漏）。当前通过。它覆盖未启动析构的生命周期路径。

### workbench.uiTextFallback

界面文案按 `ascend.workbench` 文本域解析：加载 zh-CN 资源时为中文，未加载或语言为 `en` 时使用英文默认模板，未知键与损坏资源路径都回退默认模板并记录加载错误。当前通过。它是界面文案语言资源与回退规则的证据。

### workbench.resourceResolution

语言资源随构建复制到可执行文件同目录的 `resources/`：运行时解析到的四份资源都位于可执行目录之下且可加载；运行目录缺失时回退编译期源码路径；运行目录副本的修改在重启后生效（构建会刷新副本）。当前通过。它是资源布局、运行目录优先解析与源码回退的证据。

### workbench.menuBarStructure

菜单栏包含文件、编辑、查看与运行四个菜单；运行菜单的实装命令与按钮同源（触发“单步”等同点击按钮），文件与编辑菜单的未实装项禁用占位并带后续阶段提示；查看菜单的面板开关为勾选项，模拟鼠标点击后状态面板（停靠窗口）隐藏且菜单保持展开，再次点击恢复；状态面板可拆分浮动并恢复停靠；配置为停靠面板、结果为主工作区，底部面板同样可开关。当前通过。它是菜单结构、占位约定、命令同源与面板开关行为的证据。

### workbench.captureScreenshot

按场景 A 建立双分支并推进到边界 5，分别保存曲线视图与结果表格视图的窗口截图（CTest 输出到构建目录）；截图同时作为布局人工核对材料。当前通过（离屏渲染）。

## 5. 人工核对与后续范围

自动化覆盖接口行为与离屏交互；真实桌面下的布局可读性、键盘操作、曲线与诊断文字、以及不同平台字体下的显示仍需人工核对，核对结果与平台覆盖在完成后追加到第 2 节。界面截图（曲线与表格视图）保存在构建目录，可随本轮交付一并查看。Qt 界面测试不模拟真实窗口系统，不替代桌面验收；实验文件持久化、声明与绑定编辑及依赖图的用例待相应功能落地后建立。
