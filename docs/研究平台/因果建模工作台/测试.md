> - 测试状态：26 项会话用例与 21 项 Qt 交互用例在 Linux GCC Debug／Release 与 Clang ASan／UBSan 构建中全部通过；无界面 Qt 测试不替代真实桌面人工核对

## 1. 目的与范围

本文记录工作台首版自动化测试。会话用例覆盖状态与允许操作、配置草稿与运行身份、目录与检查、共同输入与记录、单步／有限步推进与停止、失败分类、检查点与分支干预、共同逻辑帧比较、状态字段视图与记录重放、实验文件保存与打开结果分类与失败路径、模块包载入（多选文件与文件夹）与卸载、因果系统装配（新建、实例增删、需求接线与规格）与因果系统文件（`.aasm`）打开／保存；界面用例覆盖窗口打开示例、命令到会话的映射、停止与继续、检查点与分支闭环、文件保存／打开成功与失败路径、模块包载入（多选与文件夹）与卸载、开始页与研究流程、系统编辑器、中央工作区页签与停靠面板开关、运行中关闭与截图证据。真实桌面下的布局、键盘操作与数值可读性人工核对、以及打包后的运行不在自动化范围内。

测试由两个程序组织：`ascend_session_tests`（无界面，26 项）与 `ascend_workbench_tests`（Qt，21 项）；命令行参数选择用例，CMake 把每个用例注册为一项 CTest。会话用例使用可复用确定性示例组件 `ascend::experiment_model`（含参考序列）与四个测试内模型（双输入、可分别触发输入与采样失败、实例化结果不确定、状态捕获可失败）；界面用例通过对象名驱动按钮、输入框与对话框，并在无界面平台（`QT_QPA_PLATFORM=offscreen`）下运行。注册清单见 [CMakeLists.txt](../../../testbench/workbench/CMakeLists.txt)。

## 2. 运行方式与验证环境

在仓库根目录执行：

```bash
cmake -S kheker/workbench -B build/workbench -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build/workbench --config Debug --parallel 4
ctest --test-dir build/workbench --build-config Debug --output-on-failure
```

## 3. 用例

### session.adapter_int64

内建 64 位整数适配器：空文本、空白、小数、非数字与越界文本被拒绝并给出原因；上下界、显式正号与负零按精确值解析；显示与判等保持精确，超过 2^53 的曲线坐标标记为近似；未登记类型不提供查找结果。当前通过。它固定首版类型适配与编辑器精度边界。

### session.load_and_check

打开示例后处于可运行状态并建立运行编号 1；检查通过且报告包含工厂与装配、实验规格两类检查项；目录包含五个作用域路径，推进入口的说明按中文语言资源解析；实例视图包含 plant 与 input 的构造配置；输入与观测名与规格一致；构造时语言资源加载无诊断。当前通过。它是目录、检查与语言资源接入的首版证据。

### session.config_revision

相同配置不产生新修订；修改构造配置后草稿修订递增并标记陈旧，目录仍对应旧修订，旧运行继续按旧配置推进；应用重建产生新运行编号、轨迹与检查点重置，新配置在推进中生效；未登记实例给出诊断且不改变修订。当前通过。它对应场景 B 的“旧结果与新配置区分”要求。

### session.step_run_stop

相同配置与输入下逐一单步与运行 N 步得到相同轨迹；停止请求在逻辑帧边界生效，返回实际完成步数并进入已停止，继续运行后与单步会话结果一致。当前通过。它对应运行控制、停止语义与“读取次数不影响演化”。

### session.checkpoint_branches

场景 A 主体：推进到逻辑帧 2 后建立检查点，可干预字段显示 x 的精确当前值；建立对照与干预（x := 10）分支后探索轨迹保留、分支起点分别为 `(2,1,0)` 与 `(10,1,0)`；同步推进到逻辑帧 5，对照为 `(5,4,6)`、干预为 `(13,12,22)`；同一逻辑帧差值为 `(8,0,0)`、`(8,8,0)`、`(8,8,8)`、`(8,8,16)`；检查点在分支运行后不变，真值详情可见 x 的直接变化；分支模式拒绝新检查点；从检查点重建分支后轨迹回到起点并清空输入记录。当前通过。它是分支隔离、干预传播与比较的首版端到端证据。

### session.branch_order

交换分支创建顺序后各自结果不变；探索运行继续推进到逻辑帧 5 不改变检查点，分支从逻辑帧 2 恢复。当前通过。它对应“交换分支执行顺序仍得到相同结果”与“原实例继续运行不改变检查点”。

### session.intervention_errors

无状态容器、缺失字段、缺失模块、新值与现有值类型不一致、分支数量不为两个分别被拒绝；失败后会话保持源模式并可成功建立分支。当前通过。它固定 ENV-12 与首版分支数量约束下的会话级失败行为。

### session.partial_branch_failure

干预分支在推进中溢出：命令停止且保留两分支各自实际到达的逻辑帧（对照 4、干预 3），失败状态禁止推进，比较只覆盖共同有效逻辑帧并把仅一方有的逻辑帧列入未配对；已记录采样逐逻辑帧核对，失败步骤的输入范围列入说明（结果状态为部分核对）；从检查点重建分支恢复可运行；样本序列下拉在分支建立后列出运行／对照／干预三条序列。当前通过。它对应“部分成功保留各自实际到达的逻辑帧、只在共同有效逻辑帧比较”。

### session.failure_paths

示例模型溢出报 `x + a` 诊断并停留原逻辑帧、不追加采样；测试模型分别触发输入失败（逻辑帧不前进）与采样失败（推进已完成、逻辑帧前进、记录缺该逻辑帧采样），逐步事件类型与计数对应。当前通过。它对应场景 C 的“不误报已完成逻辑帧／推进”与失败分类要求。

### session.record_inputs

两次运行中使用不同共同输入（1、1、2、2）：记录按驱动前逻辑帧与顺序保存实际值，轨迹反映实际输入（x 依次为 0、1、2、4、6）。当前通过。它是“不把计划输入当作实际执行记录”的证据。

### session.replay

场景 A 全流程重放通过并核对 8 个逻辑帧，重放不修改当前运行；观测依赖进程级计数、两次实例化结果不同的模型在首个逻辑帧报告不一致分支与字段；模板缺少已核对实现标识时检查与重建失败。当前通过。它是记录追溯与重放首版的主要证据。

### session.state_rules

空会话只允许打开；外部输入可选（未设置时按模块自身配置值推进，示例 a = 1）；检查不改变轨迹；失败状态禁止推进与检查点、允许检查与重建；输入类型不匹配与未知输入被拒绝。当前通过。它固定会话状态机与允许操作表。

### session.limits

单次步数 0 与超限被拒绝；一次运行到 10000 逻辑帧后继续推进被上限拒绝且逻辑帧不变。当前通过。它锁定首版步数与逻辑帧上限，测量结果见第 2 节。

### session.dual_input_replay

双输入规格（`a`、`b`）在同一驱动前逻辑帧上各记录一条输入：推进两个逻辑帧后按记录重放，同一逻辑帧上的两项输入按顺序驱动后只推进一次，重放核对 3 个逻辑帧并通过。当前通过。它是多输入记录与重放按逻辑帧分组语义的回归。

### session.comparison_limits

对照与干预分支分别取 64 位下界与上界：起点差值超出 64 位时标注“差值超出 64 位”且不给出可比较结果与精确整数视图，其余变量差值正常。当前通过。它覆盖差值的溢出与不可比较标注及精确整数视图。

### session.localized_texts

不加载会话语言资源、语言为 `en` 时，检查项、检查范围与轨迹标签使用英文默认模板；加载 zh-CN 资源后同一批文本为中文，干预与对照的默认分支标签也按文本域给出。当前通过。它是会话层结构化文本与语言回退的证据。

### session.autonomous_replay

不设置任何输入自主推进 3 步后重放：无共同输入记录也逐逻辑帧核对全部 4 个采样，结果状态为完整（`complete`）且无未比较说明；先自主演化、随后驱动输入的混合记录同样逐逻辑帧核对全部 5 个采样。当前通过。它覆盖“重放不依赖输入记录决定推进次数”。

### session.partial_input_records

双输入步骤中 `a` 成功、`b` 失败：失败步骤不产生采样，但已成功驱动的 `a` 保留在共同输入记录中（逻辑帧 0、值 7）；重放核对已记录的采样。当前通过。它覆盖“逐输入记录实际执行结果”。

### session.exception_boundaries

状态捕获抛错时：创建检查点与建立分支的首次采样都转换为诊断返回，不逃出会话接口，运行状态、检查点与轨迹保留，恢复后可再次成功。当前通过。它覆盖会话接口的异常边界。

### session.save_open_round_trip

场景 A 保存为实验文件后在新会话打开：实现标识与重放核对通过，接管为活动运行（两分支逻辑帧 5），比较差值仍为 `8`；继续推进到逻辑帧 6 并可再次保存；保存内容包含探索轨迹、共同输入与会话检查点。当前通过。它覆盖“重新打开后继续实验”。

### session.open_record_state

含推进失败记录的文件打开为只读记录态：状态为记录态、禁止单步与运行、禁止创建检查点；轨迹与结构化失败事件可查看、重放可用；应用重建后回到可运行。当前通过。它覆盖记录态结果与失败记录的恢复路径。

### session.open_rejects_and_falls_back

实现标识不匹配与采样不一致的文件都只进入只读记录态并给出说明；空轨迹文件被拒绝且当前会话保持不变。当前通过。它覆盖打开结果分类与“打开失败不改变当前会话”。

### session.module_packages

模块库（ENV-18）：载入示例模块包后概要含定义标识、版本、实现标识与状态能力，声明／需求／资源计数正确；重复载入报诊断且列表不变；卸载后列表清空、再次卸载报诊断；未提供模块库的模板拒绝载入与卸载命令。当前通过。它覆盖工作台侧模块包载入／卸载的会话命令与视图。

### session.system_assembly

因果系统装配（WB-18 切片 A）：可用模块含宿主内置与模块库注册；空会话中编辑命令返回诊断且状态、修订与系统名不变（本地化文案，未确立身份前不进入编辑态）；新建系统清空草稿与规格并进入编辑态；未知定义、非法实例名与重名被拒绝；需求接线支持替换与重复断开，提供方实例不存在时拒绝；未接线检查失败、接上后通过；推进入口与观测显式设置，输入按公开单参数方法自动推导（`input.drive`）；应用后推进与观测与示例参考一致；结构编辑使草稿修订递增并进入未应用状态，移除实例一并移除其连接；模块库定义在载入包前因缺少宿主核对的实现标识被检查拒绝，载入包后由清单提供并通过；再次新建系统放弃运行与记录；未应用的草稿变化不改变当前运行（运行沿用已应用规格，草稿新增输入不被驱动）。当前通过。它覆盖装配编辑命令、工厂合并与实现标识解析的会话行为。

### session.system_file

因果系统文件（`.aasm` 切片 A）：编码当前装配草稿再打开到新会话——实例与连接往返一致、状态进入编辑态、系统名沿用或更新；规格不随系统保存（重新打开后推进入口为空、输入由公开方法推导），补齐规格后检查、应用与推进通过；解析失败不改变当前会话，未给名称时沿用现有系统名。当前通过。它覆盖 `encode_system`／`open_system` 与系统文件边界。

### session.open_exploration_only

只含探索轨迹的文件（无分支）按无分支单运行接管：状态为可运行、单条轨迹恢复到记录末端并可继续推进，重放完全通过；采样不一致时只进入只读记录态且重放报告不一致；探索加单分支的文件进入只读记录态（接管要求无分支单运行或双分支）。当前通过。它覆盖打开结果的接管边界与记录态回退。

## 4. Qt 界面用例

界面用例通过对象名定位控件，点击按钮或编辑文本框驱动控制层，并在无界面平台下等待命令完成；断言读取窗口发布的状态与表格内容。

### workbench.windowLoadsExample

新窗口从空白打开：状态为空、模块树为空、单步按钮不可用；经「文件 → 打开示例」后状态为可运行，模块树只含模块与公开符号（方法在前、斜体带括号，需求与连接不入树），需求与连接按模块分组非空，规格页签列出推进入口、输入与观测，时间轴信号树列出观测且游标读数表给出起点读数（无检查点时不显示参考线与分支区间），样本序列下拉列出运行序列；点击「检查」后检查表出现工厂与装配、实验规格等检查项；修改初态字段后模块树页签标注“目录陈旧”。当前通过。它是窗口到会话打开、检查命令映射、时间轴初始状态与目录陈旧标注的证据。

### workbench.stepAndVariableSwitch

世界按自身配置值（a = 1）单步：逻辑帧为 1、采样数为 2、游标读数在逻辑帧 1 的观测为 `(1,0,0)`；在时间轴信号树切换显示信号后逻辑帧、采样数与已显示的值不变。当前通过。它对应“命令映射”与“切换显示变量不改变演化结果”。

### workbench.stopDuringRun

### workbench.runNThroughput

单次运行到 10000 逻辑帧：逻辑帧与采样数（10001）符合上限，记录耗时、常驻内存与时间轴全量视图绘制耗时；该用例同时是界面侧上限路径、大批量增量与波形密集绘制的回归。当前通过，测量结果见第 2 节。

### workbench.branchComparisonAndReplay

推进到逻辑帧 2、创建检查点，经分支对话框选择 `plant/state` 的 `x` 设为 `10`：出现探索、对照与干预三条序列，状态与干预页显示“由 2 改为 10”的干预位置与前值／新值；推进到逻辑帧 5 后游标读数显示对照 `(5,4,6)`、干预 `(13,12,22)`，共同逻辑帧差值行为 `8`、`8`、`16`；信号树在分支后增加差值组，差值曲线读数在游标 B（逻辑帧 5）给出 `8`、`8`、`16`，游标 A 停在非共同帧时读数为空；点击检查点参考线后游标 A 定位到逻辑帧 2，差值读数随之给出 `8`；点击「重放」提示重放成功；点击「从检查点重建」后分支轨迹回到共同起点并可继续运行。当前通过。它是场景 A 经界面完整闭环的端到端证据。

### workbench.failedStateControls

通过初始配置表单把 `x` 改为 64 位上限并应用，提交输入后推进：会话进入失败状态，单步、检查点与分支按钮禁用，重建与重放可用，诊断列表出现记录；把配置修正为 0 并重建后恢复可运行、单步可用。当前通过。它对应场景 B、C 的界面状态限制、配置编辑命令映射与失败后重建路径。

### workbench.closeWhileRunning

运行 10000 步期间关闭窗口：关闭流程请求停止、等待当前操作返回并结束专属线程，窗口不再忙碌且不可见。当前通过。它覆盖关闭时的线程与对象生命周期。

### workbench.abandonedWorkbench

构造工作台但不启动即析构：控制层与会话资源被释放（消毒器构建下验证无泄漏）。当前通过。它覆盖未启动析构的生命周期路径。

### workbench.uiTextFallback

界面文案按 `ascend.workbench` 文本域解析：加载 zh-CN 资源时为中文，未加载或语言为 `en` 时使用英文默认模板，未知键与损坏资源路径都回退默认模板并记录加载错误。当前通过。它是界面文案语言资源与回退规则的证据。

### workbench.resourceResolution

## 5. 人工核对与后续范围

已知 Qt 回归（QTBUG-143776，6.11.3 修复）：6.10.2～6.11.2 下极端拖拽／标签化停靠面板可能崩溃，人工核对时注意规避，升级 Qt 后复测标签化与浮动分组。自动化覆盖接口行为与离屏交互；真实桌面下的布局可读性、键盘操作、曲线与诊断文字、以及不同平台字体下的显示仍需人工核对，核对结果与平台覆盖在完成后追加到第 2 节。界面截图（曲线与表格视图）保存在构建目录，可随本轮交付一并查看。Qt 界面测试不模拟真实窗口系统，不替代桌面验收；声明与绑定编辑及依赖图的用例待相应功能落地后建立。
