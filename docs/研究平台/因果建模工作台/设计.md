## 1. 目标与意义

工作台为研究者提供浏览和操作因果模型的界面，呈现模型结构、检查结果和小规模运行结果。研究者不写代码也应该能看见模型由哪些变量与机制组成、哪里有问题；而模型本身必须独立于界面存在，关闭工作台后仍可加载和运行。

运行基底是实验环境运行所需的基础能力；因果机制的代码实现及其接入规则由[实验环境与声明接入](../实验环境与声明接入/设计.md)维护。首版面向小型模型，完整代码编辑、断点调试和大规模实验管理留待后续评估。

## 3. 概念与术语

模型目录汇集已加载模型中的变量、机制、全局量和运行基底操作。绑定表示机制函数的输入、输出与模型变量之间的对应关系。依赖视图展示模型声明中的变量关系；执行视图记录某次运行的结果、诊断和实际路径。诊断说明检查或运行中发现的问题，并标明对应对象与覆盖范围。

模型声明、运行基底和机制函数的含义见[接入设计](../实验环境与声明接入/设计.md#3-概念与术语)；本设计规定工作台如何编辑与呈现模型。

首版新增以下会话概念：配置草稿是可编辑的装配定义与运行条件；草稿修订标识草稿内容的版本，运行编号标识一次已实例化运行及其结果；共同起点（检查点）是建立分支前的完整状态位置；轨迹是某分支逐逻辑帧的真值与观测采样；差值按共同逻辑帧计算“干预 − 对照”。

## 4. 已确认规则

### WB-01 首版采用轻量范围

首版包括变量与机制目录、声明和输入输出绑定编辑、依赖图浏览、检查结果及错误定位、单机制或小模型试运行。目录同时提供已声明全局量和基底操作的信息；历史与随机来源按引擎已支持的声明能力展示。

机制函数优先通过现有代码编辑器编写和修改，工作台提供来源定位或跳转。内置完整编辑器、代码补全、断点调试与复杂图形编程另行评估。

### WB-02 引擎维护检查与执行规则

工作台、命令行和批量程序调用同一引擎接口，取得模型目录、依赖、检查结果与运行结果。引擎提供检查、装配和调用能力；环境代码与运行基底依据环境规则组织计算顺序并执行领域计算。接口边界见 [ENV-06](../实验环境与声明接入/设计.md#env-06-声明与执行能力独立于工作台)。

### WB-03 编辑与视图使用同一模型定义

声明、绑定和依赖图以同一份模型定义为依据。编辑操作更新这份定义，目录和视图再由更新后的定义生成；图形连线也遵循同一数据来源。

模型定义与机制代码分别保存和加载，模型可通过工作台或无界面入口运行；文件格式与加载方式遵循 [ENV-06](../实验环境与声明接入/设计.md#env-06-声明与执行能力独立于工作台)。界面布局等工具设置单独管理。

### WB-04 展示验证范围与来源

工作台分别呈现模型声明检查、运行诊断和研究验证结果，并说明各自的检查范围与依据。目录可展示模块文档和代码中的说明，并按当前语言解析模块文本域内的结构化消息，链接到公开量、类型与形状信息及方法入口。诊断保留各层原因的归属与来源，文案加载和回退遵循[模块文案与诊断展示](../实验环境与声明接入/设计.md#模块文案与诊断展示)。结果分类遵循 [ENV-08](../实验环境与声明接入/设计.md#env-08-语义说明程序检查与实现验证分工)。

每项诊断关联对应的模型对象；引擎提供来源信息时，工作台可以定位到相应声明或函数。来源位置、检查状态和证据字段尚待定稿。

### WB-05 区分声明依赖与实际运行

依赖图展示模型声明中记录的生成关系；执行视图展示给定条件下实际经过的计算和访问。依赖图呈现模型声明的全部分支，执行视图呈现本次运行经过的路径；声明依赖的覆盖范围由相应访问约束或验证证据说明。

组合树展示模块实例的归属和边界，接口连接图展示需求与提供方之间的连接，因果图展示模型声明的生成关系。三类视图分别说明装配、接口和因果结构；计算顺序由环境实现定义。

### WB-06 工程入口与依赖方向

工作台与无界面会话编排位于 `kheker/workbench/`：会话编排为不依赖 Qt 的 C++17 静态库，Qt 应用单独作为一个目标并链接会话库与 `ascend::engine`；测试位于 `testbench/workbench/`，构建产物写入 `build/workbench/`。依赖方向为 Qt 视图与控制层 → 无界面会话编排 → 引擎与示例模块；引擎公共接口不引入 Qt 类型或事件循环，引擎与工作台各自保留独立构建入口，工作台构建在引擎目录之外完成。

首版界面采用 Qt 6 Widgets，使用 Widgets 与 Test 模块；不引入 Qt Charts 等附加模块，变量曲线用自绘控件实现。最低 Qt 版本按 6.4 及以上核对（不使用 6.4 之后新增的 API），开发环境为 6.11.2；CI 实际安装版本记录在实现与测试文档。可复用示例组件（确定性三变量模型、装配、实验规格与参考序列）由引擎示例目录提供，供命令行示例、工作台与测试共同使用；独立参考计算继续单独维护。

### WB-07 首版交互实验闭环

首版交付一次可操作、可核对的进程内实验闭环：打开内置确定性示例，浏览模块、公开量、方法、需求与接口连接；编辑初态配置与运行步数；检查并重建运行；单步、运行有限步并在逻辑帧边界停止；在检查点建立对照与干预分支；比较两分支轨迹与逻辑帧差异；从会话记录重建运行并逐逻辑帧核对重放。会话与记录可保存为实验文件并重新打开（WB-16）；窗口标题与记录汇总行显示当前文件与未保存状态，界面不设常驻提示。

界面以停靠面板组织：中央主工作区为浏览器式页签（开始页默认打开并置前，引导新建研究与打开研究；时间轴与逻辑帧差异在出现运行或记录时自动打开，空会话或新建系统尚无运行时不保留，标注当前逻辑帧、分支与共同起点；页签可拖动重排、可关闭并从查看菜单重开，至少保留一个页签），模块库（已载入模块包概要表与载入／卸载；载入可多选文件或选择文件夹）与系统编辑器（因果系统装配；见 [WB-18](#wb-18-因果系统装配编辑切片-a)）为其页签、默认不打开，载入模块包或经菜单打开时切换过去；模块管理器（模块树、规格、按模块分组的需求与连接）在左侧、配置（初始配置表单）与状态（选中项详情、状态字段、干预编辑与分支信息、真值与观测）在右侧同区标签化、诊断（诊断列表与原因链、检查、实际输入记录）在底部，均为可停靠、可浮动、可嵌套与合并（标签化）的停靠面板，由查看菜单开关；顶部为检查、重建、单步、运行 N 步、停止、检查点、分支与重放操作。布局是实现指导，调整布局不改变本节及其余规则定义的会话行为。

以现有接口连接展示装配关系；因果生成关系和实际执行路径只在有对应声明或记录依据时展示，不从接线图推定完整因果图（沿用 [WB-05](#wb-05-区分声明依赖与实际运行)）。

### WB-08 会话状态、身份与允许操作

会话持有配置草稿与已实例化运行两类身份：配置改变产生新的草稿修订，已有运行记录其来源修订与运行编号并继续有效；修改草稿不改变已有结果，只有显式应用并重建才使新配置作用于新运行，界面区分陈旧结果与新配置。目录与检查针对当前草稿，结果视图与轨迹关联其运行身份。

会话状态及允许操作：

| 状态 | 允许 | 禁止（返回会话诊断且状态不变） |
| --- | --- | --- |
| 空会话 | 打开示例、打开实验文件、新建／打开因果系统、载入／卸载模块包 | 装配编辑与其余操作（返回会话诊断且状态不变） |
| 可编辑（无有效运行） | 编辑、检查、应用并重建 | 单步、运行、检查点、分支、重放 |
| 可运行 | 编辑、检查、应用重建、单步、运行 N 步、创建检查点、建立分支、重放、从检查点重建 | 不适用 |
| 已停止 | 同可运行（可继续单步或运行） | 不适用 |
| 失败 | 编辑、检查、应用重建、从检查点重建分支、重放 | 单步、运行 N 步、创建检查点、建立分支 |
| 记录态（打开实验文件） | 编辑、检查、应用重建、从检查点重建分支、重放、只读查看轨迹／差值／时间轴 | 单步、运行 N 步、创建检查点、建立分支 |
| 运行中（控制层） | 停止、关闭窗口 | 其余操作（界面禁用，命令完成后恢复） |

每次操作返回操作后的确定状态与结果；不允许的操作说明原因，不隐式改变会话状态。运行中不派发其他命令，也不并发编辑。运行的身份与结果按运行编号关联；重建产生新运行编号并清空既有轨迹。

### WB-09 目录查询、检查与类型适配

目录、需求与连接来自当前装配定义和引擎运行目录的只读视图，不暴露可变引擎；运行目录视图在封闭后提供作用域、公开量、方法、需求与连接的实际信息。编辑实例构造配置后由重新实例化生效，不修改运行中的实例。

检查复用工厂构造与配置校验、装配检查与实验规格检查：核对推进入口存在且可用于推进、命名输入与观测引用存在、种类与签名符合实验运行要求，并核对界面类型适配支持。检查报告列明检查项与范围；检查通过只说明所检查范围，不构成实现正确性或研究资格的证明（沿用 [WB-04](#wb-04-展示验证范围与来源)）。

类型编辑、显示与绘图通过显式适配层：适配器按精确原生类型登记，不依赖 `type_info` 名称推断格式或序列化规则。首版完整支持 64 位有符号整数；其他类型只有在宿主登记适配器后才提供对应编辑与显示操作，未登记类型在目录与结果中标注为不支持。整数编辑与解析保持 64 位精度，拒绝越界与非法文本；表格与详情显示精确值，曲线可使用浮点近似坐标。

### WB-10 运行控制、线程与停止

同一运行实例的读取、推进、捕获与恢复串行执行。工作台由专属执行线程持有会话与运行对象，界面线程按提交顺序排队命令，并以值快照接收结果；界面不直接访问运行对象。运行 N 步是有限任务，结果报告实际完成的逻辑帧数；停止请求在完整操作或逻辑帧边界生效并终止当前任务，不宣称未完成的推进。界面刷新与计时器频率不参与推进语义；切换显示变量、增删读取不改变演化结果。

首版限制运行步数与轨迹逻辑帧总数，超限请求拒绝并说明上限；上限值与测量条件记录在实现、测试文档。单次机制调用无法强行中断：首版场景限定为短时有界调用，停止与关闭在操作边界等待返回，不使用强制终止线程；窗口关闭时等待当前操作完成并结束专属线程，再进行对象销毁。

### WB-11 失败处理与继续条件

每次推进分别记录输入驱动、推进与采样的结果：不把计划输入当作实际执行，不把失败推进计为已完成逻辑帧，也不因采样失败抹去已完成的推进结果。任一操作失败后工作台停止自动推进，保留诊断、已完成轨迹与最后有效检查点；失败状态下只能通过应用重建（从初态）或从检查点重建分支（存在检查点与分支时）恢复自动推进。

对照与干预分支出现部分成功时保留各自实际到达的逻辑帧，仅在共同有效采样逻辑帧比较，不伪造同步完成结果。恢复与重建产生新运行，不就地覆盖失败运行；失败前的成功结果继续可查看。

### WB-12 检查点、分支、干预与比较

分支保存未干预的共同检查点与有序干预列表；干预在检查点副本上按模块路径与状态字段路径应用，核对目标模块存在且有状态、目标字段存在且新值与现有值类型一致，然后恢复到新实例；源运行与其他分支互不影响。首版干预使用[现有对象字段路径规则](../实验环境与声明接入/设计.md#env-12-一次性外部状态干预)，不支持数组下标；不合法目标在建立分支前给出可定位诊断，不产生新运行。

观测在干预起点按实验规格采样，区分干预的直接变化与后续传播。真值与观测分别呈现；比较按变量与逻辑帧对齐，差值方向为“干预 − 对照”；差值使用精确整数运算并检查溢出，不可比较的字段明确标注。首版只支持从同一检查点建立一组对照与干预分支；检查点在建立分支前创建，分支建立后不再创建新检查点，只能从检查点重建分支。

### WB-13 记录与重放核对

会话按实际执行维护实验记录：装配定义、实验规格、已核对实现标识、实际驱动的共同输入与各分支轨迹；输入记录标明驱动前逻辑帧并按列表顺序执行，逐步区分成功与失败；共同输入由各分支实际执行结果整理，部分成功的输入保留在分支轨迹中。建立分支后记录按分支的共同起点与干预重新组织；分支建立前的探索轨迹保留在会话中供查看，不进入分支记录。

重放从记录重建装配并恢复各分支（含干预），按记录采样逐逻辑帧推进，共同输入附着在驱动前逻辑帧上（可选）；分支实际驱动的输入必须包含于共同记录，否则该步骤不可复现、比较提前结束。核对真值与观测的精确相等，报告成功或首个不一致的分支、逻辑帧与字段，以及未能比较的范围；全部采样核对完成与部分核对用不同结果状态（`complete`）区分。判等不使用显示文本或浮点近似值；重放不修改已有轨迹。记录的文件编码、打开与保存见 [WB-16](#wb-16-实验文件与打开保存) 与[接入设计 ENV-14～16](../实验环境与声明接入/设计.md#4-已确认规则)。

### WB-14 界面与会话文本的语言资源

工作台界面固有文案与会话层用户可见文本分别使用独立文本域：界面文案归 `ascend.workbench`（资源位于工作台 `app/i18n/`），会话检查项、视图占位、比较与重放说明及内建适配器错误归 `ascend.session`（资源位于工作台 `i18n/`）；模块语义说明继续使用模块自有域（WB-04）。三类文本都按当前语言解析，缺失翻译时回退消息自带默认模板；已渲染字符串不再次作为模板解释。界面模板使用 Qt 风格 `%1` 占位符并在渲染后由界面填充，会话与引擎消息使用结构化命名参数。

语言资源不嵌入二进制：构建时复制到可执行文件同目录的 `resources/`（保持源码树相对布局），运行时优先解析运行目录副本，缺失时回退编译期源码路径并如实记录加载诊断。因此复制运行目录（可执行文件与 `resources/`）即可在另一台机器保持文案，翻译迭代可直接修改运行目录副本，或修改源码后构建一次刷新副本。

首版固定中文界面（zh-CN）并如实记录资源加载失败；语言切换入口与语言选择界面属于后续阶段，切换语言不得改变接口行为、诊断类别、记录或模型状态。

### WB-15 结果时间轴视图

结果区以时间轴（波形）视图承载多变量与多序列对比，游标读数、差值表与采样详情保留为精确值视图：

- 信号选择：信号树列出可绘制变量并勾选加入波形；首版以规格观测为信号源，真值字段与层级模块结构随记录能力扩展；勾选与序列显示开关只改变呈现，不改变轨迹、记录或会话状态。
- 差值信号：两分支存在时，信号树增加“差值（干预 − 对照）”组，每个观测一条曲线，取共同逻辑帧的精确差值；不可比较或溢出的点不落在曲线上，未配对逻辑帧由差值页签列出。差值曲线与原始序列一样接受勾选开关、游标读数与采样详情联动。
- 波形：每个变量一行，序列（运行／对照／干预）叠加并按序列着色；离散时间按阶梯线呈现；纵轴按可见区间自动缩放并标注端点。
- 游标与精确读数：至少两个游标（A／B）落在逻辑帧上；读数给出精确显示值，A／B 差值在可精确计算时给出，溢出与不可比较按既有标注处理；曲线坐标仍可能近似，精确值以游标读数、差值表与详情为准。
- 事件轨与检查点：检查点、干预、分支起点、失败与停止作为时间轴标记，按类型区分形状，悬停列出同一逻辑帧的全部事件；检查点另画竖向虚线并标出分支区间（检查点之后至数据末端），点击参考线可把游标 A 定位到检查点。
- 联动：点击放置游标即选中该逻辑帧，底部采样详情跟随游标定位；运行结束后详情跟随最新逻辑帧；缩放与平移不请求会话数据。
- 性能：只渲染可见区间并按像素列降采样，10000 逻辑帧下保持可交互。

### WB-16 实验文件与打开／保存

文件菜单与开始页提供打开研究…、保存与另存为…（界面把实验文件与运行记录整体呈现为“研究”）；对话框过滤实验文件（`*.aexp`，格式见[接入设计 ENV-16](../实验环境与声明接入/设计.md#4-已确认规则)）；窗口标题与记录汇总行显示当前文件与未保存状态。

保存写入当前会话状态：运行身份、配置草稿（含修订）、输入设置、会话检查点、探索轨迹与各分支轨迹（含失败与逐步事件）。写入采用临时文件加原子替换；保存成功后清除未保存标记（文件已包含草稿）。

打开的结果分三类：

| 条件 | 结果 |
| --- | --- |
| 文件结构损坏、版本不支持、必需段缺失 | 拒绝打开；当前会话保持原样，给出可定位诊断 |
| 文件完整，但实现缺失或不匹配、重放核对非完全通过、记录含失败或未完成步骤 | 只读记录态打开：可查看轨迹、差值、时间轴、重放与失败诊断；禁止续跑；可从文件中的检查点重建分支（新运行）继续 |
| 文件完整、实现匹配、重放核对完全通过且无失败记录 | 接管为活动运行：各分支恢复到记录末端，可继续单步与运行 |

接管要求可恢复的运行态：无分支单运行（只含探索轨迹的文件按单运行恢复）或探索加两个分支；单分支等其他分支数进入只读记录态，不含任何轨迹的文件拒绝打开。保存或打开的失败原因随本次操作给出（界面提示与诊断面板），不使用历史诊断。

记录态是会话的明确状态（见会话状态表）：记录只读，草稿可编辑并通过应用重建产生新运行，可从检查点重建分支；单步、运行、创建检查点与建立分支不可用。

### WB-17 模块包载入与卸载

文件菜单提供「载入模块包…」「载入模块包文件夹…」与「卸载模块包…」。载入模块包过滤 `*.amod` 并支持一次多选多个文件；载入模块包文件夹选择文件夹后载入其中全部模块包（`*.amod` 直接子文件，按名称顺序，不含子文件夹）。选中的文件逐个独立交给会话的模块库（ENV-18）：按宿主登记的内置实现解析、核对清单与资源后登记；成功项保留并在模块库面板出现概要，失败项汇总一次给出针对本次操作的诊断（提示与诊断面板，含路径与原因），未成功的包不进入列表；重复载入提示先卸载。卸载从已载入列表选择，成功后从列表移除；首版不把包内资源登记进会话文案目录（随装配编辑落地），卸载不撤销已登记文本。

模块库是中央工作区页签（查看菜单可开关、默认不打开）：表格列出定义标识、版本、实现标识、状态能力、公开声明数、需求数与资源数；「载入…」「载入文件夹…」「卸载」按钮与文件菜单同源；载入（至少一个包成功）后自动打开并切换到该页签，页签可用关闭按钮关闭并从查看菜单重开。中央工作区页签为浏览器式：可拖动重排、可关闭、至少保留一个页签（关闭最后一个页签的请求被忽略）。载入与卸载是会话命令、与运行阶段无关，界面在忙碌时禁用入口。已载入模块经系统编辑器（[WB-18](#wb-18-因果系统装配编辑切片-a)）用于建立模型；完整声明／绑定编辑与依赖视图（WB-01～05）仍待实施；模块库不进入实验文件与装配文件。

续跑资格：只有重放核对完全通过（`complete`）才可能接管；部分核对（存在未比较范围）只进入记录态。失败运行的最后采样之后可能已发生部分输入或状态修改，重放通过不恢复该状态，因此含失败的记录一律只读打开；其恢复路径是从文件检查点重建分支或重建运行（产生新运行，不就地覆盖）。打开失败不改变当前会话；语言资源、面板布局与界面状态不进入实验文件。自动保存、最近文件与多文档并行属于后续候选。

### WB-18 因果系统装配编辑（切片 A）

三层概念：模块包（`.amod`）在模块库中载入，是可复用的模块定义；因果系统（`.aasm`）选择模块实例并接线，是研究中的模型；研究（`.aexp`）在因果系统之上加入实验规格与运行记录。开始页为默认打开的中央页签，提供新建研究（对话框：研究名称 + 创建新的因果系统或打开已有因果系统文件）、打开研究（实验文件）与打开内置示例；未打开因果系统时窗口标题不显示模型名。因果系统文件由系统编辑器打开与保存（引擎装配记录格式，不含实验规格与运行记录）；规格属于研究层，随实验文件保存。

会话提供装配编辑命令：新建空系统（名称、清空装配草稿与实验规格）、打开因果系统（`.aasm` 字节）、增加／移除模块实例（定义须可用，实例名在根作用域唯一）、连接／断开需求到提供方、设置推进入口与观测，以及编码当前系统。可用模块为宿主内置实现与模块库工厂的合并目录：模块包载入后其定义可实例化，实现标识由宿主登记或包清单提供；定义可登记默认构造配置，新建实例以它预填、配置面板按结构展开字段（如 x/y/z）；未登记默认配置的定义退回 JSON 值输入；观测未显式选择时默认记录根作用域全部公开量（可在系统编辑器取消），显式选择后不再推导；输入按公开单参数方法自动推导（引用未变的既有输入沿用原名）。编辑使草稿修订递增并标记未应用，检查与应用沿用既有流程；应用后时间轴、配置、检查点分支、比较与重放作用于新系统。

系统编辑器为中央工作区页签（编辑菜单与查看菜单可打开、默认不打开，遵循中央页签的关闭与重开规则）：新建／打开／保存系统与系统名（含文件名）、可用模块下拉与实例名、系统树（实例 → 需求与提供方）、连接／断开／移除、规格（推进入口、观测与自动推导输入）以及检查与应用入口。窗口启动时控制层发布一次模型快照，编辑器据此列出可用模块与结构；实例构造配置继续由配置面板编辑，并在应用时随装配草稿生效。

切片 A 限制：根作用域装配（嵌套组合、需求转接与接口导出后续）；观测显式选择、输入自动推导；规格草稿不随实验文件保存；依赖视图与代码来源定位在后续切片。

### 目录与检查（首版确定）

会话按当前草稿提供模块视图，包含作用域路径、公开量与方法、需求、实际连接与模块说明；目录、需求与连接来自装配定义与引擎运行目录的只读查询，不暴露可变引擎；类型信息随声明附带适配支持标记。检查返回会话级检查项与结构化诊断，覆盖工厂构造与配置校验、装配连接、实验规格的推进入口与输入／观测签名、界面类型适配；检查项与诊断保留目标、来源、字段路径与完整原因链，按语言资源解析并在缺失时回退默认模板（沿用接入设计，文本域分工见 [WB-14](#wb-14-界面与会话文本的语言资源)）。

### 编辑与身份（首版确定）

首版编辑限定为实例构造配置与单次运行步数。配置编辑产生新的草稿修订；应用并重建是使新配置作用于运行的唯一入口，重建返回新运行编号并清空既有轨迹。规格输入的驱动属于干预范畴：会话在每次推进前按规格顺序驱动已设置的输入并随记录保存，首版界面不单独提供入口，后续并入干预设置。

### 运行控制与结果（首版确定）

运行控制提供单步、运行 N 步、停止、从检查点重建、建立对照与干预分支、重放。操作返回操作后的状态、实际完成逻辑帧数、轨迹增量与诊断。运行中由控制层临时标识，命令串行执行；停止与关闭语义见 [WB-10](#wb-10-运行控制线程与停止)、[WB-11](#wb-11-失败处理与继续条件)。

### 重放（首版确定）

重放由会话按记录自动执行，返回核对通过的逻辑帧数量与首个不一致位置（分支、逻辑帧、字段或观测名）；失败与部分成功范围单独说明，不修改已有轨迹。

## 6. 边界与失败行为

声明引用缺失或绑定不合法时，展示引擎诊断并标明检查尚未完成。模型或代码在检查后发生变化时，检查和运行结果应关联到实际使用的模型与代码版本。外部编辑器修改文件后，重载、未保存编辑及冲突处理待定。自定义基底只提供部分工具信息时，展示当前可以取得的信息，并注明目录、依赖和验证结果的覆盖范围。试运行中断或失败时，展示运行状态、引擎诊断及仍可读取的结果。

首版交互闭环补充以下限制：未登记适配器的类型在检查中标注，不提供编辑入口；草稿变化后目录标注为陈旧，不自动推断结构未变；命令完成前不派发重复操作，运行中禁用编辑；不合法干预、越界数值与超限步数给出可定位诊断且不改变会话；分支部分成功时按各自实际到达的逻辑帧保留结果，只在共同有效逻辑帧比较；关闭窗口等待当前操作返回后结束专属线程。会话与运行的销毁由专属线程负责，界面不直接访问运行对象。

这些情形的交互和错误表示随接口定稿；自动保存、文件监听和热重载策略另行确定。

## 7. 取舍与候选方案

首版复用现有代码编辑器，工作台侧重模型结构浏览、检查和结果呈现。文本、表单及图形连线等操作形式，待接口和首版使用方式明确后确定。

工作台采用 Qt，复用 C++ 声明引擎；引擎先实现无界面核心，Qt 类型与事件循环不进入核心接口。界面选择 Qt 6 Widgets 而非 Qt Quick：首版以表单与表格为主，Widgets 依赖少、便于测试；曲线自绘以避免图表附加模块与第三方依赖。会话编排与 Qt 分离，使执行顺序、记录一致性与失败行为可以在无界面 CTest 中验证。

运行选择专属执行线程与值快照，代价是运行中编辑需要排队或禁用、关闭需要等待；相比在界面线程分片推进，该方案不把界面刷新频率引入推进语义，也保留后续接入较长调用时的空间。记录与重放选择与引擎实验切片一致的 `ExperimentRecord`；实验文件的保存与打开见 [WB-16](#wb-16-实验文件与打开保存)。步数上限选择拒绝超限请求而不是静默截断，使测量与失败语义明确。

### 工作区状态层与面板协议（草案，待确认）

现状：会话层已是深模块（无 Qt、只发布值快照），但表现层耦合集中在 `MainWindow`——命令入口、全部面板控件与跨面板规则（身份切换清哪些视图、何时打开结果页签、观测集合变化重建哪些视图、控件启用与页签↔动作映射）分散在多个回调里。每新增一个面板或规则需要在多处改动，近期的残留类缺陷（旧观测、旧页签、旧文件关联）即由此产生。

草案引入**工作区状态层 `WorkspaceModel`** 与**面板协议**，保持会话契约与现有界面行为不变：

- 分层与依赖：Qt 视图/面板 → `WorkspaceModel`（新，仅 QtCore）→ `SessionController`（连接层，不变）→ `Session`（无 Qt）。`MainWindow` 收敛为组装点（创建状态层与面板、注册表、菜单与状态栏）。
- 状态层输入只有控制器事件与值快照；输出一个 `WorkspaceView`（身份：研究/系统文件、名称、dirty 标记与阶段；结果：是否有运行/记录、观测与序列、比较与检查点；面板：中央页签开关与当前页；诊断日志与检查/记录视图；目录与陈旧标记）与粗粒度变更通知（身份、结果可用性、观测集合、面板、诊断、控件启用等标志位）。面板按需订阅，不做全局重建。
- 跨面板规则集中在状态层并由无控件单测覆盖：身份切换清空检查报告、采样详情、波形游标、详情面板与研究文件关联并关闭结果页签；出现运行/记录时打开时间轴与逻辑帧差异（首次切换过去，之后不打断）；观测集合随当前规格变化重建信号组与可追踪量视图；诊断日志上限与检查/记录视图；控件启用由状态推导。
- 面板协议：每个面板声明一次元数据（标识、标题文本键、停靠区域与默认可见性、视图工厂、所需状态切片），查看菜单、页签↔面板映射与关闭行为由注册表生成；面板之间不互相调用，也不直接操作其他面板。
- 表格模型：诊断、检查、记录等改为 `QAbstractTableModel`，由状态层供数；波形保持自绘控件，但数据、组与勾选状态来自状态层。

迁移分三步，每步独立提交与回归，不改变会话 API 与既有界面行为（除明确列出的调整）：

1. Stage 1：`WorkspaceModel` 与面板注册表落地，先迁移身份/生命周期/可见性与清理规则；`MainWindow` 改为委托；新增状态层单测（身份切换清理、结果可用性、观测集合、诊断上限），现有界面用例保持一致。
2. Stage 2：结果视图状态（观测、序列、信号组与勾选）从 `rebuildWaveform` 迁到状态层，时间轴只渲染状态。
3. Stage 3：诊断/检查/记录表模型化；`MainWindow` 拆分为 `app/panels/*`；查看菜单、页签映射与启用状态由注册表生成。

不做：不引入第三方事件总线或界面框架；不改变 `Session`／`SessionController` 的值快照与线程契约；不把 Qt 依赖引入会话库。风险与代价：多一层间接与初始样板；状态层内部的事件顺序需按控制器排队顺序约定并测试；停靠/浮动的具体行为仍由 Qt 与面板元数据共同决定，注册表只负责一致性。

确认后：将本节移入[已确认规则](#4-已确认规则)（编号 WB-19），并在[实现](实现.md)与[测试](测试.md)登记迁移阶段与验证记录。

## 9. 首版验收脚本

以下脚本用于阶段验收；自动化用例与验证记录在实现落地后登记于本模块测试文档，桌面人工核对范围单独标注。

### 场景 A：可手算的完整实验

采用内置确定性三变量示例：`x' = x + a`、`y' = x`、`z' = y + z`，右侧读取步开始值，观测为 `(x, y, z)`。

1. 初态 `(x, y, z) = (0, 0, 0)`，示例自身配置 `a = 1`（外部输入可选，界面不单独提供入口）。
2. 推进至逻辑帧 2，得到 `(2, 1, 0)`，创建共同检查点。
3. 对照分支恢复原检查点；干预分支在 `plant/state` 上施加 `x := 10`，起点为 `(10, 1, 0)`。
4. 两分支接受相同输入并推进至逻辑帧 5。
5. 对照为 `(5, 4, 6)`，干预为 `(13, 12, 22)`，干预减对照为 `(8, 8, 16)`。
6. 时间轴与记录逐逻辑帧对应：勾选观测并在逻辑帧 2 与 5 放置游标读出精确值；可见 `x` 的直接变化与 `y`、`z` 的后续传播；逻辑帧 2 的差值为 `(8, 0, 0)`，逻辑帧 3 为 `(8, 8, 0)`，逻辑帧 4 为 `(8, 8, 8)`。
7. 从会话记录重放，各逻辑帧真值与观测精确一致并报告成功。

### 场景 B：操作与运行一致性

- 相同配置与输入下，单步和运行 N 步得到相同结果；插入停止／继续、切换显示变量及增加读取不改变轨迹。
- 原实例继续运行不改变已有检查点；交换分支执行顺序仍得到相同的各分支结果。
- 修改草稿后能区分旧结果与新配置；重新实例化后新配置才作用于新运行。
- 双分支对比只比较共同有效逻辑帧，缺失值／失败点明确显示。
- 连续点击、运行中编辑、停止、重建和关闭按 [WB-08](#wb-08-会话状态身份与允许操作)、[WB-10](#wb-10-运行控制线程与停止) 的会话状态规则处理，不发生重入或悬空访问。

### 场景 C：失败路径与证据范围

- 非法配置、缺失连接、签名／类型不匹配、非法干预字段及不完整状态得到可定位诊断。
- `int64_t` 极值输入与计算溢出得到明确处理，不发生静默截断或有符号溢出。
- 推进失败不误报逻辑帧已完成；采样失败不误报模型未推进；输入的部分成功有对应记录。
- 恢复／执行中途失败后停止自动运行，已有成功结果可查看，可从有效检查点重建。
- 界面与无界面入口对同一模型得到相同引擎检查结果及逐步结果。
- 界面明确显示接口检查和运行核对的范围，不把小模型核对结果展示为完整研究资格证明。
