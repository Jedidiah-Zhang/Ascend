# 因果建模工作台 — 设计

> - 设计状态：讨论中
> - 适用范围：因果模型的浏览、声明编辑、验证展示与小规模试运行
> - 已确定范围：Qt 工作台方向、首版功能范围、复用 C++ 无界面核心、模型独立于界面、依赖与执行路径分开展示
> - 尚未覆盖：界面布局、Qt 版本与界面方案、项目格式、编辑接口、诊断字段与运行控制细则
> - 上级：[研究平台](../综述.md) · [实现](实现.md)

## 1. 目标与职责

为研究者提供轻量因果建模入口，查看可用变量、机制及运行基底，编辑声明与输入输出绑定，检查模型并运行小规模用例。代码函数的生成规则与研究接入边界由[实验环境与声明接入](../实验环境与声明接入/设计.md)维护。

工作台负责交互和展示，通过引擎接口查询、检查和执行模型。首版配合最小声明模型推进；完整代码编辑、断点调试、大规模实验管理不列入首版交付。

## 2. 概念与术语

| 概念 | 含义 |
| --- | --- |
| 模型目录 | 已加载模型中的变量、机制、全局量及基底操作的可查询信息 |
| 绑定 | 机制函数输入输出与模型变量的对应关系 |
| 依赖视图 | 从模型声明获得的生成依赖展示 |
| 执行视图 | 某次运行的结果、记录与实际路径展示 |
| 诊断 | 引擎返回的检查或执行信息，附带适用对象与覆盖范围 |

声明、运行基底及机制函数的定义见[接入设计](../实验环境与声明接入/设计.md#2-概念与术语)，本模块不另定模型语义。

## 3. 已确认规则

### WB-01 首版采用轻量范围

首版包括变量与机制目录、声明和输入输出绑定编辑、依赖图浏览、检查结果及错误定位、单机制或小模型试运行。目录同时提供已声明全局量和基底操作的信息；历史与随机来源按引擎已支持的声明能力展示。

机制函数优先通过现有代码编辑器编写和修改，工作台提供来源定位或跳转。内置完整编辑器、代码补全、断点调试与复杂图形编程另行评估。

### WB-02 引擎维护检查与执行规则

工作台通过引擎接口取得目录、依赖、检查结果与运行结果，复用 [ENV-06](../实验环境与声明接入/设计.md#env-06-声明与执行能力独立于工作台)。接口检查和执行编排由引擎统一提供，领域校验与计算使用模块实现；命令行与批量实验可调用相同能力，工作台不维护独立的检查或因果计算实现。

### WB-03 编辑与视图使用同一模型定义

声明、绑定及依赖图对应同一份模型定义。视图由该定义生成；若提供图形连线编辑，操作也须更新该定义，不另行维护与执行无关的手工因果图。

模型文件与机制代码可独立保存、加载和运行。界面布局等工具配置的表示待定，不作为模型执行的前提。

### WB-04 展示验证范围与来源

分别展示声明检查、执行检查与研究验证的结果及覆盖范围。声明通过不代表任意函数或研究者修改的基底已经被自动证明正确，具体保证由引擎和所用协议提供。

目录可展示模块文档或 docstring 中的语义说明，并关联公开量、类型与形状信息及方法入口。说明与单位标记不呈现为已验证结论；接口检查、模块校验及实现验证的分工遵循 [ENV-08](../实验环境与声明接入/设计.md#env-08-语义说明程序检查与实现验证分工)。

诊断应能关联对应模型对象，并在引擎提供来源信息时定位到声明或函数。来源位置、检查状态和证据字段尚未定稿。

### WB-05 区分声明依赖与实际运行

依赖图描述作者提供的模型关系，执行视图描述某次运行实际记录到的计算与访问。声明依赖是否完整反映实现须有相应验证；一次运行未触发的分支不能从声明依赖视图中被当作不存在，依赖边本身也不证明存在非零效应。

试运行可为机制指定输入或从初始条件执行小模型，展示结果与诊断。条件修改、干预及结果比较通过引擎接口实施，不由界面自行改写运行状态；具体生效语义随引擎接口确定。

## 4. 对外契约

以下为**候选接口分解**，字段、调用方式及界面操作未定：

| 能力 | 输入／输出 | 已定边界／待决部分 |
| --- | --- | --- |
| 浏览目录 | 模型与筛选条件 → 定义、来源、生产者及使用者 | 使用引擎目录；检索与分类方式未定 |
| 编辑声明与绑定 | 定义或映射修改 → 模型更新与检查结果 | 同一模型来源；保存、撤销及失效处理未定 |
| 浏览依赖 | 变量或机制 → 关联子图与定义 | 与执行路径分开；展开粒度与大图布局未定 |
| 请求检查 | 模型与检查范围 → 诊断 | 引擎执行检查；呈现方式与字段未定 |
| 请求试运行 | 初始条件、输入及运行请求 → 结果与记录 | 引擎负责执行；取消、失败及结果保留未定 |
| 定位代码 | 机制来源 → 外部编辑入口 | 优先使用现有编辑器；路径与编辑器配置未定 |

## 5. 配置与边界情况

| 情况 | 需要明确的处理 |
| --- | --- |
| 声明引用缺失或绑定不合法 | 展示引擎的具体诊断，不将未完成检查标成通过 |
| 模型或代码在检查后变化 | 检查与运行结果如何对应其实际使用的版本，避免混用 |
| 外部编辑器修改文件 | 重载、未保存编辑及冲突处理待定 |
| 自定义基底不提供部分工具信息 | 明确可展示范围，不虚构变量、依赖或验证结论 |
| 试运行中断或失败 | 展示执行状态及诊断，部分结果的可用范围由引擎说明 |

这些情形的具体交互和错误表示需随接口定稿；当前不预设自动保存、文件监听或热重载策略。

## 6. 取舍与候选方案

以目录、绑定、依赖和诊断作为首版重点，使研究者能够理解并运行模型。代码编辑复用现有工具，避免首版同时承担完整 IDE 的成本。

**候选交互**：目录列表定位变量或机制，详情展示语义及输入输出，依赖图查看关联，结果区展示诊断与试运行。文本编辑、表单绑定及图形连线的具体组合未定。

工作台采用 Qt，复用 C++ 声明引擎；引擎先实现无界面核心，Qt 类型与事件循环不进入核心接口。Qt 版本、Widgets／Qt Quick、线程调度及模型格式待选择。

## 7. 验收标准

以下为首版方向的验收场景，尚无实现或测试结果：

| 依据 | 场景 | 预期 |
| --- | --- | --- |
| WB-01 | 打开一个包含变量、机制和基底描述的小模型 | 可浏览目录、编辑绑定、查看依赖并请求检查与试运行 |
| WB-02 | 与无界面入口对同一模型发起相同检查 | 调用同一引擎规则，诊断内容及覆盖范围一致 |
| WB-03 | 修改绑定后重新加载模型并查看依赖 | 定义、执行绑定与视图对应；关闭工作台仍能加载和运行模型 |
| WB-04 | 声明通过，但某基底或运行性质没有验证证据 | 准确显示检查范围，不呈现为全部研究要求均已满足 |
| WB-04 | 查看带语义说明、接口检查与模块校验结果的方法 | 可区分说明与检查结果，不将 docstring、类型或单位标记呈现为实现正确性证据 |
| WB-05 | 对含条件分支的模型分别查看声明图与一次运行 | 保留声明依赖，实际执行路径单独标明 |
| WB-05 | 在引擎支持的条件下进行基线与干预试运行 | 使用引擎的输入与干预语义，展示各自结果及来源 |

模型变更、外部编辑及失败恢复的具体判据待接口确认后补齐。
