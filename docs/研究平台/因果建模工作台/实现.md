## 2. 代码结构与工程方案

### 工程布局

工作台位于 `kheker/workbench/`：无界面会话库 `ascend::session` 使用 C++17，不依赖 Qt，链接 `ascend::engine`；Qt 界面库 `ascend_workbench_ui` 链接会话库与 `Qt6::Widgets`，可执行目标 `ascend_workbench` 只含启动入口；示例装配与参考序列复用 `ascend::experiment_model`。语言资源 `i18n/zh-CN.json` 维护 `ascend.session` 文本域；测试位于 `testbench/workbench/`，构建产物写入已忽略的 `build/workbench/`。

工作台 CMake 以子项目方式引入引擎源码（在 `add_subdirectory` 前关闭 `ASCEND_ENGINE_BUILD_EXAMPLES` 与 `ASCEND_ENGINE_BUILD_TESTS`），因此工作台构建不需要单独安装引擎；引擎独立构建入口不受影响。`ASCEND_WORKBENCH_BUILD_GUI` 控制 Qt 目标：关闭时只构建会话库与测试，不需要 Qt。界面要求 Qt 6.4 及以上（开发环境 6.11.2，CI 实际版本见测试文档），不使用 Qt Charts 等附加模块；示例与语言资源由 CMake 在构建时复制到可执行文件同目录的 `resources/`（源码路径由 `ASCEND_WORKBENCH_*` 编译期定义作为回退），复制运行目录即可分发；完整安装包与系统资源路径属于后续阶段。

### 会话库

[session.hpp](../../../kheker/workbench/include/ascend/session/session.hpp) 定义会话的公开类型与命令：

- 模板与视图：`ModelTemplate`（装配、规格、工厂目录、已核对实现标识、语言资源与语言）、`CatalogView`／`ModuleNodeView`／`DeclarationView`／`RequirementView`／`ConnectionView`（只读目录）、`InstanceView`（草稿实例与构造配置）、`StateFieldView`（检查点上可干预字段）、`Status`／`TrackStatus`／`Phase`（会话状态）、`TrackTraceView`／`SampleView`／`SampleDetailView`（轨迹与真值详情）、`ComparisonView`（共同逻辑帧差值，单元带精确整数视图）、`RecordView`（输入记录）、`ReplayReport`（重放结果）、`DiagnosticView`（渲染后的完整原因链）与 `CheckReport`／`CheckItemView`（检查项）。
- 命令：`load`、`check`、`apply`、`set_instance_config`、`set_input`、`step`、`run`（带 `should_stop` 回调）、`create_checkpoint`、`create_branches`、`reset_branches` 与 `replay`。命令同步执行：推进与控制类命令返回 `OperationResult`（`ok`、本次完成步数、是否因停止提前结束、操作后状态与诊断），`check` 返回 `CheckReport`，`replay` 返回 `ReplayReport`；均不向调用方抛出引擎异常。会话必须在同一宿主线程串行使用。

[adapter.hpp](../../../kheker/workbench/include/ascend/session/adapter.hpp) 定义 `ValueAdapter`（稳定名称、精确显示、精确判等、可选编辑解析与曲线近似坐标）与 `AdapterRegistry`。首版内建 `Int64Adapter`：严格十进制解析并检查 64 位范围，显示与判等保持精确值，曲线坐标在超过 2^53 时标记为近似，并提供精确整数视图（`integer`，只用于游标差值等精确计算，不参与显示与判等）；解析失败返回 `TextRef` 结构化错误，由展示层按语言资源渲染。未登记类型在目录、检查与结果中标注为不支持，不提供编辑入口；不依赖 `type_info` 名称推断格式或序列化规则。

会话层全部用户可见文本（检查项、视图占位、比较与重放说明、内建适配器错误与分支默认标签）使用 `ascend.session` 文本域：默认模板为英文，中文由 [i18n/zh-CN.json](../../../kheker/workbench/i18n/zh-CN.json) 提供，渲染时按当前语言解析并在缺失时回退。

### 状态与身份

会话持有配置草稿、当前运行与记录：草稿修订在构造配置变化时递增，运行记录其来源修订与运行编号；`dirty` 表示草稿修订与运行修订不同，旧运行仍可推进，界面据此区分陈旧结果。目录在工厂与装配检查成功时按当前草稿刷新并记录修订，草稿变化后由修订差标记陈旧。规格输入的驱动属于干预范畴：会话支持在推进前按规格顺序驱动已设置的输入并随记录保存（不产生配置修订；未设置时按模块自身配置值推进，内置示例默认 a = 1，世界可自主演化）。驱动阶段逐输入、逐分支记录实际成功执行的输入；共同输入由各分支结果整理，部分成功的输入保留在分支轨迹中。首版界面不单独提供输入编辑入口，后续并入干预设置。

状态规则按设计 [WB-08](设计.md#wb-08-会话状态身份与允许操作) 实现：空会话只接受打开；可编辑（检查失败等无有效运行的情形）允许编辑、检查与重建；可运行与已停止允许全部实验操作；失败状态禁止推进与创建检查点，允许检查、重建、从检查点重建分支与重放；不允许的操作返回诊断且不改变状态。分支建立后不再创建新检查点，只能从检查点重建分支。

### 运行控制与失败处理

`run` 在每步开始检查停止请求，在每个逻辑帧边界停止；命令返回实际完成步数，停止不算失败，状态进入已停止。推进按“驱动已设置的输入 → 推进 → 采样”组织：输入、推进与采样失败分别记录为逐步事件与计数，失败不追加采样、不误报已完成逻辑帧；任一失败停止当前命令并进入失败状态。共同输入由各分支实际执行结果整理：所有参与分支都成功驱动的输入按驱动前逻辑帧与列表顺序写入记录，部分成功的输入保留在分支轨迹中。单次命令步数与单分支轨迹逻辑帧数上限分别为 `max_steps_per_command` 与 `max_trace_frames`（均为 10000），超限请求在推进前拒绝。检查点状态捕获与分支首次采样的引擎异常同样转换为诊断并保留原运行、检查点与轨迹。

### 分支、干预与比较

`create_branches` 要求源模式与已有检查点，恰好两个请求（默认标签“对照”“干预”）；请求中的干预按顺序记录，先做目标字段类型预检，再在检查点副本上经 `apply_interventions` 应用并恢复到独立实例；任一步失败不产生新运行。建立分支时保留探索轨迹供查看，记录按分支的共同起点与干预重新组织，共同输入记录重新累计。`reset_branches` 用保存的标签与干预重建分支并清空其轨迹。差值按共同逻辑帧计算“干预 − 对照”，使用 64 位精确减法并检查溢出；缺失观测与不可比较类型明确标注，仅一方有采样的逻辑帧列入未配对列表；可比较的差值单元同时携带精确整数视图，供时间轴差值曲线与游标读数使用。

### 记录与重放

记录为进程内 `ExperimentRecord`：装配定义（含配置与连接）、实验规格、已核对实现标识、实际驱动的共同输入与各分支轨迹（含干预、实际成功驱动的输入、逐步采样与推进失败）。`replay` 先核对记录与宿主模板的实现标识，再按记录的装配 JSON 重建实例、恢复各分支（含干预），按记录采样逐逻辑帧推进（共同输入附着在驱动前逻辑帧上，同一逻辑帧多项按列表顺序驱动后只推进一次；未驱动任何输入时同样逐逻辑帧核对全部采样）并核对真值与观测的精确相等；分支实际驱动的输入必须包含于共同记录，否则该步骤不可复现、比较提前结束。报告通过逻辑帧数、首个不一致的分支／逻辑帧／字段、未比较范围说明与整体状态（`complete`：全部记录采样核对完成）。失败步骤不产生采样，其输入范围列入说明；推进失败写入分支轨迹的失败记录。重放不修改当前运行与轨迹。会话另提供实验文件内容（`experiment_file()`）与打开（`open_experiment`）：打开时核对实现标识并按记录重建核对，接管为活动运行或进入只读记录态（记录态禁止推进，可应用重建或从检查点重建分支）。界面文件菜单提供打开实验…、保存与另存为…（原子写入、标题与记录汇总行显示文件与未保存标记），打开结果按 WB-16 三类处理。

### Qt 界面与专属线程

[workbench.hpp](../../../kheker/workbench/app/workbench.hpp) 的 `Workbench` 负责装配：创建适配器登记表与会话控制层，把控制层移入专属 `QThread`，创建主窗口并在关闭时停止当前操作、退出线程事件循环、等待线程结束后回收控制层；重复调用无副作用。[session_controller.hpp](../../../kheker/workbench/app/session_controller.hpp) 的 `SessionController` 持有会话，公开槽全部为串行命令，结果以值快照发布：状态、模型快照（目录、实例、输入、状态字段、序列元数据与记录）、轨迹增量、比较、检查报告、重放报告、采样详情与诊断；停止请求由界面线程以原子标志设置，控制层在每个逻辑帧边界检查。[main_window.hpp](../../../kheker/workbench/app/main_window.hpp) 的 `MainWindow` 只提交命令并呈现快照：窗口标题为“Ascend 因果建模工作台：<模型名>”，菜单栏含文件、编辑、查看与运行（运行菜单与按钮同源、占位项禁用；查看菜单可开关五个面板（模块管理器、配置、结果、状态、诊断）且选择后保持展开），顶部为检查、重建、检查点、分支、从检查点重建、重放与单步／运行／停止；结果为主工作区（时间轴与共同逻辑帧差值）；模块管理器（模块树（方法在前，斜体与括号区分公开量；草稿变化后页签标注“目录陈旧”）、规格（推进入口、输入与观测）、按模块分组的需求与连接）、配置（初始配置表单）、状态（选中项详情、状态与干预、真值与观测）与诊断（诊断与原因链、检查、实际输入记录）为可停靠、可浮动、可嵌套与合并的停靠面板，由查看菜单开关。时间轴由 [waveform_widget.hpp](../../../kheker/workbench/app/waveform_widget.hpp) 自绘：信号树选择观测（首版信号源为规格观测）与差值（两分支存在时每个观测一条“干预 − 对照”曲线，取比较单元的精确整数视图），每个信号一行、序列叠加并按序列着色，离散时间按阶梯线呈现；游标 A／B 落在逻辑帧上，读数表按信号与序列给出精确显示值与 A／B 差值（使用采样单元的精确整数视图计算，溢出标注）；事件轨按类型区分形状（检查点旗标、分支起点圆点、干预菱形、失败叉、停止方块）并悬停列出同一逻辑帧的全部事件；检查点画竖向虚线、以淡色标出分支区间，点击参考线把游标 A 定位到检查点；滚轮缩放、拖拽平移、双击适配，只渲染可见区间，密集区间按像素列聚合（绘制成本与像素数同阶）；点击放置游标即选中该逻辑帧，采样详情跟随游标定位；运行结束后跟随最新逻辑帧。差值表与游标读数保留为精确值视图。配置编辑由 [config_editor.hpp](../../../kheker/workbench/app/config_editor.hpp) 按适配器生成，干预选择与数值输入由 [branch_dialog.hpp](../../../kheker/workbench/app/branch_dialog.hpp) 完成。会话与记录仅在进程内存活，记录视图的汇总行注明“记录仅进程内保存”，界面不设常驻提示。

界面在命令执行期间禁用编辑与运行控件（停止与关闭除外），运行结束后按状态恢复；只读快照请求（比较、记录、采样详情）不占用忙碌标记，运行中切换标签页不影响停止与关闭。配置编辑器在同值回显时保留控件，避免打断后续输入；切换显示变量与序列只重建曲线，不访问会话。

### 界面文案与语言资源

界面固有文案使用 `ascend.workbench` 文本域（[ui_text.hpp](../../../kheker/workbench/app/ui_text.hpp)）：`load_ui_texts` 在启动时加载 [app/i18n/zh-CN.json](../../../kheker/workbench/app/i18n/zh-CN.json)，`ui_text` 按语言渲染并在缺失翻译时回退默认模板；资源加载失败不阻止启动，错误文本进入诊断列表。界面模板使用 Qt 风格 `%1` 占位符，渲染后由 `QString::arg` 填充；会话与引擎消息使用结构化命名参数。工作台当前固定 zh-CN，语言切换入口属于后续阶段（[WB-14](设计.md#wb-14-界面与会话文本的语言资源)）。

语言资源不嵌入二进制：构建时把四份资源（引擎、会话、界面与示例模块）复制到可执行文件同目录的 `resources/`（保持源码树相对布局），运行时由 `resource_paths_from`／`default_resource_paths` 优先解析运行目录副本，缺失时回退 `ASCEND_WORKBENCH_*` 编译期源码路径（开发构建不复制也能直接运行）。因此复制运行目录（可执行文件＋`resources/`）即可在另一台机器保持文案；翻译迭代可直接修改运行目录副本，或修改源码后执行一次构建刷新副本（资源复制目标每次构建都运行）。

## 3. 当前实现范围与限制

已实现：首版交互实验闭环——无界面会话编排（配置草稿与运行身份、目录与检查（工厂、装配、推进入口与输入／观测签名、类型适配、实现标识）、共同输入编辑、单步与有限步运行、逻辑帧边界停止、失败分类与恢复、检查点、对照与干预分支、共同逻辑帧差值与真值／观测详情、输入记录与逐逻辑帧重放）与 Qt 界面（模块树（方法与公开量）、需求、连接、配置表单、时间轴（含差值曲线）、差值、状态字段、诊断原因链、检查与记录视图）；专属执行线程与值快照控制层、类型适配层与 64 位精确编辑；界面与会话用户可见文本接入语言资源与回退，语言资源随构建复制到运行目录并按可执行文件同目录解析，诊断原因链按语言渲染。设计中的场景 A、B、C 由[测试文档](测试.md)覆盖（会话级自动化与 Qt 交互测试已通过；真实桌面人工核对待执行）。

尚未实施：桌面人工核对与平台覆盖记录、面向完整 WB-01～05 的声明／绑定编辑与依赖视图、实验文件持久化、机制代码来源定位、界面语言切换入口与完整安装包布局（平台安装包与系统资源路径）。

限制：会话为单线程同步契约，命令在专属线程串行执行，运行中不并发编辑；记录、检查点与语言资源仅进程内交接，不定义文件格式；规格输入的驱动首版只支持单参数方法；每次只支持一组两个分支；状态字段编辑只支持 64 位整数字段，数组下标与整体对象编辑受现有干预路径规则约束；重放不要求复现记录中的失败操作，失败步骤之后的采样不进入比较范围；时间轴曲线坐标为近似值，精确值以游标读数、表格与详情为准；判等不使用显示文本或浮点近似值；单次机制调用无法强行中断，关闭窗口等待当前操作返回。首版上限（10000 步／10000 逻辑帧）在目标示例下的测量见[测试文档](测试.md#2-运行方式与验证环境)。

## 4. 构建与运行入口

依赖 CMake 3.20、支持 C++17 的编译器与 Qt 6.4 及以上（Widgets 与 Test 模块）。在仓库根目录执行：

```bash
cmake -S kheker/workbench -B build/workbench -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build/workbench --config Debug --parallel 4
ctest --test-dir build/workbench --build-config Debug --output-on-failure
```

只构建无界面会话库与测试时可加 `-DASCEND_WORKBENCH_BUILD_GUI=OFF`，此时不需要 Qt。启动工作台：`build/workbench/ascend_workbench`（多配置生成器在 `build/workbench/<配置>/` 下）；测试入口为 `build/workbench/tests/ascend_session_tests <用例名>` 与 `build/workbench/tests/ascend_workbench_tests <用例名>`。开发构建通过编译期路径加载内置示例与中英文资源文件；移动构建目录后需重新配置。

一次完整实验（对应[场景 A](设计.md#场景-a可手算的完整实验)）：

1. 启动后自动打开内置确定性三变量示例；点击「检查」查看工厂、装配、规格、类型适配与实现标识的检查项。
2. 把顶部步数设为 `2`，点击「运行」推进到逻辑帧 2（示例按自身配置 `a = 1` 演化），时间轴游标读数在逻辑帧 2 给出 `(2,1,0)`。
3. 点击「检查点」在当前逻辑帧创建共同检查点；点击「分支…」，在对话框中选择 `plant/state` 的 `x` 字段并把新值改为 `10`，确认后得到干预起点的 `(10,1,0)`。
4. 把步数设为 `3` 点击「运行」，两分支推进到逻辑帧 5：时间轴游标读数显示对照 `(5,4,6)`、干预 `(13,12,22)`；“共同逻辑帧差值”标签页显示 `(8,8,16)`。
5. 点击「重放」依据会话记录重建并逐逻辑帧核对全部记录采样：界面流程不驱动输入，重放按记录采样推进（无共同输入记录时同样核对全部采样），提示重放成功；底部「实际输入记录」为空。驱动输入的重放覆盖见[测试文档](测试.md)的会话用例。
6. 修改初态字段后，「重建运行」应用新配置并重置轨迹；失败状态可从检查点重建分支或重建运行后继续。

记录、检查点与语言资源只在进程内交接；关闭窗口后不保留。
