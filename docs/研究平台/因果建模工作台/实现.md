## 1. 设计依据

交互实验闭环与基础装配编辑遵循[设计 WB-06～19](设计.md#4-已确认规则)，验收场景见[首版验收脚本](设计.md#9-首版验收脚本)。会话状态、失败、分支、重放及文件契约由设计维护；本文记录组件、源码入口和当前限制。

## 2. 代码结构与工程方案

### 工程布局

代码位于 `kheker/workbench/`，测试位于 `testbench/workbench/`，构建产物写入 `build/workbench/`。工程使用 C++17、CMake 3.20，界面要求 Qt 6.4 及以上的 Widgets 与 Test。

| 目标 | 职责与依赖 |
| --- | --- |
| `ascend::session` | 无界面会话库，依赖 `ascend::engine`，不依赖 Qt |
| `ascend_workbench_workspace` | 工作区状态层，仅依赖 QtCore 与会话库，可无控件测试 |
| `ascend_workbench_ui` | 控制器、外壳、面板与控件，依赖状态层、会话库及 Qt Widgets |
| `ascend_workbench` | 应用启动入口 |

[CMakeLists.txt](../../../kheker/workbench/CMakeLists.txt) 通过子项目引入引擎，并关闭引擎示例与测试目标，无需预先安装引擎。`ASCEND_WORKBENCH_BUILD_GUI=OFF` 只构建无界面部分。示例装配与参考序列复用引擎的 `ascend::experiment_model`。

### 会话库

| 入口 | 作用 |
| --- | --- |
| [session.hpp](../../../kheker/workbench/include/ascend/session/session.hpp) | 模板、目录与结果视图，以及装配、检查、运行、分支、重放和文件命令的公开接口 |
| [session.cpp](../../../kheker/workbench/src/session.cpp) | 草稿／运行身份、目录刷新、命令状态与失败边界；同步执行并将引擎异常转为操作诊断 |
| [adapter.hpp](../../../kheker/workbench/include/ascend/session/adapter.hpp) | 类型适配器登记、精确显示与判等、编辑解析、可选曲线近似坐标 |
| [project.hpp](../../../kheker/workbench/include/ascend/session/project.hpp) | 项目目录约定与文件读写：根下唯一 `*.aexp`、`records/*.arec`、原子写入与记录清单 |
| [assembly.hpp](../../../kheker/engine/include/ascend/assembly.hpp) | 引擎装配定义与工厂目录，供草稿编辑、实例化及系统文件往返复用 |

会话必须在同一宿主线程串行调用。配置和结构编辑作用于装配草稿，应用后建立独立运行；草稿修订、运行编号与目录修订分别标识其来源。结构编辑后尝试刷新目录，失败时保留上次目录并给出诊断。工厂目录由模板与已载入模块库合并；实现标识先取模板登记，再取模块库核对结果。

推进按“驱动已设置输入 → 推进 → 采样”组织，按实际成功范围维护记录；重放复用记录中的装配与实现标识。运行记录打开先重建核对，再按 [WB-16](设计.md#wb-16-研究项目与打开保存) 接管运行或进入记录态。文件编码复用引擎：项目根下唯一 `*.aexp` 是文本研究文件，`records/` 下的 `*.arec` 是运行记录容器，`.aasm` 只存装配；项目目录解析与文件读写由会话库的 [project.cpp](../../../kheker/workbench/src/project.cpp) 提供，不依赖 Qt。

内建 `Int64Adapter` 提供严格十进制解析、64 位范围检查与精确判等；曲线超过 2^53 时标记近似，游标和差值使用精确整数视图，溢出明确标注。未登记类型不提供编辑，不从 `type_info` 名称推断格式。配置表单由 [config_editor.hpp](../../../kheker/workbench/app/config_editor.hpp) 结合定义默认配置与适配器生成，无默认配置时使用 JSON 值输入。

### Qt 界面与专属线程

```text
面板操作 → MainWindow 命令／对话框 → SessionController（专属线程）→ Session
                 ↑                        │
                 └── WorkspaceModel ← 值快照
                      按变更域渲染面板
```

| 组件 | 职责与入口 |
| --- | --- |
| `Workbench` | [workbench.hpp](../../../kheker/workbench/app/workbench.hpp)：组装适配器、会话控制器与窗口；关闭时停止操作、等待线程退出并回收对象 |
| `SessionController` | [session_controller.hpp](../../../kheker/workbench/app/session_controller.hpp)：专属线程串行命令、发布值快照；停止使用原子请求，在逻辑帧边界检查 |
| `MainWindow` | [main_window.hpp](../../../kheker/workbench/app/main_window.hpp)：外壳组装、菜单、状态栏、命令、项目／记录对话框与文件对话框；只呈现快照 |
| 面板 | [app/panels/](../../../kheker/workbench/app/panels/)：开始页、模块库、系统编辑器、时间轴、差异、模块管理器、配置、状态与诊断 |
| 时间轴 | [waveform_widget.hpp](../../../kheker/workbench/app/waveform_widget.hpp)：自绘阶梯线、游标与事件轨；仅绘可见区域，密集点按像素列聚合 |

运行命令占用忙碌标记；比较、记录及采样详情等只读快照请求不占用该标记，切换页签不阻断停止与关闭。配置同值回显保留编辑控件。交互布局与命令行为见 [WB-07](设计.md#wb-07-首版交互实验闭环)、[WB-15～18](设计.md#wb-15-结果时间轴视图)。

### 工作区状态层与面板协议（WB-19）

[workspace_model.hpp](../../../kheker/workbench/app/workspace/workspace_model.hpp) 与 [workspace_view.hpp](../../../kheker/workbench/app/workspace/workspace_view.hpp) 保存工作区状态、派生控件条件并发布信息域变更；更新逻辑集中在 [workspace_model.cpp](../../../kheker/workbench/app/workspace/workspace_model.cpp)。外壳的唯一状态渲染入口是 `onWorkspaceChanged`，具体清理与刷新边界遵循 [WB-19](设计.md#wb-19-工作区状态层与面板协议)。

- `beginIdentity` 更新身份文件与检查状态，再通知外壳清理瞬时视图；保存与脏标记为静默簿记，由文件流程显式刷新。
- 轨迹整体替换和采样增量使用不同通知；观测、比较、检查、记录与诊断各自更新，避免记录请求触发目录重建。
- [PanelRegistry](../../../kheker/workbench/app/workspace/panel_registry.hpp) 统一面板元数据、查看菜单和页签映射，位于界面目标。
- 面板通过 [PanelContext](../../../kheker/workbench/app/panels/panel_context.hpp) 取得只读状态与命令回调；底部诊断面板只接收文案，数据由渲染入口传入。无需公共面板基类。
- 检查、记录与诊断采用 [只读表模型](../../../kheker/workbench/app/panels/table_models.hpp)。诊断保留最近 200 条，空批次不通知；相同模块包概要不重复通知。

### 界面文案与语言资源

会话使用 `ascend.session` 文本域，界面使用 `ascend.workbench`，引擎及示例模块分别维护自身资源。[ui_text.hpp](../../../kheker/workbench/app/ui_text.hpp) 提供界面解析入口；界面模板使用 `%1`，会话与引擎消息使用结构化命名参数。当前固定 zh-CN，缺失文案回退消息默认模板，加载错误进入诊断。

构建将引擎、会话、界面与示例的四份语言资源复制到可执行文件同目录的 `resources/`，保持相对布局。`default_resource_paths` 优先选择运行目录副本，缺失时回退编译期源码路径。复制可执行文件及其 `resources/` 可保持文案；直接修改运行目录副本重启即生效，重新构建会刷新副本。

## 3. 当前实现范围与限制

| 范围 | 当前落地 |
| --- | --- |
| 实验闭环 | 无界面与 Qt 均支持配置、检查、运行／停止、检查点、对照与干预分支、差异比较与逐帧重放 |
| 文件与模块 | 项目新建／打开／保存（研究文件、装配文件与运行记录）、记录列表与打开、模块包载入／卸载、基础系统装配编辑及系统文件往返 |
| 工作区 | 状态层、独立面板、注册表、只读表模型与局部刷新 |
| 验证 | 会话、无控件状态层和 Qt 交互自动化覆盖，入口与人工核对缺口见[测试](测试.md) |

主要限制：

- 装配编辑限根作用域；完整声明／绑定编辑、嵌套组合、依赖视图与机制代码来源定位尚未实施。
- 项目另存为（目录复制）、项目内模块包自动解析与载入、自动保存与最近文件尚未实施；模块包目前仍经文件菜单手动载入。
- 记录列表逐条读取记录文件：摘要只解码 meta 段，但容器仍整文件读入；记录较大或数量较多时刷新成本上升，按段读取待优化。
- `.aasm` 不保存实验规格；`.aexp` 研究文件保存世界引用与规格；运行记录保存装配快照与规格，不保存配置草稿。模块包内容不进入研究文件与运行记录。
- 包内资源尚未登记进会话文案目录；语言切换入口、平台安装包与系统资源路径待实施。
- 会话单线程串行，运行中不并发编辑；单次机制调用无法强行中断，关闭窗口等待当前调用返回。
- 输入驱动限单参数方法；每次只支持一组两个分支；状态字段编辑限 64 位整数，数组下标与整体对象编辑受引擎干预路径规则约束。
- 重放不要求复现失败操作，失败步骤之后的采样不进入比较范围；曲线为近似坐标，精确值以游标、表格与详情为准。
- Qt 6.10.2～6.11.2 已知停靠区回归 [QTBUG-143776](https://bugreports.qt.io/browse/QTBUG-143776)：极端拖拽／标签化可能崩溃，Qt 6.11.3 已修复。平台覆盖与桌面人工核对见测试文档。

### 上限与性能测量

首版 `max_steps_per_command` 与 `max_trace_frames` 均为 10000。以下测量仅适用于确定性目标示例（GCC 16.2.1），不代表其他模型成本：

| 场景与条件 | Release | Debug |
| --- | --- | --- |
| `session.limits`：单分支 10000 步、10001 个采样、10000 条输入，含进程启动与资源加载 | 约 0.02 秒、峰值常驻约 24 MiB | 约 0.17 秒、峰值常驻约 24 MiB |
| `workbench.runNThroughput`：离屏界面运行 10000 帧、保留 10001 个采样，含 Qt 与界面轨迹副本 | 约 0.03 秒、常驻约 86 MiB | 约 0.17 秒、常驻约 86 MiB |
| 同用例波形全量视图：3 信号、源序列、574×240 像素、按像素列聚合 | 约 1 毫秒 | 约 2 毫秒 |
| `workbench.stopDuringRun`：运行开始后立即停止，点击至恢复空闲，含事件调度 | 约 5 毫秒 | 约 5 毫秒 |

会话测量不是全程吞吐测量；停止时间不代表机制调用耗时。绘制成本随像素数与序列数增长，不随逻辑帧数增长。

## 4. 构建与运行入口

在仓库根目录执行：

```bash
cmake -S kheker/workbench -B build/workbench -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build/workbench --config Debug --parallel 4
ctest --test-dir build/workbench --build-config Debug --output-on-failure
```

不安装 Qt 时，在配置命令加 `-DASCEND_WORKBENCH_BUILD_GUI=OFF`。启动入口为 `build/workbench/ascend_workbench`，多配置生成器使用 `build/workbench/<配置>/`。测试程序与环境见[测试文档](测试.md#2-运行方式与验证环境)。移动开发构建目录后需重新配置。

### 体验一次实验

选择「打开内置示例」→「检查」→ 运行 2 步 →「检查点」→「分支…」，把 `plant/state` 的 `x` 改为 `10` → 再运行 3 步 → 查看时间轴与逻辑帧差异 →「重放」。模型、逐步参考值与预期结果集中在[场景 A](设计.md#场景-a可手算的完整实验)。界面示例不驱动外部输入，因此「实际输入记录」为空。

通过「保存」写入项目（研究文件、装配文件与当前运行记录），「打开记录…」列出记录并可接管续跑；修改初态后「重建运行」使配置生效。自建模型从开始页「新建研究」填写名称与位置（项目文件夹为「位置／名称」），进入系统编辑器添加实例、接线并选择推进入口，检查与应用后保存。
