## 1. 设计依据

依据[设计目标](设计.md#2-目标与验收)及 ENV-01～18 推进，具体落地范围见第 3 节。注册、调用、文件与失败契约由设计维护，本文解释工程结构与入口；Qt 界面和会话编排由[工作台](../因果建模工作台/实现.md)维护。

## 2. 代码结构

### 工程布局

核心位于 `kheker/engine/`，使用 C++17、CMake 3.20，静态库 `ascend_engine` 对外提供 `ascend::engine`，不依赖 Qt、Godot、Python 或第三方运行库。测试位于 `testbench/engine/`，构建目标与选项见 [CMakeLists.txt](../../../kheker/engine/CMakeLists.txt)。

| 接口入口 | 职责 |
| --- | --- |
| [engine.hpp](../../../kheker/engine/include/ascend/engine.hpp) | 模块、作用域、登记、连接、检查、类型化调用与状态交接 |
| [config.hpp](../../../kheker/engine/include/ascend/config.hpp) · [state.hpp](../../../kheker/engine/include/ascend/state.hpp) | 结构化配置／状态值与快照 |
| [assembly.hpp](../../../kheker/engine/include/ascend/assembly.hpp) | 工厂目录、装配定义、编辑与文本往返 |
| [experiment.hpp](../../../kheker/engine/include/ascend/experiment.hpp) | 实验规格、运行、检查点、干预、真值／观测与记录 |
| [study_file.hpp](../../../kheker/engine/include/ascend/study_file.hpp) · [record_file.hpp](../../../kheker/engine/include/ascend/record_file.hpp) | 研究文件（文本）与运行记录（容器）的字节缓冲编解码、记录摘要 |
| [module_package.hpp](../../../kheker/engine/include/ascend/module_package.hpp) · [module_library.hpp](../../../kheker/engine/include/ascend/module_library.hpp) | 清单导出与核对、包编解码、宿主实现登记和载入卸载 |
| [text.hpp](../../../kheker/engine/include/ascend/text.hpp) · [i18n.hpp](../../../kheker/engine/include/ascend/i18n.hpp) | 结构化消息、诊断文案与语言资源目录 |

实现主要位于同名 `.cpp`；[engine_internal.hpp](../../../kheker/engine/src/engine_internal.hpp) 保存运行装配及失败边界等内部类型。公共头保留契约、类型擦除句柄和模板入口，不暴露运行内部结构。

### 模块、装配与类型传输

`Module` 保存公开量、方法、需求、子模块及连接描述；`Engine` 管理根作用域，`check` 汇总诊断，`seal` 一次发布运行装配。未封闭目录由缓存草稿生成，结构改变后失效重建。类型化绑定取得句柄时完成名称解析，外部句柄保活整个装配，回调 `Context` 仅弱引用装配。

模板取得原生类型，运行时通过 `std::type_index` 精确匹配，`std::any` 传递可复制值；参数封装与结果解包经统一失败边界转换诊断。执行前拒绝和执行后失败的区别见[执行与读取契约](设计.md#执行与读取)。

`ModuleFactoryDirectory` 保存定义到构造入口的映射及默认配置、文案资源；`AssemblyDefinition` 的作用域树同时驱动序列化、工具编辑与实例化。实例化先登记根实例，再递归建立子作用域，最后处理根连接，成功返回未封闭引擎。纯作用域容器自动声明无状态。继承转接失败只撤销本次新增需求，避免污染既有定义。

### 记录格式与加载

[assembly.cpp](../../../kheker/engine/src/assembly.cpp) 先解析记录结构，再查工厂并实例化；字段规则见[装配记录](设计.md#装配记录)。[json.cpp](../../../kheker/engine/src/json.cpp) 供配置、装配、研究文件与运行记录元数据及资源解析共用，统一 UTF-8、整数范围和容器深度检查。

装配保存先完成序列化校验再打开目标文件；它不保证写入中途失败的原子恢复。需求、接线与导出的来源映射随引擎保留，延迟检查仍可定位，修改接线则清除旧来源。工厂诊断以所属实例为外层目标，作者原始目标及来源保存在 `cause`。

研究文件与运行记录由 [study_file.cpp](../../../kheker/engine/src/study_file.cpp) 与 [record_file.cpp](../../../kheker/engine/src/record_file.cpp) 编解码，规格 JSON 助手由 [experiment_json.cpp](../../../kheker/engine/src/experiment_json.cpp) 共用；宿主（工作台会话层的项目层）负责文件 I/O 与原子替换。研究文件保存世界引用与规格；运行记录结合共用容器编码保存装配快照、规格、实现标识及会话轨迹，编码规格集中在 ENV-14～16。

### 通用文案层

`TextRef` 按值保存原文或消息树，`std::optional` 区分缺失与空默认模板；`Diagnostic::text` 是诊断消息唯一来源，`cause` 使用不可变共享所有权。`render_text` 单次扫描模板，参数渲染后作为原文插入；`EngineError::what()` 缓存默认语言结果，展示层可重新本地化。

`TextCatalog` 按语言和文本键索引，语言文件经 `Config`／JSON 校验后在目录副本上合并并交换发布；复制成本随已有目录规模增长，暂无性能测量。工厂资源登记不构造实例或读取文件，宿主负责加载计划；内存资源使用 `load_text`。核心资源位于 `i18n/zh-CN.json`，示例各自维护文本域。完整回退及冲突契约见[设计](设计.md#模块文案与诊断展示)。

### 模块状态与实验运行

`Module::StateDeclaration` 保存类型擦除的捕获／恢复回调，运行期由内部 `StateEntry` 映射到模块路径。捕获和恢复统一经失败边界转换异常；恢复先核对集合、契约及无状态值，再逐模块写回，失败不回滚。状态的独立副本由模块作者提供。

`ExperimentRun` 构造时先校验规格名称，再实例化、检查、封闭并绑定推进入口。输入、推进、观测、采样、捕获与恢复使用 `Operation` 栈守卫拒绝回调重入，正常和异常退出均释放保护。`observe` 只读取观测，`sample` 先捕获真值再读取观测；帧边界与失败语义见 ENV-11。

`apply_interventions` 在检查点副本上按对象成员路径修改。宿主填充 `RunTrace` 与 `ExperimentRecord`，并负责实际输入、失败及实现身份的真实性；记录不是自动执行日志。示例组件 [experiment_model.hpp](../../../kheker/engine/examples/include/ascend/example/experiment_model.hpp) 提供三变量工厂、装配、规格和参考序列，供命令行、工作台与测试共用。

### 模块包与模块库

`ModuleManifest` 从代码登记的实例导出声明、需求与状态能力，以稳定类型名和相对引用保存。包编解码复用文件容器，`check_module_manifest` 核对运行时声明。`ModuleLibrary` 解析宿主已链接实现，构造空配置探测实例，核对清单并预校验资源后登记；卸载移除元数据及工厂登记，不撤销宿主已登记文本。它提供工厂目录供装配实例化，不加载动态库或安装产物；行为规则见 ENV-17、18。

## 3. 当前实现范围与限制

| 目标／范围 | 当前落地与验证入口 |
| --- | --- |
| G-01、G-02 模块组装与连接 | 注册、精确类型绑定、逐项需求、嵌套组合、显式导入导出及被动目录；[基础](测试.md#3-引擎基础用例)与[组合用例](测试.md#4-组合装配用例) |
| G-03 说明与检查分工 | 结构化文案、原因链、模块资源与接口检查；实际访问核验和研究证明协议未定；[文案用例](测试.md#6-通用文案层用例) |
| G-04 无界面复用 | 工厂、装配编辑与文件往返、只读运行目录；完整模型声明文件未定；[记录用例](测试.md#5-装配记录用例) |
| G-06、G-08 状态与实验 | 捕获恢复、独立分支、一次性外部干预、真值／观测、记录、研究文件与运行记录；[实验用例](测试.md#7-实验切片用例) |
| ENV-17、18 模块接入 | 清单导出核对、包编解码与内置实现载入卸载；同上实验用例及[示例](测试.md#8-示例程序输出检查) |

G-05 的通用基底扩展接口、G-07 的一般数值判等协议，以及随机管理、历史／机制记忆接口、行动通道、自动调度、实际访问追踪、动态库和跨工具链 ABI 尚未实施。**装配文件的模块需求与版本核对（设计 ENV-15、ENV-18）尚未实施**：装配记录根字段仍只有 `format`／`version`／`instances`／`scopes`／`connections`／`forwards`／`exports`，模块版本保存在清单与概要中但不参与解析或核对；工作台侧对应的「项目内模块包自动解析」也未实施。研究文件的 `interventions`（干预设计）字段形式待定，编解码不写入该字段、读取时按未知字段忽略，携带该字段的文件保存后会丢失该内容。完整 Qt 能力的落地情况另见[工作台实现](../因果建模工作台/实现.md)。

使用限制：

- 单线程宿主接口，不提供并发或事务保证；调用与恢复中途失败可能已改变状态，重建路径见设计。
- 原生类型匹配限同进程；值副本不保证内部共享资源深复制，回调及借用资源生命周期由模块作者负责。
- 上下文只解析本实例需求，不限制原生代码以其他方式访问外部对象，不是隔离沙箱。
- 状态以结构化数据承载，干预无数组下标寻址，尚无大张量／自定义二进制载体；恢复不核对构造配置差异，契约相等不证明结构兼容。
- 运行记录可编码结构化状态，但输入参数与观测只支持 64 位整数；快照不写入装配文件。
- 文案层尚无自动资源发现／安装器、复数与日期数字格式化、翻译参数静态核验。

### 成本基线

研究采样保存每帧完整真值，内存随“步数 × 状态大小”增长；干预复制整份快照及路径途经的同级成员。`sizeof` 测量（GCC 16.2.1、Clang 22.1.8，x86-64 Linux）：`Config` 104 字节、`ModuleState` 176 字节、`Sample` 80 字节、`RunTrace` 160 字节，每个标量按完整 `Config` 计费。运行记录摘要（`summarize_record_file`）仍需读入整个容器文件后只解析 meta 段，轨迹段复制后丢弃；按段偏移／流式读取为后续优化。尚无引擎吞吐测量；接入空间场或大张量时需复核载体与记录策略，工作台示例测量由其实现文档维护。

## 4. 构建与运行入口

在仓库根目录执行：

```bash
cmake -S kheker/engine -B build/engine -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build/engine --config Debug --parallel 4
ctest --test-dir build/engine --build-config Debug --output-on-failure
```

构建产物在 `build/engine/`，多配置生成器的可执行文件在 `<配置>/` 下。示例目标及输出检查见[测试索引](测试.md#8-示例程序输出检查)；入门运行 `build/engine/ascend_minimal_model`，分支实验运行 `build/engine/ascend_experiment_branch`。

带资源参数的示例：

```bash
build/engine/ascend_text_catalog kheker/engine/i18n/zh-CN.json kheker/engine/examples/accumulator/i18n/zh-CN.json
build/engine/ascend_module_library build/engine
```

装配记录示例使用随机系统临时目录并在完成后清理；模块库示例将演示包写入给定目录。作为子项目消费时，可关闭 `ASCEND_ENGINE_BUILD_EXAMPLES` 与 `ASCEND_ENGINE_BUILD_TESTS`，保留库目标及可复用实验模型。
