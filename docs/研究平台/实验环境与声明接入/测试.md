# 实验环境与声明接入 — 测试

> - 测试状态：74 项用例在 Linux GCC Debug／Release 与 Clang ASan／UBSan 构建中全部通过；跨平台 CI 配置及历史结果见第 2 节
> - 适用范围：声明引擎、模块组合、装配记录、模块文案与诊断展示、示例程序输出
> - 上级：[研究平台](../综述.md) · [设计](设计.md) · [实现](实现.md)

## 1. 目的与范围

本文记录声明引擎当前每一项自动化测试的目的、达成情况和它对项目的意义。测试检验的是接口行为：登记、引用、连接、检查、调用、诊断、装配记录的保存加载，以及示例程序的端到端输出。通过测试说明相应行为在当前实现与验证环境内成立，不构成任意模块实现正确性的证明，也不构成性能承诺；模块实现是否符合语义说明，依据各自的验证证据判断。

测试按四个程序组织。`ascend_engine_tests` 覆盖单模块引擎的基础行为，`ascend_assembly_tests` 覆盖显式连接与嵌套组合，`ascend_assembly_record_tests` 覆盖模块工厂与装配记录，`ascend_text_tests` 覆盖通用文案层。每个程序由命令行参数选择用例，CMake 把每个用例注册为一项 CTest；四个可执行示例另有输出检查。共 74 项：20 项引擎基础、15 项组合装配、20 项装配记录、15 项通用文案层、4 项示例输出。注册清单见 [CMakeLists.txt](../../../testbench/engine/CMakeLists.txt)。

用例与设计目标的对应关系在条目中说明：引擎基础用例主要支撑 G-01 与 G-03，组合装配用例主要支撑 G-02，装配记录用例主要支撑 G-04，文案层用例支撑 G-03 的语义说明呈现与 G-04 的说明解析；随机、历史、干预与访问核验尚无对应用例。

## 2. 运行方式与验证环境

在仓库根目录执行：

```bash
cmake -S kheker/engine -B build/engine -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build/engine --config Debug --parallel 4
ctest --test-dir build/engine --build-config Debug --output-on-failure
```

也可以直接运行测试程序并指定用例名，例如 `build/engine/tests/ascend_engine_tests non_spatial_model`。多配置生成器使用对应配置目录下的可执行文件。

## 3. 引擎基础用例

### engine.non_spatial_model

建立一个只含两个变量与一条变化规则的最小模型，先读取初值，再显式推进两次并核对结果；随后以不同初值建立第二个独立实例，确认两套运行互不影响。当前通过。它证明引擎能够运行不含空间、实体或游戏时钟的因果系统，是 G-01 与 ENV-03 的最小证据。

### engine.custom_values

以模块自定义的矩阵类型作为公开量和方法的参数、结果参与传输；越界参数由方法代码拒绝并转换为执行诊断。当前通过。它说明引擎没有内置空间量或张量假设，模块可以携带自己的值类型。

### engine.transport_values

把通用容器本身作为公开值类型，检查读取与调用往返不会意外展开内层值。当前通过。它说明值传输对模块自定义类型保持封装。

### engine.catalog_is_passive

查询目录不执行读取函数或方法；条目按模块与符号稳定排序；修改返回的说明文本不会回写引擎；模块变化后草稿失效，新模块立即出现在下一次查询中。当前通过。它是目录与诊断只读语义的证据。

### engine.scoped_references

登记时保存接口快照：模块登记后追加的符号不出现在目录中；不同模块可以使用相同符号名。当前通过。它说明登记完成后接口集合稳定，运行不依赖后续修改。

### engine.invalid_declarations

空模块名、空符号名、空实现、参数数量不符、参数名重复或缺失、非法依赖引用等声明被逐一拒绝。当前通过。无效声明在登记阶段即被拒绝，不会进入运行装配。

### engine.duplicate_registration

同一模块内重复符号、同一引擎内重复模块分别报告对应诊断；失败后引擎目录保持原样。当前通过。重复登记不会产生歧义引用。

### engine.configuration_validation

模块提供的配置校验在登记前执行，失败时引擎保持空；修正配置后重试成功，且校验不在封闭时重复执行。当前通过。它确定了模块配置的检查时机与失败恢复路径。

### engine.validation_reentry

配置校验函数在校验过程中反过来操作引擎，不会破坏登记状态，而是得到相应诊断。当前通过。校验期间的重入不能绕过登记规则。

### engine.unresolved_dependencies

方法声明读取与写入的公开量；缺少提供方时封闭失败并汇总全部缺失项；补齐模块后检查通过并可调用。当前通过。它是声明依赖检查与可修复装配的证据。

### engine.dependency_kind

依赖引用指向方法而不是公开量时报告种类错误。当前通过。依赖必须指向可读数据，种类不符会被明确拒绝。

### engine.lifecycle

封闭前不能绑定或调用公开接口；重复封闭没有副作用；封闭后不能再添加模块，也不再执行模块校验。当前通过。它确定运行装配的边界。

### engine.binding_checks

取得绑定句柄时检查符号存在、种类、结果类型、参数类型与参数个数，错误在绑定阶段报告。当前通过。类型与签名在进入调用前即被核对。

### engine.invocation_checks

调用时检查参数个数与类型；错误参数不执行方法；合法调用正常执行。当前通过。调用检查在方法执行前完成，错误输入不会产生副作用。

### engine.callback_failures

读取与调用中的标准及非标准异常都转换为执行诊断并保留说明；异常发生前完成的状态变化保留，不回滚。当前通过。它确定失败行为：诊断可定位，模块状态由作者负责。

### engine.binding_argument_failures

参数复制抛出异常时方法不执行，诊断带有目标引用，标准与非标准异常都覆盖。当前通过。参数封装失败与执行失败区分明确。

### engine.binding_value_failures

读取公开量时结果取出失败转换为执行诊断；读取函数已经执行。当前通过。传输失败不伪装成读取函数未运行。

### engine.binding_result_failures

方法返回值取出失败时报告诊断，且方法已经执行、不回滚。当前通过。结果传输失败保留已发生的状态变化，与设计约定一致。

### engine.binding_lifetime

绑定句柄让运行装配在引擎对象销毁后继续可用；句柄全部释放后资源回收。当前通过。它验证外部句柄保活与资源释放的边界。

### engine.stateful_callbacks

绑定到方法的可调用状态在多次调用之间保持。当前通过。方法可以携带自己的内部状态，不要求把它注册成公开量。

## 4. 组合装配用例

### assembly.model

两套嵌套组合各自包含状态与更新模块，通过不同提供方接线；分别推进并读取输出，结果符合规则且互不影响。当前通过。它是 G-02 的主要证据之一，覆盖嵌套组合、显式连接与实例隔离。

### assembly.stimulus

输入模块与受测组合分开：驱动输入不隐含推进，显式调用推进后输出才更新，随后采样。当前通过。它对应设计中的测试驱动约定：宿主决定何时输入、推进和读取。

### assembly.discovery

需求目录、候选查询、组合内目录与连接目录可用；候选按种类、精确类型与契约标识筛选；查询不执行读取函数。当前通过。目录能力为工作台和诊断提供只读信息来源。

### assembly.missing

需求未连接时封闭失败；连接到不存在的提供方报告缺失；补齐模块后成功；封闭前读取被拒绝。当前通过。它覆盖显式连接、缺失诊断与修正的完整路径。

### assembly.mismatches

种类、契约、结果类型、参数个数与参数类型不匹配分别报告对应诊断；完全匹配的连接可以封闭。当前通过。连接检查按多个维度分别给出明确原因。

### assembly.names

重复子模块、重复需求、空契约、导出名与自身符号冲突、重复转接等被拒绝。当前通过。组合内命名与作用域规则在登记阶段生效。

### assembly.boundaries

含 `/` 的模块名非法；不允许跨作用域直接连接；内部路径不对外可读；目录只列直接子模块；未知作用域报告诊断。当前通过。它确定组合边界：可以浏览内部结构，但不能绕过边界调用。

### assembly.exports

导出目标缺失在封闭时报告；后续补齐子模块后可重新检查并成功导出。当前通过。导出检查与修正路径明确。

### assembly.forwarding

子需求必须显式转接；转接未声明需求报错；外层需求与子需求类型不一致时给出诊断。当前通过。需求转接不会隐式按名称导入提供方。

### assembly.order

先添加模块还是先连接不影响最终接线，运行结果一致。当前通过。接线关系与登记顺序解耦。

### assembly.cycles

两个模块互相引用并以终止条件收敛；调用计数正确，绑定释放后资源回收。当前通过。接口引用环是允许的，只要模块代码提供终止条件，且不产生内部所有权环。

### assembly.lifetime

上下文为弱引用：运行装配销毁后，保存的上下文读取失败并报告诊断；同一个模块对象用于两套装配时，需求按当前上下文解析。当前通过。它验证上下文身份与生命周期的约定。

### assembly.closed

封闭重复执行无副作用；封闭后的断开、连接与添加都被拒绝。当前通过。运行装配在封闭后不再变化。

### assembly.context_identity

来自其他模块的需求对象不能用当前上下文解析，返回执行诊断。当前通过。上下文只解析当前实例声明的需求。

### assembly.failures

提供方异常经需求调用向上传播，诊断包含内层接口位置；嵌套组合中的配置校验失败定位到完整路径，失败后引擎保持空。当前通过。嵌套诊断可以定位到具体接口。

## 5. 装配记录用例

### record.factories

工厂目录按定义标识登记，查询接口稳定；对同一标识的每次构造返回独立实例。当前通过。定义标识与实例身份分开管理。

### record.definition

由普通 C++ 代码构建的装配定义可直接实例化、检查并驱动，三轮采样结果符合预期。当前通过。同一份定义既能保存也能运行，是 G-04 的主要证据。

### record.roundtrip

保存为文本再解析回来，文本与运行结果一致；记录只引用公开边界，不包含工厂内部模块名或内部契约。当前通过。它同时验证往返一致性与工厂内部结构的封装。

### record.config_change

修改实例构造配置后，运行结果按新配置变化。当前通过。构造配置被如实保存并传入工厂。

### record.wiring

记录中的显式连接决定提供方，与列出顺序无关；换用其他提供方得到不同结果。当前通过。接线选择不依赖记录遍历顺序。

### record.independence

同一份记录实例化两次得到互不影响的运行实例。当前通过。重复加载会创建独立状态。

### record.config_values

大于双精度可精确表示范围的整数、64 位上下界、转义字符串、小数、布尔与数组在解析、工厂交接与保存中保持精确；逗号小数区域下记录中的小数点仍可正确解析与输出；重复成员名与隐式类型转换被拒绝。当前通过。它验证配置数据的精度与本地化边界。

### record.record_errors

覆盖语法错误带行列、不支持的版本、格式缺失或错误、版本类型错误、未知字段、缺少实例名、根作用域出现转接或导出、作用域名非法或重复、重复字段、整数溢出路径，以及顶层非对象、空输入与多余内容；省略可选数组与配置仍是有效记录。当前通过。损坏记录与非法结构给出可定位的诊断，而不是通用失败。

### record.factory_errors

重复定义、空定义标识、未知定义（直接创建与经记录加载，带字段路径）、缺少必需配置、超出范围、类型错误，以及工厂返回实例名不一致，分别保留对应错误类别。当前通过。工厂与配置错误按记录位置定位，不混为同一种配置错误。

### record.factory_target

工厂在根模块、子模块、与根同名子模块及未完成归属的深层模块中重复声明符号，分别通过直接构造、根记录和嵌套作用域实例化验证：外层目标始终指向所属实例，内部原始位置保留在 `cause`；构造成功后发现的缺失需求仍定位完整内部路径。当前通过。它验证构造期诊断不凭局部名称猜测模块归属。

### record.factory_causes

嵌套工厂抛出带独立配置文件来源的诊断，检查外层实例、嵌套工厂及原始错误逐层保留目标、类别、来源与字段路径，诊断复制后仍可读，消息包含原因链；目录查找和返回名错误不虚构内部原因。当前通过。它验证跨工厂交接既能定位装配实例，也能保留作者给出的原始错误。

### record.assembly_errors

重复实例由引擎诊断并附带记录路径；缺失连接在封闭时报告；未知提供方、契约、种类、类型与签名不匹配复用引擎诊断；跨作用域与嵌套非法连接定位到对应记录位置。当前通过。加载层不另写一套装配规则，诊断保留记录来源。

### record.builder_errors

构建装配定义时拒绝重复或非法作用域名、未知目标作用域、未知转接与导出目标；合法定义往返后保持一致。当前通过。记录构建与解析使用同一套结构约束。

### record.rollback

实例化任一阶段失败时，临时构造的模块状态被释放且不发布；此前加载的运行实例继续可用；普通工厂异常转换为配置交接诊断。当前通过。它验证实例发布与临时资源清理，是 G-04 的边界证据；不证明作者代码对外部系统的副作用可回滚。

### record.file

保存与加载往返后运行结果一致；文件不存在、读取失败（目录路径）与写入失败（父目录不存在）都保持 I/O 故障分类，不误报为记录格式错误。当前通过。文件层错误与内容层错误分开报告。

### record.diagnostic_locations

销毁装配定义并移动引擎后，延迟 `check` 与 `seal` 仍定位原记录；修正接线后清除旧接线位置；嵌套连接、同名需求与导出、继承转接分别定位到对应字段。当前通过。它验证诊断来源随实际装配关系维护，不依赖加载对象继续存活。

### record.forward_transaction

目标子需求已经连接时，继承转接失败撤销本次新建的需求，保留先前已有需求；随后合法接线仍可检查并封闭。当前通过。它验证失败操作不留下多余需求，也不删除已有声明。

### record.json_depth

含记录外层容器在内的 128 层 JSON 可解析并往返，超过上限的输入、代码构造配置和深层作用域在解析或序列化时被拒绝，诊断保留来源与配置位置。当前通过。它验证读写使用一致的容器深度边界。

### record.utf8_serialization

拒绝非法 UTF-8、过长编码、截断序列、代理码点及越界码点；非法配置值或对象键保存失败时，已有目标文件内容保持原样；包含空字符与合法多字节字符的字符串可往返。当前通过。它验证读写文本校验和先校验再截断的保存顺序，不覆盖写入中途故障的文件恢复。

### record.pointer_paths

配置整数溢出和未知字段的键名含 `/`、`~` 时，错误路径分别按 `~1`、`~0` 转义。当前通过。它验证字段定位不会把键名误当成路径层级。

## 6. 通用文案层用例

### text.define_resolve

登记带文本域的翻译，检查包含查询、语言列表、默认模板和最终 `domain:key` 回退；原文中的花括号不解释，空翻译与空默认模板不误判为缺失；空语言、文本域和键被拒绝。当前通过。它确定文本身份与原文、空文本的区别。

### text.locale_fallback

目标语言未命中时依次尝试主标签、默认语言及其主标签；目标与默认语言相同时仍能回退主标签；空目标语言可使用默认语言，清空默认语言后使用消息自带模板。当前通过。

### text.placeholders

重复占位符全部替换，缺少参数与普通花括号保留；重复参数名、空参数名、含花括号的参数名以及空文本域在构造时拒绝。当前通过。

### text.load_merge

加载同域同语言的多个文件，默认拒绝重复键；发生冲突时，不提前发布该文件中的新键，也不覆盖已有条目。显式指定 `replace` 后新键与覆盖同时生效，未涉及的旧键保持。单条登记同样核对冲突策略。空包会登记语言，但不产生条目，查询仍按默认模板或默认语言回退；仅设置默认语言不改变已登记语言列表。当前通过。

### text.load_errors

文件缺失、以目录作为文件读取、JSON 语法错误、格式、版本、文本域、语言、条目结构、未知字段与必需字段缺失分别诊断；字段路径转义 `/` 与 `~`。文件中先有合法条目、后有非法条目时，目录不留下部分内容。当前通过。目录读取用例覆盖 I/O 错误分类，不模拟设备读取到一半中断。

### text.diagnostic_texts

错误参数调用产生带域的结构化消息，默认及指定语言渲染均正确；完整诊断附带目标位置，`what()` 与默认渲染一致；目录说明同样携带 `TextRef`。当前通过。

### text.shipped_pack

加载核心 `i18n/zh-CN.json`，检查引擎、装配、JSON 与 i18n 的代表性键；真实提供方类型不匹配和需求转接不匹配的组合诊断，外层和内层原因均能完整显示中文。当前通过。代表性键检查不代替全部翻译的语义审查。

### text.depth_messages

嵌套超限在解析与序列化两条路径上使用不同的文本键：解析路径带行列参数，序列化路径不带位置；两者经语言包解析后都不残留占位符。当前通过。它保证同一语义在不同参数形态下都有对应文本。

### text.parameter_literals

参数值包含另一个占位符时保持原样，调换参数排列结果一致；真实 JSON 重复键 `{line}` 的诊断保留键名，不被行号替换；Unicode、路径和花括号组合原样插入。当前通过。这是占位符递归替换问题的回归。

### text.fallback_once

未知定义名包含 `{definition}` 时，语言未命中的渲染与默认消息一致，不重复扩展名称；命中翻译后也只插入一次，切换语言不修改原消息；作者原文不参与解释。当前通过。这是诊断回退二次格式化问题的回归。

### text.nested_messages

外层与内层消息来自不同文本域，使用同一目标语言渲染，内层参数中的花括号不再解释；缺失翻译时各自使用默认模板。消息树允许到 128 层，超过上限拒绝。当前通过。

### text.nested_diagnostics

同一提供方直接调用和通过需求嵌套调用时，内层诊断的键、类别和目标保持；完整断言两层中文输出，包含外层目标、消息、换行后的“原因：”分隔符及内层目标与消息，并保留默认 `what()` 读出。当前通过。这是嵌套调用丢失本地化信息问题的回归。

### text.boundary_diagnostics

配置校验、公开量读取、类型化参数复制和工厂构造分别抛出结构化 `EngineError`，验证操作边界保存原诊断；来源、字段路径、文本参数及内部目标不丢失，外层沿用各操作的错误分类。当前通过。既有引擎用例继续覆盖结果解包、标准及非标准异常的行为。

### text.domains

不同文本域可以使用同一局部键且互不串用，未知域使用自己的默认模板；即使指定替换，资源声明域与文件域不符也拒绝，不污染其他域。当前通过。

### text.module_resources

工厂登记自己的语言文件，查询和加载资源均不执行构造代码；创建两个不同名称的实例后，共享同一文本域与翻译。非法资源登记不留下定义，未知定义查询报错。当前通过。覆盖显式资源接入，不代表已经实现包自动发现。
