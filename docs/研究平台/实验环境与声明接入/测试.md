# 实验环境与声明接入 — 测试

> - 适用范围：引擎接口、装配、状态与实验、文件和模块资源的验证目的及入口
> - 上级：[研究平台](../综述.md) · [设计](设计.md) · [实现](实现.md)

## 1. 目的与范围

测试验证已定义的接口行为，不证明任意模块忠于因果声明，也不授予研究资格。以下按关键保证索引用例，具体输入与断言由测试代码维护；完整注册见 [testbench/engine/CMakeLists.txt](../../../testbench/engine/CMakeLists.txt)，示例输出注册见[引擎 CMake](../../../kheker/engine/CMakeLists.txt)。实际通过情况以运行和 CI 为准。

基础与文案用例支撑 G-01、G-03，组合用例支撑 G-02，装配记录支撑 G-04，实验切片支撑 G-06、G-08 的首版范围。随机、历史管理、行动通道和实际访问核验尚无对应用例。目录可读与类型匹配不等于代码访问受限，实例释放不证明作者外部副作用可回滚。

## 2. 运行方式与验证环境

构建与整套 CTest 命令见[实现](实现.md#4-构建与运行入口)。五个测试程序在 `build/engine/tests/`，命令行参数选择用例，例如 `ascend_engine_tests non_spatial_model`；多配置生成器使用对应配置子目录。也可按组筛选：

```bash
ctest --test-dir build/engine --build-config Debug -R '^experiment\.' --output-on-failure
```

开发环境为 Linux x86-64，使用 GCC／Clang 的 Debug／Release 及 Clang AddressSanitizer＋UndefinedBehaviorSanitizer 构建。[CI](../../../.github/workflows/engine.yml) 在 Linux 与 Windows 构建测试，macOS 未纳入；跨平台通过情况以实际运行记录为准。此套用例不提供吞吐测量。

## 3. 引擎基础用例

前缀 `engine.`；源码 [test_engine.cpp](../../../testbench/engine/test_engine.cpp)，程序 `ascend_engine_tests`。

| 关键保证与验证目的 | 用例入口（省略前缀） | 重要边界 |
| --- | --- | --- |
| 可运行独立的非空间模型 | `non_spatial_model` | 两变量规则与不同初态实例，结果独立，不注入空间、实体或时钟 |
| 自定义类型传输保持封装 | `custom_values`、`transport_values` | 矩阵与容器作为完整值传递，领域越界由方法拒绝 |
| 目录与作用域查询被动且稳定 | `catalog_is_passive`、`scoped_references`、`scopes` | 不调用 getter，稳定排序，登记接口快照与返回副本不被外部修改；草稿失效可刷新 |
| 非法声明与重复登记不污染装配 | `invalid_declarations`、`duplicate_registration` | 名称、实现、参数、依赖与命名空间检查 |
| 配置校验只在正确边界执行 | `configuration_validation`、`validation_reentry` | 登记前执行，失败可修正，重入不绕过规则，封闭不重复执行 |
| 依赖检查可修复 | `unresolved_dependencies`、`dependency_kind` | 汇总缺失项，拒绝方法充当量依赖，补齐后可运行 |
| 封闭与绑定控制运行生命周期 | `lifecycle`、`binding_checks`、`binding_lifetime` | 封闭前拒绝调用，封闭后固定；精确种类／签名，外部句柄保活及最终释放 |
| 调用前拒绝与调用后失败分别记录 | `invocation_checks`、`callback_failures`、`binding_argument_failures`、`binding_value_failures`、`binding_result_failures` | 错误参数和参数复制失败不执行方法；回调／结果解包失败保留已发生变化；标准与非标准异常均定位 |
| 回调自身可持有状态 | `stateful_callbacks` | 多次调用之间的可调用对象状态保持，不要求它成为公开量 |

## 4. 组合装配用例

前缀 `assembly.`；源码 [test_assembly.cpp](../../../testbench/engine/test_assembly.cpp)，程序 `ascend_assembly_tests`。

| 关键保证与验证目的 | 用例入口（省略前缀） | 重要边界 |
| --- | --- | --- |
| 嵌套实例独立，输入与推进分开 | `model`、`stimulus` | 不同提供方产生各自结果，驱动输入不隐含推进 |
| 接线显式且与登记顺序无关 | `discovery`、`missing`、`mismatches`、`order` | 被动候选查询不自动接线，缺失可补齐，种类／契约／签名分别诊断 |
| 作用域边界不能由浏览绕过 | `names`、`edge_cases`、`exports`、`forwarding` | 重复与非法名字、跨层直连、内部直接调用被拒绝；导出可补齐，需求必须显式转接 |
| 引用环与上下文生命周期受控 | `cycles`、`lifetime`、`context_identity` | 可终止的引用环可运行且无内部所有权环；过期上下文或他模块需求拒绝，当前装配身份正确 |
| 封闭和失败定位一致 | `closed`、`failures` | 封闭后不可编辑，嵌套调用／配置错误保留内部完整位置 |

## 5. 装配记录用例

前缀 `record.`；源码 [test_assembly_record.cpp](../../../testbench/engine/test_assembly_record.cpp)，程序 `ascend_assembly_record_tests`。

| 关键保证与验证目的 | 用例入口（省略前缀） | 重要边界 |
| --- | --- | --- |
| 定义与实例身份分离 | `factories`、`independence`、`factory_merge` | 每次构造独立；默认配置可查，合并先到者优先且可重复 |
| 同一装配定义驱动保存与运行 | `definition`、`roundtrip`、`config_change`、`wiring` | 配置与接线决定输出，顺序不隐式选提供方，工厂内部结构不泄漏到记录 |
| 工具编辑只影响对应草稿 | `definition_access`、`editing_instance` | 实例快照只读，配置重建后生效；移除清理同作用域引用，断开与重接可往返 |
| 配置解析精确且不受区域格式影响 | `config_text`、`config_values` | 64 位整数与复杂值往返，逗号小数区域仍使用 JSON 小数点；尾随内容、重复键与隐式转换拒绝 |
| 结构错误可定位 | `record_errors`、`builder_errors`、`assembly_errors` | 版本／格式、未知字段、非法作用域与连接定位到记录路径，可选集合省略仍有效，装配复用引擎检查 |
| 工厂错误保留所属实例和原始原因 | `factory_errors`、`factory_target`、`factory_causes` | 不猜测同名局部对象的归属；根／嵌套工厂的类别、目标、来源和原因链分别保留 |
| 失败不发布半成品 | `rollback`、`forward_transaction` | 临时实例释放，既有运行可用；失败转接撤销新增需求而保留已有需求，不覆盖外部副作用 |
| 文件与延迟诊断保持来源 | `file`、`diagnostic_locations`、`pointer_paths` | I/O 与结构错误分开，定义销毁后延迟检查仍定位；改线清旧来源，键中的 `/`、`~` 正确转义 |
| 文本读写边界一致 | `json_depth`、`utf8_serialization` | 含外层容器的深度限制与 UTF-8 双向校验；序列化失败保留原文件，不模拟写入中途故障恢复 |

## 6. 通用文案层用例

前缀 `text.`；源码 [test_text.cpp](../../../testbench/engine/test_text.cpp)，程序 `ascend_text_tests`。

| 关键保证与验证目的 | 用例入口（省略前缀） | 重要边界 |
| --- | --- | --- |
| 文本身份与回退不混淆原文和空值 | `define_resolve`、`locale_fallback`、`domains` | 域隔离、空翻译有效、语言及主标签回退；资源域不符即拒绝 |
| 参数只插入一次 | `placeholders`、`parameter_literals`、`fallback_once` | 非法参数名拒绝，缺失占位符保留；参数中的花括号、路径和 Unicode 不递归解释，顺序不影响结果 |
| 整份资源原子合并 | `load_merge`、`load_errors` | 冲突或后续字段错误不部分提交，显式替换，空包登记语言；不模拟设备中途读取中断 |
| 消息树与诊断链保留结构 | `diagnostic_texts`、`nested_messages`、`nested_diagnostics`、`boundary_diagnostics` | 跨域嵌套、深度限制、默认 `what()` 与本地化；配置／读取／传输／工厂边界不丢目标和来源 |
| 随附资源与参数形态一致 | `shipped_pack`、`depth_messages` | 代表性键及真实嵌套错误的中文渲染，解析／序列化深度消息无残留占位符；不代替全部翻译语义审查 |
| 定义级资源可跨实例共用 | `module_resources` | 登记与查询不执行工厂，实例名不决定域，非法登记不留下定义；不代表自动包发现 |

## 7. 实验切片用例

前缀 `experiment.`；源码 [test_experiment.cpp](../../../testbench/engine/test_experiment.cpp)，程序 `ascend_experiment_tests`。

| 关键保证与验证目的 | 用例入口（省略前缀） | 重要边界 |
| --- | --- | --- |
| 状态声明完整且恢复可核对 | `state_declarations`、`capture_restore`、`restore_mismatches` | 互斥声明，缺失即整体失败，按路径核对集合／契约／无状态值；乱序可恢复，中途失败不回滚 |
| 检查点与分支独立于源运行 | `deep_copy`、`branch_isolation`、`lifetime` | 非初始检查点续跑，交换推进顺序不影响各分支，源／中间分支销毁不影响快照与其他分支 |
| 一次干预可观察直接变化与延迟传播 | `intervention_propagation`、`trace_record` | 三变量参考模型逐帧核对，共同起点不变，干预只记入对应分支 |
| 字段路径与作者校验各司其职 | `intervention_errors`、`nested_fields` | 缺失／无状态／非对象路径拒绝；空路径替换整体，同路径按顺序覆盖；非法结构由恢复回调拒绝 |
| 读取不驱动演化，观测不泄漏真值 | `sampling_stability`、`observation_memory`、`run_directory` | 改变采样频率结果相同；只读目录无副作用，`observe` 不捕获私有记忆，主体只接收观测而非运行对象 |
| 规格、失败与重入边界明确 | `spec_errors`、`step_failure`、`reentrant_operations`、`frame_limit` | 名称检查先于工厂；推进失败不增帧但保留写入；六类操作互斥，异常退出释放守卫；帧上限在模型执行前拒绝 |
| 组合容器与共用示例满足状态契约 | `nested_assembly`、`example_model` | 纯容器无状态不掩盖子模块缺失；参考序列、资源回退及两处整数溢出核对 |
| 记录足以重建已核对的实验 | `trace_replay` | 原装配、工厂目录与运行销毁后，依据记录和核对后的实现重新驱动；宿主仍负责标识与记录真实性 |
| 运行记录编码完整且拒绝损坏 | `record_file_round_trip`、`record_file_depth_limits` | 身份、检查点、输入与轨迹诊断往返；魔数／版本／截断／不支持类型及过深读写拒绝；深度边界覆盖 128 层通过、129 层拒绝；摘要只读 meta 段 |
| 研究文件编码完整且拒绝损坏 | `study_file_round_trip`、`study_file_errors` | 世界引用、规格与可选模型名往返；格式、版本、相对路径与字段错误拒绝 |
| 包清单与运行时声明对应 | `module_package_round_trip`、`module_library_load_unload` | 稳定类型与相对引用、清单顺序无关；篡改、实现缺失／不匹配、重复与非法资源拒绝且不登记；可卸载重装并实例化 |

### 参考值与证明边界

- 干预传播使用 `x' = x + a`、`y' = x`、`z' = y + z`，右侧读取步开始值；起点与逐帧结果见[工作台场景 A](../因果建模工作台/设计.md#场景-a可手算的完整实验)。测试核对手工参考序列，不仅比较两份相同实现。
- `trace_replay` 在共同检查点后使用变化输入 `2, -1, 3`，最终对照为 `(6,3,7)`，干预为 `(14,11,23)`，验证记录没有依赖固定输入假设。
- `observation_memory` 恢复后输出应为 `8, 15`；遗漏私有记忆时首步为 `6`。此反例检验捕获范围，不代表原生代码沙箱或一般历史管理已实现。
- 模块包用例验证内置实现载体；不能推断动态库 ABI、任意模块完整状态或跨进程闭环复现。
- 装配文件的模块需求与版本核对（ENV-15、ENV-18）尚未实现，无对应用例；结构化值深度按「含外层容器 128 层」，原因链按「顶层诊断之外 128 层原因」，文本按「命名参数 128 层（不含字面量）」，读写同界。
