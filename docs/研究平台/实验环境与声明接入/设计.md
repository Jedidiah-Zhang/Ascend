# 实验环境与声明接入 — 设计

> - 设计状态：讨论中
> - 适用范围：因果实验环境的声明、函数接入、检查与执行
> - 已确定范围：运行基底的语义与实现分离及研究者扩展、机制函数接入、全局量声明、随机数管理入口、无界面引擎与工具共用接口
> - 尚未覆盖：声明格式、函数访问约束、历史管理、干预时序、数值等价标准及具体验证判据
> - 上级：[研究平台](../综述.md) · [实现](实现.md)

## 1. 目标与职责

提供因果声明与执行引擎，接入研究者定义的变量、机制函数及运行基底，组织声明检查、实际执行与结果读取。支持整体替换实验环境，包括不具有空间、实体或游戏时钟的因果系统；适用范围由[平台综述](../综述.md#自定义因果实验环境)维护。

研究依据为作者的[研究综述](../../研究理论/研究综述.md)：§1.1 的已知生成机制、§2.1 的完整状态与平行轨迹、§2.2 的受限感知。本文记录经讨论确认的工程方向，不将工程选择等同于综述原有条款。

本模块维护模型声明及引擎行为；[因果建模工作台](../因果建模工作台/设计.md)提供编辑与展示。实验组织、评价协议及主体信息权限由对应研究议题细化。引擎可加载和执行某个环境，不等于该环境已支持全部研究保证。

## 2. 概念与术语

| 概念 | 含义 |
| --- | --- |
| 环境定义 | 变量含义、生成机制、依赖关系及适用条件的定义 |
| 模型声明 | 将环境定义、机制函数及其输入输出组织为可检查模型的描述 |
| 机制函数 | 实际产生模型结果的代码函数 |
| 运行基底 | 承载因果系统运行的底层支持，具体组成由环境选用 |
| 基底语义 | 运行基底对所承载系统承诺的量、关系与操作的含义 |
| 基底实现 | 实现基底语义的算法、数据结构与调度方式 |
| 声明依赖／执行路径 | 模型描述的生成依赖／某次运行实际经过的计算与访问 |

声明依赖不等于每次运行都产生非零影响；一次执行路径也不代表所有条件下的完整依赖。因果图用于表达结构，机制函数决定具体结果，二者共同构成模型描述。

## 3. 已确认规则

### ENV-01 运行基底的语义与实现分离

运行基底需要明确声明其对所承载世界意味着什么。参与因果计算的量、关系与操作具有明确的基底语义；基底实现负责满足这些声明。

采用时间或空间能力时，本地时间、位置、距离及相关操作具有相应语义；这些例子不要求所有环境具有时间或空间。世界库自身的规则由其模块维护，本模块不重复定义。

索引结构、任务队列与数据布局由实现选择，不必逐项成为模型中的因果变量；它们须维持声明的行为。影响后续结果的内部信息需由实现正确维护或重建，不能因世界内部不可见而忽略。

### ENV-02 运行基底的研究者扩展边界

允许研究者替换、增加或删除运行基底，由研究者自行维护修改后的可用性。ENV-01 的语义与实现关系仍适用。

运行基底不属于因果声明自动验证的保证范围。声明检查通过不代表自定义基底实现已被验证正确；检查结论须说明其覆盖范围及对所用基底的依赖。具体扩展接口未定。

### ENV-03 生成机制以可执行函数表达

生成机制以代码函数表达，执行时直接调用该函数。声明将函数与模型变量的输入输出对应起来，不要求作者另写等价数学公式或逐机制提交形式化证明。

函数可表达分支、循环等计算，不要求每个程序步骤成为独立因果节点。机制可调用运行基底提供的操作；语言、函数签名及执行约束未定。仅有函数注册或边列表不能自动保证任意代码遵守声明依赖。

### ENV-04 全局量随运行基底声明

全局变量与运行基底一同声明，机制函数可以访问这些已声明的量。全局可访问不意味着它对机制结果的影响可以省略描述；访问接口、可变量的写入权限与读取版本未定。

### ENV-05 统一随机数管理入口

提供随机数生成管理器，机制通过该入口获取随机数。算法、请求标识、配对与恢复方式仍待设计。旧随机系统的地址化抽取仅供方案比较，不自动成为新要求。

### ENV-06 声明与执行能力独立于工作台

引擎提供可无界面调用的目录查询、声明检查、执行与诊断能力，供工作台、命令行及批量实验共用。检查与执行规则由引擎维护，工作台不另行实现一套。

模型文件与机制代码可独立保存、加载和运行，不以启动工作台为前提。目录、依赖视图与诊断来源于实际加载的模型及基底描述；声明检查、执行检查与研究验证分别说明范围，不能以一个无范围的“通过”替代。

## 4. 对外契约

以下为**候选接口分解**，语义方向已明确，字段与签名未定：

| 能力 | 输入／输出 | 已定边界／未定部分 |
| --- | --- | --- |
| 模型加载 | 声明、机制与基底引用 → 模型及诊断 | 可无界面调用；文件格式、引用和错误表示未定 |
| 目录与依赖查询 | 已加载模型 → 变量、机制、全局量、基底操作及依赖 | 为工作台提供实际模型信息；来源定位与查询粒度未定 |
| 绑定与检查 | 函数输入输出映射 → 检查结果 | 检查范围须明确；类型、值域、依赖与访问规则待细化 |
| 建立与执行运行 | 初始条件、输入及执行请求 → 结果或失败信息 | 按环境自身语义求值；更新、提交及失败细则未定 |
| 干预与读取 | 目标、计算位置及条件 → 接入结果、读出及记录 | 支持方向已明确；合法位置、时序及观测权限待讨论 |

函数使用全局量、历史或随机入口时，声明如何描述对应依赖、引擎如何约束实际访问，须随接入方式确定。

## 5. 配置与边界情况

| 项目 | 当前边界 | 待定部分 |
| --- | --- | --- |
| 环境形式 | 不强制空间、实体、秒制或固定帧 | 所支持的求值与演化方式 |
| 数值语义 | 结果判等需有明确依据 | 精确一致、容差及适用范围 |
| 依赖变化 | 分支执行路径不等于完整声明依赖 | 条件依赖、循环与动态目标的表达 |
| 全局量 | 随基底声明且可访问 | 初始化、可变性、写入与读取版本 |
| 历史与记忆 | 管理方式仍为候选 | 初始值、历史不足、保留及分支恢复 |
| 随机条件 | 使用统一管理入口 | 请求对应、共享与配对方式 |
| 基底修改 | 允许研究者替换、增删 | 扩展接口及模型依赖缺失时的诊断 |

声明存在不等于实际执行忠实遵守声明。自动检查范围需与所选语言、运行环境及基底假设一致。

## 6. 取舍与候选方案

**函数与声明配合**：代码承担生成计算，声明组织模型变量及依赖，避免重复维护一份公式和一份实现。任意代码的完整依赖不能仅凭边列表证明；显式参数、受限上下文及访问检查等方案仍需比较。Lean 等工具可用于验证具体性质，使用范围未定。

**历史与机制记忆**：候选方案将过去值或窗口作为输入，将机制旧记忆作为输入、新记忆作为输出，由运行时保管。函数自行定义记忆更新逻辑，无需默认保存全部历史。显式参数与上下文访问尚未选择；一次调用内的临时数据仍可由函数自行处理。

**完整运行条件**：建议明确环境定义、当前状态、后续输入与随机条件的范围，区分可重建数据和必须延续的信息。哪些信息属于模型状态、哪些由基底维护，以及保存恢复的对应方式仍待确定。

**平行比较**：建议显式列出共同条件、干预生效位置及改变的因素。相同种子是否实现所需配对，需结合实际随机机制检查。具体实验组织和判据后续设计。

## 7. 验收标准

以下对应已确认方向；具体测试随接口确定后实现，尚无新方案验证结果：

| 依据 | 场景 | 预期 |
| --- | --- | --- |
| ENV-01 | 对一个基底操作定义有效输入与预期行为 | 可按声明核对对外行为，不以特定索引或调度结构作为模型要求 |
| ENV-02 | 使用研究者修改的运行基底并检查模型声明 | 支持扩展接入；检查结果不将基底实现标为已自动验证 |
| ENV-03 | 绑定含分支或循环的机制函数并执行 | 调用所绑定函数产生输出，无需另交等价公式；依赖核验范围明确 |
| ENV-04 | 机制访问随基底声明的全局量 | 可建立相应访问与模型依赖；具体读写规则按定稿接口检查 |
| ENV-05 | 机制请求随机输入 | 通过统一管理器提供，具体取值与配对按后续随机语义检查 |
| ENV-06 | 由工作台与无界面入口加载同一模型并发起同一检查 | 使用同一引擎与检查规则，结果对应相同模型和检查范围 |
| 平台接入方向 | 加载不依赖空间、实体和游戏时钟的最小因果系统 | 能检查并执行其声明，不要求装配官方世界 |

历史恢复、干预配对、完整状态及数值等价的验收须在相应语义确认后补充，不能从上述方向推断已获保证。
