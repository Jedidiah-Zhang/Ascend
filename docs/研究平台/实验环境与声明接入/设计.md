# 实验环境与声明接入 — 设计

> - 设计状态：讨论中
> - 适用范围：因果实验环境的声明、函数接入、检查与执行
> - 已确定范围：C++ 无界面核心、模块声明公开量与方法、语义说明与程序检查及实现验证的分工、研究者扩展、机制函数接入、全局量与随机入口、引擎与工具共用接口
> - 尚未覆盖：持久化声明格式、跨语言与插件接口、实际访问核验、历史管理、随机及干预时序；首个原生接入切片见第 4 节
> - 上级：[研究平台](../综述.md) · [实现](实现.md)

## 1. 目标与职责

提供具有研究描述能力的模块化执行引擎。模块声明公开量与方法并提供具体实现，引擎负责注册、引用解析、绑定、已支持的接口检查、依赖组织和执行。支持整体替换实验环境，包括不具有空间、实体或游戏时钟的因果系统；适用范围由[平台综述](../综述.md#自定义因果实验环境)维护。

研究依据为作者的[研究综述](../../研究理论/研究综述.md)：§1.1 的已知生成机制、§2.1 的完整状态与平行轨迹、§2.2 的受限感知。本文记录经讨论确认的工程方向，不将工程选择等同于综述原有条款。

本模块维护模型声明及引擎行为；[因果建模工作台](../因果建模工作台/设计.md)提供编辑与展示。实验组织、评价协议及主体信息权限由对应研究议题细化。引擎可加载和执行某个环境，不等于该环境已支持全部研究保证。

## 2. 概念与术语

| 概念 | 含义 |
| --- | --- |
| 环境定义 | 变量含义、生成机制、依赖关系及适用条件的定义 |
| 模型声明 | 将环境定义、机制函数及其输入输出组织为可检查模型的描述 |
| 模块接口声明 | 模块公开量、方法及其引用和实现绑定的描述，供引擎与使用方接入 |
| 语义说明 | 向开发者和研究者解释量、关系及操作在世界中的含义与使用约定 |
| 机制函数 | 实际产生模型结果的代码函数 |
| 运行基底 | 承载因果系统运行的底层支持，具体组成由环境选用 |
| 基底语义 | 运行基底对所承载系统承诺的量、关系与操作的含义 |
| 基底实现 | 实现基底语义的算法、数据结构与调度方式 |
| 声明依赖／执行路径 | 模型描述的生成依赖／某次运行实际经过的计算与访问 |

声明依赖不等于每次运行都产生非零影响；一次执行路径也不代表所有条件下的完整依赖。因果图用于表达结构，机制函数决定具体结果，二者共同构成模型描述。

## 3. 已确认规则

### ENV-01 运行基底的语义与实现分离

运行基底说明其对所承载世界有语义的量、关系与操作，并通过模块接口声明暴露相应能力。基底实现负责具体计算与行为；语义说明、接口检查和实现验证的分工见 ENV-08。

采用时间或空间能力时，本地时间、位置、距离及相关操作具有相应语义；这些例子不要求所有环境具有时间或空间。世界库自身的规则由其模块维护，本模块不重复定义。

执行组织参数、索引结构、任务队列与数据布局由运行基础维护，不因参与执行就自动成为世界语义声明项或模型因果变量。是否具有世界语义与主体能否直接感知分开判断。影响后续结果的内部信息仍需由实现正确维护或重建；执行与复现所需记录也不等于世界语义声明。世界固定步长的具体边界由 [TIME-03](../../世界/世界框架/时间系统/设计.md#time-03-固定本地步长与步内阶段)维护。

### ENV-02 运行基底的研究者扩展边界

允许研究者替换、增加或删除运行基底，由研究者自行维护修改后的可用性。ENV-01 的语义与实现关系仍适用。

运行基底不属于因果声明自动验证的保证范围。声明检查通过不代表自定义基底实现已被验证正确；检查结论须说明其覆盖范围及对所用基底的依赖。具体扩展接口未定。

### ENV-03 生成机制以可执行函数表达

生成机制以代码函数表达，执行时直接调用该函数。声明将函数与模型变量的输入输出对应起来，不要求作者另写等价数学公式或逐机制提交形式化证明。

函数可表达分支、循环等计算，不要求每个程序步骤成为独立因果节点。机制可调用运行基底提供的操作；首个切片使用 C++ 原生函数，其他语言与扩展后端待定。仅有函数注册或边列表不能自动保证任意代码遵守声明依赖。

### ENV-04 全局量随运行基底声明

全局变量与运行基底一同声明，机制函数可以访问这些已声明的量。全局可访问不意味着它对机制结果的影响可以省略描述；访问接口、可变量的写入权限与读取版本未定。

### ENV-05 统一随机数管理入口

提供随机数生成管理器，机制通过该入口获取随机数。算法、请求标识、配对与恢复方式仍待设计，并在接口设计阶段比较候选方案。

### ENV-06 声明与执行能力独立于工作台

引擎提供可无界面调用的目录查询、声明检查、执行与诊断能力，供工作台、命令行及批量实验共用。接口检查与执行编排由引擎统一提供，领域校验与具体计算由模块实现，工作台不另行实现一套。

模型文件与机制代码可独立保存、加载和运行，不以启动工作台为前提。目录、依赖视图与诊断来源于实际加载的模型及基底描述；声明检查、执行检查与研究验证分别说明范围，不能以一个无范围的“通过”替代。

### ENV-07 模块声明公开量与方法

领域概念由提供能力的模块引入。模块定义公开量及其类型、形状等接口信息，暴露方法并绑定数据访问与可执行实现；其他模块通过公开引用使用这些能力。具体计算、功能和机制由模块内部实现，引擎不从概念名称或自然语言说明自动生成算法。

例如，空间模块提供宽、高、位置及几何操作的定义，实例给出相应数据。引擎不预置所有环境都具有这些概念；未加载相应定义时，引用不能凭名称获得有效含义。替换模块后，使用方与新定义的对应关系须重新检查。

整数、张量等属于接口可采用的数据类型，具体量的表示由所属模块决定。模块内部存储布局、索引及私有辅助方法不要求逐项公开。公开量的所属实例、引用方式、类型与形状规则、读取版本和写入方式仍需接口设计。

### ENV-08 语义说明、程序检查与实现验证分工

声明中的信息按实际用途使用，不要求将全部世界含义编码为一套通用形式化语言。机器消费的字段须对应明确的注册、绑定、执行或检查行为；纯说明允许使用文档或 docstring。

| 内容 | 使用方 | 作用与保证范围 |
| --- | --- | --- |
| 标识、引用及数据／方法绑定 | 引擎 | 连接实际数据与实现；具体解析规则待定 |
| 接口采用的类型、形状等信息 | 引擎与开发工具 | 检查已支持的接口条件；具体类型系统和检查项待定 |
| 单位、领域含义及使用约定 | 开发者与研究者 | 解释模型；采用结构化标记时，也只按已实现的规则检查 |
| 模块提供的校验代码 | 加载或运行入口 | 检查特定配置、输入及状态条件；调用阶段和失败接口待定 |
| 测试、参考计算及其他验证证据 | 开发者与研究者 | 支持对具体实现行为的判断，结论限于验证范围 |

单位标记、类型匹配和参数检查不单独保证计算结果正确。复杂约束可由模块代码实现，不要求转换成固定规则语言；实现是否符合语义说明仍由模块作者维护和验证。

作者提供的因果依赖可用于组织和展示声明图。其是否完整反映实际执行，需要访问约束或相应验证；引擎不能仅凭声明获得任意方法内部的完整因果结构，单次运行记录也不构成完整性证明。

## 4. 对外契约

以下为**候选接口分解**，语义方向已明确，字段与签名未定：

| 能力 | 输入／输出 | 已定边界／未定部分 |
| --- | --- | --- |
| 模块注册 | 公开量、方法及实现绑定 → 可引用目录与诊断 | 领域定义由模块提供；标识、所属实例、类型与绑定规则未定 |
| 模型加载 | 声明、机制与基底引用 → 模型及诊断 | 可无界面调用；文件格式、引用和错误表示未定 |
| 目录与依赖查询 | 已加载模型 → 变量、机制、全局量、基底操作及依赖 | 为工作台提供实际模型信息；来源定位与查询粒度未定 |
| 绑定与检查 | 数据／方法引用、函数输入输出映射 → 绑定及检查结果 | 只检查明确支持的条件；类型、形状与访问规则待细化 |
| 模块校验 | 配置、输入或运行状态 → 模块校验结果 | 约束可由代码表达；触发阶段、失败行为和诊断接口未定 |
| 建立与执行运行 | 初始条件、输入及执行请求 → 结果或失败信息 | 按环境自身语义求值；更新、提交及失败细则未定 |
| 干预与读取 | 目标、计算位置及条件 → 接入结果、读出及记录 | 支持方向已明确；合法位置、时序及观测权限待讨论 |

函数使用全局量、历史或随机入口时，声明如何描述对应依赖、引擎如何约束实际访问，须随接入方式确定。

### 首个无界面实施切片

核心采用 C++，先以代码注册验证量、方法与引用的闭环。以下接口方案为**暂定**，在接入持久化模型、Qt 数据展示或跨二进制模块时复核；不作为稳定插件 ABI。

| 能力 | 本切片契约 |
| --- | --- |
| 模块与引用 | 模块标识在一个引擎实例内唯一，同时区分本切片中的模块实例；公开符号在模块内唯一。引用由模块标识、符号名称两部分构成 |
| 公开量 | 绑定返回值的 getter；读取时调用实现并返回值副本，不提供引擎侧直接写入。自定义值内部的共享资源由模块管理 |
| 公开方法 | 显式声明 C++ 输入输出类型并绑定函数。允许无参数及无返回值方法，状态改变由方法实现；参数名称供目录与诊断使用 |
| 类型 | 使用本进程内的精确 C++ 类型匹配，无隐式数值转换；支持可复制的自定义值类型。形状和领域约束由模块代码检查，本切片不规定通用张量布局 |
| 生命周期 | 注册阶段可浏览目录、检查引用；封闭注册时核对全部声明读写引用。成功后才能读取、绑定或调用，且不再增删模块；检查失败可补齐模块后重试 |
| 声明依赖 | 方法可提供读、写的公开量引用；封闭时检查目标存在且为量。只检查声明结构，不检查函数实际访问，也不由这些引用自动排出更新计划 |
| 模块校验 | 注册前调用模块提供的配置校验函数，异常导致该模块不注册。调用时的领域条件由方法代码检查 |
| 诊断 | 返回错误类别、目标引用与说明；错误参数在方法执行前拒绝。回调及类型化绑定内部参数封装、结果解包的异常转为执行诊断；方法已产生的状态改变不自动回滚 |
| 目录与绑定 | 目录按模块与符号名称稳定排序，不执行 getter 或方法。绑定句柄保存可调用入口的所有权，重复调用无需再次解析名称 |
| 执行范围 | 单线程宿主显式调用方法；独立引擎实例管理各自注册集合。模块通过回调持有其数据，回调及外部资源的生命周期由提供者负责 |

原生类型信息用于本进程接口匹配，不作为跨平台序列化标识。语义说明只供展示；固定宽度整数用例用于验证本切片，不据此承诺任意模块的跨平台数值一致性。声明文件加载、调度、快照、随机管理与干预协议继续按相应待决项设计。

类型化绑定内部复制／移动自定义值失败时，抛出携带当前目标引用的 `EngineError`（`execution_failed`）。参数封装失败时不执行方法；结果解包失败时保留已执行的状态改变。调用方在进入接口前构造／转换参数，或在接口返回后处理结果产生的异常，由调用方处理。

## 5. 配置与边界情况

| 项目 | 当前边界 | 待定部分 |
| --- | --- | --- |
| 环境形式 | 不强制空间、实体、秒制或固定帧 | 所支持的求值与演化方式 |
| 数值语义 | 结果判等需有明确依据 | 精确一致、容差及适用范围 |
| 依赖变化 | 分支执行路径不等于完整声明依赖 | 条件依赖、循环与动态目标的表达 |
| 公开数据与方法 | 通过已加载的模块定义引用和绑定 | 实例归属、可变数据访问、别名及写入控制 |
| 全局量 | 随基底声明且可访问 | 初始化、可变性、写入与读取版本 |
| 历史与记忆 | 管理方式仍为候选 | 初始值、历史不足、保留及分支恢复 |
| 随机条件 | 使用统一管理入口 | 请求对应、共享与配对方式 |
| 基底修改 | 允许研究者替换、增删 | 扩展接口及模型依赖缺失时的诊断 |

声明存在不等于实际执行忠实遵守声明。自动检查范围需与所选语言、运行环境及基底假设一致。

## 6. 取舍与候选方案

**函数与声明配合**：代码承担生成计算，声明组织模型变量及依赖，避免重复维护一份公式和一份实现。任意代码的完整依赖不能仅凭边列表证明；显式参数、受限上下文及访问检查等方案仍需比较。数学性质的形式化验证方式与适用范围待讨论。

**声明载体**：首个切片使用 C++ 代码注册；持久化描述文件、注解及其他载体仍待选择。语义说明可与接口就近维护，无需另建覆盖全部领域含义的规则语言。

**方法依赖与数据访问**：候选方案由提供方描述公开方法的读写依赖，引擎结合调用目标和参数组织使用方的依赖。依赖描述不等于实际访问核验。公开数据可评估只读视图与受管理的批量写入，具体权限、版本、别名和性能方案尚未选择。

**历史与机制记忆**：候选方案将过去值或窗口作为输入，将前一时刻的机制记忆作为输入、新记忆作为输出，由运行时保管。函数自行定义记忆更新逻辑，无需默认保存全部历史。显式参数与上下文访问尚未选择；一次调用内的临时数据仍可由函数自行处理。

**完整运行条件**：建议明确环境定义、当前状态、后续输入与随机条件的范围，区分可重建数据和必须延续的信息。哪些信息属于模型状态、哪些由基底维护，以及保存恢复的对应方式仍待确定。

**平行比较**：建议显式列出共同条件、干预生效位置及改变的因素。相同种子是否实现所需配对，需结合实际随机机制检查。具体实验组织和判据后续设计。

## 7. 验收标准

以下对应已确认方向；当前切片的验证范围与证据见[实现](实现.md#5-验证与性能)，其余场景随接口定稿补齐：

| 依据 | 场景 | 预期 |
| --- | --- | --- |
| ENV-01 | 对一个基底操作定义有效输入与预期行为 | 可按声明核对对外行为，不以特定索引或调度结构作为模型要求 |
| ENV-02 | 使用研究者修改的运行基底并检查模型声明 | 支持扩展接入；检查结果不将基底实现标为已自动验证 |
| ENV-03 | 绑定含分支或循环的机制函数并执行 | 调用所绑定函数产生输出，无需另交等价公式；依赖核验范围明确 |
| ENV-04 | 机制访问随基底声明的全局量 | 可建立相应访问与模型依赖；具体读写规则按定稿接口检查 |
| ENV-05 | 机制请求随机输入 | 通过统一管理器提供，具体取值与配对按后续随机语义检查 |
| ENV-06 | 由工作台与无界面入口加载同一模型并发起同一检查 | 使用同一引擎与检查规则，结果对应相同模型和检查范围 |
| ENV-07 | 加载模块后引用其公开量和方法；另行构造缺少对应定义的模型 | 前者绑定到模块提供的数据与实现；后者报告缺失引用，不由引擎补造领域定义 |
| ENV-08 | 查看一个接口的语义说明、接口检查和模块校验结果 | 分别说明用途与覆盖条件，不将说明或检查通过标为实现正确性证明 |
| ENV-08 | 模块提供特定条件的校验函数，并提交违反该条件的输入 | 在约定阶段执行校验并报告失败；阶段与错误格式随接口定稿 |
| 平台接入方向 | 加载不依赖空间、实体和游戏时钟的最小因果系统 | 能检查并执行其声明，不要求装配官方世界 |

历史恢复、干预配对、完整状态及数值等价的验收须在相应语义确认后补充，不能从上述方向推断已获保证。
