> - 设计状态：讨论中
> - 适用范围：完全重构的两库两平台、依赖方向和扩展边界
> - 已确定范围：分区与语言方向、必备基础框架、官方默认世界与可替换因果实验环境、作者构建模组与使用方免编译、游戏与研究要求分离
> - 尚未覆盖：具体绑定、扩展后端、共享工具归属、构建及安装布局

## 1. 定位与文档边界

Ascend 同时承载基因改造模拟游戏和世界模型研究。本文维护跨分区架构，世界机制、玩法与实验协议分别由所属模块维护。文档规范见[贡献指南](../CONTRIBUTING.md#文档维护)。

项目按完全重构规划，现有实现、编译器、声明格式及目录布局不作为新方案的约束。本文是新架构设计，不代表已有代码结构；各叶模块的 `实现.md` 记录实际落地情况。

## 2. 已确认基础

- 世界与智能体为两个独立库，由游戏平台、研究平台按需装配和打包；研究平台还须支持研究者自行声明的因果实验环境，不以接入官方世界库为统一前提。
- 世界库按 C++ 方向规划；智能体可采用 Python，利用 NumPy／PyTorch 生态，算法和推理部署尚未确定。
- 客户端继续采用 Godot；绑定、宿主入口语言和链接方式未定。
- 使用世界库空间和时间能力的运行组合采用对应模块已确认的语义，详见[空间设计](世界/世界框架/空间系统/设计.md)与[时间设计](世界/世界框架/时间系统/设计.md)；这些世界约定不自动成为所有因果实验环境的前提。
- 产品保留必备基础框架，官方提供完整的默认游戏世界，其机制与内容通过模组管理，可由多个官方模组组成；社区新算法不承担研究准入义务，游戏加载以兼容续玩为目标。模组作者构建可安装产物，使用者无需编译。完整游戏规则由 [MOD-01～04](游戏平台/模组管理/设计.md#3-已确认规则)维护。
- 研究者可以替换整个官方世界，按研究声明流程制作自己的因果实验环境；环境不必具有游戏世界、空间或实体形式，由[研究平台](研究平台/综述.md#自定义因果实验环境)核验声明、实现及证据是否满足相应研究要求。

## 3. 职责与连接方案

两库两平台的职责划分已明确；研究平台接入的是因果实验环境，官方世界是其中一种实现。下图表示逻辑使用关系，具体适配接口与共享运行能力的代码归属仍待设计。

```text
游戏平台 ──→ 世界库＋官方／自定义游戏模组

研究平台 ──→ 因果实验环境
                 ├── 世界库装配的世界
                 └── 研究者自行声明的其他因果系统

两个平台 ──→ 智能体库（按需接入）
```

| 分区 | 职责 | 主要边界 |
| --- | --- | --- |
| 世界 | 状态、机制及实际演化 | 身体感知和行动后果归世界，行动合法性及冲突不由智能体自行裁定 |
| 智能体 | 内部信息处理、记忆与决策 | 通过观测、行动和反馈数据被驱动 |
| 游戏平台 | 玩法、玩家输入、会话与产品装配 | 选择和连接能力，兼顾模组续玩与玩家体验 |
| 研究平台 | 因果实验环境接入、声明核验、实验运行、证据与评价 | 对实际环境及装配集合检查研究适用性，不要求实验环境采用官方世界模型 |

**候选依赖方案**：世界不依赖智能体实现或平台；智能体不链接、导入世界库的具体实现，由平台连接数据契约。接口数据是否单独形成公共包未定；复用时钟等能力时，可通过小型公共能力或注入接口，避免引入完整世界运行时。

独立库不等于独立进程。建议首版优先评估同进程绑定；跨进程、网络协议和原生推理按需要扩展，不预设首版必须支持双传输。

**宿主**是创建并驱动库的程序；**薄编排**表示不重复实现世界规律或智能体决策，并不意味着平台代码必然少。包管理、会话、协议、实验和工具仍可有完整实现及性能成本。

## 4. 模块与装配边界

| 概念 | 定义 |
| --- | --- |
| 基础框架 | 库与平台提供的必备运行和装配能力，不随可选内容模组的取消而消失 |
| 因果实验环境 | 按研究规则声明并可执行的因果系统；可以是模拟世界，也可以不具有空间、实体或游戏玩法 |
| 模块 | 代码或机制的职责单元，有明确接口，不要求每个函数都可动态加载 |
| 扩展包／模组包 | 可安装和组合的分发单位，可包含多个模块、内容及资源 |
| 配置档 | 选定的包、版本、功能与参数，组织一套产品或实验 |
| 模组管理器 | 发现、安装、选择包和展示诊断的工具 |

**候选装配方案**：一个包可包含世界、智能体、客户端、游戏配置和研究工具等部分，分别交由所属库或平台接收。可选部分与硬依赖须明确，不假定任何游戏模组都能脱离客户端或智能体运行。

建议共享可无界面调用的发现、依赖解析、配置记录和可选锁定能力，研究平台无需依赖游戏菜单。世界只接收世界模块集合，不安装整套产品。共享工具归属尚未决定。

**已确认的框架边界**：世界库与各平台保留必备基础框架，模组装配建立在框架之上。游戏平台本身具有启动、会话组织和装配能力，模组管理器是其中一个模块。框架内部仍可按职责划分模块，模块化不等于可由玩家逐项禁用，也不限定其静态或动态链接方式。

游戏产品默认交付官方世界，不以仅有引擎、没有规则与内容的配置作为独立产品目标。研究平台则允许以另一个因果系统整体替换官方世界，遵循研究声明和实验环境接入契约。该契约不能预设必须有二维空间、身体、秒制时钟或固定逻辑帧；复用世界库能力的部分仍需遵守相应模块契约。通用研究接入与世界模块装配是否复用执行器、以及共享能力的拆分仍待设计。

建议以小型核心承载通用运行能力，具体能力清单与核心／机制分界仍待细化；官方与社区共用公开扩展接口仍是建议。详细扩展契约及执行路径候选见[声明与装配](世界/运行支撑/声明与装配/设计.md)，官方拆包、基础游戏所需模组与兼容恢复见[模组管理](游戏平台/模组管理/设计.md)。

## 5. 公共能力与平台策略

下表中的世界能力约束使用它们的运行组合；其他因果实验环境按研究声明提供相应能力，不自动继承全部世界模块约定。

| 议题 | 公共能力 | 平台责任与来源 |
| --- | --- | --- |
| 模块接入 | 注册、调用与状态交接；附加描述能力另行提供 | [模组管理](游戏平台/模组管理/设计.md)规定游戏准入；[研究平台](研究平台/综述.md)判断协议适用性 |
| 保存恢复 | 所选实验环境或世界、以及智能体分别管理自己的状态 | 平台组织组合存档，游戏选择兼容路径，研究按协议锁定或建立分支 |
| 时间与执行 | 世界时间行为约束使用该时间系统的执行实现 | 其他因果实验环境按声明确定求值／演化语义；现实耗时与模型时间分开 |
| 身份与复现 | 包、规则、模型与输入的记录能力 | 相同摘要说明身份，不单独证明兼容或复现 |

保存能力的待讨论范围见[运行支撑](世界/运行支撑/综述.md)。固定权重可引用可取得且摘要匹配的模型产物，记忆等可变私有状态按实际方案保存，详见[智能体](智能体/综述.md)。

世界输入重放、重跑智能体的闭环复现和统计重复性是不同承诺；固定版本与种子不自动保证 GPU、多线程或社区算法位级一致。研究协议的具体条件由研究平台维护，不反向成为全部游戏模组的门槛。

## 6. 性能与交付候选

以下均为实现方向，尚无新架构性能证据：

- 世界优先评估连续数据布局和按机制批处理；原生语言不自动保证性能或确定性。
- 智能体可按到期时刻批量处理，不禁止低频控制的个体循环，也不强制异构策略同批执行。
- 绑定避免逐格、逐字段跨语言调用。原生区域若不访问 Python 对象，可评估释放 GIL；数据所有权、独立实例线程安全、推理线程池和过度并行仍需验证。
- 平台入口、pybind11、CMake、静态／动态链接均未选择；C++ 世界库不消除 Python 智能体的发行依赖。
- 新算法需要可执行交付路径，具体后端比较由[装配实现](世界/运行支撑/声明与装配/实现.md)维护。

| 问题 | 阻塞范围 | 后续归属 |
| --- | --- | --- |
| 核心与官方模组怎样分界 | 默认拆包、必需依赖和构建目标 | 世界、模组管理 |

| 组合存档与模块迁移如何协作 | 兼容加载及研究续跑 | 运行支撑、两平台 |
| 智能体内部方案及批处理边界 | 推理部署与性能预算 | 智能体 |

清单字段、绑定签名、内部调度器、安装布局及性能指标在相应边界明确后细化。状态与实体保持待讨论，当前优先收束整体架构。
