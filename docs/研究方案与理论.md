# Ascend — 研究方案与理论框架 (v0.1)

## 1. 研究动机

因果表征学习与世界模型领域当前有一个根本困境：**缺乏可验证的 ground truth**。在真实数据上训练的模型声称"学到了因果结构"，却无法用反事实干预来证明——因为你无法干预现实世界。

另一面，程序化生成、物理因果仿真、结构化事件日志这些技术已经相当成熟，却鲜有被有意识地面向"世界模型训练"进行系统设计。

Ascend 试图填补的正是这个交叉领域：以可复现、可干预的因果世界为平台，提供带已知 ground truth 的标准测试环境，研究世界模型在结构化因果空间中的学习行为。

---

## 2. Ascend 的独特研究资产

在因果 ML 研究语境下，Ascend 提供三项能力：

| 资产 | 研究价值 |
|------|----------|
| **已知因果 DAG（WorldTree）** | 事件间因果关系可由 `caused_by` 等字段显式声明（事件图结构与归档已实现；当前发布路径未设置关系字段，生产运行中图边仅存在于测试） |
| **完整时空序列日志** | 事件全量归档（保存脉搏 flush-and-drop），构成时序序列；**"每个因果事件携带父节点数值快照"未实现**——事件 data 只承载事件自身载荷，无父节点快照字段 |
| **可干预、可复现** | seed + 初始状态配置 + headless 批量运行 + 快照回滚，实现任意 do-operator 干预 |

核心研究假设：**从已知 DAG + 时空序列中，世界模型可以学到 ε-精度的因果映射，且在有 DAG 先验时样本复杂度由最大因果入度决定，而非变量总数。**这个方向的前提（事件因果边与父节点快照）尚待实现，见 §6 阶段 1。

## 3. 理论框架

### 3.1 结构因果模型（SCM）

SCM 用数学方程描述"什么导致什么"，而非仅描述相关性。每个变量由一个结构方程决定，其输入是该变量的全部直接原因：

```text
因果 DAG (WorldTree) + 结构方程 = SCM

    气温                 气温 = f₁(纬度, 海拔)
     ↓
    降水                  降水 = f₂(气温, 湿度)
     ↓
    河流水位              水位 = f₃(降水, 地形)
```

关键是方程是**不对称的**——调气温会影响降水，反向却不成立，这一点与相关性（对称）有本质区别。

在 Ascend 中，WorldTree 提供了已知的 DAG 结构，于是训练世界模型的问题就退化为：给定因果图，拟合结构方程。因为有 ground truth DAG，无需盲猜因果方向，问题难度大幅降低。

### 3.2 Granger 因果

Granger 因果提供时序预测层面的因果检验手段：

```text
预测₁: Y(t) ≈ g₁(Y(t-1), Y(t-2), ...)
预测₂: Y(t) ≈ g₂(Y(t-1), Y(t-2), ..., X(t-1), X(t-2), ...)

若 预测₂ 显著优于 预测₁ → X Granger-导致 Y
```

要特别注意：Granger 因果 ≠ 真正因果（公鸡叫 → 太阳升起就是反例）。但在封闭系统中、当所有相关变量均被观测时，Granger 因果逼近真因果，而 Ascend 的封闭世界满足这个前提。

### 3.3 两种框架在 Ascend 中的分工

| 框架 | 角色 | Ascend 优势 |
|------|------|-------------|
| SCM | 理论先验："我知道 DAG 结构，只需拟合方程" | WorldTree 提供完整 DAG |
| Granger | 实验验证："从数据中检验模型是否学到了因果方向" | 时序日志提供检验数据集 |

## 4. 核心理论方向：已知 DAG 条件下的样本复杂度

### 4.1 问题定义

给定已知因果 DAG，学习器到底需要多少条因果链样本，才能让世界模型对所有结构方程达到 ε-精度（置信度 1−δ）？

### 4.2 核心洞察：DAG 带来的降维

已知 DAG 时，联合分布可以分解为独立的子问题：

$$P(\text{降水} \mid \text{气温}, \text{湿度}) \times P(\text{水位} \mid \text{降水}, \text{地形}) \times P(\text{NPC行为} \mid \text{水位}, \text{目标}, \text{记忆}) \times \dots$$

每个节点只依赖其父节点（WorldTree 已标注）。每个条件分布**独立学习**，整体复杂度由入度最大的节点决定：

$$m \propto O(\exp(n)) \quad \text{无 DAG}，\qquad m \propto O(\exp(k)) \quad \text{有 DAG}$$

其中 $n$ 为变量总数、$k$ 为最大入度。Ascend 的因果链是稀疏的（物理因果路径通常不长），$k$ 天然可控。

### 4.3 待推导的三个子问题

**子问题 1：有 DAG vs 无 DAG 的样本差距**

无 DAG 学习联合分布，样本复杂度随变量数指数增长；有 DAG 分解为局部条件分布，复杂度仅取决于最大入度。Ascend 可同时跑两种训练模式，实验验证理论差距。

**子问题 2：因果路径长度与误差传播**

因果链 $A \to B \to C \to D$ 上每步都有 $\varepsilon$ 拟合误差，我们关心经过 $k$ 步后累积误差的增长速率——它直接关联"感知窗口需要多深的历史"。

**子问题 3：因果覆盖度判据**

需要多少条不同的因果路径才能保证泛化？答案是使用 do-operator 主动采样稀有因果路径，而不是被动等自然演化。

### 4.4 预期理论形式

基于 SCM + PAC-Bayes / Rademacher 复杂度框架，预期可导出一个 sample complexity bound：

$$m \ge O\!\left(\frac{d^k}{\varepsilon^2} \cdot \log\frac{1}{\delta}\right)$$

其中 $d$ 为变量值域，$k$ 为最大因果入度，$\varepsilon$ 为精度，$\delta$ 为置信度。关键洞察是有 DAG 时 $k \ll n$（$n$ 为总变量数），而无 DAG 时 $k \approx n$。

## 5. 对 WorldTree / 事件系统的设计要求

理论成立依赖以下五项约束，均可在设计阶段保证。

### 5.1 DAG 完备性

每个事件节点的 cause 集合必须是该节点的**充分因果集**——不能遗漏决定该事件的变量：

```text
正确: event.snow_start, cause: {temperature, humidity, wind}
错误: event.snow_start, cause: "天气变冷"（不可量化，且可能遗漏关键变量）
```

Ascend 的优势在于代码逻辑是确定性的，校验 cause 是否充分相对容易：任一影响节点输出的输入变量若未出现在 cause 中，即为遗漏。（当前发布路径未设置 `caused_by` 关系，该约束待事件系统补全因果边后落地，见 §6 阶段 1。）

### 5.2 DAG 无环

因果边只能从时间早的事件指向时间晚的事件，每个事件携带时间戳，禁止同时刻互指。Ascend 自然满足这一点：物理时间单调递增，不存在"回到过去"的因果边。语义层面需要警惕——比如"尸体腐烂影响生态 → 影响未来天气"应建模为指向未来时间点的事件，而非回环。

### 5.3 父节点值可量化

每个事件必须携带其全部父节点在触发时刻的数值快照，构成 $(X_1, X_2, \dots, X_k \to Y)$ 的训练样本。这条要求与 5.1 协同保证：cause 中的每个键不仅是标签，更是带数值的 kv 对。（当前 `Event` 无父节点快照字段，未实现，见 §6 阶段 1。）

### 5.4 最大入度可控

若某节点有 20 个父节点，样本需求将指数爆炸，因此需要约束 max indegree ≤ 5~6。Ascend 的物理系统天然低入度：天气依赖少数气象参数，生态依赖少量环境变量，只需在设计事件系统时显式约束。

### 5.5 支持干预采样

自然演化可能极难覆盖某些因果路径组合，需要 do-operator 主动注入。实现方案无需修改生产代码：

- **seed + 初始状态配置**：设定外生变量初始值，让因果链自然演化
- **checkpoint / restore**：存档读档，精确复现任何场景
- **headless 批量运行**：前后端分离使得无头模式自然支持

这等价于标准 do-operator 语义：$\mathrm{do}(X=x)$，然后让结构方程自己跑。

## 6. 研究路线图

> 与 [README「执行阶段」](../README.md) 的对应关系：本文档阶段 1–4 属
> README **第一阶段（可验证因果世界，施工中）** 的 1-B（WorldTree 合规）与
> 1-C（世界基座验证）；本文档阶段 5（行为层）属 README **第二阶段
> （智能体构造，未开始）**。

### 阶段 1：事件系统合规

确保 WorldTree 满足 §5 中的五项要求。当前事件总线与归档已实现，但生产发布路径未设置 `caused_by` / `observes` 等关系字段（因果图仅在测试中构建），且 `Event` 无父节点数值快照字段。补全上述两点、满足 §5 的约束后，再进行审查。

### 阶段 2：基线实验

- 在已知 DAG 条件下训练世界模型，度量时序预测精度
- 用 Granger 检验验证模型学到的是因果方向而非伪相关
- 在无 DAG 条件下训练同等容量模型，量化 DAG 先验带来的提升

### 阶段 3：理论推导

- 推导已知 DAG 条件下世界模型的样本复杂度 bound
- 在 Ascend 上用不同因果路径数量做消融实验，验证 bound 的紧度
- 分析因果路径长度对误差传播的影响

### 阶段 4：反事实验证

- 用 do-operator 做干预实验：改变某个变量，验证模型预测的行为变化与引擎实际运行一致
- 量化模型在未见因果路径上的泛化能力

### 阶段 5：行为层（纯涌现，无 LLM）

行为层设计见 [心智系统 / AI 原生 NPC](心智系统/AI原生NPC/设计.md)：NPC 行为从"需求奖励 + 世界模型想象评估"中涌现，不依赖 LLM、不依赖手写行为规则。**未动工**——依赖需求/生理系统、实体感知完备、演化接口与行为评估基线就绪后方可开工；动工前须先过探针 3（微世界纯涌现验收）的通过标准。
