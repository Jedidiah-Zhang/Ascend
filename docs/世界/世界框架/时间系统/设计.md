# 时间系统 — 设计

> - 设计状态：基础确定
> - 适用范围：通用时钟域、空间本地更新与跨域输入的时间语义
> - 已确定范围：秒制、固定本地步长、嵌套流速、暂停恢复、接收边界及步内因果顺序
> - 尚未覆盖：精度数值、调度算法、同批输入裁决及接口签名
> - 上级：[世界框架](../综述.md) · [实现](实现.md)

## 1. 目标与职责

为独立演化的空间提供可组合的时间关系，明确状态属于哪个时刻、输入何时生效、机制按什么依赖顺序求值。时钟域可由其他系统复用，不要求所有使用者采用空间的更新方式。

本模块定义时间语义；执行队列、并行和提交算法由[运行支撑](../../运行支撑/综述.md)实现；具体动作、传输、日历和环境过程维护自身的持续时长与作用规则。空间范围引用[空间系统](../空间系统/设计.md)，不在此重复定义。

## 2. 概念与术语

| 概念 | 含义 |
| --- | --- |
| 时钟域 | 具有本地时间及与参考时钟关系的计时单元 |
| 根时钟 | 协调其他时钟关系的参照，不直接作为空间内部机制的时间输入 |
| 本地时间 | 某时钟域内部实际经过的时长；与现实执行耗时分开 |
| 本地步长 | 一次完整空间更新覆盖的本地时间间隔 |
| 逻辑帧 | 完整更新的编号与状态边界，不额外形成一套帧时钟 |
| 步内阶段 | 一次更新内部的求值依赖顺序，不自动代表额外时长 |
| 相对／有效倍率 | 相对父时钟的配置倍率／组合上游关系后相对根时钟的倍率 |
| 目标／完成进度 | 按时钟关系应到达的位置／状态实际完成演化的位置 |
| 时钟进度 | 尚未形成完整本地步的映射进度，与实体的亚刻度运动累计不同 |

## 3. 已确认规则

### TIME-01 秒制与精度

时间以秒为单位，精度在一次运行中固定。空间步长必须能被配置的时间精度精确表示。精度数值和存储类型尚未选择；时间精度不意味着所有机制必须每个刻度执行。

### TIME-02 独立、可嵌套的时钟域

空间创建时本地时间从零开始，恢复已有空间不重置时钟。不同创建时刻的空间即使同速，本地时间也可以不同。

时钟关系允许嵌套。下游保留自己的相对倍率，上游变速生效后其有效流速自然联动，不逐层追加变速指令或延迟。祖先暂停会停止关联子树推进，后代不能用非零倍率绕过它。各空间内部状态和演化规律仍独立。

根时钟只协调关系，空间内机制按本地时间工作；不要求从本地时刻逆推唯一根时刻。具体父关系表示及是否允许运行中改变父关系见待决问题。

### TIME-03 固定本地步长与步内阶段

空间在实例化时配置固定本地步长，不同空间可以不同；运行中变速不改变步长。一次完整空间更新对应一个本地时间步。

一次更新可以含多个因果求值阶段。阶段不自动细分时间、不等分步长；真正的数值时间子步或物理延迟必须由机制另行声明。通用时钟域不强制其他使用者采用空间的固定步长。

### TIME-04 变速、暂停与恢复

允许正流速与零流速，默认相对流速相同，根时钟也可暂停。流速变更在下一逻辑帧开始前生效，不打断当前帧。

暂停停留在边界，仍能处理控制请求；恢复不能依赖暂停时钟先完成下一帧。处理恢复请求不提前推进本地时间或执行世界机制。变速、暂停、恢复均保留本地时间与不足一步的时钟进度，不补算本地暂停期间未经过的时长。

当前不支持负流速。零流速域的进入、传输和等待效果由对应机制维护，本模块不赋予统一边界行为。

### TIME-05 明确读取版本与因果顺序

按本模块求值契约接入的机制须明确读取步开始旧值还是本步前序阶段的新值。使用新值的计算必须等待其依赖完成；读取旧值则不必等待对应新值产生。同阶段只读取该阶段开始前已确定的值，阶段内写入归属明确。

求值依赖展开后无环，不能由容器遍历或线程先后改变结果。双方互相依赖尚未产生的新值时，不能擅自将一方改读旧值；真实反馈延迟应由模型声明，联合方程求解需独立定义求解语义。

帧边界读取不暴露中间状态，不妨碍后续阶段使用声明依赖的中间结果。扩展算法内部可见的依赖粒度由其接入契约决定，参见[声明与装配](../../运行支撑/声明与装配/设计.md)，不能将外部调用顺序视为完整内部因果图。

### TIME-06 跨域下一更新接收

跨空间通信在接收方下一更新点生效；发送与接收边界同刻时，本次输出不进入接收方本次更新。接收帧由逻辑时间规则确定，不取决于线程执行或消息实际抵达的先后。

交接期间实体或转移量可以不属于任何空间。交接状态的保存与归属由状态和交互接口细化。接收后的输入可以参与该步内部因果传播，不要求每条内部因果边再等待一步。

边界读取隔离不保证跨域延迟不可感知：其他域可能观察到尚未收到回复或连接仍被占用。

### TIME-07 流速与局部确定性

对初态、规则、参数、随机条件和逐本地步输入相同、且满足确定性契约的运行组合，变速安排或现实执行耗时不改变按本地步比较的轨迹。根时钟、流速和现实执行耗时不作为局部机制求值的直接输入；流速不直接修改机制公式或随机抽样语义。

开放空间的输入内容与生效帧可能随相对流速改变，所以相同种子不单独保证相同轨迹。时钟到达目标不意味着状态已经完成计算，不能只修改时间值而跳过演化。

### TIME-08 时间读出

提供秒制本地时间及时间关系的读出能力，供外部与现实时间配对。配置倍率与实际执行速率分开；现实时间采样不成为局部机制的隐式输入。具体字段与一致性接口见下文候选。

## 4. 对外契约

下表整理已确认的行为语义，尚不是函数签名。未确定部分不得自行补成默认行为。

| 能力 | 输入与前提 | 结果／生效时机 | 未定或失败边界 |
| --- | --- | --- | --- |
| 创建空间时钟 | 初始参考关系、精度、固定步长 | 本地从零开始，形成可推进时钟 | 关系结构、非法数值及错误编码 |
| 修改流速 | 目标域和新倍率 | TIME-04；保持时间、进度和步长 | 不支持负值；同批控制顺序未定 |
| 暂停／恢复 | 目标域和控制请求 | 边界处理；暂停中可恢复 | 父子同时控制、恢复后待接收输入顺序未定 |
| 推进与交付 | 已声明的时间目标和输入 | TIME-03、TIME-06；只暴露对应已完成状态 | 调度策略、发送方完成与接收边界协调未定 |
| 读取时间 | 指定时钟域 | TIME-08，不因读取推进世界 | 完成进度、目标进度等字段为候选 |

候选读出字段：域身份、本地秒数、帧号、父域身份、相对与有效倍率、暂停状态、目标与完成进度。应取自一致边界，具体一致性实现待定。

## 5. 配置与边界情况

| 配置／状态 | 已确定约束 | 未确定内容 |
| --- | --- | --- |
| 时间单位 | 秒 | 无 |
| 时间精度 | 运行内固定 | 数值、全局统一或域间配置关系 |
| 空间步长 | 实例化配置并固定，各空间可不同 | 具体数值及机制周期的相容性 |
| 流速 | 可变，默认同速，可为零，不支持负值 | 倍率范围、算术表示及溢出处理 |
| 时间相位 | 变速与暂停恢复不丢失已有进度 | 精确保存或重建方式 |

本地时间零点不自动指定昼夜、季节或日历的初相位。延迟事件的计时时钟、迁移后的剩余时长、暂停域的交互效果由对应机制声明。

位置精度和最小非零位移遵循空间设计；时间步长与移动规则需共同满足它们，不从毫米精度推导唯一时间步长。

## 6. 取舍与候选方案

- **独立本地时间与根协调**：保留不同流速的表达，同时避免局部规则直接依赖外部执行速度。
- **固定本地步长**：变速只改变推进节奏，避免隐式改变数值模型；慢机制的更新周期仍需按交互设计。
- **步内依赖与时间分开**：既允许同一步中因果求值，又不把每个中间计算误当时间子步。
- **候选数值实现**：整数刻度、有理数倍率、父子锚点及精确到期比较，见[实现方案](实现.md#2-实现方案)。未选定统一最小公共步长。
- **候选在途状态**：显式保留交接身份、载荷与目的地，防止保存恢复时丢失或重复；接口需与状态模块共同确定。
- **后续逆演化**：仅在实际机制可逆时再评估封闭空间或封闭多空间结构；封闭性不自动保证可逆，快照回放也不等于逆转移。

## 7. 验收标准

以下是已确认规则的验收场景，尚无实现验证结果。示例数字不是默认参数。

| 依据 | 条件与操作 | 预期 |
| --- | --- | --- |
| TIME-01～03 | 在不同创建时刻建立不同步长的空间时钟 | 各自从零开始，按各自步长完整推进 |
| TIME-02 | 相对倍率依次为 2、1/2；上游改为 4 | 下游相对倍率不改，有效倍率从 1 变为 2 |
| TIME-04 | 有未满一步进度时暂停，再在边界恢复 | 恢复请求不额外推进时间，已有进度和步长保持 |
| TIME-02、04 | 暂停根时钟或祖先时钟，然后提交恢复控制 | 后代不能绕过暂停；控制无需等待本地时间前进 |
| TIME-02、04 | 不足一步时保存、恢复并继续推进 | 本地时间不置零，时钟进度不丢失、不重复推进 |
| TIME-04 | 本帧提出变速 | 本帧完成不受影响，下一帧开始前应用 |
| TIME-05 | 后序机制读取前序新值，改变无依赖计算的执行分组 | 依赖先完成，输出不因无关排序改变 |
| TIME-06 | 两空间同刻更新并产生输出 | 输出不进入对方本次更新，执行先后不改变接收帧 |
| TIME-07 | 固定完整初态及逐步输入，改变倍率和执行批次 | 对满足契约的组合，本地轨迹一致 |
| TIME-08 | 高倍率运行时，机器未完成映射出的目标进度 | 读出能区分配置与已完成进度 |

交接中保存恢复不丢失／重复的检查，在交接接口确认后补充具体判据。
