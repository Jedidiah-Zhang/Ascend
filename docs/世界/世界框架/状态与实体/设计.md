# 状态与实体 — 设计

> - 设计状态：待讨论（暂停推进，尚无已确认方案）
> - 适用范围：完整状态、实体身份、生灭与关系
> - 上级：[世界框架](../综述.md) · [实现](实现.md)

## 1. 目标与意义

定义世界完整状态的构成、寻址与区分，以及实体身份、位置、生灭和关系；与运行支撑共同明确读取、提交和持久化责任。场、实体、全局状态与槽位都是待比较概念，不构成已确定的数据模型。

## 2. 研究输入

[接入设计 ENV-09～13](../../../研究平台/实验环境与声明接入/设计.md#env-09-模块运行状态声明与完整捕获) 已规定首版状态声明、捕获恢复、分支与字段干预约束；载体及文件编码的实际限制见[接入实现](../../../研究平台/实验环境与声明接入/实现.md#3-当前实现范围与限制)。本模块须讨论如何将这些约束用于空间场、张量与实体，不以完整工作台交付为前提。

## 3. 待决问题

| 议题 | 要明确的边界 |
| --- | --- |
| 完整状态与载体 | 场、实体和全局状态的分工；逐模块结构化编码、空间块与二进制载体的选择，对应 ENV-09 基线复核 |
| 字段与访问 | 是否采用槽位；值域、单位、精度、缺失值及写者的表达 |
| 实体身份与关系 | 稳定引用、类型、生灭、生命周期与迁移 |
| 权威状态与派生信息 | 派生量、缓存和索引的保存范围及重建方式 |
| 读取与提交 | 读取版本、冲突、执行顺序及跨空间交接与时间语义的协调 |
| 持久化 | 规范编码、保存恢复、部分卸载及平台续玩策略的责任划分 |

以上均阻塞本模块实施，验收条件待规则确认后补充。依赖[时间](../时间系统/设计.md)、[空间](../空间系统/设计.md)、机制演化、随机与数值及[运行支撑](../../运行支撑/综述.md)。
