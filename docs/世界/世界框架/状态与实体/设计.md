# 状态与实体 — 设计

> - 设计状态：待讨论（暂停推进）
> - 适用范围：完整状态、实体身份、生灭与关系
> - 已确定范围：无
> - 尚未覆盖：概念、规则、接口、数据表示与验收
> - 上级：[世界框架](../综述.md) · [实现](实现.md)

## 1. 目标与职责

拟定义世界完整状态的构成、寻址与区分，以及实体身份、位置、生灭和关系；与运行支撑共同明确读取、提交和持久化的责任边界。先由[研究接入设计](../../../研究平台/实验环境与声明接入/设计.md)明确所需访问、运行状态与恢复约束，本模块保留讨论骨架。

## 2. 规则、接口与验收状态

尚无已确认方案。场、实体、全局状态、槽位等只是待比较的概念，不能作为已确定的数据模型。具体接口、配置和验收在设计讨论后补充。

## 3. 待决问题

以下问题均阻塞本模块实施，待相关研究约束明确后共同讨论，不以建模工作台交付为前提：

| 问题 | 影响与关联 |
| --- | --- |
| 状态载体如何划分：场、实体、全局各负责什么 | 完整状态边界与存储 |
| 是否采用槽位；值域、单位、精度、缺失值与写者如何表达 | 模块注册与读写接口 |
| 实体身份、类型、生灭及关系如何定义 | 稳定引用、生命周期和迁移 |
| 派生量、缓存、索引与权威状态如何区分 | 保存范围与重建 |
| 读取版本、提交与跨空间交接如何协调 | 时间语义、冲突与执行顺序 |
| 规范编码、保存恢复与部分卸载如何划界 | 公共持久化及平台续玩策略 |

依赖[时间系统](../时间系统/设计.md)、[空间系统](../空间系统/设计.md)、机制演化、随机与数值及[运行支撑](../../运行支撑/综述.md)。
