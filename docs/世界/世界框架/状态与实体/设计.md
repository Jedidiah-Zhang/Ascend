## 1. 目标与意义

本模块拟定义世界完整状态的构成、寻址与区分，以及实体身份、位置、生灭和关系；与运行支撑共同明确读取、提交和持久化的责任边界。它回答世界里有什么、这些内容如何被可靠地保存与恢复，是机制演化、空间与时间等模块的共同基础。

先由[研究接入设计](../../../研究平台/实验环境与声明接入/设计.md)明确研究所需的访问、运行状态与恢复约束，本模块保留讨论骨架；不以建模工作台交付为前提。

## 3. 候选概念

尚无已确认方案。场、实体、全局状态、槽位等只是待比较的概念，不能作为已确定的数据模型。值域、单位、精度、缺失值与写者如何表达，派生量、缓存、索引与权威状态如何区分，都待讨论后确定。

## 4. 待决问题

状态载体如何划分，即场、实体、全局各负责什么，决定完整状态的边界与存储方式。

是否采用槽位，以及值域、单位、精度、缺失值与写者如何表达，影响模块注册与读写接口。

实体身份、类型、生灭及关系如何定义，影响稳定引用、生命周期和迁移。

派生量、缓存、索引与权威状态如何区分，影响保存范围与重建方式。

读取版本、提交与跨空间交接如何协调，影响时间语义、冲突与执行顺序。

规范编码、保存恢复与部分卸载如何划界，影响公共持久化及平台续玩策略。
