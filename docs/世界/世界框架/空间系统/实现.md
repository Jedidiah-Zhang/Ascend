## 1. 设计依据

依据 [SPACE-01～05](设计.md#4-已确认规则) 与[暂定实施基线](设计.md#实施基线暂定)。几何与数值规则由设计维护，具体落地限制见第 3 节。

## 2. 代码结构与工程方案

世界库位于 `olam/`，采用 C++17 与 CMake，构建为静态库 `ascend_olam`，调用方链接目标为 `ascend::olam`，不依赖声明引擎、Qt、Godot、Python 或第三方运行库。公共头文件为 [space.hpp](../../../../olam/include/olam/space.hpp)，实现为 [space.cpp](../../../../olam/src/space.cpp)，命名空间为 `olam`；测试位于 `testbench/olam/`。

`SpaceDescription` 汇总身份、层序、绝对原点与尺寸，登记时一次校验。`Space` 是登记后的只读空间，提供身份、层序、原点、尺寸、上界、点包含判定及局部与绝对位置的平移转换。`SpaceSet` 持有全部空间，按身份与层序建立索引，提供创建、查找与定位。

登记依次校验身份、尺寸、原点、上界溢出、身份唯一性及同层重叠，失败返回 `SpaceError`。索引分配失败则回滚已推送空间并重新抛出 `std::bad_alloc`，不留下部分登记。几何判定与转换遵循设计，越界或未命中返回空。

声明接入是独立目标 `ascend_olam_module`，位于 `olam/module/`，仅该目标链接 `ascend::engine` 与 `ascend::olam`；核心空间库仍不依赖声明引擎。公共头文件为 [space_module.hpp](../../../../olam/module/include/olam/module/space_module.hpp)，实现为 [space_module.cpp](../../../../olam/module/src/space_module.cpp)，语言资源为 [zh-CN.json](../../../../olam/module/i18n/zh-CN.json)。

模块定义标识为 `olam.space`，实现标识为 `olam.space.v1`，模块实例对应一个空间集合。默认构造配置为单个空间（原点 `(0, 0)`、尺寸 `1000×1000`、层序 `0`）；配置对象可平铺描述单空间，也可用 `spaces` 数组描述同一集合内的多个空间。空间身份缺省取实例名（数组元素取 `实例名#序号`），创建校验失败转为带原因链的 `invalid_config` 诊断。

公开量均为 64 位整数：`space_count`、`layer_count`，以及首个登记空间的 `origin_x`、`origin_y`、`width`、`height`、`layer`、`upper_x`、`upper_y`。空集合的计数为 `0`，首个空间相关字段为 `-1`；合法层序也可以是 `-1`，读取 `layer` 时应先参考 `space_count`。公开方法 `locate(layer, x, y)` 返回登记序号或 `-1`，`contains(layer, x, y)` 返回 `1/0`，`local_x(layer, x, y)` 与 `local_y(layer, x, y)` 返回局部坐标或 `-1`。方法使用稳定类型 `int64`，未命中不夹取、不跨层查找。

状态契约为 `olam.space.state.v1`：捕获值保存 `spaces` 数组，每项必须含 `id`、`layer`、`origin_x`、`origin_y`、`width`、`height`；恢复时逐项核对字段存在与类型，再重新执行同样的创建校验并替换集合，结构非法由引擎报告 `invalid_state`。[space_package.cpp](../../../../olam/module/tool/space_package.cpp) 从代码登记实例导出清单并生成 `olam.space.amod`，可附加包内语言资源。

## 3. 当前实现范围与限制

已实现的范围包括：创建校验与同层不重叠、异层重叠；按身份查找、按层序与绝对位置定位；点包含（左闭右开）、局部与绝对位置转换及越界拒绝；登记顺序的只读遍历；失败不改变已有空间。声明接入已提供模块工厂、公开量、方法、状态捕获／恢复契约、包清单导出与 `.amod` 生成；工作台宿主登记 `olam.space` 内置实现并可载入随构建生成的包。测试用例见[测试文档](测试.md)。

尚未实施：形状与路径查询、批量查询、范围与位置及层序的动态变更、连接描述与几何映射、模块状态以外的文件级空间持久化、更新覆盖与调度。

使用限制：单线程宿主接口，返回空间指针在下次 `add` 前有效；位置与尺寸使用暂定整数刻度，无浮点入口或超精度舍入。声明接口公开量只描述首个登记空间，多空间通过配置的 `spaces` 数组建立并使用方法按层查询；空间查询方法均为三参数，工作台的输入自动推导只识别单参数方法，因此这些方法供其他模块或代码调用，不作为界面输入。状态契约首版无迁移规则。没有性能测量，不作吞吐承诺。

## 4. 构建与运行入口

依赖 CMake 3.20 及支持 C++17 的编译器。在仓库根目录执行：

```bash
cmake -S olam -B build/olam -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build/olam --config Debug --parallel 4
ctest --test-dir build/olam --build-config Debug --output-on-failure
```

构建产物位于已忽略的 `build/olam/`；Visual Studio 等多配置生成器在 `build/olam/<配置>/` 下生成对应可执行文件。测试程序的用例清单与运行方式见[测试文档](测试.md)。

存在声明引擎源码时，`ASCEND_OLAM_BUILD_MODULE` 默认为 `ON`，同时构建 `ascend::olam_module` 与包工具；只构建核心空间库时加 `-DASCEND_OLAM_BUILD_MODULE=OFF`。手工生成模块包：

```bash
build/olam/ascend_olam_space_package build/olam/modules olam/module/i18n/zh-CN.json
```

工作台界面构建（`ASCEND_WORKBENCH_BUILD_GUI=ON`）会把同一包生成到可执行文件同目录的 `modules/olam.space.amod`，并复制语言资源到 `resources/olam/module/i18n/`；在工作台「文件 → 载入模块包…」选择该文件后，即可在系统编辑器中添加 `olam.space` 实例。
