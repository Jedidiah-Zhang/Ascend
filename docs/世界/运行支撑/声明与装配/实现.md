## 2. 实现方案

作者构建可安装模组产物、使用者无需编译的交付要求已确认。以下承载路径仍为候选，不要求首版全部支持：

| 路径 | 可提供能力 | 主要取舍 |
| --- | --- | --- |
| 源码共同构建（开发验证用途） | 原生新算法，可先验证公开源码接口 | 不能作为要求使用者重编游戏的模组安装路径 |
| 匹配版本的原生插件 | 独立交付算法二进制 | 需定义 ABI、生命周期、平台与版本兼容范围 |
| 作者编译的字节码及配套运行时 | 交付可由宿主加载执行的编译产物 | 需设计运行时、绑定、批量状态访问、兼容范围及运行成本 |

Lua、WASM、解释执行、代码生成与 C ABI 均未确认。JSON 或参数配置只能扩展已有表达能力，不能单独承载任意新算法。

建议先用批量原生入口验证 C++ 核心的调用和数据边界，再比较满足已确认交付要求的社区后端。注册时解析名称，热路径使用句柄；避免逐格跨语言调用。是否支持并行取决于状态所有权与线程安全，不由语言或解除 GIL 自动保证。
