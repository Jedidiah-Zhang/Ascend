## 1. 设计依据

## 2. 实现方案

以下路径均为候选，尚未选择，也不要求首版全部支持：

| 路径 | 可提供能力 | 主要取舍 |
| --- | --- | --- |
| 源码共同构建 | 原生新算法，可调用公开源码接口 | 作者需要工具链，分发依赖构建环境 |
| 匹配版本的原生插件 | 独立交付算法二进制 | 需定义 ABI、生命周期、平台与版本兼容范围 |
| 一种脚本／字节码运行时 | 可支持作者不编译原生代码 | 需设计绑定、批量状态访问、依赖及运行成本 |

Lua、WASM、解释执行、代码生成与 C ABI 均未确认。JSON 或参数配置只能扩展已有表达能力，不能单独承载任意新算法。

建议先用批量原生入口验证 C++ 核心的调用和数据边界，再按作者交付需求选择社区路径。注册时解析名称，热路径使用句柄；避免逐格跨语言调用。是否支持并行取决于状态所有权与线程安全，不由语言或解除 GIL 自动保证。
