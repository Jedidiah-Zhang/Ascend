# 声明与装配 — 设计

> - 设计状态：讨论中
> - 适用范围：世界模块的运行接入与可选描述能力
> - 已确定范围：运行接入依托必备框架、支持自定义世界规则、作者构建模组产物、游戏算法接入不以研究证据为前提
> - 尚未覆盖：注册契约、状态访问方式、调度接口与可执行后端
> - 上级：[运行支撑](../综述.md) · [实现](实现.md)

## 1. 目标与意义

本模块接收平台选出的世界模块，组织其配置、注册、校验和执行入口，让世界能够独立运行，并让使用者在世界库内装配自定义机制。安装整个产品、选择客户端资源和管理研究工具由平台负责。

这里同时要维持一条政策边界：游戏扩展不因缺少研究材料而被拒绝，研究适用性由研究平台独立判断。本模块整理已有架构候选，不因独立建档而确认接口；游戏扩展政策的唯一来源是 [MOD-02](../../../游戏平台/模组管理/设计.md#mod-02-社区算法不承担研究准入义务)。

## 2. 目标与达成情况

本节记录设计目标、当前达成状态与概念性验收标准。本模块尚无实现，达成状态指设计层面的确定程度。

### 世界模块的运行接入

**当前状态**：接入边界已确认，注册契约未定。

**验收标准**：提供满足运行契约的算法即可装配；缺失依赖可诊断；文件枚举顺序变化不改变显式组合的结果。

### 使用者可在世界库内装配自定义机制

**当前状态**：方向已确认，替换粒度与冲突解析接口未定。

**验收标准**：显式组合决定装配结果，替换与冲突有明确规则；研究者整体替换实验环境的入口由研究平台定义，不限于世界机制扩展。

### 承载作者构建、使用者免编译的模组产物

**当前状态**：交付要求已确认（[MOD-04](../../../游戏平台/模组管理/设计.md#mod-04-作者构建与使用者免编译)），接口和执行后端未选择。

**验收标准**：在没有编译工具链的使用环境安装作者提供的兼容产物后，无需编译模组或重编游戏即可完成装配。

### 游戏准入与研究审查分开

**当前状态**：政策边界已确认。

**验收标准**：提供满足运行契约但无研究证明的算法时，不因缺少研究材料拒绝游戏装配；研究使用方独立判断协议适用性。使用世界空间和时间接口的实现仍需满足其已确认行为，这些约定不自动成为其他因果实验环境的研究准入条件。

### 描述不等于证明

**当前状态**：边界已确认。

**验收标准**：登记算法调用不会因此获得完整内部因果图；注册元数据不证明实现忠于描述；任意社区组合不自动获得位级确定或精确重放保证；对内部不透明的模块，只承诺框架实际控制和可观察的边界。

## 3. 概念与术语

运行契约是模块接入、调用、访问状态和保存恢复所需的工程约定。机制描述是模块可提供的读写、时序、随机性、可干预点等描述，粒度取决于实际接口。研究证据是支持相应协议主张的验证材料，不等于注册元数据。执行入口是运行时实际调用算法的位置；数据定义不能替代任意新算法的执行后端。

## 4. 已确认规则与适用约束

世界模块接入依托[必备基础框架](../../../整体架构.md#4-模块与装配边界)，不将全部运行支撑视为可随内容模组一并取消的能力。具体核心能力清单与机制边界仍待细化。本模块支持使用者在世界库内装配自定义机制，具体替换粒度和冲突解析接口仍待设计。研究者整体替换实验环境、声明其他形式因果系统的入口由[研究平台](../../../研究平台/综述.md#自定义因果实验环境)定义，不限于本模块的世界机制扩展。

可执行模组的作者构建与使用者免编译要求由 [MOD-04](../../../游戏平台/模组管理/设计.md#mod-04-作者构建与使用者免编译)维护，世界接入须能承载相应可安装产物；接口和执行后端尚未选择。

世界接入不得把完整研究因果声明或研究证明隐式作为所有游戏算法的准入条件，依据 MOD-02。登记算法调用不代表获得完整内部因果图，注册元数据也不能证明实现忠实遵守其描述。任意社区组合不自动获得位级确定或精确重放保证，研究适用性由[研究平台](../../../研究平台/综述.md)检查。具体运行契约尚未制定。

## 5. 对外契约

以下均为**候选**能力，尚未形成实施规格。

模块注册接收身份、依赖、配置与实现入口，形成可装配的模块集合；重复注册、缺失依赖及版本关系待明确。

状态接入提供读取、写入及所有权边界；布局、句柄、批量访问与提交待明确。

更新接入声明时钟或更新位置和必要调用依赖；不透明模块的调度边界及冲突处理待明确。

保存恢复管理模块自身数据与必要元信息；数据版本、恢复顺序及失败处理待明确。

附加描述可携带读写版本、随机用途、干预点与证据等说明；适用协议、内部可见粒度和验证方式待明确。

## 6. 边界与失败行为

清单字段与默认值尚未确定。模块、可安装包和配置档的区别见[整体架构](../../../整体架构.md#4-模块与装配边界)。

世界只校验已解析集合中的运行依赖；实验锁定与游戏兼容恢复由平台选择。包依赖顺序、步内因果顺序和同刻输入裁决分别定义，不用一个“加载顺序”代替三者。接口不匹配或无法建立执行计划时给出具体诊断；哈希身份本身不证明接口兼容。对内部不透明的算法，只承诺框架实际控制和可观察的边界，不推断内部依赖。

## 7. 取舍与候选方案

必备框架的存在已确认。候选职责划分是以小型核心提供时钟、空间、状态访问、注册执行、保存和诊断，具体生态、生命及基因机制通过模块接入；具体核心划分仍待确认，模块化不要求每个函数都动态加载。

**候选可执行交付路径**：源码共同构建适合开发验证，但不能作为要求使用者重编游戏的模组安装路径；匹配版本的原生插件可以独立交付算法二进制，需要定义二进制接口、生命周期、平台与版本兼容范围；作者编译的字节码及配套运行时可以由宿主加载执行，需要设计运行时、绑定、批量状态访问、兼容范围及运行成本。Lua、WASM、解释执行、代码生成与 C 兼容接口均未确认；纯数据与参数配置只能扩展已有表达能力，不能单独承载任意新算法。

**描述与执行**：描述可支撑调度与验证，但不要求自造完整方程语言；真正的新算法需要可执行交付路径。装配阶段可以将名称解析成执行句柄，运行热路径按批调用机制；可选描述可提供成本提示，实际预算需要测量。运行中机制热替换仍待决定，与模组运行时产生行为分开。是否支持并行取决于状态所有权与线程安全，不由语言或解除全局解释器锁自动保证。

## 8. 待决问题

核心与机制的边界尚未确定，阻塞注册范围和构建拆分，解决位置为整体架构。

构建产物后端、接口及平台兼容范围尚未确定；作者构建、使用者免编译的要求已确定，尚未确定的是产物形式与兼容规则，解决位置为本模块与平台交付。

状态访问和不透明模块的调度尚未确定，阻塞调用接口与并行方案，需与状态与实体、机制演化协同。

保存恢复、迁移的责任划分尚未确定，阻塞持久化接口，解决位置为公共保存与平台加载策略。

描述能力与协议对应关系尚未确定，阻塞特定研究保证，不阻塞普通游戏使用，解决位置为研究平台。
