# 世界架构 02：模块接入协议

> **归档材料**：本文仅记录旧研究设计与实现，不作为新架构依据。当前研究最高依据为[研究综述](../../../研究理论/研究综述.md)。

> **关系**：本协议是[《世界架构 00：总纲》](00-总纲.md)的工程操作规程；
> 世界语义以《[世界契约](../../研究理论/世界契约.md)》条款为准。

**一句话**：接入一个模块 = **声明 + 证据 + 测试，零框架改动**。

新模块只写三处：

```
olam/modules/<name>.py      # 声明（六种声明 + 参数/旋钮 + 证据义务）
testbench/world/test_<name>.py          # 测试（行为 + 边界 + 负例）
docs/...                                    # 模块说明（可选；声明内 notes 为主）
```

**不得**修改 `olam/kernel`、`olam/meta`、`olam/compile`、`olam/runtime`、
`olam/protocols` 与验收框架。需要改它们 = 扩展接入位，不是模块接入。

## 1. 接入清单（机器门禁）

门禁：`olam.evidence.protocol.module_protocol_issues(pack)`，
测试：`testbench/world/test_protocol.py`。零缺口（或按 §3 登记豁免）方可接入。

| 项 | 要求 | 门禁码 |
| --- | --- | --- |
| 模块说明 | `ModulePack.notes` 非空（用途与边界） | `module.notes` |
| 证据清单 | `ModulePack.evidence` 非空（测试/黄金/判据引用） | `module.evidence` |
| 槽位研究元数据 | state/derived 槽位的 `role`/`schedule`/`quantization`/`metric` 非空 | `slot.metadata` |
| 权限元数据 | `intervene` 权限 → `access_interventions` 非空；`observe` 权限 → `observation_protocols` 非空 | `slot.access` |
| 机制方程 | `MechanismDecl.equation` 非空（规范语义文本） | `mechanism.equation` |
| 边界情形 | `boundary_cases` 非空（clamp/拒绝/退化输入） | `mechanism.boundary_cases` |
| 误差界元数据 | 每条父引用：`lipschitz`（linear）或 `jump_bound`（jump）非空 | `parent.modulus` |
| 有效域 | 每条父引用 `valid_domain` 非空 | `parent.valid_domain` |

编译器（C0–C2）另行强制：单写者、引用存在、无环、阶段序、周期刻度、
地址唯一、见证覆盖与重跑、误差界否证（G7）、字段级不变量。

## 2. 证据义务（按模块类型）

| 类型 | 额外义务 |
| --- | --- |
| **投影模块**（进入 `equations.json` 研究投影） | 全部槽位研究元数据 + 观测协议 + 每条父引用的误差界元数据；V4 独立参考对拍覆盖（方程可解析或登记 `REFERENCE_IMPLS`） |
| **生产模块**（引擎求值面，如 terrain） | 内核对（参考 ↔ 加速逐位一致）+ 黄金向量；误差界元数据可登记豁免（见 §3） |
| **演练模块**（drill.*） | 与投影模块同级（完整元数据），但不必进投影；验收判据（W 系列）可引用其模块 id |

新模块的**负证据**与正证据同等重要：每个机制至少一组见证对（只变一个父、
输出不同），每条不变量至少一个可触发的违规路径，每个拒绝分支至少一个测试。

## 3. 豁免登记（缺口显式化）

无法立即补齐的项按模块登记在 `protocol.PROTOCOL_EXEMPTIONS`，并满足：

1. 目标支持前缀通配（如 `terrain.integrate<-*`）；
2. 给出理由与缺口说明（terrain 场内核的逐父误差界元数据在内核契约内声明）；
3. `testbench/world/test_protocol.py::test_exemptions_are_load_bearing` 锁定豁免
   仍然承重——补齐后豁免必须删除（否则测试暴露"豁免已失效"）。

**豁免不是放水**：它把缺口从"静默通过"变成"显式登记 + 有理由说明 + 有测试盯防"。

## 4. 验收（接入演练判据）

**新模块演练**：不改契约、元模型与验收框架，仅凭声明 + 证据接入一个全新模块，
全门禁绿。已完成接入演练的模块：

| 模块 | 演练点 | 证据 |
| --- | --- | --- |
| `drill.conservation` | 流量 + 跨槽位守恒不变量 + 多分辨率（restrict/prolong） | W6 + `test_conservation.py` |
| `drill.harvest` | 实体 + 事件门控 + 双链接（目标/归属）+ Γ 指派 | W7 + `test_harvest.py` |
| `drill.momentum` | 全新模块（接入演练验收）：lag=2 递推 + 检查点充分性 | `test_momentum.py` + 协议门禁 |

## 5. 条款↔证据对账（WC-11.2）

对账表：`kheker/acceptance/clause_evidence.py`（每条契约条款一行：
状态 / 判据码 / 证据文件 / 正负证据 / note）。
门禁：`kheker/acceptance/clause_ledger.py --check`（CI 步骤同名），校验
条款一一对应、状态合法、判据码存在于 `world_checks.CHECK_CODES`、证据文件存在；
`partial`/`gap` 必须给出原因与补齐计划。

**新增条款或判据时**：先登记对账表，再改代码/测试——对账表是治理面的事实源。
