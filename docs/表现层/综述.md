# 表现层 — 综述

表现层定义玩家感知到的一切：视觉、界面、音频。不包含游戏逻辑，只负责"呈现"。由 Godot 前端（`frontend/`）实现，所有游戏状态来自 Python 后端。

## 子模块关联

```
视觉风格 → 角色外观
    ↓         ↓
  界面交互 ← 音频音效
```

- **视觉风格**定义场景、tile、美术方向（已实现：2D 正俯视 TileMapLayer 地形 + 海拔五信号 + 显示值追赶 + 分层 pawn + 区块流式加载；未实现：天气粒子、洞穴、基因外观差异）
- **角色外观**定义基因如何驱动角色视觉差异（部位拼接、颜色、纹理）（部分实现：分层部件渲染路径就位，默认物种规格为纯色占位；基因驱动待后端 genome 定型）
- **界面交互**定义 HUD、面板、菜单、操作反馈（已实现：调试终端、F3 调试面板、事件日志、键鼠操作方案、设置界面）
- **音频音效**定义环境音、动作音、对话音（未实现）

### 前后端职责划分

前端只做呈现与输入采集，逻辑全部在后端：

- **前端**：2D 地形渲染（TileMapLayer 平铺 + 海拔五信号）、状态显示值追赶（覆雪/结冰/湿润渐进）、实体分层 pawn 呈现、采集输入、显示 UI；相机跟随玩家（2D 正俯视，滚轮缩放）
- **后端**：世界生成、时间推进、天气解析、实体管理；前端通过 `request/response` 拉取数据（get_chunks、get_weather、entity_snapshot、player_state、terminal_cmd、save_*），通过 `event` 推送接收状态变更（minute_change、world_progress、world_initialized、player_teleported 等）
- **进程模型**：后端分菜单进程（服务模式，仅存档管理）与世界进程（`--world-id` 直启）；前端经 `Connection.restart_backend` 切换（进入世界 / 回滚 / 返回菜单）
- **通信**：JSON over TCP（1 字节版本 + 4 字节大端长度帧）。前端启动时自动探测端口并按需拉起后端进程
- **网络层（net/）**：`Connection` 为门面（仅装配/转发/调度），四个子层各司其职——进程生命周期（`backend_process`）/ TCP 传输（`tcp_transport`）/ 握手（`handshake`，hello 帧队首发送）/ 后台解码（`decode_worker`）。详见 [界面交互/技术](./界面交互/技术.md)

## 与其他大类的接口

- ← **世界框架**：地图、群系、季节的视觉呈现（已接入：地形/海拔/坡度/气候/天气数据经 get_chunks、get_weather 与天气事件流入调试面板、2D 地形渲染与显示值追赶）
- ← **基因系统**：基因效果在角色外观上的可视化（未实现）
- ← **生命个体**：受伤、疾病、需求状态的外观表现（未实现）
- ← **群体社会**：关系值、记录、管理界面的 UI 呈现（未实现）
- ← **玩家行动**：所有玩家操作的界面和操作反馈（已接入：移动/菜单/终端指令经 Connection 发往后端）
