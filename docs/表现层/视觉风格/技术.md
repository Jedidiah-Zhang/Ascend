# 视觉风格 — 技术

前端 2D 渲染由 `scripts/world/main_world.gd` 编排，相机/光照拆分为协作类
（`camera_rig.gd` 焦点 + 缩放、`lighting_controller.gd` CanvasModulate 昼夜色调），
地形为 TileMapLayer 平铺 + 海拔五信号（`terrain_tile_builder.gd` 纯数据），
实体为分层 Sprite2D pawn（`pawn_renderer.gd` 纯数据）。协作类只做纯逻辑，
无场景依赖，可单测。

## 节点结构

```
Main (Node2D, main_world.gd)
├── World (Node2D)
│   ├── Camera2D             焦点跟随玩家，滚轮缩放（zoom=1 即 1 tile = 16px）
│   ├── CanvasModulate       全局昼夜色调（夜晚蓝紫暗色）
│   ├── Terrain (Node2D)
│   │   ├── ChunkPool (Node2D)
│   │   │   └── Chunk_<cx>_<cy> (TileMapLayer)      地形层（每 chunk 一个）
│   │   │       └── 五信号层各一 TileMapLayer（cliff/shadow/decor/contour）
│   │   └── StatesPool (Node2D)                     显示值追赶动态层（恒置顶）
│   │       └── States_<cx>_<cy> (TileMapLayer)     状态层（moisture/snow/ice）
│   ├── Water (Node2D)
│   │   └── Water_<cx>_<cy> (TileMapLayer)  半透明水面（无水域 chunk 不建）
│   ├── Entities (Node2D, y_sort)    实体容器：玩家 + 快照/事件驱动的 pawn
│   ├── Caves (Node2D)     洞穴子场景（空占位，未实现）
│   └── WeatherFX (Node2D) 天气特效（空占位，未实现）
├── TerminalLayer (CanvasLayer, z=100)
│   └── TerminalWidget
├── DebugLayer (CanvasLayer, z=200)
│   ├── DebugOverlay
│   └── EventLog
└── PauseLayer (CanvasLayer)
    └── PauseMenu
```

坐标约定：后端 2D XY ↔ 前端 XZ（wx→x, wz→y）；`_world_to_screen` 是
全部渲染接缝的唯一换算（`Vector2(x, z) × TILE_PIXEL_SIZE`）。

## 相机（CameraRig）

| 参数 | 值 |
|------|-----|
| 类型 | Camera2D（正俯视，锁死旋转/投影） |
| 缩放 | 默认 1.0（1 tile = 16px），滚轮 ±1.2 倍，clamp(0.5, 4.0) |
| 跟随 | 每帧 `position = focus`，focus = 玩家屏幕坐标（吸附/传送/平滑过渡时同步） |
| 调试 | visible_radius 纯函数（缩放 → 视野 tile 半径）驱动流式加载视野 |

## 地形渲染（TileMapLayer 平铺 + 海拔五信号）

### 构建

每 chunk 用 `TerrainTileBuilder.build_cells`（后台线程纯数据）生成六层 cell
数组：`terrain / water / cliff / shadow / decor / contour`，`_mount_built_chunk`
（主线程）按层挂 TileMapLayer。逐 tile 由海拔/坡度/地形类型推导五信号：

| 信号 | 数据源 | 做法 |
| --- | --- | --- |
| 地形材质色 | terrain 数组 | 8 种材质映射色块/纹理（TERRAIN_TILE_COLORS，与后端 TerrainType 8 材质对齐） |
| 崖壁贴片 | 相邻 tile 海拔差 > CLIFF_ELEVATION_DIFF_M(8m) | 高侧边缘画悬崖 tile |
| 固定方向投影 | 光照方向固定（西北），东南侧高差 > SHADOW_ELEVATION_DIFF_M(6m) | 半透明阴影贴片 |
| 装饰密度 | 海拔档位 DECOR_ELEVATION_TIERS(300/1000/2000m) | 岩石/砾石渐密（确定性哈希，非随机）；雪顶已移除——覆雪为动态状态，由状态层自然形成 |
| 等高线调试层 | 500m 间隔（CONTOUR_INTERVAL_M） | 调试开关 CONTOUR_LAYER_ENABLED，可关 |

状态层（`states`）不走 build_cells——由显示值追赶系统直接驱动（见下）。

### 水面

独立半透明 TileMapLayer，每 chunk 一个（无水域 chunk 不建节点）；
与 3D 时代相比不再需要深度雾 shader（平地形无遮挡）。

### 流式加载

`ChunkStreamMachine` 状态机驱动（UNKNOWN → FIELD_REQUESTED → TILE_REQUESTED
→ RECEIVED → CONSTRUCTING → BUILT）：

- 视野内缺失的 chunk → 发 `get_chunks` 请求（含 BLOB tile 数据）
- 数据到达 → 后台构建（`build_cells` 纯数据）→ 主线程 `_poll_build_results`
  挂载 TileMapLayer；在飞上限 `MAX_BUILD_INFLIGHT`
- 超出视野 → 缓存淘汰移出（见存档系统/技术.md 的 LRU）
- `_mount_built_chunk` 对重复构建/双响应竞态补记 BUILT，防状态卡死
- **接缝连续性**：构建提交时收集已加载邻居的紧邻边条（`_collect_neighbor_context`
  → `build_cells(terrain, elevation, neighbors)`），崖壁/投影/等高线在边界
  改读邻居边条（西邻东列/东邻西列/北邻南行/南邻北行），已加载邻居时接缝
  连续；缺失邻居回退无邻居语义（孤岛 chunk 不误报）

## 数据版本协商（BLOB 单一来源）

tile 数据 BLOB 版本由握手协商：客户端 hello 上报其已知版本
（`Config.TILE_BLOB_VERSION`），服务端以数据格式权威版本（`TILE_GRID_VERSION`）
裁决兼容性（客户端版本过低即拒绝连接），并在 hello_ack 回传协商结果；
前端以其作为解码基准（期望尺寸/版本头校验）。原先前后端各自硬编码的
版本号不再需要人肉同步，仅保留前端已知版本表 `_STATE_NAMES_BY_VERSION`
作为各版本的状态段解码依据（未知版本已被握手拦截）。

## 状态渲染（显示值追赶）

后端真值（BLOB v1 的 moisture/snow/ice 段）为权威，前端 `display_*` 渐进收敛：

- `StateDisplayChaser`（纯逻辑）：真值 vs 显示值对齐数组逐帧随机抽样步进
  （CHASE_STEP=10、SAMPLE_PER_SEC=0.6、档位量化 level=v×4/256，档 0 擦除）；
  全局每帧抽样预算 `MAX_SAMPLES_PER_FRAME`（12000），已收敛 chunk 跳过——
  常态零开销（9×40k tile 实测 base 2.7ms / 暴雪 8.3ms / 收敛 0µs）
- 加速（"快下快铺"）：`precipitation_start`(snow) → ×2/30s、`storm_start`
  → ×3/20s；只提抽样密度不改真值，时长自然衰减
- 真值刷新：每 8s 对玩家周围 BUILT chunk（半径 1，每周期至多 3 块）重拉
  完整响应换真值——解码全部字段（terrain/elevation/slope/states）不重建
  地形，BLOB 校验失败回滚旧缓存；断线/卸载/重置清理在途表
- 渲染：独立 `States_<cx>_<cy>` TileMapLayer（挂 Terrain/StatesPool，恒在
  信号层之上），初始格子立即应用、跨档更新、归零擦除

## 实体渲染（分层 pawn）

`PawnRenderer`（纯逻辑）按体型规格产出确定性部件列表，main_world 实例化：

- 槽位序（渲染序）：头/躯干/左右附肢 + 基因变异层 + 装备层（SLOT_ORDER），
  叠层 z = 列表序；后端 genome/body grammar 定型前用默认物种规格
  （CREATURE 人形 / PLANT 冠茎 / 其余石块）
- 部件坐标：节点原点 = 脚底中心（Y-sort 深度排序），y 向上整数像素偏移；
  朝向反转 = 部件 x 偏移镜像（左右附肢换位），无逐部件纹理翻转
- 数据流：`entity_snapshot` 全量生成 pawn、`entity_born/moved` 事件增量
  维护、`entity_died` 移除；世界重建/断线清空（`_clear_pawns`）；
  玩家由 player_state/快照独占消费（entity_born 过滤 PLAYER 防双渲染）
- 头顶名称浮层：独立 Label（固定宽居中，不占身体像素预算），本地化
  实体类型名（entity.type.* 键）
- 玩家局部光源：`PlayerTorch` PointLight2D（径向渐变占位纹理），
  `LightingController.is_night` 昼夜驱动开关

## 光照

### 全局（CanvasModulate）

`lighting_controller.gd` 按游戏时间/日出日落/日照强度调制全局色调：

- 太阳高度角驱动昼夜插值（夜晚 NIGHT_COLOR 蓝紫 → 白天中性），
  日出日落 smoothstep 平滑 ramp 无跳变
- 雨天（日照强度低）整体调暗（WEATHER_DIM_MIN=0.85 亮度下限）

### 局部（PointLight2D）

`is_night(game_hour, game_minute, sunrise, sunset)` 纯判据：日出前/日落后为夜
（daylight≤0 保守视为白天）。当前只有玩家火炬；火把/营火/建筑窗户光源
与洞穴内点光源待对应系统接入（纹理/能量/范围参数化生成）。

## 遮挡虚化（未实现）

平地形无遮挡——整类问题消失，不再需要。

## 洞穴（未实现）

`Caves` 节点为空占位。洞穴入口触发、屋顶切换、内部场景均无实现
（`layer_id` 只在后端数据与事件中存在，无地下生成）。

## 天气粒子（未实现）

`WeatherFX` 节点为空占位。雨/雪/沙尘粒子（GPUParticles2D）未实现；降水
当前只体现在天气数据、事件日志与状态显示值追赶（覆雪/结冰/湿润）。
