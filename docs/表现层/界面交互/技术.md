## Connection 单例

管理与 Python 后端的 TCP 连接与**后端进程切换**，`_process` 每帧轮询驱动状态机。

### 进程模型（一进程一模式）

后端进程两种模式，前端经 `restart_backend(args)` 切换（非阻塞状态机）：

- **菜单进程**（无参）：服务模式，仅存档管理——主菜单 / 存档选择页
- **世界进程**（`--world-id <id> [--snapshot <file>]`）：直接构建世界观——进入世界 / 回滚

切换流程：置 `_restarting`（抑制断线广播，UI 不闪错）→ SIGTERM 优雅停旧进程（最终落盘）→ 轮询退出（超时 3s 强杀兜底）→ 以新参数 `OS.create_process` 拉起 → 端口探测 → 重连。`backend_args` 暴露当前模式（UI 据此感知）。

### 协议

- 帧格式：1 字节协议版本 + 4 字节大端长度前缀 + JSON 体（与后端 `struct.pack(">BI")` 一致，`frame_codec.gd` 封装；跨语言一致性由前后端测试锁定）
- 消息：`{type, seq, payload, ...}`；`type ∈ {request, response, event, error}`，`seq` 自增
- 消息上限 16 MiB；信号：`connection_established / connection_lost / message_received / backend_failed`
- 握手：TCP 建立后先发 `hello{token, protocol_version}`，收到 `hello_ack` 才视为已连接；token 每次重连重读（进程切换后 token 变化），握手拒绝自动重试

### 后端进程自管理

启动流程（非阻塞状态机，避免主线程卡顿）：

1. `_start_backend()` 先非阻塞探测 `127.0.0.1:9081`（`PROBE_TIMEOUT = 0.2s`）
2. 端口已开放 → 直接连接（复用已运行后端）；未开放 → 拉起 `.venv/bin/python backend/run_server.py`
3. 等待期间每 0.5s 重新探测，超时 60s 进入 FAILED 终态（可手动重试）
4. 退出时（`NOTIFICATION_PREDELETE`）SIGTERM 优雅停止（等 3s 超时强杀兜底）——最终落盘不丢状态

断线后 2s 间隔自动重连（`_restarting` 主动切换期间抑制）。

### 后台解码线程

JSON 解析移出主线程：`_read_messages()` 主线程只做拆帧，帧体经 Mutex+Semaphore 队列交给 `Thread` 解码，`_collect_decoded()` 主线程收集结果并发射 `message_received`。`last_process_us` 记录每帧耗时供性能分区显示。进程切换时 `_finish_restart_spawn` 停解码线程并清空收发缓冲（防帧错位）。

## MainWorld 消息路由

`_on_message()` 按 `type` 分发：

- `response`：`get_chunks` → 缓存/建网格（经 `ChunkStreamMachine` 状态机）；`get_weather` → 日出日落/日照更新；`player_state` / `entity_snapshot` / `player_move` → 权威玩家位置吸附（`_apply_authoritative_position`）；`player_interact` → 未实现标记提示；`terminal_cmd` → 终端输出；`save_snapshot` / `save_list` → 手动存档节点编号回填暂停菜单
- `event`：`world_progress` / `world_initialized`（世界进程就绪信号：加载提示 / 复位世界 + 拉取权威状态）；`minute_change`（时间分区 + TPS 推算 + 日期分隔线）；`player_teleported`（位置吸附 + 日志，先于 overlay 检查处理）；其余事件广播给调试覆盖层与事件日志
- `error`：`push_error`

玩家状态同步（权威实体在后端 `PlayerService`）：

- 连接建立时（`_on_connected`）请求 `entity_snapshot`（全量实体快照）+ `player_state`（标记本地控制的 entity_id）；`world_initialized` 事件到达时再请求一次（覆盖生成期间连接建立、事件先到的情况）
- WASD 移动本地即时显示，main_world 每 0.2s（`MOVE_REPORT_INTERVAL`）节流上报 `player_move`；后端权威裁决（钳制越界），响应吸附纠正
- `entity_snapshot` 仅消费本地控制的玩家实体（其余实体渲染后续接入）

世界就绪流程（进程模型）：`save_select` 点进入/回滚 → `backend_launcher` 以 `--world-id [--snapshot]` 拉起世界进程 → 连接就绪（`connection_established`）切 `main.tscn` → 世界进程大陆生成期间广播 `world_progress`（前端进度条）→ `world_initialized`（含出生点）= 就绪信号。

调试数据推送（`_update_debug_sections()`，仅面板可见时执行）：

- 每帧推送相机/玩家/区块统计/性能计时
- 玩家移动到新 tile 时才查询地形/气候（避免每帧字典查找）
- 每 0.5s 轮询一次 `get_weather`（`_weather_query_accum` 限流）

## DebugSection 架构

分区基类为 RefCounted（非节点），DebugOverlay 统一 `_draw()` 渲染，避免节点树开销：

```
DebugSection (基类)
├── label: String            分区标题（DebugOverlay.get_section(label) 检索键）
├── enabled: bool             关闭时跳过渲染
├── get_lines() -> PackedStringArray   子类覆写，返回文本行
└── update_from_backend(data)          事件型分区覆写
```

三种数据更新模式：

- **自取型**：`get_lines()` 内直接读 Engine/Performance（内存、连接分区）
- **推送型**：MainWorld 每帧设置属性（相机、玩家、区块分区）
- **事件型**：`update_from_backend()` 注入后端数据（时间、气候、天气、地形分区）

DebugOverlay 每 0.25s（`REFRESH_INTERVAL`）`queue_redraw()`，绘制时先收集全部行测量背景宽度，再统一绘制。

## TerminalWidget

全部通过 `_draw()` 自绘（无 RichTextLabel 子节点）：

- 打开时 `_input()` 捕获全部键盘事件并 `set_input_as_handled()`，实现输入独占
- 输出环形缓冲 500 行、历史 100 条、单行输入上限 200 字符，光标 0.5s 闪烁
- 本地指令注册表：`register_command(name, handler, help_text)`（模仿 DebugSection 模式），handler 签名 `(args: PackedStringArray) -> String`；内置 `clear`，MainWorld 注册 `tp`
- 回车后匹配本地指令直接处理；`help`/`?` 显示本地帮助并继续转发后端追加远程帮助；其余发射 `remote_command_submitted` 信号由 MainWorld 转发后端
- 指令表见 [终端指令](./终端指令.md)

## EventLog

- `push_event(line)` 头插，超 20 条截断；`_pending_redraw` 标记 + 0.5s 节流合并高频事件的重绘
- 固定面板宽 280px，避免每帧测量字符串宽度

## 性能约定

- 调试 UI 一律自绘 + 节流刷新（0.25s/0.5s），关闭时零开销
- 覆盖层 `mouse_filter = IGNORE`，不参与命中测试
- 热路径缓存节点引用（`@onready`），禁止每帧 `get_node`
