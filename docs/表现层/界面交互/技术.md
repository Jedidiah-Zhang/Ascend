## Connection 单例

管理与 Python 后端的 TCP 连接与**后端进程切换**，`_process` 每帧轮询驱动状态机。

### 进程模型（一进程一模式）

后端进程两种模式，前端经 `restart_backend(args)` 切换（非阻塞状态机）：

- **菜单进程**（无参）：服务模式，仅存档管理——主菜单 / 存档选择页
- **世界进程**（`--world-id <id> [--snapshot <file>]`）：直接构建世界观——进入世界 / 回滚

切换流程：置 `_restarting`（抑制断线广播，UI 不闪错）→ SIGTERM 优雅停旧进程（最终落盘）→ 轮询退出（超时 3s 强杀兜底）→ 以新参数 `OS.create_process` 拉起 → 端口探测 → 重连。`backend_args` 暴露当前模式（UI 据此感知）。

### 协议

- 帧格式：1 字节协议版本 + 4 字节大端长度前缀 + JSON 体（与后端 `struct.pack(">BI")` 一致，`frame_codec.gd` 封装；跨语言一致性由前后端测试锁定）
- 消息：`{type, seq, payload, ...}`；`type ∈ {request, response, event, error}`，`seq` 自增
- 消息上限 16 MiB；信号：`connection_established / connection_lost / message_received / backend_failed`
- 握手：TCP 建立后先发 `hello{token, protocol_version}`，收到 `hello_ack` 才视为已连接；token 每次重连重读（进程切换后 token 变化），握手拒绝自动重试

### 后端进程自管理

启动流程（非阻塞状态机，避免主线程卡顿）：

1. `_start_backend()` 先非阻塞探测 `127.0.0.1:9081`（`PROBE_TIMEOUT = 0.2s`）
2. 端口已开放 → 直接连接（复用已运行后端）；未开放 → 拉起 `.venv/bin/python backend/run_server.py`
3. 等待期间每 0.5s 重新探测，超时 60s 进入 FAILED 终态（可手动重试）
4. 退出时（`NOTIFICATION_PREDELETE`）SIGTERM 优雅停止（等 3s 超时强杀兜底）——最终落盘不丢状态

断线后 2s 间隔自动重连（`_restarting` 主动切换期间抑制）。

### 后台解码线程

JSON 解析移出主线程：`_read_messages()` 主线程只做拆帧，帧体经 Mutex+Semaphore 队列交给 `Thread` 解码，`_collect_decoded()` 主线程收集结果并发射 `message_received`。`last_process_us` 记录每帧耗时供性能分区显示。进程切换时 `_finish_restart_spawn` 停解码线程并清空收发缓冲（防帧错位）。

## MainWorld 消息路由

`_on_message()` 按 `type` 分发：

- `response`：`get_chunks` → 缓存/建网格（经 `ChunkStreamMachine` 状态机，后台线程构建见下）；`get_weather` → 日出日落/日照更新；`player_state` / `entity_snapshot` / `player_move` → 权威玩家位置对账（`_apply_authoritative_position`）；`player_interact` → 未实现标记提示；`terminal_cmd` → 终端输出；`save_snapshot` / `save_list` → 手动存档节点编号回填暂停菜单
- `event`：`world_progress` / `world_initialized`（世界进程就绪信号：加载提示 / 复位世界 + 拉取权威状态）；`minute_change`（时间分区 + TPS 推算 + 日期分隔线）；`player_teleported`（重置对账基准 + 位置硬吸 + 日志，先于 overlay 检查处理）；其余事件广播给调试覆盖层与事件日志
- `error`：`push_error`

玩家状态同步（权威实体在后端 `PlayerService`）：

- 连接建立时（`_on_connected`）请求 `entity_snapshot`（全量实体快照）+ `player_state`（标记本地控制的 entity_id）；`world_initialized` 事件到达时再请求一次（覆盖生成期间连接建立、事件先到的情况）
- WASD 移动本地即时显示（客户端预测），main_world 每 0.2s（`MOVE_REPORT_INTERVAL`）节流上报 `player_move`；后端权威裁决（钳制越界），响应回传裁决后的权威位置
- **权威位置对账**（`_apply_authoritative_position`）：TCP 有序保证响应与上报一一对应，用"权威位移 vs 上报位移"判定后端是否认可本次移动（与 RTT 无关）：
  - **认可（跟随）**：权威位移与上报位移逐分量差 ≤ `SNAP_FOLLOW_TOLERANCE`（0.5 tile）→ 权威只是滞后，**零纠正**——滞后 ≠ 偏离，回显原样即位置正确，消除每 0.2s 一次的回跳
  - **未认可（真偏离）**：钳制/读档复位等 → 按差距三档纠正：< `SNAP_TOLERANCE`（2 tile）忽略；≥ `SNAP_HARD_THRESHOLD`（8 tile）硬吸（传送/读档复位/初始定位）；中间 `SNAP_DURATION`（0.15s）平滑过渡（`_process_snap` 按剩余差距比例推进，期间输入位移逐帧保留）
  - 对账基准（`_last_reported` / `_last_authority`）与在途过渡在传送（`player_teleported`）/ 出生（`_set_birth_chunk`）/ 世界重建（`_reset_world_state`）时经 `_reset_authority_state()` 统一重置，防止插值"撤销"跳变
- `entity_snapshot` 仅消费本地控制的玩家实体（其余实体渲染后续接入）

### 区块加载（流式状态机 + 后台线程构建）

`ChunkStreamMachine` 驱动流式加载（结构性无双请求，Issue #27 思想延续）；`CONSTRUCTING` 状态把"完整数据到达"与"网格构建完成"解耦——构建移出主线程，避免主线程每块 ~240ms 卡顿。构建分两阶段：

- **后台（WorkerThreadPool）**：`TerrainMeshBuilder.build_data` 只做纯数据计算（顶点/法线/UV/顶点色 AO），不创建 ArrayMesh、不接触 RenderingServer 与材质——规避退出时工作线程访问已销毁的 RenderingServer（资源泄漏）
- **主线程**：`_poll_build_results` 轮询结果队列（Mutex 保护，`seq` 失配/状态非 CONSTRUCTING 的陈旧结果丢弃）→ `make_mesh` 组装 ArrayMesh 并挂材质 → `_mount_built_chunk` 挂载

在飞上限 `MAX_BUILD_INFLIGHT`（2）；断线将 CONSTRUCTING 降级 RECEIVED（数据保留，重连后重建，旧结果按序号丢弃）；`_exit_tree` 清空结果队列并断开信号。

### 创建 / 进入世界流程（进程模型 + 进度页，Issue #8）

两条入口都汇聚到 `world_loading.tscn` 进度页：

- **创建世界**：主菜单「开始游戏」无存档（或存档页「新建游戏」）→ `world_setup.tscn` 多步调参（当前 1 步：地图生成——seed / 大陆占比 / 尺寸档位 + `map_preview` 实时地形预览，预览请求在途至多 1 个，变化即补发合并；预览面板可切换 **地形 / 温度 / 降雨 / 气候** 视图——请求固定携带 `layers` 一次算全，切换仅换着色函数零往返；响应缺图层字段（旧后端）自动降级仅地形视图）→ 「创建世界」发 `save_create`（seed + gen_params 随档定案）→ 停菜单进程、以 `--world-id <id>` 拉起世界进程（与进入共用 `restart_backend` 状态机）→ 切 `world_loading.tscn`，不等连接就绪
- **进入世界 / 回滚**：`save_select` 直接以 `--world-id [--snapshot]` 拉起世界进程 → 切 `world_loading.tscn`

进度页状态机 `LAUNCHING → LOADING → (world_initialized | ERROR)`：后端大陆生成期间逐阶段广播 `world_progress`（elevation/climate/erosion/water/width/done/chunks，顺序单源 `WorldStageLabels.ORDER`），进度条按阶段刻度推进——阶段切换进入 0.6s 快速补间窗口（25%/s）快速增长，阶段内 1%/s 缓慢爬升；时间兜底（120s 超时比例）封顶 90%。`world_initialized`（含出生点）= 就绪信号：进度页经 Relay（SceneTree process_frame ONE_SHOT，自持强引用跨场景存活）转发给 `main.tscn` 的 MainWorld，保证其订阅就位时事件不丢失。超时 / 连接中断 / 后端失败 → 错误态（返回主菜单 / 重试）。

调试数据推送（`_update_debug_sections()`，仅面板可见时执行）：

- 每帧推送相机/玩家/区块统计/性能计时
- 玩家移动到新 tile 时才查询地形/气候（避免每帧字典查找）
- 每 0.5s 轮询一次 `get_weather`（`_weather_query_accum` 限流）

## DebugSection 架构

分区基类为 RefCounted（非节点），DebugOverlay 统一 `_draw()` 渲染，避免节点树开销：

```
DebugSection (基类)
├── label: String            分区标题（DebugOverlay.get_section(label) 检索键）
├── enabled: bool             关闭时跳过渲染
├── get_lines() -> PackedStringArray   子类覆写，返回文本行
└── update_from_backend(data)          事件型分区覆写
```

三种数据更新模式：

- **自取型**：`get_lines()` 内直接读 Engine/Performance（内存、连接分区）
- **推送型**：MainWorld 每帧设置属性（相机、玩家、区块分区）
- **事件型**：`update_from_backend()` 注入后端数据（时间、气候、天气、地形分区）

DebugOverlay 每 0.25s（`REFRESH_INTERVAL`）`queue_redraw()`，绘制时先收集全部行测量背景宽度，再统一绘制。

## TerminalWidget

全部通过 `_draw()` 自绘（无 RichTextLabel 子节点）：

- 打开时 `_input()` 捕获全部键盘事件并 `set_input_as_handled()`，实现输入独占
- 输出环形缓冲 500 行、历史 100 条、单行输入上限 200 字符，光标 0.5s 闪烁
- 本地指令注册表：`register_command(name, handler, help_text)`（模仿 DebugSection 模式），handler 签名 `(args: PackedStringArray) -> String`；内置 `clear`，MainWorld 注册 `tp`
- 回车后匹配本地指令直接处理；`help`/`?` 显示本地帮助并继续转发后端追加远程帮助；其余发射 `remote_command_submitted` 信号由 MainWorld 转发后端
- 指令表见 [终端指令](./终端指令.md)

## EventLog

- `push_event(line)` 头插，超 20 条截断；`_pending_redraw` 标记 + 0.5s 节流合并高频事件的重绘
- 固定面板宽 280px，避免每帧测量字符串宽度

## 性能约定

- 调试 UI 一律自绘 + 节流刷新（0.25s/0.5s），关闭时零开销
- 覆盖层 `mouse_filter = IGNORE`，不参与命中测试
- 热路径缓存节点引用（`@onready`），禁止每帧 `get_node`
