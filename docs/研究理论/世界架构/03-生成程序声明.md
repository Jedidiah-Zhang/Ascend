# 世界架构 03：生成程序声明

> **关系**：本文件是[《世界架构 00：总纲》](00-总纲.md)的生成侧补充；
> 世界语义以《[世界契约](../../研究理论/世界契约.md)》条款为准；
> 接入协议见[《02：模块接入协议》](02-模块接入协议.md)。

**一句话**：大陆 / 水文 / 瓦片 / 统一天气场是**声明的边界生产者**——
不是世界模块（无槽位/机制），而是"种子 + 参数 + 坐标 → 内容场"的
确定性程序；它们的身份（源码 + 常量 + 版本指纹）与采样协议成文，
`slice_boundary` 由此消解为"已声明边界 + 内容数据"。

## 1. 声明载体

`backend/ascend/world/generation.py`：`GenerationDecl` +
`GENERATION_PROGRAMS`（四个程序）+ `generation_fingerprint()` /
`generation_identity()`。

每个程序声明：

| 字段 | 含义 |
| --- | --- |
| `inputs` | 声明的输入（种子 / 参数 / 上游内容） |
| `outputs` | 产出的内容名（非槽位 id） |
| `feeds` | 喂给的**声明槽位**（游戏程序的 external 槽位） |
| `source_files` | 参与指纹的源码（backend 根相对路径） |
| `constants` | 参与指纹的配置常量名（`ascend.config`） |
| `determinism` | 确定性说明（同输入同输出） |
| `sampling` | P₀ 采样协议（证据如何取样） |

## 2. 四个程序

| 程序 | 输入 → 输出 | feeds（声明槽位） | 源码 + 常量 |
| --- | --- | --- | --- |
| `generation.continent` | seed + 大陆参数 → 陆海掩膜 / 海拔 / 气候属性 / 构造块 / 冰川 / 火山 / 海岸 | 纬度代理、年均温、年降雨、季节/昼夜温差振幅（5 槽位） | continent / continent_data / noise / `_perlin.c` + 大陆与地形噪声常量 |
| `generation.hydrology` | 大陆场 + 参数 → 侵蚀 / 汇流 / 河流 / 湖泊 / 降雨 / 气候档 | 湿度基线、风速基线、湿度锐度、降水强度、季节/昼夜湿差振幅（6 槽位） | hydrology / streamlines / climate / `_hydrology.c` / `_streamlines.c` + 侵蚀/河湖/雨影/气候标定常量 |
| `generation.tile` | seed + chunk 坐标 + 气候/群系模板 → 群系 / 材质 / 高度 / 坡度 / 覆盖 | `terrain.terrain_id` / `terrain.slope` / `terrain.cover`（3 槽位） | tile_gen / tile_grid / biome / terrain / noise / `_perlin.c` / `_state.c` + 瓦片材质常量 |
| `generation.weather_field` | seed + 世界坐标 + 时刻（+ 特征核输入） → 温度/湿度/风扰动、风倍率、降水信号 | `weather.field.*` 五个边界槽位 | field / atmosphere / features / noise / `_perlin.c` + 场/特征/代理常量 |

**边界绑定（可执行证据）**：`feeds` 的并集 == 游戏程序全部 external 槽位
减去时钟/驱动/引擎桥接槽位（`DRIVER_INPUT_SLOTS`）；测试
`tests/world/test_generation.py::TestBoundaryBinding` 锁定。

## 3. 身份与确定性

- **指纹**：`generation_fingerprint(decl)` = 声明版本 + 配置常量值 +
  源码文件内容摘要（`digest_object` / `file_digest`）。源码在场时任一
  文件/常量变化即变；打包模式（源码缺失）退位到"版本 + 常量"锚点，
  与旧 `compute_gen_fingerprint` 同策略。
- **清单对齐（漂移门禁）**：旧生成环境指纹的源码清单
  （`space.generator._GEN_SOURCE_FILES`）与常量清单
  （`config.CONTINENT_GEN_CONSTANT_NAMES`）必须被四个程序**完整覆盖**；
  新增文件/常量未归属即红。
- **确定性**：四个程序均为纯函数（无 IO、无时钟、不依赖加载/物化顺序）；
  水文 C 内核与 Python 参考逐位一致（内核对测试）。
- **物化无关性**：同 (seed, 坐标) 重复生成/采样逐位一致；瓦片生成与
  生成顺序无关（单块 vs 多块）；天气场采样与顺序/批量形状无关。

## 4. P₀ 采样协议

每个程序在 `sampling` 中声明证据取样方式（测试逐条落实）：

- 重复取样 → 逐位一致（确定性）；
- 顺序/批量无关（物化无关性）；
- 内核对 / 边界连续性（水文 C ↔ Python；瓦片 chunk 边界隶属度混合）；
- 缓存命中与重生成一致（大陆缓存）。

## 5. slice_boundary 的消解

研究投影（`research/equations/equations.json`）的 `slice_boundary` 由
"生成管线在切片之外"改为：**生成程序已声明（指纹 + 采样协议），其输出
作为声明边界输入进入本切片；`data/*.json` 是内容而非算法**。此后
`slice_boundary` 不再承载"未声明的生成算法"这一灰区。
