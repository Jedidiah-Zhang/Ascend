# 世界基座 09：完整存档

> 记号按[工程符号体系](../工程符号体系.md) §2–§4 与
> [第一阶段实施定义](../第一阶段实施定义.md) §3、[世界验收协议](04-世界验收协议.md) §3.5。
> 工程侧入口是 `backend/ascend/save/`（状态载荷）与各子系统的
> `persist_*` / `restore_*` 接口。

## 1. 定位

本篇对应 issue #46 的 P4 交付：**完整存档**。第一阶段要求世界状态
$\mathcal W_t$ 必须包含一切会改变未来演化的信息（实施定义 §3.1），
删除缓存并由 $\mathcal W_t$ 重算后轨迹必须一致。W4 验收就是这个断言。

P2 交付干预执行器后，世界多了一类**声明之外**的状态：研究者施加的干预
（替换规格 × 时长）与强制注入的特征核。它们不由 seed 派生、不能重算，
却真实改变未来。P4 之前这些状态不落盘——读档后干预消失、强制天气消失，
W4 实测失败。

**一句话边界**：存档只存"删掉它未来就会变"的东西。

| 分量 | 处置 | 依据 |
| --- | --- | --- |
| 时钟时间/速度/暂停 | 落盘 | 不可重算 |
| 玩家实体与位置 | 落盘 | 实体状态不可重算 |
| 干预表（生效记录） | 落盘 | 研究者施加的替换，不在声明内 |
| 注入的特征核 | 落盘 | 研究者施加的运行时核，非 seed 派生 |
| 自然特征核时间线 | 重建 | 由 seed + 块坐标 + 段索引确定性派生 |
| 统一天气场 / 气候代理 | 重建 | 由 seed + 时钟派生 |
| chunk 天气基线 | 重建 | chunk 注册时由气候模板与基线派生 |
| 区域跟踪器 / 季节去重标记 | 重建 | 每帧从场与时钟重算 |
| 区块 / 事件归档 | 各自通道 | chunks.db / events.db |

可重算量**不得**落盘：多存会让"删缓存由状态重算"失去检验意义，
也会把解析量固化成第二个事实源。

## 2. 状态载荷

`state.json.enc`（加密 + HMAC，见[存档系统](../../世界框架/存档系统/技术.md)）：

```json
{
  "state_version": 1,
  "clock":   {"time": 0, "speed": 1.0, "paused": false},
  "player":  {"entity_id": null, "x": 0.0, "y": 0.0},
  "weather": {
    "interventions": [ <record_plain 视图> ],
    "feature_cores": [ <注入核视图> ]
  },
  "archive_max_timestamp": 0
}
```

- **干预记录**只含**生效**记录（同键后到覆盖先到的胜者、未被清除者）。
  被替换的历史不落盘——它是研究溯源对象（P3 trace / 研究 API），不是
  $\mathcal W_t$。记录携带 `seq` / `applied_at`，读档回填原值，
  研究溯源不会因读档而重编号。
- **注入核**携带坐标、类型、出生帧、时长、中心、半径、强度与移动矢量；
  `core_id` 由身份派生（`inj:{cx}:{cy}:{type}`），存档里的 `core_id`
  必须与身份一致，否则拒绝。

### 2.1 版本与 fail-closed

`STATE_VERSION = 1`，**无向后兼容**：读档在任何副作用之前校验版本，
缺失（旧格式）、非整数或与当前不符一律 `ValueError`。项目约定是
"不承诺向后兼容、重构优先"，因此不写逐版本迁移——格式变更即旧档不可读，
错误信息明确区分"旧格式"与"未来格式"。

恢复路径逐条重新校验，**存档不是绕过校验的后门**：

- 干预记录重新走 `InterventionTable.commit` 的六条执行前校验（目标已声明
  且已接线、值属声明值域、帧/时长合法、权限允许、实例匹配、参数标环境变化）；
- 注入核逐条校验类型已注册、`core_id` 与身份一致、坐标与数值类型/有限性；
- 任一条非法 → **整体拒绝**，不留下半成品表或半成品核集合。

### 2.2 实例存在性：读档期的按需装载

干预目标实例（chunk）可能已被 LRU 淘汰而不在加载集内——这不是存档损坏。
`InterventionTable.restore(payload, instance_loader=...)` 接受一个装载器：
实例不存在时先尝试把它拉回来，仍不可用才拒绝。装载器**只在本次恢复调用
期间生效**，运行期登记不做隐式加载（避免"登记时偷偷加载 chunk"的副作用）。

世界接线方（`GameEngine._ensure_intervention_instance`）负责实现它：
从 `chunk_store` 取或生成目标 chunk，经 chunk 服务注册器注册（天气 +
地形状态引擎同源），tile 就绪时广播结算。

## 3. 世界设置（manifest）

存档位介绍信息（明文）记录定义这个世界的全部输入：

| 字段 | 内容 | 来源 |
| --- | --- | --- |
| `seed` | 世界种子 | 创建时定案 |
| `gen_params` | 世界生成调参（陆地比例、尺寸） | 创建世界流程 |
| `mechanism_declaration` | 声明 ID + 全量摘要 + 观测协议版本 | `MechanismRegistry.declaration_settings()` |

读档时 `validate_world_settings` 与当前注册表比对：

- **一致** → 放行；
- **不一致** → 拒绝加载。用新公式继续跑旧状态会得到一条"合法但不属于
  任何已声明世界"的轨迹，属于静默错误，必须挡住；
- **未记录**（P4 之前的存档）→ 放行，并由 `_persist_manifest` 立即补写，
  使下一次加载有可比对的事实。

## 4. 验收（W4）

04 §3.5 要求：从检查点复制 $\mathcal W_t$、清空可重建缓存、在相同未来
输入与随机地址下继续运行，两条轨迹一致。P4 的等价断言在
`tests/unit/test_save_completeness.py`：

1. **往返**：`collect_state` → JSON → `apply_state` → 再采集，逐字段相同
   （含干预与注入核）；
2. **双跑一致**：世界 A 施加干预 + 注入核后存档，世界 C 读档，世界 B
   完全不存档——B 与 C 在后续帧的逐 chunk 天气读出必须逐位一致；
3. **判别力**：把干预与注入核从载荷里去掉后，B 与 C 必须**分叉**。
   没有这条负例，双跑一致可能只是"两边都没生效"的假通过。

另有两层防护：恢复是**整体替换**（目标世界的残留注入核不得存活），
干预的 `seq` / `applied_at` 往返不变（研究溯源不可重编号）。

集成层（`tests/integration/test_game_engine.py`）走真实路径验证：进程 A
施加干预与强制特征核 → 保存脉搏落盘（state + manifest）→ 进程 B
`load_world` 后两者完整回来；世界设置不一致时拒绝加载。

## 5. 边界与遗留

- **W5 观测隔离未实现**：当前没有智能体观测主体（实体管理器"视野=全部"，
  事件桥接面向渲染），`AccessPolicy.observation_protocols` 已声明但无消费方。
  观测映射层与 W5 验收推迟到 P5（统一验收 runner）；届时 $G^i$ 只能从声明
  派生，研究日志不得成为智能体后门。**P3 研究 trace 同样推迟**——
  它服务于"逐节点对账"，而 W4 的双跑诊断在 P5 runner 里才需要它。
- **实体表全量持久化（issue #25）**：仍只有玩家位置随状态保存。
- **快照格式**：`.ascendsave` v2 不动，本交付只改其内的 state 载荷。
- **未存档的运行时状态**：天气引擎的 `_last_season`（事件去重标记）与
  区域跟踪器的上一帧区域集合按"可由 $\mathcal W_t$ 重算"处置，不入载荷；
  若将来某个标记影响未来轨迹（例如依赖历史做迟滞判定），必须改为分量。
