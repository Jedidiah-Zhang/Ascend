# 世界基座 12：世界树角色与帧调度（架构决策）

> **地位**：架构决策记录（ADR）。世界语义以《[世界契约](../世界契约.md)》为准；本文只规定"执行与记录如何分工"，不新增世界语义。

## 1. 背景：总线即因果的四个问题

早期设计沿用互联网事件总线模型：所有模块发布事件、订阅自己关心的事件并**据此改变状态**。在"可复现、可干预、可追溯"的世界基座里，这条路径有四个结构性问题：

1. **订阅关系是隐式输入**：机制读集不是声明的，而是"订了什么"；结果依赖订阅者在不在场（chunk 被 LRU 淘汰即退订）、投递顺序、线程时序——违反 WC-2.3（无隐式耦合）与 WC-3.2（状态闭合）。
2. **因果不可结构验证**：写者散落在动态订阅里，无法在声明层检查单写者/无环/求值序——违反 WC-4.2。
3. **调度污染 CRN**：事件驱动改变求值时点，抽取地址集合随调度变化，平行实验臂失去配对——违反 WC-5.1/5.2。
4. **缓存策略成为世界语义**：加载集影响演化，同一存档、不同加载路径未来分叉。

具体案例：地形状态曾订阅 `precipitation_start` 即时涂抹，chunk 是否加载、事件到达顺序都会改变地形轨迹（C2 已消除）。

## 2. 决策

**D1 世界树 = 记录/观测中枢。**
世界树继续发布不可变事件、归档、向 UI/日志/探针/未来观测协议分发；但**订阅者只能读，不得回写世界状态**。事件是"世界在说什么"的记录，不是"世界怎么变"的通道。

**D2 世界内部因果 = 声明机制图。**
状态槽位、机制读集/写集/微步/地址是声明数据（机制注册表 + `state_slots.json`）；规则的改动 = 新世界身份（WC-1.3）。

**D3 唯一执行入口 = FrameScheduler。**
世界状态更新只能由**声明的更新点**触发：`register(name, period, callback)`，按注册顺序确定性执行；驱动信号来自时钟 `tick/skip`，不经世界树事件。每个更新点每次推进至多触发一次；跨多边界（快进）由系统按**状态游标**补齐（义务即槽位，WC-3.3）。

**D4 因果量 vs 观测事件。**
可能的"因"是**声明量**（节点/场/参数）与由它们派生的观测；未来智能体感知走观测协议 G（帧边界、可见性/量化），行动经声明注入点写入。事件订阅不作为因果入口。

**D5 帧失败语义。**
一次推进批次是一个帧事务：任一更新点抛错即整帧回滚（影子写入丢弃、本批边界恢复），记录回调只在提交成功后执行——回滚的帧与提交失败的帧都**不留事件**。**首次失败在下一帧重试；连续失败按指数退避节流**（2 的幂次 tick，上限 64），退避窗口内推进直接跳过（不执行、不重抛）：持久失败的世界停步可见、重试代价可控，仅在首次与 2 的幂次失败时记一条 WARNING 汇总。时钟层逐回调隔离异常（`WorldClock.tick`）不变：单点失败不阻断其它时钟回调；观察缓存（天气等级/昼夜/核集合/观察域）与事件一并挂帧事务，回滚的帧不推进缓存，重试不丢事件。
