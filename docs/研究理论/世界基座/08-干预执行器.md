# 世界基座 08：干预执行器

> 记号按[工程符号体系](../工程符号体系.md) §5 与[第一阶段实施定义](../第一阶段实施定义.md) §7。
> 干预执行器（intervention executor）是研究者/研究 API 对世界施加干预的工程入口。

## 1. 定位

本篇对应 issue #46 的 P2 交付：**干预执行器**（`backend/ascend/causal/intervention*.py`，
终端 `do` 指令组 + net `research_*` 研究 API + 天气引擎挂载点）。
它把一次干预（do）形式化为一条不可变**干预记录**（`InterventionRecord`），登记进
**干预表**（`InterventionTable`，单一事实源），在节点/参数求值点按固定规则替换生成。

与 P1 的关系（[世界基座 07](07-机制注册表.md)）：注册表是不可变声明；
干预执行器以注册表为**挂载点**——覆盖感知求值器（`InterventionEvaluator`）包裹
`ASCEND_MECHANISMS`，在求值点按 (目标, 实例, tick) 解析并替换。

两条正交声明决定一次干预能否登记：

| 声明 | 含义 | 事实源 |
| --- | --- | --- |
| `AccessPolicy.interventions` | 世界语义上是否允许该类干预 | 节点声明（`mechanisms.py` 的 `_access_for`） |
| `registry.wired_nodes` / `wired_parameters` | 当前引擎是否真的执行该生成点 | `causal/world.py` 的 `WIRED_NODES`（漂移巡检锁死） |

**两者都必须满足**。已声明但未接线的分量会被**拒绝登记**（fail-closed），
不再出现"登记成功却永不生效"的静默无效干预。

## 2. 干预的两轴模型（替换规格 × 时长）

干预执行器按**替换规格 × 时长**两正交轴建模：

| 替换规格（rep） | 时长（duration） | 语义 |
| --- | --- | --- |
| value（换常数） | 1（帧） | 节点干预：只替换一次生成结果，断入边 |
| value（换常数） | >1（窗口） | 持续干预：窗口 `[t0, t0+dur)` 内逐帧替换，窗口结束自然演化 |
| value（换常数） | None（长期） | 持续钉住直至被替换/清除 |
| mechanism（换公式） | 默认 None（长期） | 机制干预：自生效帧起用新公式 $f'$ |
| parameter（换参数） | None（长期） | 参数干预：环境变化，独立报告 |

合法组合由 `causal/intervention.py` 的 `_DURATION_RULES` **一处声明**，
校验只查该表：

| (目标空间, 替换规格) | 允许的时长类别 |
| --- | --- |
| (node, value) | single / window / forever |
| (node, mechanism) | forever / window（缺省 forever） |
| (parameter, value) | forever |
| (field_feature, value) | forever |

- 节点干预 ≡ 持续干预时长=1 的特例（Lean 定理 `persist_one_eq_nodeDo` 同义，
  Python 侧 `test_lean_persist_one_eq_node_do` 显式对拍）。
- 目标空间：`node` / `parameter` / `field_feature`（统一天气场特征核控制桥接，
  仅 value，且只经 `WeatherEngine.force_feature` 写入）。

## 3. 优先级与重叠（固定规则，无人工数字）

研究者**原子序列执行**干预，重叠规则硬编码，校验通过即无歧义：

1. **后到覆盖先到**：同一 (目标空间, 目标, 实例, 替换规格) 后登记替换先登记。
2. **数值 > 机制**：同一节点同时存在活跃值覆盖与机制覆盖时，值覆盖优先
   （值影响范围小于公式）。
3. **参数空间独立**：环境变化作用于参数槽位，不与节点空间冲突。

## 4. 记录字段与执行前校验

`InterventionRecord`：`target_space / target / instance / rep / value / mechanism /
frame_t0 / duration / version / applied_at / seq`。

- `applied_at` / `seq` 由 `InterventionTable.commit` **盖章**（`applied_at` 取自
  构造时注入的世界时钟，`seq` 为表内自增），构造方无法设置——登记时刻
  只可能有一个来源。
- `environment_change` 不是字段而是派生属性（`target_space == "parameter"`），
  不存在"参数干预未标记"的可能。
- 帧基准为时间模块 tick；终端 `do` 与 net API 的缺省解析共用
  `InterventionTable.default_frame()`（下一 tick）与 `default_duration()`。

执行前校验（第一阶段实施定义 §7 六条，全部 fail-closed）：

- 目标分量/参数已声明，且**在当前引擎求值点上**（未接线即拒绝）。
- 替换值属声明值域（复用注册表 `require_node_value` / `require_parameter_value`）。
- 生效帧/时长合法，且时长类别属于 `_DURATION_RULES` 的允许集合。
- 目标允许该种干预（`AccessPolicy.interventions`：value 单帧→`node`、
  value 窗口/长期→`persistent`、mechanism→`mechanism`；参数→`intervention_allowed`）。
- **目标实例存在**：实例域形状匹配（`global_singleton` 空元组 / `spatial_field`
  整数 (cx, cy)），并经世界句柄校验实例真实存在（chunk 已注册）。
- 读出分量保护：`readout` 与 `slice_boundary` 节点**不得声明干预权限**
  （注册表 C0 声明期不变量；登记时按声明拒绝）。
- 参数干预自动派生 `environment_change=True`。

## 5. CRN 随机流契约

- **值覆盖整段不消费**：被替换方程绑定的随机地址从不被抽取（保留）。
- **机制覆盖**：替换机制可复用原机制地址、可新增**全新地址**（身份派生、
  抽取顺序无关，新地址不影响任何无关流）；**禁止**与无关机制声明的随机源
  重叠（`shared_by` 声明的共享除外）。
- C1 见证评估对未显式给定上下文的随机源使用占位值 0.5；见证可用
  `DependencyWitness.random_values` 显式指定随机上下文，避免"父依赖恰好
  在占位值处抵消"的误拒（`TestWitnessRandomContext` 已对拍）。带随机源的
  机制因此可以声明并通过 C1——CRN 契约可在真实注册表上验证，不再依赖桩对象。
- 验收由 `InterventionFrameExecutor.drawn`（已消费随机地址集合）直接断言：
  值覆盖帧不出现该源、机制覆盖只出现替换机制声明的源。

## 6. 生产接线

```
干预表 InterventionTable（单一事实源）
   ├──→ weather_engine.evaluate_node（查询/事件唯一求值入口）
   │      ├─ _tick_context 全局实例（tick 派生 7 节点）
   │      ├─ _compute_params chunk 实例（13 节点）
   │      └─ region_tracker 注入回调（降水阈值 / 强度，与查询路径同一点）
   ├──→ force_feature：登记 field_feature 干预 + 特征核注入/移除
   ├──→ 终端 do 指令组（do value/mech/param/clear/list）
   └──→ net 研究 API（research_do / research_do_clear / research_do_list）
```

- **单一求值点（查询 / 事件路径）**：tick 派生、chunk 查询期合成与
  `region_tracker` 事件判定都经 `WeatherEngine.evaluate_node`（后者以该入口
  为注入回调），`field.py` 的降水阈值/强度包装函数已删除——同一节点在任何
  **查询/事件**消费路径上只有一个求值实现。chunk 派生基线（`register_chunk`
  → `derive.py`）仍直连注册表且未接线，见 §9。
- **单一事实源（特征核）**：`force_feature` 的 no-op 判定与解除只看注入核
  （`features.get_injected`），记录仅作校验/历史；强制核 `duration=None`
  与记录的"长期"语义一致，核不会先于记录过期。
- **撤销语义**：`clear` 返回实际清除的替换规格元组，`rep=None` 清空该键
  全部规格（值 + 机制），终端 `do clear ... [rep ...]` 与 net API 一致。
- **同源原则**：终端 do 与研究 API 落进同一干预表（同一校验、同一历史、
  同一缺省）；`space="feature"` 的 API 请求转发到 `force_feature`，与终端
  `weather set` 同一写入路径。
- 过去时刻查询按干预记录窗口确定性解析（无需重放）。

## 7. 接口契约（终端 `do` / 研究 API）

两个入口共用同一干预表、同一校验、同一缺省解析（下一 tick 生效；值干预缺省
单帧、机制干预缺省长期）。

**终端 `do`**（`backend/ascend/terminal/intervention_commands.py`）

| 指令 | 语义 |
| --- | --- |
| `do list` | 当前有效干预（目标、生效窗口、序号） |
| `do value <node> <value> [cx cy] [at T] [dur N]` | 值干预 |
| `do mech <node> <mechanism_id> [cx cy] [at T] [dur N]` | 机制干预 |
| `do param <parameter_id> <value> [at T]` | 参数干预（环境变化，长期） |
| `do clear <node\|param\|feature> <target> [cx cy] [rep value\|mechanism]` | 清除；`rep` 仅 node，缺省清空该键全部规格 |

值按目标声明值域解析：`integer`/`float` 转数值，`enum` 按 `choices` 元素类型
解析（整数枚举用整数，如 `weather.tick.season` 取 0–3），其余保持文本；
未识别或多余的参数一律报错。

**研究 API**（`backend/ascend/net/handlers/research_handler.py`）

| 请求 | 载荷 | 成功响应 |
| --- | --- | --- |
| `research_do` | `{space, target, instance, rep?, value / mechanism_id?, frame_t0?, duration?, version?}` | `{success, record}` |
| `research_do`（`space="feature"`） | `{space, target, instance, value:{active}}`，其余字段一律拒绝 | `{success, changed}` |
| `research_do_clear` | `{space, target, instance?, rep?}`（`rep` 仅 node） | `{success, cleared:[...]}` |
| `research_do_list` | — | `{snapshot, history}` |

字段校验全部 fail-closed：`instance` 必须是列表/元组（`null` 视作空元组），
`rep` 必须是 `value|mechanism`，非法输入一律返回 `{success: false, error}`，
不抛异常；`record` / `history` 为 `InterventionTable.record_plain` 的可序列化视图。

## 8. 验收与 Lean 对拍

- **W1**（04 §3.2）：研究切片 rt→med→out+ind 上节点干预——干预分量等于指定值、
  原父引用（rt、U_med）切断、后代用干预值演化（out=m+U_out）、非后代逐位不变；
  CRN 由带真实外生源的切片断言"值覆盖帧不消费随机地址"。
- **W2**（04 §3.3）：同一分量 x_{t+1}=x_t+1 分别执行 值(1帧)/值(2帧)/机制(+100)，
  三条轨迹互异且可手算（10,11,12 / 10,10,11 / 100,200,300）。
- **Lean 对拍**（`InterventionTypes.lean`，全部逐数值对上）：
  - `persist_window_one` / `persist_one_eq_nodeDo`：时长 1 的持续 ≡ 节点。
  - `nodeDo_before_eq_traj`：干预帧之前轨迹与基线一致。
  - `mechDo_same_eq_traj`：$F'=F$ 时与无干预一致（替换惰性）。
  - 数值见证 `nodeDo_t1=10 / nodeDo_t2=11 / persist2_t2=10 / persist2_t3=11 /
    mech_t1=100 / mech_t2=200`。
  - Lean 无对应声明、因此**不对拍**的部分：数值优先于机制的优先级、参数空间
    独立、长期钉住的 `duration=None`（Lean 只有 nodeDo/persist/mechDo）、实例维度。

## 9. 边界与遗留

- **不存档**：干预表是运行时状态，P4 完整存档（含注入核）时随 $\mathcal W_t$
  序列化；本期重开游戏干预状态丢失（明确接受）。
- **生效范围 = `WIRED_NODES`**：只有列在 `causal/world.py::WIRED_NODES`
  的 20 个节点可被干预（tick 派生 7 + chunk 查询期 13）。其余 **27** 个已声明
  节点登记会被拒绝：chunk 派生基线 **12**、`weather.field.*` 边界分量 5、
  `weather.instant.precipitation_type` 1（由 UI/瓦片层经 `derive.precip_type_for`
  消费，不在干预切片内）、`world.clock.tick` 1、世界生成层 8（biome / climate_zone /
  altitude / 5 个噪声）。`WIRED_NODES` 与源码求值点的漂移由单测巡检锁死。
- **参数可达性**：`registry.wired_parameters` 由"被已接线机制绑定的参数"派生，
  无独立声明；仅被未接线机制消费的参数（如 `weather.parameter.latitude.*`）
  登记会被拒绝。
- **机制干预的生产可达性**：注册表 C0 强制"节点单写者"，当前生产无第二公式
  可替换——生产 `do mech` 只能登记恒等替换（F'=F，Lean `mechDo_same_eq_traj`
  语义）；真正的公式替换由研究切片 runner（`InterventionFrameExecutor`，W1/W2）完整
  验证，待注册表开放多机制后生产生效。
- **行动干预 do(A=a')（智能体决策替换）**：不属于本期，留智能体/多智能体层。
- **统一天气场内部机制、大陆/水文/河流/瓦片算法管线**：仍为 slice_boundary
  边界输入，未登记；对它们的干预不在本期范围（边界分量不声明干预权限）。
- **持续/机制干预的多节点 SCM/DAG 层 Lean 证书**：Lean 现有 `subSCM` 仅覆盖
  节点干预（换常数方程）；持续/机制的多节点证书留待后续 Lean 扩展。
- **P3 研究 trace / P4 完整存档 / P5 统一验收 runner**：干预表已保留完整历史
  （`history` / `research_do_list` 返回 `history`，含 seq/applied_at）为 P3/P4 就位；
  批量原子干预计划、假设求值（不落表的对照臂）留待 P3。
