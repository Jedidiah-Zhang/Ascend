# 世界基座 07：因果机制注册表（声明单一事实源）

## 1. 定位

本篇对应 issue #46 的 P1 交付：**机制注册表**（`backend/ascend/causal/`）。
它把[第一阶段实施定义](../第一阶段实施定义.md) §2 的声明契约变成可执行的数据结构：
声明不再是研究侧的平行文档，而是生产求值的唯一事实源。

```
全局机制注册表 ASCEND_MECHANISMS（backend/ascend/causal/world.py 组装）
   ├── 声明片段：weather/mechanisms.py（天气全部标量公式）
   │            + space/mechanisms.py（世界生成公式链）
   ├──→ 生产求值（derive.py / weather_engine._compute_params /
   │    climate.py 委托 evaluate，输入/输出按声明值域 fail-closed 校验）
   ├──→ 声明快照（确定性序列化，declaration hash 稳定）
   │        → research/equations/equations.json（自动生成，禁止手改）
   │        → gen_lean.py → GenDeclarationData.lean → Lean 对账定理
   └──→ 构造期验收：C0 声明完整性 + C1 结构最小性（见证实测重跑）
```

后续 P2 干预执行器、P3 研究 trace、P4 完整存档均以本注册表为挂载点。

## 2. 数据契约

全部规范类 `frozen dataclass`（`backend/ascend/causal/spec.py`），
注册表构造后不可变（属性赋值抛 `AttributeError`）。

| 类 | 职责 | 对应实施定义条款 |
| --- | --- | --- |
| `NodeSpec` | 内生变量模板：角色（机制状态/持久状态/读出量）、实例域、值域（类型/单位/界/量化/缺失）、状态归属与重建规则、更新微步与携带规则、干预/追踪/观测权限、误差元数据 | §2 表格 14 项 |
| `ParentSpec` | 结构父模板：lag、源微步、空间偏移、实体关系、聚合/广播/边界算子、guard、Lipschitz 常数、分析角色 | §5 空间声明 |
| `ParameterSpec` | 环境参数：类型/单位/界/当前值/版本/可否环境干预/来源 | §2 参数条款 |
| `ExogenousSourceSpec` | 原始随机源：分布、抽取微步、实例索引、地址模板、共享关系（首批切片无外生源，接口已就绪） | §6 随机源声明 |
| `MechanismSpec` | 可执行方程：函数 + 显式父/参数/随机绑定 + 边界情况 + C1 见证 | §2 结构方程 |
| `DependencyWitness` | C1 功能依赖见证：固定上下文，仅替换一个父值，输出必须改变 | 04 篇 C1 |

**关键语义**：

- **执行角色与解释标签分离**：求值边一律 `structural`；物理反推解释
  （如海面温度→纬度代理）只存 `analysis_role` 元数据。
- **fail-closed**：C0 任何字段只能显式填写或由已文档化规则唯一推出；
  `evaluate` 拒绝多余/缺失父值、越出声明值域、bool 冒充数值、NaN/Inf。
- **值域诚实化**：大陆校准拉伸后的年均温/年降雨/海拔**无先验闭界**，
  相应声明为 `bounds=None`（显式无界有限值域）并在 `valid_domain` 说明；
  无界不是漏声明，而是校准语义本身的属性。
- **方程版本三层次**：`equation_version` = 方程函数与显式依赖的摘要——
  Python 可调用对象哈希源码，C 实现/数据文件（`_hydrology.c`、`climate.json`、
  `config.py`、`world.json`）作为 `Path` 依赖哈希文件字节；`parameter_version`
  = 参数值 + 来源摘要；`resolved_version` = 方程 + 参数 + 边界组合摘要；
  声明级 `declaration.hash`。无源码环境构造失败（fail-closed）。
- **父微步一致性**：C0 强制父模板 `source_microstep` 等于父节点自身的
  `update.microstep`，且同帧父必须位于更早微步。

## 3. C0/C1 构造期验收

注册表构造即执行全部 C0 校验与 C1 见证**实测重跑**，任何失败直接
`ValueError`——漂移无法在构造后存活。契约测试见
`backend/tests/unit/test_causal_registry.py`（重复声明、签名漂移、
见证陈旧、值域越界、参数类型不符、微步纪律、文件源缺失等负例全覆盖），
另有**独立参考对拍**（测试内手写参考公式逐节点比对注册表链式求值）。

## 5. 快照与防漂移管线

```text
causal/world.py（ASCEND_MECHANISMS）
   │ export_registry.py           .venv/bin/python research/equations/export_registry.py
   ▼
research/equations/equations.json（schema v3，自动生成，禁止手改）
   │ gen_lean.py                  .venv/bin/python research/equations/gen_lean.py
   ▼
research/lean/.../GenDeclarationData.lean（数据段 + 对账定理）
```

- `export_registry.py --check` / `gen_lean.py --check` 两级漂移门禁已接
  CI（watch 路径覆盖 causal/**、weather、space、config、data 文件）；
- 研究侧图投影（`schema.py` v3 加载 `variables/edges`）仅供
  `graph_check.py` / `gen_lean.py` 消费，不反向驱动生产；
- graph_check 阈值随切片扩展重注册（G2 W_MAX=2000，注释记录日期与理由；
  G3 相对预算为绑定判据）。

## 6. 改公式 / 新增机制的流程

1. 改 `weather/mechanisms.py` 或 `space/mechanisms.py` 中对应方程函数
   （必要时更新见证与参数表）；
2. 重跑 `export_registry.py` 与 `gen_lean.py`，提交生成物；
3. 两个 `--check` + `verify_equations.py` + `graph_check.py` + 全量单测全绿。

已登记公式的改动面 = 一个函数 + 见证 + 两个生成物，注册表构造期自动
重跑全部 C1 见证拦截漂移。
