# 世界基座 13：世界程序编译（架构决策）

> **地位**：架构决策记录（ADR）。承接《[12 世界树角色与帧调度](12-世界树角色与帧调度.md)》：执行权只来自声明；本文规定**声明如何编译为可执行程序**。
> **状态**：第一步已生效（波次/内核绑定/更新点/身份 + 程序驱动执行）；后续分期见 §6。

## 1. 核心式子

**运行一个世界 = WorldProgram + 种子 + 初始状态 + 输入时间线。**

程序是声明的编译产物、不可变；编译只依赖声明，不依赖运行实例。这一条式子同时支撑：可复现、可回放、多世界变体（#49）、快照校验与跨平台对拍。

## 2. 编译输入（五类声明）

| 输入 | 来源 | 现状 |
| --- | --- | --- |
| 机制注册表（节点/机制/微步/依赖/版本摘要） | `causal/world.py` 组装的不可变注册表 | 已有 |
| 状态槽位表 | `causal/declarations/state_slots.json` | 已有 |

## 3. 编译产物（WorldProgram）

| 部件 | 内容 |
| --- | --- |
| 波次计划 | 机制按输出节点微步分组；同组无同帧依赖 → 组内可并行、组间有序 |
| 内核绑定表 | 机制 → 参考实现（Python）+ 加速实现位（暂缺，填后须对拍）+ 方程/组合版本摘要 |
| 更新点计划 | 声明序（order 唯一）+ 周期（符号刻度 → tick）+ 写入槽位 |
| 世界身份 | 契约版本 + 四份声明摘要 + 日历刻度 + 波次/内核/更新点的规范摘要（`sha256:`） |

世界身份分两层：`WorldProgram.identity`（程序身份）与 `world_identity(seed)`（世界身份 = 程序 + 种子）。

## 4. 静态校验（编译期 fail-closed）

1. **单写者**：同一输出节点至多一个机制；
2. **同帧依赖序**：以父节点**实际更新微步**为准（并与机制声明的源微步交叉校验），同帧（lag=0）父必须位于更早微步——跨波倒置/环在此拒绝；
3. **更新点 ↔ 槽位互相覆盖（双向）**：`update.stage` 与更新点 id 对齐，且每个 mechanism 槽位必须被对应更新点的 `slots` 收录；`driver_frame_advance` 槽位不得被更新点认领；
4. **周期刻度**：键必须恰为 `game_minute/game_hour/game_day`，值为正整数 tick；
5. 编译两次身份逐位一致（声明不变 → 身份不变）。

## 5. 运行时接入

- 调度器（`runtime/frame_scheduler.py`）只执行程序声明的更新点；
- 装配（`runtime/execution.py`）按声明顺序注册，**绑定缺失或多余一律拒绝**；
- GameEngine 不再手工注册更新点，装配即编译 + 绑定；程序身份随启动日志落账（manifest 入账留 §6）。
