> **地位**：架构决策记录（ADR）。承接《[12 世界树角色与帧调度](12-世界树角色与帧调度.md)》：执行权只来自声明；本文规定**声明如何编译为可执行程序**。
> **状态**：第一至六步已生效（编译产物/帧事务/内核对拍与波次执行器/程序身份入 manifest/⑤a 区域通报观察化/机制图成为唯一执行路径）；⑤b 观测协议元数据见 §6。

## 1. 核心式子

**运行一个世界 = WorldProgram + 种子 + 初始状态 + 输入时间线。**

程序是声明的编译产物、不可变；编译只依赖声明，不依赖运行实例。这一条式子同时支撑：可复现、可回放、多世界变体（#49）、快照校验与跨平台对拍。

## 3. 编译产物（WorldProgram）

| 部件 | 内容 |
| --- | --- |
| 波次计划 | 机制按输出节点微步分组；同组无同帧依赖 → 组内可并行、组间有序 |
| 内核绑定表 | 机制 → 参考实现（Python）+ 加速实现（可缺）+ 方程/组合版本 + 内核版本 |
| 更新点内核 | 更新点锚点 → 参考实现 + 加速实现 + 内核语义版本（如 `terrain.integrate`） |
| 更新点计划 | 声明序（order 唯一）+ 周期（符号刻度 → tick）+ 写入槽位 |
| 世界身份 | 契约版本 + 四份声明摘要 + 日历刻度 + 波次/内核/更新点的规范摘要（`sha256:`） |

**内核对契约**（`causal/kernels.py`）：同一锚点的参考实现与加速实现必须**逐位一致**（bit-identical）；对拍由 `tests/unit/test_kernels.py` 锁定，任何"近似相等"的偏差都是语义漂移，必须改实现而不是放宽容差。机制输出锚点的 `reference` 必须与注册表声明的实现为**同一可调用对象**（注册表是唯一事实源，编译期校验不一致即拒绝）。当前首个内核对为地形状态演化内核（Python 参考 `space/state_reference.py` ↔ C 加速 `space/tile_state.state_evolve_arrays`）。

**波次执行器**（`runtime/wave_executor.py`）：按波次计划求值机制实例——串行按声明序、并行同波并发，结果逐位一致（`tests/unit/test_wave_executor.py` 用真实天气图对拍引擎手工顺序，并断言串行/并行一致）。

世界身份分两层：`WorldProgram.identity`（程序身份）与 `world_identity(seed)`（世界身份 = 程序 + 种子）。

## 4. 静态校验（编译期 fail-closed）

1. **单写者**：同一输出节点至多一个机制；
2. **同帧依赖序**：以父节点**实际更新微步**为准（并与机制声明的源微步交叉校验），同帧（lag=0）父必须位于更早微步——跨波倒置/环在此拒绝；
3. **更新点 ↔ 槽位互相覆盖（双向）**：`update.stage` 与更新点 id 对齐，且每个 mechanism 槽位必须被对应更新点的 `slots` 收录；`driver_frame_advance` 槽位不得被更新点认领；
4. **周期刻度**：键必须恰为 `game_minute/game_hour/game_day`，值为正整数 tick；
5. **内核对**：锚点必须是已声明的机制输出或更新点，锚点唯一，参考实现可调用（机制输出锚点的参考实现须与注册表声明一致），加速实现（若给）可调用；内核语义版本进身份；
6. 编译两次身份逐位一致（声明与内核对不变 → 身份不变）。

## 5. 运行时接入

- 调度器（`runtime/frame_scheduler.py`）只执行程序声明的更新点；
- 装配（`runtime/execution.py`）按声明顺序注册，**绑定缺失或多余一律拒绝**；
- **帧事务**（`runtime/state_store.py`，WC-7.6）：一次推进批次是一个帧事务——更新点在事务内只写影子（`stage`/`stage_apply`），批次末尾 `commit` 在锁内一次性发布；任一更新点抛错则整帧回滚（影子丢弃、本批边界恢复，下一帧重试；连续失败按指数退避节流，见 [12 篇](12-世界树角色与帧调度.md) D5）；记录回调 `stage_after_commit` 只在提交成功后执行，回滚的帧不留事件；提交阶段应用动作抛错时已执行动作不回滚（幂等重放）、本帧记录回调一律不执行（重试帧重新登记）；天气事件与观察缓存（季节/等级/昼夜/核集合/观察域）经此挂入帧事务；事务按线程隔离——tile 生成线程的补齐不并入 tick 批次，各自在自己的边界提交（全局提交锁串行化发布）；
- 跨字段读取方（ChunkStore 序列化状态数组）持 `guard`（提交锁）读取，任何读者只能看到某一已提交版本，不存在半帧；
- 地形积分是首个影子写方：演化写入状态数组副本，提交时 `replace_states` 整组替换 + 游标/脏标记更新；
- **程序身份入 manifest**：世界设置校验在读档最前（先于昂贵的世界生成）比对 manifest 记录的程序身份与当前编译产物，不一致拒绝加载；旧存档未记录时放行并在落盘时补写（与机制声明的既有口径一致）；
- **波次执行器**（`runtime/wave_executor.py`）：机制图求解器——串行按波次声明序、并行同波并发（实例分区）；天气引擎的查询与驱动路径**只经波次执行器**求值（手工顺序已退役，`_tick_context`/`_compute_params` 删除），边界输入（基线/场采样/时钟）由引擎预计算；挂载研究 trace 时自动降级串行（记录顺序确定）；地形侧仍是声明更新点 + 内核对（对拍），一并满足唯一执行路径；
- **区域通报观察化（⑤a）**：降水区域事件改为纯函数 `f(场(t−1), 场(t))` + 观察者声明域（玩家窗口）；气候基线（阈值/强度校准）改纯查询 `space/climate_lookup.py`，与加载集解耦；观察域移动时前后帧各用**当时**的域比较（走入既有雨带 → start，走出 → stop），上一帧域随帧事务推进；域半径是观察层参数（`weather/region_tracker.DEFAULT_REGION_RADIUS`，**不进 config/世界身份**），⑤b 由观测协议元数据接管。
- 编译缓存：生产路径 `get_default_program()` 进程内按身份缓存一次（声明在进程存续期内不可变；测试改写声明后 `cache_clear()`）；
- GameEngine 组装共享同一 `FrameStateStore`（ChunkStore/TileStateEngine/FrameScheduler），世界程序在设置校验前装配。
