# 世界基座 08：神迹系统（干预执行器）

> 记号按[工程符号体系](../工程符号体系.md) §5 与[第一阶段实施定义](../第一阶段实施定义.md) §7。
> 神迹系统是研究者/研究 API 在世界上执行干预的正式名称（"上帝之手"）。

## 1. 定位

本篇对应 issue #46 的 P2 交付：**神迹系统**（`backend/ascend/causal/miracle*.py`，
终端 `do` 指令组 + net `research_*` 研究 API + 天气引擎挂载点）。
它把一次干预（do）形式化为一条不可变**神迹记录**（`MiracleRecord`），登记进
**神迹表**（`MiracleTable`，单一事实源），在节点/参数求值点按固定规则替换生成。

与 P1 的关系（[世界基座 07](07-机制注册表.md)）：注册表是不可变声明；
神迹系统以注册表为**挂载点**——覆盖感知求值器（`MiracleEvaluator`）包裹
`ASCEND_MECHANISMS`，在求值点按 (目标, 实例, tick) 解析并替换。

## 2. 干预的两轴模型（替换规格 × 时长）

原文档的"节点/持续/机制/参数四类平铺"是两正交轴的混写，神迹系统按两轴建模：

| 替换规格（rep） | 时长（duration） | 语义 |
| --- | --- | --- |
| value（换常数） | 1（帧） | 原"节点干预"：只替换一次生成结果，断入边 |
| value（换常数） | >1（窗口） | 原"持续干预"：窗口内逐帧替换，窗口结束自然演化 |
| value（换常数） | None（长期） | 持续钉住直至被替换/清除 |
| mechanism（换公式） | 默认 None（长期） | 原"机制干预"：自生效帧起用新公式 $f'$ |
| parameter（换参数） | None（长期） | 原"参数干预"：环境变化，独立报告 |

- 节点干预 ≡ 持续干预时长=1 的特例（Lean 定理 `persist_one_eq_nodeDo` 同义）。
- 目标空间：`node` / `parameter` / `field_feature`（统一天气场特征核控制桥接，
  仅 value）。

## 3. 优先级与重叠（固定规则，无人工数字）

研究者**原子序列执行**干预，重叠规则硬编码，校验通过即无歧义：

1. **后到覆盖先到**：同一 (目标空间, 目标, 实例, 替换规格) 后登记替换先登记。
2. **数值 > 机制**：同一节点同时存在活跃值覆盖与机制覆盖时，值覆盖优先
   （值影响范围小于公式）。
3. **参数空间独立**：环境变化作用于参数槽位，不与节点空间冲突。

## 4. 记录字段与执行前校验

`MiracleRecord`：`target_space / target / instance / rep / value / mechanism /
frame_t0 / duration / version / environment_change / applied_at / seq`。
帧基准为时间模块 tick；终端 `do` 缺省"下一 tick 生效"，也可显式 `at <tick>`。

执行前校验（第一阶段实施定义 §7 六条，全部 fail-closed）：

- 目标分量实例存在（节点/参数未声明即拒绝）。
- 替换值属声明值域（复用注册表 `require_node_value` / `require_parameter_value`）。
- 生效帧/时长为合法 tick。
- 目标允许该种神迹（`AccessPolicy.interventions`：value 单帧→`node`、
  value 窗口→`persistent`、mechanism→`mechanism`；参数→`intervention_allowed`）。
- 重叠规则固定（见 §3），无歧义。
- 读出分量保护：`readout` 与 `slice_boundary` 节点不可独立干预
  （`mechanism_state`/`persistent_state` 且 `origin=mechanism` 才可）。
- 参数神迹自动标记 `environment_change=True`（环境变化）。

## 5. CRN 随机流契约

- **值覆盖整段不消费**：被替换方程绑定的随机地址从不被抽取（保留）。
- **机制覆盖**：替换机制可复用原机制地址、可新增**全新地址**（身份派生、
  抽取顺序无关，新地址不影响任何无关流）；**禁止**与无关机制声明的随机源
  重叠（`shared_by` 声明的共享除外）。
- 生产切片当前 `random_sources=()`，契约由 W1 CRN 测试 + 校验锁死。

## 6. 生产接线

```
神迹表 MiracleTable（单一事实源）
   ├──→ weather_engine：MiracleEvaluator 按 (节点, chunk, tick) 覆盖求值
   │      （_tick_context 全局实例；_compute_params chunk 实例）
   ├──→ force_feature：登记 field_feature 神迹 + 特征核注入/移除（薄封装）
   ├──→ 终端 do 指令组（do value/mech/param/clear/list）
   └──→ net 研究 API（research_do / research_do_clear / research_do_list）
```

同源原则：终端 do 与研究 API 落进**同一神迹表**（同一校验、同一历史），
前端控制台只是 UI 壳（未知指令原样转发 `terminal_cmd`），无需改动。
过去时刻查询按神迹记录窗口确定性解析（无需重放）。

## 7. 验收与 Lean 对拍

- **W1**（04 §3.2）：研究切片 rt→med→out+ind 上节点神迹——干预分量等于指定值、
  原父引用（rt、U_med）切断、后代用干预值演化（out=m+U_out）、非后代与无关源
  逐位不变、停止消费随机值后无关地址不漂移。
- **W2**（04 §3.3）：同一分量 x_{t+1}=x_t+1 分别执行 值(1帧)/值(2帧)/机制(+100)，
  三条轨迹互异且可手算（10,11,12 / 10,10,11 / 100,200,300）。
- **Lean 对拍**（`InterventionTypes.lean`，全部逐数值对上）：
  - `persist_window_one` / `persist_one_eq_nodeDo`：时长 1 的持续 ≡ 节点。
  - `nodeDo_before_eq_traj`：干预帧之前轨迹与基线一致。
  - `mechDo_same_eq_traj`：$F'=F$ 时与无干预一致（替换惰性）。
  - 数值见证 `nodeDo_t1=10 / nodeDo_t2=11 / persist2_t2=10 / persist2_t3=11 /
    mech_t1=100 / mech_t2=200`。

## 8. 边界与遗留

- **不存档**：神迹表运行时状态，P4 完整存档（含 `_injected`）时随 $\mathcal W_t$
  序列化；本期重开游戏神迹丢失（明确接受）。
- **生效范围**：神迹只在**接线求值点**生效——weather_engine 的 tick 派生与
  instant 合成/天文求值路径（按 (节点, chunk, tick) 解析）。chunk 派生层的
  持久化基线（`register_chunk` 时落盘的振幅族等）与世界生成层（climate.py）
  本期未接线：登记成功的这类节点不产生效果（占位声明），需 P4/P5 接线下游
  或重派生。已清除/被替换的神迹不参与过去查询回溯（过去查询按当前有效记录
  的窗口确定性解析）。
- **机制神迹的生产可达性**：注册表 C0 强制"节点单写者"，当前生产无第二公式
  可替换——生产 `do mech` 只能登记恒等替换（F'=F，Lean `mechDo_same_eq_traj`
  语义）；真正的公式替换由研究切片 runner（`MiracleFrameExecutor`，W1/W2）完整
  验证，待注册表开放多机制后生产生效。
- **force_feature 双轨时长**：神迹记录 `duration=None`（长期），注入核
  `duration=10×GAME_YEAR` 会自然过期——核过期后 `do list` 仍显示活跃，需
  `do clear` 后再激活；非新回归（旧 `has_injected` 同样不过期判断），P4 存档
  化时统一为记录驱动。
- **行动干预 do(A=a')（智能体决策替换）**：不属于本期，留智能体/多智能体层。
- **统一天气场内部机制、大陆/水文/河流/瓦片算法管线**：仍为 slice_boundary
  边界输入，未登记；对它们的干预不在本期范围。
- **持续/机制干预的多节点 SCM/DAG 层 Lean 证书**：Lean 现有 `subSCM` 仅覆盖
  节点神迹（换常数方程）；持续/机制的多节点证书留待后续 Lean 扩展。
- **P3 研究 trace / P4 完整存档 / P5 统一验收 runner**：神迹表已保留完整历史
  （`history`，含 seq/applied_at），为 P3/P4 就位。
