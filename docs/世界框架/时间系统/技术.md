# 时间系统 — 技术

## 时钟实现

以 **tick** 为原子时间单位，时钟频率 **24Hz**（1 真实秒 = 24 tick）。所有时间状态（`clock.time`）均为整数 tick 计数。

### 时间常量（`olam/constants.py`）

```python
GAME_MINUTE = 120        # 1 游戏分钟 = 120 tick（5 真实秒）
GAME_HOUR   = 7200       # 1 游戏小时 = 7200 tick
GAME_DAY    = 172800     # 1 游戏天 = 172800 tick（2 真实小时）
GAME_YEAR   = 62208000   # 1 游戏年 = 360 天
```

## WorldClock API（`olam/runtime/clock.py`）

时钟是运行时的**逻辑时间源**（驱动层）：只提供 tick 推进与回调分发，
不承载世界语义、不发布世界树事件。

```python
from olam.runtime import WorldClock, tick_to_hms

clock = WorldClock()          # 默认 epoch = 6 * GAME_HOUR（上午 6 点）
clock.time                    # int,   当前世界时间（tick）
clock.speed                   # float, 时间倍率（≥0，1=正常）
clock.paused                  # bool,  是否暂停（只读）
clock.tick_count              # int,   累计时间推进操作次数（见说明）

clock.game_days()             # float, 已经过的游戏天数
clock.game_years()            # float, 已经过的游戏年数
```

> **`tick_count` 语义**：这是"推进操作次数"，不是"世界实际经过的 tick 数"。`speed=2` 时一次 `tick()` 推进 2 tick 但 `tick_count` 只 +1。要获取世界实际经过的 tick 数请用 `time` 属性。

### 信号分发：直接回调，不经过 WorldTree

高频 tick 信号通过直接回调分发，避免每帧淹没 WorldTree。帧调度器
（`FrameScheduler.bind_clock`）据此按声明周期驱动世界更新；表现层
观察者据此本地派生边界。

```python
unsub_tick = clock.on_tick(lambda game_time: ...)
unsub_skip = clock.on_skip(lambda skipped, game_time: ...)

unsub_tick()   # 取消订阅，幂等
unsub_skip()
```

- `on_tick(cb)`：每 tick 调用 `cb(game_time: int)`，返回 unsubscribe 函数
- `on_skip(cb)`：跳转时调用 `cb(skipped: int, game_time: int)`，返回 unsubscribe 函数

### tick() — 每帧推进

```python
clock.tick()  # 由 GameEngine 每帧调用，无参数
```

- 暂停或 speed≤0 时不推进
- 使用浮点累加器：每帧累加 `speed`，整数部分为推进 tick 数
- 每帧最多触发 1 次 on_tick 回调（无论推进多少 tick）
- 例：speed=0.5 时每 2 帧推进 1 tick

### run_to(target) — 批量模拟

```python
clock.speed = 120              # 设置高速
clock.run_to(clock.time + 3 * GAME_DAY)  # 模拟 3 天
```

- 以当前 speed 逐 tick 推进到目标时间
- 期间每个中间 tick 正常触发 on_tick 回调（世界周期更新与观察者
  边界检测均按 tick 逐次发生）
- 完成后恢复原始暂停状态
- target 必须在当前时间之后，否则抛出 ValueError
- 暂停状态请用 `resume()` 或 `step()`，瞬跳请用 `skip()`

### skip(ticks) — 瞬间跳转

```python
clock.skip(30 * GAME_DAY)      # 瞬间跳 30 天，不模拟中间过程
```

- 直接增加时间，触发 1 次 on_skip 回调（携带 skipped、game_time）
- 不补发中间边界：世界机制按"义务即状态"（WC-3.3）以状态游标自行
  补齐，观察者按本地游标比较前后时刻
- ticks 必须 > 0

### step() — 调试单步

```python
clock.step()                   # 强制 1 tick，忽略暂停和 speed
```

- 调试/终端手动控制用
- 正常游戏循环不应调用

## 时刻派生（无日历组件）

日/时/分等时刻量全部由 `clock.time` **纯函数**派生，不保存游标、
不发布世界事件：

```python
from olam.constants import GAME_DAY
from olam.runtime import tick_to_hms

day = clock.time // GAME_DAY + 1                 # 当前游戏日（从 1 开始）
elapsed_days = clock.time // GAME_DAY            # 经过天数
hour, minute, second = tick_to_hms(clock.time)   # 当日时刻
```

- **世界内时间量**由声明机制从 `world.clock.tick` 派生（如
  `olam/modules/weather/module.py` 的 `weather.tick.hour_of_day` /
  `day_of_year` / `season` 等 derived 槽位），世界推进由
  `FrameScheduler` 按声明周期（`minute` / `hour` 更新点）驱动；
- **需要日/时边界的世界机制**：在 `olam/modules/` 声明周期更新点
  （`period = GAME_DAY` 等）或事件门控，不引入日历组件；
- **表现层边界通知**：自行按"上一观察时刻 → 当前时刻"本地比较
  （观察游标，非世界状态）。

## 表现层时间同步（time_sync）

前端时间显示 / 昼夜光照 / TPS 估算 / 事件日志日期分隔由引擎的
`time_sync` 消息驱动（跨游戏分钟边界广播一次）：

```json
{
  "type": "event",
  "event_type": "time_sync",
  "payload": {
    "timestamp": 360000,
    "game_hour": 2,
    "game_minute": 0,
    "data": {"day": 3, "game_time": 360000}
  }
}
```

- 世界外元操作：直接经服务器广播，**不进世界树**——时间边界是派生
  观察量，不是因果事件；
- 由 `GameEngine._sync_time_broadcast` 在 tick 循环中发送（读档/跳转
  后按当前时刻重同步）。

## 性能

- **实时 tick**：24Hz 累加器，每帧运算为一次浮点加法 + 一次整数截断 + 一次回调遍历，开销极低
- **run_to 模拟**：speed=120 时 3 游戏天约 4320 次 tick，纯回调驱动，毫秒级完成（注：`run_to` 为时钟原语，当前无游戏侧调用方）
- **skip 跳转**：O(1)，仅一次回调（不补发中间边界）

## 整合点

### WorldClock — 依赖

WorldClock 是纯计时器：只依赖 `olam.constants`（时间刻度）与标准库
logging，不 import 事件总线、实体管理等任何运行时服务。通过
`on_tick` / `on_skip` 回调列表向订阅者分发高频 tick 信号。

### WorldClock — 被依赖

| 调用方 | 方式 | 调用的方法 / 属性 |
|--------|------|------------------|
| **GameEngine** (`miskhak/app.py`) | 直接构造，持有引用 | `WorldClock()`、`tick()`（每帧）、`pause()`/`resume()`、`paused`、`time` |
| **FrameScheduler** (`olam/runtime/driver.py`) | 构造注入 | `clock.on_tick(...)`、`clock.on_skip(...)`（`bind_clock`） |
| **WeatherEngine** (`olam/adapters/weather/weather_engine.py`) | 构造注入 | `clock.time`（读取当前 tick 数，计算季节、昼夜、大气漂移） |
| **CommandExecutor** (`miskhak/terminal/executor.py`) | 构造注入 | `clock.time`、`clock.speed`、`clock.paused`、`clock.step()`、`clock.skip()` |
| **PlayerService** (`miskhak/entity/player.py`) | 构造注入 | `clock.time`（记录操作时间戳） |
| **研究探针**（`kheker/historical/`） | 直接构造 | 构造时钟并手动推进 |

### 间接消费

- **EventBridge**：通配符订阅 `*`，转发世界树事件到 Godot 前端（事件
  载荷附 `game_hour` / `game_minute` 换算）
- **前端**：`time_sync` 消息驱动时间分区 / TPS 推算 / 日期分隔线
- **未来模块**（群体/生态/心智）：需要日更结算时声明周期更新点
  （`period = GAME_DAY`），不订阅时间边界事件
