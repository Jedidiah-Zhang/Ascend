# 地图生成 — 技术

## 双层架构

世界地图分两层生成，层 1 是低分辨率宏观场，层 2 是玩家活动粒度的详细 tile。

```
层1 宏观场（100m/格，1000×600）          层2 详细 tile（1m/格，200×200/chunk）
─────────────────────────────────       ─────────────────────────────────────
  ContinentGenerator.generate()            TileGenerator.generate_chunk(cx,cy)
  ├─ 海拔（Perlin + 分位数校准）             ├─ 从层1双线性采样宏观海拔（÷100 换算）
  ├─ 气候（纬度温度 + 降雨 + 雨影）         ├─ 叠加高频细节噪声(±50m)
  ├─ 侵蚀（10轮，降雨驱动，C加速）          ├─ 按海拔带分类 TerrainType
  │   → DEM + D8流向 + 流量累积 + 沉积       ├─ 叠加河流(render_river_chunk)
  ├─ 湖泊盆地（填洼差>1m的洼地）            └─ 叠加湖泊(render_lake_chunk)
  ├─ 河流网络（三级方向场RK4积分）
  └─ 河流宽度场（log(流量)）
```

层 1 一次生成整个大陆（约 5-30s），存于 `ContinentData`；层 2 按 chunk 请求时从层 1 采样现算，可并行。坐标换算：宏观场 1 格 = 100m = 100 tile，tile 坐标 (cx*200+tx, cy*200+ty) 采样宏观场格索引 (cx*2+tx/100, cy*2+ty/100)（`sample_altitude` 系列 ÷ 100）。

## 层 1 宏观场生成（ContinentGenerator）

`ContinentGenerator(seed).generate()` 产出 `ContinentData`，管线顺序：

1. **海拔 + 陆地掩码**：双层 Perlin（低频大陆轮廓 0.7 + 高频细节 0.3 + 中心倾向），分位数校准到 `land_ratio`（默认 0.55 = `config.CONTINENT_LAND_RATIO` 单一事实来源，创建世界调参可覆盖，见下节），海平面 = `(mixed - sea_level) × 4000`
2. **海拔校准**：拉伸 P90-P99 段保证陆地 P99 ≥ 2500m（高山存在）
3. **气候**：纬度梯度 + Perlin 摆动 → 海平面温度；Perlin → 降雨；雨影因子（双风向混合 + 水分预算追踪）；气温直减率（仅作用于陆地）；大陆度修正（距海越远越冷）
4. **降雨/温度交叉校准**：保证沙漠（<200mm）、热带（≥20°C）、极地（<-5°C）覆盖
5. **侵蚀**（`erode()`，C 加速）：10 轮迭代，每轮 填洼→D8→累积→侵蚀步。侵蚀公式 `K × flow^0.5 × slope`，质量守恒（上游侵蚀、下游沉积）。自适应收敛 `max_delta < tolerance` 提前退出
6. **水文提取**：从侵蚀结果提取河流树（D8 拓扑 + Strahler 分级）、湖泊盆地（填洼差>1m 的连通分量）、河流网络（见下节）
7. **河流宽度场**：`width = min + (max-min) × log(1+ratio×20)/log(21)`，基于 log(流量)

### 地形预览（创建世界调参，Issue #8）

创建世界流程的地形调参需要秒级反馈，走 `ContinentGenerator.generate_preview()`：与完整管线共用同一噪声场，但只做**海拔 + 陆地掩码**两步粗采样（分辨率 1000m/格，尺寸 = km 数），跳过侵蚀与水文 → 秒级返回海拔缩略图 + 实测陆地占比。预览与真实世界略有偏差（未侵蚀），仅作形状与占比参考；同 (seed, land_ratio, 尺寸) 预览完全确定。尺寸变化是**延伸而非缩放**（同一噪声场的更大取样窗口）。参数范围契约单源在 `manifest.py`（`SEED_MAX`/`LAND_RATIO_MAX`/`SIZE_KM_MIN`/`SIZE_KM_MAX`），`map_preview` 请求与 `save_create` 校验共用。

**气候图层（温度/降雨/气候带视图）**：请求可带 `layers: ["temp", "rain", "climate"]`（缺省仅海拔，向后兼容；非法图层名/非数组拒绝）。气候在海拔后补跑与完整管线同序的计算——`_compute_climate`（纬度梯度 + 雨影 + 大陆度）→ `_calibrate_climate_merged` → `_inject_missing_climates`——返回 `temperature`（int °C）/ `rainfall`（int mm/年）/ `climate`（int 0-7 档）行优先数组，与海拔同网格。**海拔快照在气候层之后**（与完整管线同序）：兜底注入抬升的个别高山像素同样反映在海拔视图，海拔/气候层自洽。侵蚀/水文依旧跳过：气候只是 4 个噪声八度 + 数次 O(N) 校准遍历（默认 100×60km = 6000 格，最大 200×200km = 40000 格），大图全图层约 20ms，秒级反馈不受影响。预览气候与最终世界一致（侵蚀只改海拔不重算温雨场）。前端切换视图仅换着色函数、零往返；响应缺图层字段（旧后端）时自动降级仅地形视图。

**温度/降雨为海陆全域场**：`temperature` 为**地表温度**——海域 = 海面温度（C 端纬度梯度场，clamp [-20, 38]，直减率仅作用于陆地，负海拔不产生伪影）；陆地 = 海面温度 − 海拔×直减率 − 大陆度修正。生产链路的 `sea_temp` 与预览海域同源（`temp + max(0, alt)×直减率`，海域 alt<0 时即地表温度），逐点严格比对。`rainfall` 为噪声场全域值；`climate` 档位仅陆地有意义（海域未校准），前端气候视图海域保持深蓝。前端温度/降雨视图海域显示数值（`_cell_color`），地形视图海域保留深度渐变。

### 河流网络生成（streamlines.py）

`build_river_network()` 用**三级方向场 RK4 积分**追踪自然弯曲河流：

1. **Dijkstra 代价场** `dist[]`：从所有海洋格反向 Dijkstra，`cost(q) = max(0, dem[q]) + 1 - 1.5·log(1+flow_acc[q])`。高海拔贵、高流量便宜。作为全局可达性约束
2. **源头检测**：`flow_acc >= threshold` 且无更高 acc 上游流入的格子，按流量降序
3. **三级方向场 RK4 积分**（每条河从源头追踪到海）：
   - **a. dem 平滑梯度**（高斯 σ=1.5）：跟随山谷自然弯曲。仅当与 dist 下降同向时启用，否则视为跨分水岭
   - **b. flow_acc 平滑场 +梯度**：平原区指向下游高流量主流。须与 dist 下降同向（防局部极大绕圈打转）
   - **c. dist 场**：纯几何兜底，保证到海
4. **Chaikin 切角平滑** 2 轮：消除格子线
5. **汇流合并**：流线经过已有河流 2 格范围内 → 截断并汇入（前段 <15 步碰到则丢弃，消除平行短支流）。截断时追加末端点至主流格子中心，避免间隙
6. **Strahler 分级**：基于 parent_indices 拓扑从叶向根传播

设计取舍：纯 dem 梯度会跨分水岭、纯 dist 平原退化为平行直线、纯 flow_acc 局部极大处打转。三级混合取长补短——山地 dem 弯曲、平原 flow_acc 弯曲、分水岭/兜底靠 dist。

### 湖泊盆地提取（hydrology.py）

`extract_lake_basins()`：被动检测侵蚀后 DEM 留下的洼地。
- 洼地像素 = `filled_dem[i] - dem[i] > 1.0`（填洼后升高超 1m）
- BFS 找 8 连通分量，过滤 <5 像素
- 湖面高程 = 盆地边界像素的 `filled_dem` 最低值（溢出口高度）
- 面积 = 像素数 × 0.01 km²（100m/px）

## 层 2 详细 tile 生成（TileGenerator）

`TileGenerator(seed, continent).generate_chunk_for(chunk)` 返回 `TileGrid`：

1. **宏观海拔采样**：`sample_altitude_bilinear()` 从层 1 双线性插值
2. **细节噪声**：±50m，波长 200m，4 octaves（一次 C 调用算 40K tile）
3. **chunk 级群系隶属度**：温度降雨取 chunk 中心值（大陆 C 模型校准后缓存），海拔和 moisture 噪声逐 tile 变化，`biome_membership()` 算对各群系的隶属度
4. **TerrainBias 混合**：`bias = Σ weight_i × bias_i`，数值字段加权平均
5. **地形分类**：`_classify(elev, bias)` 按偏移后海拔带 → `TerrainType`（DEEP_WATER/SHALLOW_WATER/SAND/FERTILE_SOIL/GRASSLAND/ROCK/MOUNTAIN_PEAK）。**STEEP_SLOPE 不在此处判定**——由后续坡度计算重分类
6. **坡度计算 + 陡坡重分类**：`_compute_slopes()` 对每个 tile 取 8 邻域最大高程差作为局部梯度（m/m），存入 `grid._slope`。`_reclassify_steep()` 将梯度 > 1.0m/m（≈45°）的陆地 tile 重分类为 `STEEP_SLOPE`，水体/沙滩/山巅不受影响。**坡度基于宏观海拔计算（不含 ±50m 细节噪声）**——噪声纹理不产生虚假陡坡
7. **叠加河流**：`render_river_chunk()` 从层 1 river_network 取穿过的流线，沿点画河道圆（深水→浅水→沃土过渡），插值填充间隙
8. **叠加湖泊**：`render_lake_chunk()` 宏观海拔 < surface_elev → 水体；大湖中央 → DEEP_WATER；湖面以上 0-2m → MARSH 湿地

群系通过 TerrainBias 偏移地形分类阈值，不同群系产出不同地形分布。chunk 边界因隶属度混合而连续（实测 0 跳变）。

## TileGrid 存储（tile_grid.py）

```
TileGrid
├── _data: array('H')       200×200 地形类型（TerrainType 枚举）  80KB
├── _elevation: array('f')  200×200 tile 级连续高度 (m)            160KB
├── _slope: array('f')      200×200 tile 级局部梯度 (m/m)          160KB
└── _states: dict           200×200 × 状态数（湿润/覆雪/结冰，B=1/格，
                            顺序 = STATE_TYPES 注册顺序）          40KB×状态数
```

高度场供 2.5D 渲染抬升 tile 顶面，坡度场供 isometric 渲染选择斜坡变体。网络导出与 SQLite 持久化走二进制 BLOB（`to_bytes()`，version 头 + uint16 地形 + float32 高度 + float32 坡度 + 状态段，当前 v2），经 base64 传前端（map_handler）。状态层驱动与演化见《地形状态/技术.md》。

## Z 轴设计

Z 轴拆为两个正交概念，避免事件/寻路/碰撞进入 3D 复杂度：

### 渲染 Z（连续高度）

`TileGrid._elevation` 的 float 值，只给 Godot 抬高顶面用。`TileGrid._slope` 的 float 值，供 Godot 选择 isometric 斜坡 tile 变体。事件系统、寻路、碰撞不碰它们——"这个 tile 高 23.5m 还是 24m"对游戏逻辑无意义。

### 逻辑 Z（离散 layer_id）

层 id 枚举：`0=地表，-1=浅洞，-2=深洞`。每层内部是纯 2D XY 平面。

- `Entity.layer_id: int = 0` — 实体所在 Z 层
- `Event.layer_id: int = 0` — 事件所在 Z 层
- `Event.location` 保持层内平面坐标 `(chunk_x, chunk_y, tile_x?, tile_y?)`，layer_id 作为正交字段
- 空间索引 key = `(layer_id, chunk_x, chunk_y, sub_cx, sub_cy)` 5 元组——不同层落入不同桶，天然隔离；chunk 内按 16×16 tile 细分为 sub-cell（13×13 格），支持 tile 级精度的区域查询

**跨层交互**不做成 3D 事件，而是两个 2D 事件联动：地表塌方 → layer=0 触发"塌方"，同时 layer=-1 同 (x,y) 生成"顶部塌落"事件。寻路、碰撞、视野、势力范围全保持 2D 算法。洞穴生物的"特殊基因"挂在 layer_id=-1 的实体上，天然和地表种群隔离。

`ChunkData.tile_grid` 代表地表层（layer_id=0）。未来洞穴层的 chunk 数据结构待定（可能是 `ChunkData` 内嵌 `caves: dict[int, TileGrid]` 或独立 `CaveChunkData`），当前不预留字段避免过早抽象。

## 分块协调（WorldGenerator）

`WorldGenerator(seed)` 封装层 1 + 分块生成流程：

- `ensure_continent()`：主动生成并缓存 `ContinentData`（默认惰性，首次 `get_altitude` 才跑）。GameEngine 启动时主动调用
- `generate_chunk(cx, cy)`：同步生成层 1 ChunkData（群系/气候/海拔，不生成 tile）
- `generate_parallel(chunks, max_workers)`：并行生成多个分块
- `get_biome(cx, cy)` / `get_climate(cx, cy)`：快速查询

### 大陆磁盘缓存

大陆宏观场是 seed 的确定性函数（同 seed 结果逐字段一致），生成耗时 5-30s
（侵蚀+水文模拟）。`ensure_continent()` 首次生成后序列化落盘到
`<world_id>/continent.bin`（zlib 压缩显式二进制 schema，约 20MB），之后
读档直接反序列化恢复（秒级，实测 ~0.2s vs 生成 ~5s）。

- 缓存**随档分发**（在世界目录内）：存档可移植，换机后首次加载同样秒开
- 不进快照包（可再生数据，保持回退点精简）；回滚时与快照目录一同保留
- 格式头含 `CONTINENT_CACHE_VERSION`：序列化格式变更时递增，旧缓存失效重新生成；生成算法/调参变化不使缓存失效（每个存档的大陆在创建时定案），`gen_fingerprint` 仅用于加载时漂移诊断（告警 + continent status 查询），不符时沿用缓存
- 数据损坏/截断/版本不符 → 返回 None → 重新生成并覆盖（原子写 tmp+rename）
- **加载时校验缓存 seed == 生成器 seed**：不符（错档拷贝/旧随机化窗口残留）
  视为未命中重新生成，防止世界静默不一致
- 序列化为显式二进制 schema（struct + array，无 pickle）：缓存随档分享，
  pickle 反序列化可执行任意代码（RCE），显式格式无代码执行面；
  网格字段长度须等于 `grid_width × grid_height`（防截断/篡改）

## 线程安全

| 模块 | 策略 |
|------|------|
| `noise.py` | 每个线程独立 PerlinNoise 实例（种子相同则结果相同），无共享状态 |
| `continent_data.py` | ContinentData 生成后不可变（值对象） |
| `continent.py` | ContinentGenerator 无可变状态 |
| `hydrology.py` | 侵蚀各步骤纯函数；C 模块无共享状态 |
| `streamlines.py` | build_river_network 无可变状态；RiverNetwork 构造后只读 |
| `tile_gen.py` | TileGenerator 持有独立 PerlinNoise，无共享可变状态 |
| `tile_grid.py` | TileGrid 归属单个 chunk，由该 chunk 的生成线程独占 |
| `chunk.py` | ChunkData 值对象，大地图层不可变，详细层创建后归属调用线程 |

## 加载窗口

- 启动时预生成出生点周边 `INITIAL_CHUNK_RADIUS=2`（5×5=25 chunk）的详细 tile
- 运行时按请求懒加载：前端按玩家视野请求 chunk（get_chunks），已落盘的从存档恢复，否则现算
- 无主动的"跨边界窗口卸载"——远离的 chunk 由 ChunkStore LRU 淘汰移出内存（见存档系统/技术.md）
- 纯生成的 chunk 可丢弃重算（确定性 seed 保证一致），玩家改造过的 chunk 持久化

## 整合点

### 依赖

| 依赖 | 方式 | 用途 |
|------|------|------|
| `ascend.config` | 模块级 import | 噪声频率、侵蚀参数、海拔缩放、tile 分类阈值等全部常量 |

`ascend/space/` 内部子模块自包含（`ContinentGenerator` → `hydrology` → `streamlines` → `river_render` → `lake_render`），不依赖外部运行时服务。

### 被依赖

| 调用方 | 方式 | 调用的方法 / 属性 |
|--------|------|------------------|
| **GameEngine** (`game.py`) | 直接构造，持有引用 | `WorldGenerator(seed)`、`ensure_continent()`、`generate_parallel(coords)`；`TileGenerator(seed, continent)`、`generate_chunk_for(chunk)`；`ChunkStore(db_path)`、`put(chunk)`、`items()`、`close()` |
| **MapHandler** (`net/handlers/map_handler.py`) | 函数参数注入 | `WorldGenerator.generate_chunk(cx,cy)`、`TileGenerator.generate_chunk_for(chunk)`、`ChunkStore.get(cx,cy)`、`ChunkStore.put(chunk)` |

GameEngine 在 `start()` 中调用 `ensure_continent()` 主动生成大陆宏观场，再用 `generate_parallel()` 预生成出生点周边 chunk 的层 1 数据，最后用 `TileGenerator` 生成层 2 tile。运行时 chunk 按需加载走 MapHandler。
