## 统一天气场（双分量）

天气参数由**统一天气场**驱动：每个采样点（通常为 chunk 中心）= 纹理分量 + 特征分量。

```
UnifiedWeatherField
├── 纹理分量（TextureField）   # 连续、全局、缓慢演化
│   ├── 温度通道 (7500m 波长)   # 多 octave Perlin + 漂移
│   ├── 风通道   (2500m 波长)
│   ├── 降水通道 (1500m 波长)   # 云量相关，兼作湿度/日照扰动源
│   └── 通道独立 seed（fate 派生去相关，见随机系统/设计.md）
└── 特征分量（FeatureField）   # 稀疏、离散事件、确定性派生
    ├── 空间块 (16km) 内按段（1 游戏年）生成特征核
    ├── 高斯 falloff 核（寒潮/热浪/风暴）+ 带形核（锋面）
    ├── 注入核（调试 force API，no_ramp 立即满强度）
    └── 核身份 (core_id) 稳定 → 跨 tick 事件匹配
```

- 采样：1km 网格点上合成值 + Catmull-Rom Hermite 双三次插值（4×4 邻域，C1 连续），再叠 tile 级确定性噪声（波长 10m，掩网格线折痕）
- **解析量**：场 = seed + 时间完全可重算，不持久化、无调度窗口 → 任意过去时刻查询精确
- 特征核预收集：一次采样收集 4×4 邻域 + 核完整 falloff 范围（2×最大半径，经 `cores_overlapping` margin 参数外扩）内的核，跨 16 个插值点复用
- 性能共享（纯函数复用，解析值不变）：同点多通道共享一次核收集 + 一次漂移偏移（t 依赖量预计算）；批量栅格采样 `sample_grid` 同路径，供解析结算器

## 解析算公式

每游戏分钟对每个注册 chunk 从头计算（无快照、无缓存）：

```python
# 温度：基线 + 季节 + 昼夜 + 场合成（纹理扰动 + 特征核偏移）
temperature = baseline_temp
            + seasonal_temp_offset(...)                     # 余弦，±amplitude
            + diurnal_temp_offset(hour, diurnal_amp)        # 余弦，峰值14:00
            + field.sample(CH_TEMPERATURE, x, y, now) * TEMP_PERTURB_SCALE
            # 场合成含特征核：寒潮/热浪 ±15°C 高斯 falloff（可叠加抵消）

# seasonal_amp 从年均温+年降雨连续推导（derive_seasonal_amp，derive.py），非气候带离散取值：
#   base = lerp(28, 2, (T - (-5)) / (35 - (-5)))   # 极地28°C, 赤道2°C
#   rain_bonus = clamp((2000 - R) / 2000, -0.5, 1.0) * 4   # 干旱+4, 海洋调节-2
#   seasonal_amp = clamp(base + rain_bonus, 1, 30)
# 保证气候带交界处温度无跳变（baseline 连续 → seasonal_amp 连续）

# 湿度：基线 + 季节（余弦或 tanh 阶梯）+ 昼夜（反比）+ 场降水纹理扰动
humidity = baseline_humidity
         + seasonal_humidity_offset(...)                   # 余弦或 tanh 阶梯
         + diurnal_humidity_offset(hour, amp)              # 反比于温度曲线
         + field.sample(CH_HUMIDITY, x, y, now) * HUMIDITY_PERTURB_SCALE

# 风速：基线 + 场扰动，再 × 特征核倍率
wind_speed = (baseline_wind + field.sample(CH_WIND, x, y, now) * WIND_PERTURB_SCALE)
           * field.wind_multiplier(x, y, now)              # 风暴核 ×1.5-4.5（叠乘）

# 日照：天文日照时长 + 场降水纹理扰动（云量相关）
day_of_year = (now // GAME_DAY) % 360
sunshine = daylight_hours(day_of_year, latitude)           # 天文日照时长（随纬度+季节）
         + field.sample(CH_HUMIDITY, x, y, now) * SUNSHINE_PERTURB_SCALE

# 降水：场降水信号 + 气候带校准（连续标定，无调度）
signal = field.precip_signal(x, y, now)        # 纹理 [0,1] + 特征核提升（风暴/锋面）
threshold = precip_threshold(annual_rainfall)  # 干旱带高阈 0.55 → 湿润带低阈 0.25
rainfall = max(0, signal - threshold) * PRECIP_INTENSITY_SCALE * mean_intensity
```

所有结果钳制在物理边界内（温度 [-30, 50]、湿度 [0, 100]、风速 [0, 50]、日照 [0, 24]）。

### 降水校准（field.py）

`precip_threshold(annual_rainfall)`：年降雨量 → 越阈水平连续标定（50mm/年 → 0.55 难下雨；3500mm/年 → 0.25 常下雨）。降雨强度 = 超阈量 × 2 × 气候带基准强度（mm/h）。基准强度为**数据驱动**：`ClimateTemplate.mean_precip_intensity`（`data/climate.json` 8 档显式声明，如赤道雨林 10.0 / 沙漠 2.0），改内容只改数据文件。无事件队列、无预排窗口——"何时下雨"完全由场信号与阈值决定，年降雨量仅作阈值标定输入。

## 气候生成链

```
纬度噪声 [-1,+1] → 海平面温度 (-5~35°C)
降雨噪声 [-1,+1] → 年降雨量 (50~3500mm)
海拔 (m)
    ↓
气温直减率 (9°C/1000m): 实际温度 = 海平面温度 - 海拔 × 9/1000
    ↓
classify(年均温, 年降雨, 海拔) → ClimateZone (8 档判定)
    ↓
annual_baseline(...) → WeatherParams (六参数基线，存入 ChunkData)
    ↓
WeatherEngine.register_chunk(cx, cy, baseline, climate, sea_level_temp)
    ↓
运行时解析算 → 发布 per-parameter 事件
```

### 气候档位判定（classify）

纯静态决策树，顺序优先：

1. 海拔 ≥ 2000 → ALPINE（覆盖纬度气候）
2. 温度 < -5 → POLAR_TUNDRA
3. 降雨 < 200 → DESERT
4. 降雨 < 600 且 T > 5 → STEPPE
5. T ≥ 20 → EQUATORIAL_RAINFOREST (R≥1500) / TROPICAL_SAVANNA
6. T ≥ 5 → TEMPERATE_FOREST
7. -5 ≤ T < 5 → SUBARCTIC_TAIGA (R≥400) / POLAR_TUNDRA

## WeatherEngine

核心编排器，模块中唯一持有运行时可变状态的类（注入核、chunk 注册、事件跟踪缓存）。

### 生命周期

```python
engine = WeatherEngine(clock, seed=42)        # 构造：订阅 minute_change
engine.register_chunk(cx, cy, baseline, climate, sea_level_temp)  # 注册：每个已加载 chunk
engine.unregister_chunk(cx, cy)               # 注销：ChunkStore LRU 淘汰时
engine.shutdown()                             # 销毁：取消订阅

# 调试控制（终端 weather set 指令的底层）
engine.force_feature(cx, cy, type_name, active)  # 注入/移除特征核 → bool | None
```

### 每 tick 流程

```
minute_change 事件 (from GameCalendar)
    │
    ├─ tick 级预计算 _tick_context()（所有 chunk 复用）
    │   └─ season/hour/day_of_year/solar_decl/season_cos/diurnal_cos
    │
    ├─ 全局季节事件
    │   └─ season 变化 → 发布 season_change（location=(0,0)）
    │
    ├─ 区域降水事件（RegionTracker.update）
    │   ├─ 越阈 chunk → 连通域（4-邻接）→ 与上帧重叠匹配
    │   └─ 区域出现 → precipitation_start（质心处温度判 rain/snow，含强度）
    │       区域消失 → precipitation_stop
    │       移动/变形/分裂/合并不发事件（"还在下雨"）
    │
    └─ per-chunk 循环
        ├─ _compute_params() → WeatherParams（场采样）
        ├─ 温度/湿度/风速/日照等级变化 → 发布 *＿change（含 prev_tier/tier）
        ├─ per-chunk 昼夜切换（chunk 纬度算 sunrise/sunset）
        │   ├─ 夜→昼 → 发布 sunrise（含 daylight_hours）
        │   └─ 昼→夜 → 发布 sunset（含 daylight_hours）
        └─ _sync_feature_events()：核身份 diff（首刻静默，注入核除外）
            ├─ 核出现 → 发布 {type}_start（含 wind_multiplier/rain_multiplier）
            └─ 核消失 → 发布 {type}_stop
```

事件触发从数值阈值改为等级比较：`classify_temperature(params.temperature) != field.last_temp_tier`。等级边界由 `config.py` 的 `*_TIER_BOUNDARIES` 定义（整数等级，事件携带 `prev_tier`/`tier` 供下游判定趋势）。分级函数（`classify_*`）与降水类型判定（`precip_type_for`）为纯函数，实现于 `weather/derive.py`（引擎、终端与查询 API 共用同一实现）。

### 线程安全

由 GameEngine 后台单线程驱动；查询 API（`get_weather` 等）用 `_query_lock` 保护，handler 线程可并发查询。

### 降水类型判定

```python
precip_type = "snow" if round(temperature, 1) <= 0 else "rain"
```

（先四舍五入再判定，保证事件广播与 UI 显示一致；区域事件用质心 chunk 的温度）

### per-chunk 昼夜切换

每个 chunk 用自己的纬度（`_ChunkWeatherBaseline.latitude`）算当日日出/日落时刻，检测昼夜切换并发布 sunrise/sunset 事件（携带 `daylight_hours = sunset - sunrise`）。不同纬度 chunk 的昼夜时刻独立，极地极昼极夜自然体现。`season_change` 仍为全局事件（location=(0,0)）。

## 季节计算（season.py）

纯函数，无状态。

```python
season_of(day)           # 游戏日 → Season(0=春,1=夏,2=秋,3=冬)，每季 90 天
day_of_season(day)       # 季节内日 [0, 90)
day_of_year(day)         # 年内日 [0, 360)

seasonal_temp_offset(season, dos, amplitude)  # 余弦曲线，夏季中点 +amp，冬季中点 -amp
seasonal_humidity_offset(season, dos, amp, sharpness)
    # sharpness=0: 标准余弦
    # sharpness=2.5 (MONSOON): tanh 阶梯化，旱湿切换突兀
    # sharpness 数据驱动：ClimateTemplate.humidity_sharpness（data/climate.json，
    # 仅季风档 2.5，其余 0.0——契约测试绑定季节模式与系数一致）
```

## 昼夜计算（diurnal.py）

纯函数，无状态。

```python
diurnal_temp_offset(hour, amplitude)     # 余弦，峰值 14:00(+amp)，谷值 02:00(-amp)
diurnal_humidity_offset(hour, amplitude) # 反比余弦，峰值 14:00 湿度最低
hour_of_game_time(game_time)             # tick → 当日小时 [0, 24)

# 日出/日落（基于太阳赤纬 + 纬度）
sunrise_hour(day_of_year, latitude_deg)  # 日出时刻 [0, 12]
sunset_hour(day_of_year, latitude_deg)   # 日落时刻 [12, 24]
daylight_hours(day_of_year, latitude_deg)  # 当日天文日照时长 = sunset - sunrise [0, 24]
```

日出/日落使用标准天文公式：

- 太阳赤纬 = 23.44° × sin(2π × (day - 45) / 360)
- 半昼长 = arccos(-tan(lat) × tan(decl)) / 15
- 日出 = 12 - 半昼长，日落 = 12 + 半昼长
- 处理极昼（日出=0h）和极夜（日出=12h）边界

`daylight_hours` 同时用于 sunrise/sunset 事件携带的当日日照时长（供下游种植/生理系统）。

per-chunk 昼夜切换用 chunk 自己的纬度（由海面温度连续推导，`derive_latitude(sea_level_temp)`，实现于 `weather/derive.py`），不再使用全局参考纬度。

## 纹理分量（atmosphere.py — TextureField）

```python
class TextureField:
    def __init__(self, seed, wavelength=7500m, drift_rate=1e-5)
    def sample(channel, world_x, world_y, game_time) -> float   # 归一化 [-1, 1]
    def wind_vector_at(world_x, world_y, game_time) -> (float, float)  # 单位向量
```

- 多 octave Perlin（4 层，振幅衰减 0.5，频率倍增 2），通道独立波长（温度 7.5km / 风 2.5km / 降水 1.5km）
- 气团漂移：采样坐标 = 空间坐标/wavelength + 风向 × drift_rate × game_time（风向由低频噪声驱动，季节性缓慢旋转）
- 相邻位置采样连续，O(1) 无需邻居查询

## 特征分量（features.py）

数据驱动的低频极端天气系统。添加新特征类型只需在 `data/weather.json` 加一项
（命名空间键 + effect/rates/持续时长/强度/事件类 id；运行时 `type_name` =
local 部分，事件类经代码侧映射）。

### 架构

```python
@dataclass(slots=True)
class FeatureConfig:
    type_name: str                              # "cold_snap" / "heat_wave" / "storm" / "front"
    effect: str                                 # "temperature" | "multiplier" | "precip"
    rates: dict[ClimateZone, float]             # 各气候带年均事件数，0=永不发生
    mean_duration: int                          # 典型持续时长，实际 0.5x-1.5x 随机化
    base_intensity: float                       # 基准强度
    radius_range: (min, max)                    # 影响半径 (m)
    speed_range: (min, max)                     # 移动速度 (m/s)
    precip_boost: float                         # 对降水信号的峰值贡献
    start_event_cls / stop_event_cls            # start/stop 事件类（front 为 None）
```

### 当前注册表

| 类型         | 效果类别      | 基准强度  | 典型持续 | 降水提升 | 说明 |
| ------------ | ------------- | --------- | -------- | -------- | ---- |
| `cold_snap` | temperature   | -15°C    | 3 天     | 0        | 亚寒带(2.0)、极地(2.0)、高山(1.5)、温带(1.0)、草原(0.3)，其余 0 |
| `heat_wave` | temperature   | +15°C    | 5 天     | 0        | 沙漠(2.0)、草原(1.5)、热带草原(1.0)、温带(0.5)、高山(0.2)，其余 0 |
| `storm`     | multiplier    | ×3.0     | 6 小时   | 1.0      | 热带草原(2.0)、热带雨林(1.5)、温带(1.0)、高山(1.0)、草原(0.5)、亚寒带(0.5)、极地(0.3)、沙漠(0.1) |
| `front`     | precip        | 带形      | 10 小时  | 1.0      | 各带 0.5-6.0；纯降水无事件类（`weather set rain` 的底层） |

### 生成与采样

- 空间块（16km）× 段（1 游戏年）确定性派生：RNG = (seed, 块, 段)，段间互不依赖 → 任意段 O(1) 生成
- 核中心块内均匀、半径/强度/速度/方向随机化；核出生即移动（带形锋面需速度判定）
- 采样 = 高斯 falloff（d=0 → 1.0，d=r → ~0.135）· 生命周期包络（ramp 进出 20%）· 强度
- 温度类偏移累加（寒潮+热浪可抵消）；倍率类叠乘（≥1.0）；锋面带形沿移动方向延伸
- `cores_overlapping(x0,y0,x1,y1,t,margin=0)`：按核半径做圆-矩形相交判定（双段扫描：当前段 + 上一段末出生核），块遍历外扩最大半径；`margin` 显式外扩查询矩形——事件判定用默认值，采样收集传 2×最大半径补足 falloff 覆盖（相交按半径、强度按 2×半径的不一致由此弥合）

### 注入核（调试 force）

`inject_core` 注入 `no_ramp=True` 的核（立即满强度，与自然核同代码路径）。注入核是唯一运行时状态（存档不序列化）。core_id = `inj:{cx}:{cy}:{type}`，事件身份跟踪与自然核一致。

## 区域跟踪器（region_tracker.py）

```python
class RegionTracker:
    def set_chunk_baseline(cx, cy, annual_rainfall, mean_intensity=5.0)
    def remove_chunk(cx, cy)
    def update(now) -> list[RegionEvent]   # kind="start"|"stop"，含质心/强度
```

- 按注册 chunk 中心采样降水信号（与 `get_weather` 查询路径完全一致）> 阈值 → 越阈集合
- 4-邻接连通域 → 区域（chunk 粒度，区域 ~5km 尺度）
- 与上帧重叠匹配：持续存在（移动/变形）不发事件；分裂/合并不发事件（"还在下雨"）；完全消失发 stop、全新出现发 start
- 事件数与 tile 数无关（chunk 粒度）；`start` 事件含质心处降雨强度（mm/h）
- 所有 chunk 注销后：补发最后区域的 stop 事件（`test_region_stop_when_dry` 语义）

## 事件契约（events.py）

事件类型由 `WorldEvent` 子类契约类声明（字段即 data 键，event_type 由类属性声明，见事件系统/技术.md）。无注册表、无运行时校验——契约由 dataclass 字段本身在构造时强制。

感知类事件携带整数等级（非字符串标签）：

- `temperature_change`: {temperature: float, prev_tier: int, tier: int, season: int, time_of_day: int}
- `humidity_change`: {humidity: float, prev_tier: int, tier: int, time_of_day: int}
- `wind_change`: {wind_speed: float, prev_tier: int, tier: int, wind_dir_x: float, wind_dir_y: float, time_of_day: int}
- `sunshine_change`: {sunshine: float, prev_tier: int, tier: int, season: int, time_of_day: int}
- `precipitation_start`: {precip_type: str, intensity: float, time_of_day: int}
- `precipitation_stop`: {time_of_day: int}
- `season_change`: {season: int, time_of_day: int}（全局，location=(0,0)）
- `sunrise` / `sunset`: {time_of_day: int, daylight_hours: float}（per-chunk）

特征核事件由 `FEATURE_TYPES` 注册表自动生成（`{type}_start` / `{type}_stop`，字段见 `events.py` 契约类）。

## 查询 API

WeatherEngine 提供三个公开查询方法，供需要精确值的模块（UI 面板、生态模拟）直接调用。**查询支持当前或过去任意时刻（场为解析量，无调度窗口修剪），未来时刻抛 `ValueError`**：

```python
# 当前/过去时刻的完整天气参数（含所有特征核效果）
def get_weather(cx, cy, time=None) -> WeatherParams | None

# 等级索引字典 {"temperature": 3, "humidity": 1, "wind": 0, "sunshine": 2}
def get_tiers(cx, cy, time=None) -> dict[str, int] | None

# 当前时刻完整报告（网络 handler 专用）：天文与噪声只算一次，降雨衰减自动含特征核
def get_weather_report(cx, cy) -> (WeatherParams, sr, ss, daylight, intensity, azimuth) | None
# 返回 (天气参数, 日出时刻, 日落时刻, 当日日照时长, 当前日照强度, 太阳方位角)
```

网络层通过 `weather_handler.py` 的 `get_weather` 请求类型对外暴露：逐坐标校验（畸形坐标跳过不毁整批）、单请求上限 `MAX_WEATHER_QUERY_CHUNKS`；响应含 round 后的显示值与等级、日出日落/日照强度/方位角。前端 F3 面板每 1s 轮询一次更新天气分区（实时值）；气候分区显示 chunk 年均基线。

## 参数存储

- 每个 chunk 的"年均基线"（WeatherParams）存储在 `ChunkData.annual_baseline`，chunk 生成时由 `annual_baseline()` 确定。日照基线固定为 12.0（天文年均），季节变化由运行时 `daylight_hours()` 实时计算
- WeatherEngine 注册时从基线 + 气候模板派生 `_ChunkWeatherBaseline`（含温度/湿度/风速/降雨/日照基线 + 季节振幅（从年均温+降雨连续推导）/昼夜振幅 + SeasonalityMode + 纬度）
- 实时天气值不持久化——每 tick 解析算（场为解析量，存档可完全重放）

## 整合点

- **GameEngine** (`game.py`)：创建 WeatherEngine，遍历已加载 chunk 调用 `register_chunk()`，LRU 淘汰时调用 `unregister_chunk()`，停止时调用 `shutdown()`；注册 weather_handler 至 MessageDispatcher
- **GameCalendar** (`time/calendar.py`)：发布 `minute_change` 事件（含 `game_time`, `day`, `hour`, `minute`），是天气引擎的唯一 tick 来源
- **WorldTree** (`world_tree/`)：事件总线，天气引擎发布天气事件
- **ChunkData** (`space/chunk.py`)：提供 `annual_baseline`、`climate_zone` 和 `sea_level_temp` 作为天气注册输入
- **weather_handler** (`net/handlers/weather_handler.py`)：处理前端 `get_weather` 请求，调用 `get_weather_report()`，经 i18n 翻译降水描述（晴/雨/雪），等级为整数透传

## 下游消费

当前已实现的消费者：

- **EventBridge**：通配符订阅全部天气事件，转发至 Godot 前端事件日志
- **F3 天气面板**：通过 `get_weather` API 每 1s 轮询，显示温度/湿度/风速/光照/日出日落
- **终端指令**（`weather status` / `weather set`）：`set` 走 `force_feature` 注入/移除特征核（rain → front 带形核，cold_snap/heat_wave/storm → 同名核），事件由引擎核身份 diff 自动发布
