# 季节气候 — 设计

> **本文档描述的是"统一天气场"目标架构，未实现**。当前实现为 per-chunk
> 解析算 + 独立调度（见技术.md）。文中"统一天气场（特征 + 纹理分量）"、
> "场驱动降水"、"区域级事件"等均无代码——实际为 per-chunk 事件调度。

## 两层模型

```
气候（离散档位）              天气（连续值）
─────────────────           ─────────────────
群系分类的依据               此刻的真实数值
指导天气范围                  作为生理/种植/基因的输入
季节嵌入气候内部              随时钟实时波动
```

- **气候**：离散档位（8 种 ClimateZone），描述一个区域的长期气象特征。用于群系分类、大致判断"这里冷不冷、干不干"
- **天气**：连续值，此刻的具体数值——温度是 23.7°C 而不是"温暖"。用于生理需求计算、作物生长判定、基因适应区间匹配

## 气象参数池

可扩展。初始六项：

| 参数     | 单位                           | 说明                                                                                          |
| -------- | ------------------------------ | --------------------------------------------------------------------------------------------- |
| 温度     | °C                            | 体感温度，影响生理需求（体温维持）、作物生长期                                                |
| 降雨量   | mm/年（基线）/ mm/小时（实时） | 基线决定气候档位；实时值为降雨强度，影响土壤湿度、洪涝事件                                    |
| 日照时长 | 小时/天                        | 影响作物光合作用、某些生物的活动周期                                                          |
| 海拔     | m                              | 决定气压（推导值），影响体能消耗和某些基因表达。同时是气候判定的第一优先级（≥2000m → 高山） |
| 湿度     | %                              | 相对湿度，影响腐烂速度、霉菌生长、体感舒适度                                                  |
| 风速     | m/s                            | 影响体感温度、风暴事件、某些飞行生物的移动                                                    |

海拔推导值：气压 = 1013.25 × (1 - 海拔/44330)^5.255，含氧量等比例变化。

## 四层叠加（解析算架构）

天气采用**解析算**（resolved computation）——无快照、无缓存，每游戏分钟从零计算：

```
年均基线（气候档位 + 噪声，chunk 生成时确定）
    +
季节偏移（余弦曲线，由 SeasonalityMode 控制形状）
    +
昼夜偏移（余弦曲线，峰值 14:00 / 谷值 02:00，湿度反转）
    +
统一天气场（特征分量 + 纹理分量，空间连续，见下）
    =
此刻天气
```

关键设计：

- **温度**：四层全部参与
- **湿度**：四层全部参与（季节偏移可受 SeasonalityMode 阶梯化；昼夜偏移反比于温度——夜间高湿、午间低湿）
- **风速**：基线 + 统一天气场（不参与季节/昼夜调制）
- **日照**：拆为两个独立维度——
  - **日照时长**（daylight_hours）：天文计算 `daylight_hours(day_of_year, latitude)`，日级值，季节+纬度驱动
  - **日照强度**（sunshine_intensity）：`sin((hour - sunrise) / daylight × π)` 正弦曲线，正午峰值，夜间=0，含降雨衰减 + 天气场纹理分量微调
- **日照时长感知**按日长分级（极短/较短/适中/较长/很长/极长），**日照强度感知**按明暗分级（夜/昏暗/适中/明亮/强光）
- **降水**：场驱动（统一天气场合成值 + 阈值判定），非 per-chunk 独立调度。降水类型由当前温度判定：>0°C 为雨，≤0°C 为雪

## 气候档位（8 种）

用于群系分类的离散标签。判定顺序（纯静态，由年均温+年降雨+海拔决定）：

| 优先级 | 条件                        | 气候档位                         | 季节模式    |
| ------ | --------------------------- | -------------------------------- | ----------- |
| 1      | 海拔 ≥ 2000m               | 高山 (Alpine)                    | ALPINE      |
| 2      | 年均温 < -5°C              | 极地苔原 (Polar Tundra)          | POLAR       |
| 3      | 年降雨 < 200mm              | 沙漠 (Desert)                    | NONE        |
| 4      | 年降雨 < 600mm 且 T>5°C    | 草原 (Steppe)                    | FOUR_SEASON |
| 5      | T≥20°C, R≥1500mm         | 热带雨林 (Equatorial Rainforest) | NONE        |
| 5      | T≥20°C, R<1500mm          | 热带草原 (Tropical Savanna)      | MONSOON     |
| 6      | 5°C ≤ T < 20°C           | 温带森林 (Temperate Forest)      | FOUR_SEASON |
| 7      | -5°C ≤ T < 5°C, R≥400mm | 亚寒带针叶林 (Subarctic Taiga)   | POLAR       |
| 7      | -5°C ≤ T < 5°C, R<400mm  | 极地苔原（合并入冷干）           | POLAR       |

温度季节振幅不再由气候档位离散决定，而是由 WeatherEngine 从年均温+年降雨连续推导（详见下文"季节"节），保证气候带交界处无跳变。

### 季节性模式（SeasonalityMode）

| 模式        | 气候带         | 温度曲线       | 湿度曲线                                             |
| ----------- | -------------- | -------------- | ---------------------------------------------------- |
| NONE        | 赤道雨林、沙漠 | 余弦，振幅极小 | 余弦（sharpness=0）                                  |
| MONSOON     | 热带草原       | 余弦           | **tanh 阶梯化**（sharpness=2.5），旱湿切换突兀 |
| FOUR_SEASON | 温带森林、草原 | 标准余弦       | 余弦（sharpness=0）                                  |
| POLAR       | 亚寒带、极地   | 余弦，振幅大   | 余弦（sharpness=0）                                  |
| ALPINE      | 高山           | 余弦           | 余弦（sharpness=0）                                  |

## 季节

季节嵌入气候类型——不是独立的全局时钟切换。四季划分：

- 每年 360 天，每季 90 天
- 春=0, 夏=1, 秋=2, 冬=3
- 季节调制是连续余弦波——夏季中点（progress=1.5）取 +amplitude，冬季中点（progress=3.5）取 -amplitude，平滑过渡

温度季节振幅由年均温+年降雨连续推导（非气候档位离散取值）：

- 基础振幅随年均温线性变化：极地(-5°C)→28°C，赤道(35°C)→2°C
- 干旱修正：低降雨大陆性气候 +最多 4°C，高降雨海洋调节 -最多 2°C
- 钳制在 [1, 30]
- 保证气候带交界处无跳变（年均温/降雨连续 → 振幅连续）

## 昼夜

- 温度峰值 14:00（+amplitude），谷值 02:00（-amplitude）
- 湿度反转：14:00 最低湿，02:00 最高湿
- 昼夜振幅 = 季节振幅 × 0.5（昼夜变化小于季节变化）
- 日出/日落基于太阳赤纬 + 纬度公式计算，支持极昼/极夜边界
- **per-chunk 昼夜**：每个 chunk 用自己的纬度判定昼夜切换，发布 sunrise/sunset 事件（携带当日 `daylight_hours` 供下游种植/生理系统使用）。不同纬度 chunk 的日出日落时刻不同，极地极昼极夜单独体现

## 统一天气场

**单个场对象，两个分量**。下游只认 `sample(x, y, t)`，不感知分量存在——防止未来又拆回两个系统。

```
统一天气场（1km 采样网格，seed 派生，沿风向漂移）
├─ 特征分量：锋面 / 风暴核 / 寒潮 / 热浪——有中心、半径、移动矢量的结构化特征
│   （极端天气频率统计按气候带，保留为特征生成器的参数）
└─ 纹理分量：2D Perlin 多八度噪声——无结构的日常波动
    （波长按参数独立：温度 5-10km / 风 2-3km / 降水 1-2km）
→ 合成值 → 阈值判定 → 状态引擎批量涂抹 + 区域级事件
```

### 尺度与连续性

- **采样网格 1km**（≈5 个 chunk，按"玩家感知粒度 × 2-5 倍 chunk"推导，不按气象学尺度）：降水的空间结构（最高需求消费方）匹配出营探索节奏——走出营地 500m 能感知"进了雨区"
- **C1 平滑插值**（Hermite/bicubic，非双线性）：双线性在 1km 网格线上有梯度折痕，C1 让网格线从数学上消失
- **tile 级确定性噪声叠加**：5-20m 波长，打散场元规律性，掩盖任何残余折痕（渲染质感与防边缘感共用此机制）
- **时间连续**：场带漂移（`drift_rate` × 风向矢量），值随时间连续——风暴"扫过"地图而非逐 chunk 瞬移
- **相邻位置连续**：插值后的值天然跨 chunk 平滑——chunk 不再是天气真值，只读场

### 特征分量

- 锋面：线性梯度 + 法向移动（雨带/雪带边界平滑过渡）
- 风暴核 / 寒潮 / 热浪：高斯核（中心 + 半径 + 强度 + 移动矢量），falloff 几何上平滑
- 生成：seed 派生 + 气候带频率统计（各气候带年均事件数保留为特征生成参数）
- 合成：多核求和入场

### 纹理分量

- 2D Perlin 多八度，波长按参数独立（温度低频平滑、降水较高频）
- 采样坐标沿风向漂移（现有 AtmosphereField 机制升级）

### 确定性

场完全 seed 派生 + 确定性漂移——任意时刻可重算（**解析量不存**），存档可复现，符合确定性要求。

## 降水模型（场驱动）

降水不是 per-chunk 独立调度的离散事件，而是**统一天气场合成值 + 阈值判定**：

```
降雨强度(x, y, t) = 场合成值（特征雨核 + 纹理扰动）
    气候带校准：场阈值/振幅按气候带连续标定（同 seasonal_amp 连续推导的模式）
    → 越阈 → 区域内连续"正在下雨"；区域边缘是场的平滑梯度，不是 chunk 线
```

- 场值越阈 → 该连续区域发一条**区域级** `precipitation_start`（含 precip_type/intensity）——不是每 chunk 一条
- 各气候带降雨档位作为**校准参数**（决定场阈值/振幅的标定目标），气候带交界处降水统计微软化——交界处本来就是锋面/过渡带，统计微软是自然结果而非缺陷
- **降水类型判定**：当前温度 > 0°C → 雨（rain），≤ 0°C → 雪（snow）；温度场连续 → 雪/雨分界是平滑雪线

### 各气候带降雨档位（校准参数）

| 气候带       | 平均强度 (mm/h) | 平均持续 (h) | ramp 比例 |
| ------------ | --------------- | ------------ | --------- |
| 热带雨林     | 10.0            | 2.0          | 0.15/0.15 |
| 热带草原     | 8.0             | 1.5          | 0.2/0.2   |
| 沙漠         | 2.0             | 0.5          | 0.35/0.35 |
| 草原         | 4.0             | 1.5          | 0.25/0.25 |
| 温带森林     | 5.0             | 2.0          | 0.2/0.2   |
| 亚寒带针叶林 | 3.0             | 1.5          | 0.2/0.25  |
| 极地苔原     | 2.0             | 1.0          | 0.25/0.3  |
| 高山         | 3.0             | 1.0          | 0.25/0.25 |

## 事件与查询（双通道）

天气数据通过两个互补通道对外提供：

### 粗粒度感知事件

事件只在**等级变化**时发布，不再按固定数值阈值。由角色的直观体感定义等级边界，而非气象学精度：

| 参数     | 级数  | 等级边界（tier 边界阈值，℃/%/m/s/小时）                                                                               |
| -------- | ----- | ---------------------------------------------------------------------------------------------------------------------- |
| 温度     | 10 级 | -10 → -3 → 5 → 13 → 20 → 25 → 30 → 36 → 43（共 10 档：严寒…极热）                                                    |
| 湿度     | 5 级  | 25 → 50 → 72 → 88（干燥…闷热）                                                                                        |
| 风速     | 6 级  | 1.5 → 4 → 8 → 14 → 23（无风…狂风）                                                                                    |
| 日照时长 | 6 级  | 1.5h → 4.5 → 8 → 12 → 15.5（极短…极长）                                                                               |
| 日照强度 | 5 级  | 0.01 → 0.25 → 0.55 → 0.80（夜…强光）                                                                                  |

每个事件携带**整数等级**（`prev_tier`/`tier`）+ 精确数值，供 AI 决策（`if tier < 2: seek_shelter`）的同时不必二次查询。等级边界由 `config.py` 的 `*_TIER_BOUNDARIES` 定义，属 `mind/标签与信息` 三层管道（数值→等级→自然语言）的中间层；自然语言化由心智系统下游完成。

以下离散事件保持原逻辑不变：

| 事件类型                | 触发                 | 携带数据                                                   |
| ----------------------- | -------------------- | ---------------------------------------------------------- |
| `temperature_change`  | 温度等级变化         | temperature, prev_tier, tier, season, time_of_day          |
| `humidity_change`     | 湿度等级变化         | humidity, prev_tier, tier, time_of_day                     |
| `wind_change`         | 风速等级变化         | wind_speed, prev_tier, tier, wind_dir_x/y, time_of_day     |
| `sunshine_change`     | 日照时长等级变化     | sunshine, prev_tier, tier, season, time_of_day             |
| `precipitation_start` | 雨区开始（区域级，场越阈） | precip_type (rain/snow), intensity, location 区域 |
| `precipitation_stop`  | 雨区结束（区域级）         | time_of_day, location 区域                        |
| `season_change`       | 季节切换             | season, time_of_day（全局，location=(0,0)）                |
| `sunrise`             | per-chunk 日出       | time_of_day, daylight_hours                                |
| `sunset`              | per-chunk 日落       | time_of_day, daylight_hours                                |
| `cold_snap_start`     | 寒潮核进入场（区域级）    | temperature_offset, time_of_day, location 区域             |
| `cold_snap_stop`      | 寒潮核移出场              | time_of_day                                                |
| `heat_wave_start`     | 热浪核进入场（区域级）    | temperature_offset, time_of_day                            |
| `heat_wave_stop`      | 热浪核移出场              | time_of_day                                                |
| `storm_start`         | 风暴核进入场（区域级）    | wind_multiplier, rain_multiplier, time_of_day              |
| `storm_stop`          | 风暴核移出场              | time_of_day                                                |

> 降水与极端天气事件均挂在**区域**（location=场特征覆盖区域），不再 per-chunk 独立触发——事件数与 tile 数量无关。

### 精确查询 API

需要精确值的模块（UI 面板、温度计、生态模拟）直接调用 API，不依赖事件推送。
查询仅支持**当前或过去时刻**——未来时刻抛 `ValueError`（未来天气对角色不可知，且降雨/极端天气调度只预排有限窗口）：

```python
# 当前时刻天气（含所有修改器效果）
params = engine.get_weather(cx, cy)           # → WeatherParams

# 过去时刻（time ≤ 当前时钟）
params = engine.get_weather(cx, cy, time)

# 等级索引字典（整数等级，与事件 tier 同源）
tiers = engine.get_tiers(cx, cy)              # → {"temperature": 3, "humidity": 1, ...}

# 网络 handler 专用：一次计算返回完整报告（WeatherParams、日出/日落时刻、当日日照时长、当前日照强度、太阳方位角；降雨衰减自动含修改器效果）
params, sr, ss, daylight, intensity, azimuth = engine.get_weather_report(cx, cy)
```

F3 面板每 1s 轮询 `get_weather` 更新天气分区（实时温湿度等）；气候分区显示年均基线，两个分区不重复。
感知事件只进事件日志，不直接写面板（避免原始标签与翻译标签双写闪烁）。

## 极端天气（场特征）

极端天气**不是独立的修改器系统**，而是统一天气场的**特征分量**——寒潮 = 大半径负偏移核，热浪 = 正偏移核，暴风雨 = 移动雨核 + 风矢量场。ModifierSchedule 调度并入"场特征生成器"。

### 设计原则

- **各气候带有不同频率**——寒潮只发生在温带/寒带，热浪主要发生在热带/沙漠/草原，暴风雨在热带最频繁（频率统计保留为特征生成器参数，seed 派生）
- **效果分两类**：temperature（温度偏移，单位 °C）和 multiplier（风速+降雨倍率）
- **场驱动**——核进入场/移出场 → 区域级 start/stop 事件（非 per-chunk 独立开关）
- **可叠加**——多个特征核同时活跃时，temperature 类偏移累加、multiplier 类倍率叠乘
- **空间平滑**——核的 falloff 决定影响区域边缘渐弱，无区块直线边界

### 三种特征

| 特征 | 效果 | 典型强度 | 典型持续 | 发生气候带 |
| ---------------- | ------------- | -------- | -------- | ----------------------------- |
| 寒潮 (cold_snap) | 温度下降      | -15°C    | 3 天     | 草原/温带/亚寒带/极地/高山    |
| 热浪 (heat_wave) | 温度上升      | +15°C    | 5 天     | 热带草原/沙漠/草原/温带/高山  |
| 暴风雨 (storm)   | 风速+降雨倍增 | ×3.0     | 6 小时   | 全气候带（沙漠极罕见 0.1/年） |

### 游戏影响

- **生存压力**：寒潮/热浪期间，不适应极端温度的个体获得负面标签（"寒冷不适""中暑"），通过标签系统送入 LLM 上下文
- **种植风险**：寒潮可能冻死作物，热浪加速土壤蒸发
- **暴风雨**：高风速影响体感温度和飞行生物，强降雨驱动湿润状态快速上升（见《地形状态/设计.md》）
- **基因选择压**：频繁的极端天气事件驱动玩家选择更宽温度适应区间的基因型

## 基因适配

每个天气参数定义生物的基因适应区间。例如：

- 耐寒基因：温度适应下限降到 -20°C
- 耐旱基因：年降雨量适应下限降到 200mm
- 喜光基因：日照时长适应下限提升到 10 小时

生物的实际适应区间由多个基因叠加决定。超出区间的个体产生负面标签（"寒冷不适""脱水"），通过标签系统送入 LLM 上下文。

## 与其他模块的接口

- → **群系生态**：气候档位决定群系分布；连续参数值决定群系内的具体物种构成
- → **生命个体**：天气参数直接输入生理需求计算（温度→体温、湿度→体感舒适、海拔→含氧量→体能消耗）
- → **基因系统**：天气参数区间作为基因适应性的判定基准
- → **玩家行动**：种植条件由天气参数的每日值决定（温度窗口、降雨量、日照时长）
- → **地形状态**：统一天气场合成值 → 阈值判定 → 湿润/覆雪/结冰沉积与融化（见《地形状态/设计.md》）
- → **时间系统**：季节调制由世界时钟的 `minute_change` 事件驱动；WeatherEngine 订阅该事件作为唯一 tick 来源
- → **事件系统**：天气事件通过 WorldTree 发布（感知类别变化 + 区域级离散切换），任何下游系统可订阅
- → **表现层**：`get_weather` API 通过 `weather_handler` 响应前端轮询；感知事件转发至 Godot 事件日志
