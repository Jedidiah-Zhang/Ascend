# 随机系统 — 设计

随机系统（Loom of Fate · 命运的织机）是世界级的确定性随机源。它统一管理种子派生、独立随机流与可复现性——让世界里的"偶然"既真实存在，又能被完全追溯与重现。

研究侧动机与形式化见 [研究理论 / 世界基座 / 00-假设与记号](../../研究理论/世界基座/00-假设与记号.md) §2（CRN 前提 (a)）与 [02-误差传播与反事实](../../研究理论/世界基座/02-误差传播与反事实.md)（定理 2.5）。

## 织机只织"偶然性"

世界演化 = 机制 + 状态 + 行动 + 偶然性。随机系统只负责其中"偶然性"这一份，不越界：

```
              Fate Loom（本模块：外生随机性 U）
                        │
        ┌───────────────┴───────────────┐
        ↓                               ↓
   世界机制 F（状态如何演化）        代理策略 π（行动如何选择）
        ↓                               ↓
                     World_{t+1} = F(World_t, Action_t, U_t)
```

- **Fate Loom 不决定 NPC 做什么**——它只为机制与策略提供可追溯的随机因素。
- seed 只决定 U，不决定状态与行动：总可能性 = 2^256 个"噪声宇宙" × 每宇宙内由代理行动产生的无界分支。
- 无代理的封闭世界在同 seed 下是唯一确定轨迹——这正是研究所需的"已知 SCM + 可复现"基质；确定性 ≠ 可预测（强非线性机制）。

## 为什么需要确定性随机

随机系统要解决的核心问题：**同一种子，必须得到同一个世界。**

- **研究前提（CRN）**：世界基座验证要求"已知 SCM + 可复现"——do 干预改变执行路径时，未干预的部分必须逐位不变。这要求每个随机决策点有独立、可重算的随机流，而不能共用单一全局流（全局流会因消费顺序被打乱而污染未干预变量）。
- **存档零持久化**：随机性全部由种子派生 → 天气等解析量随时可完全重算，不落盘、不存流状态。
- **跨进程一致**：基线 vs do 双跑都从同 seed 从头重放，T 之前天然位级一致，无需 checkpoint 回滚。

## 世界种子

- 世界根种子为 256-bit 整数（1..2^256-1；0 = 随机占位）。
- 协议层以 **hex 字符串**传输（至多 64 字符，小 seed 短表示，如 `2a`；`""`/`"0"`/缺省 = 随机占位）。
- **为什么 hex 字符串**：Godot JSON 解析器原生只有 int64——256-bit 整数直传会精度丢失。引擎内部保持 int，仅在协议边界（map_preview / save_create / save_list / world_initialized）字符串化。
- **种子唯一随机源 = 后端**：随机占位由后端预览时定案并随响应回传，前端不再本地随机——预览与创建用同一种子，确定性一致。

## 独立随机流

每个"身份"（namespace + 实体 + 用途 + tick）对应一个独立、确定性的随机流。随机性不再共享，而是按身份分发：

- **同身份同序列**：同一身份任意时刻重算 → 逐位一致（无视求值顺序）。
- **异身份独立**：流之间统计独立（256-bit 碰撞抗性，生日界 2^128）。
- **顺序无关**：流取值 = H(seed, 身份)，与消费顺序无关 → do 干预改变执行路径不搅动未干预流。
- **原子 do 天然成立**：tick 入身份 → 同节点不同 tick 是不同流，单 tick 干预不影响节点自身的未来流。
- **禁重播种**：可复现性由身份派生保证，重播种即破坏可复现性。

## 随机性可追溯（fate_path）

每个消费随机流的事件记录其流身份（`fate_path`）——反事实 abduction 只需记录流身份即可重算噪声实现（U 由身份派生，无需存 U 值）。生产示例：天气降水事件 `weather/precip/{cx}/{cy}@{tick}`。事件 → 具体特征段（block/seg）的逐噪声溯源留给阶段 1 因果声明层（父节点快照任务）。

## 为 do-operator 预留的契约

阶段 1 因果声明层动工时的接口约定（本模块在接口层面保证 CRN 前提）：

1. **声明层**：每个节点的结构方程登记其噪声流身份（node → fate_path）。
2. **机制层**：`do(X=x)` = 用常数方程替换 f_X → X 的流**从不被消费**；其余节点流照常 → 未干预流逐位不变（CRN）。do 替换整方程，整流不消费（半干预为未定义行为）。
3. **验证层**：单元级 CRN 检验（`test_fate_loom.py::TestLoomOfFate::test_crn_discipline_do_intervention`）+ 引擎级同 seed 双跑探针（E5）。
4. **双跑协议**：基线 vs do 都从同 seed 从头跑，T 之前天然位级一致，无需 checkpoint 回滚。

## 设计红利

| 性质 | 来源 | 研究意义 |
| --- | --- | --- |
| 顺序无关 | 流取值 = H(seed, 身份)，与消费顺序无关 | CRN 前提 (a)：do 干预改变执行路径不搅动未干预流 |
| 原子 do 天然成立 | tick 入身份：同节点不同 tick 是不同流 | 单 tick 干预不影响节点自身的未来流 |
| 无状态 | 全部由 seed 派生，不存任何流状态 | 存档零持久化；与天气"解析量可重算"一致 |
| 线程安全 | FateStream 每次调用新建，无共享可变状态 | 未来多线程/ECS/并行模拟 |
| 跨平台位级一致 | sha256 + 整数运算；MT 播种确定性 | 同架构跨机器黄金 hash 承诺 |

## 未实现与规划

- **NPC 心智接入**：NPC 决策流（personality/decision 等）规划中（namespace 表已登记）。动工前置：实体 ID 确定性——`Entity.id` 目前为 `uuid4()`，同 seed 双跑时实体 ID 不同 → 流不同 → CRN 失效；方案为 birth 时从织机派生确定性 ID。
- **space 层迁移**：大陆/chunk/tile 生成的 ad-hoc 偏移（`seed + 10002` 等）暂不迁移——被 test_determinism 黄金 hash 锁定；如需统一，按"刻意重固化黄金值"流程单独进行。
- **确定性卫生**：确定性路径避免依赖 set 迭代序（跨进程不稳定，PYTHONHASHSEED 加盐）；用 list 或显式排序。
