# 存档系统 — 设计

存档系统负责把世界状态保存到本地，并在需要时恢复。它回答三个问题：**存在哪、存什么、什么时候存**。

## 基本安排

- **实时保存**：世界状态持续写入本地。遇到崩溃或退出，恢复的就是最近保存的状态，最多丢失数秒的变化。
- **一个存档位对应一个世界**：存档位内含唯一的实时状态 + 若干手动回退点。手动保存 = 给当前世界添加一个回退点，不产生新世界。
- **手动回退点**：玩家随时可以创建，用于"从某个点重新继续游戏"。离开当前进度去回滚时，离开时的进度会先被保留下来（最新分支不丢失）。
- **内容防直读/防篡改**：存档内容经加密处理，其他工具打开看到的是乱码。密钥随档分发、游戏自动解锁，存档可移植可分享。防线是签名校验和读档时的完整性检查。

## 目录结构

```
~/.ascend/saves/                        # 存档根目录（默认位置；可通过环境变量 ASCEND_SAVE_ROOT 调整）
  <存档位>/                             # 一个存档位 = 一个目录 = 一个世界
    manifest.json                       # 世界介绍信息（明文）
    state.json.enc                      # 最近一次保存的时刻状态（加密）
    chunks.db                           # 地图区块数据
    events.db                           # 事件记录
    continent.bin                       # 大陆整体地形（可再生，随档分发秒开）
    snapshots/                          # 回退点集合
      @<时间>-<编号>-manual.ascendsave  # 手动回退点
      @<时间>-<编号>-auto.ascendsave    # 自动记录（回滚保护）
```

存档位编号是一串随机字符。回退点放在世界目录内的一个子目录中：回滚 = 用回退点内容替换当前文件，回退点子目录在替换期间先移出再放回——回退点自身不受影响（否则回滚会删掉自己的回退点）。回退点文件名 `@<时间>-<编号>-<类型>.ascendsave`，类型标识来源：`manual` 手动、`auto` 自动记录、`quit` 退出保存（预留）。

## 文件内容

### 世界介绍信息（manifest.json）

明文存放，因为存档选择页必须在不解锁的情况下展示世界列表。内容包括：名称、种子、出生点、创建时间、最近游玩时间、累计游玩时长、游戏时间、回退点数量、生成参数（如陆地比例），以及密钥的混淆串。

### 密钥（藏在介绍信息里）

- 密钥不单独存成文件：用存档位编号 + 种子派生一个保护密钥，把真正的密钥加密后藏进介绍信息里的 `secrets_blob` 字段（混淆层）。
- 效果：防的是"其他工具打开直读/篡改"（看到的是乱码），不防"懂行的人"——编号和种子都在明文里，派生密钥可被推算。存档可移植、可分享，换机器可玩。
- 种子在创建存档时定案（缺省即随机并写入介绍信息）：密钥身份与介绍信息从一开始就一致。
- 真正的防篡改防线：状态文件的签名校验 + 读档时对两个数据文件的完整性检查（结构性损坏拒绝加载）。

### 时刻状态（state.json.enc）

加密保存最近一次保存的时刻：时钟（时间、速度、暂停）、玩家位置、事件记录里的最新事件时间（读档时对齐时钟用，防止时间倒退）。天气不保存——天气由种子和时钟确定性重建。

### 地图区块与事件记录（chunks.db / events.db）

两个普通数据文件（无法整文件加密，且区块/事件数据敏感度低）。篡改防护：读档时做完整性检查，结构性损坏拒绝加载；记录内的字节改动不在检测范围。

地图区块保存的是**已加载区块的全部内容**（包括确定性生成的区块）：首次加载的区块在保存时落盘，读档/再次访问直接恢复、不用重新生成；已落盘且内容没变的区块不重复写。玩家改动过的区块必然落盘（玩家的修改无法再生）。区块数据经压缩存储。

### 回退点文件（.ascendsave）

把世界文件打包成一个文件，整体加密，附签名。读档时先验签名再解开，展开为存档位目录。回退点头部携带本次打包用的会话密钥（每次打包随机生成，只解锁自己，不解锁世界）。

回退点采用**增量打包**：以时间线上最近的手动回退点为参照，只记录与它的差异（自动记录与退出保存记录不作参照）；没有可参照的手动回退点时保存全部内容。这样反复保存的成本低。

## 什么时候保存（统一保存脉搏）

三样数据（状态、事件、区块）由同一个**保存脉搏**驱动（默认每 5 秒一次）在同一次保存中落盘。崩溃 → 恢复到最近完成的脉搏，丢失统一 = ≤5 秒的尾部。

| 内容 | 时机 | 方式 |
|---|---|---|
| 事件 → events.db | 每个脉搏 | 内存中的事件全部写入记录并清空内存 |
| 区块 → chunks.db | 每个脉搏 + 被挤出时立即 | 已加载区块全部落盘；被挤出的区块立即写回 |
| 状态 → state.json.enc | 每个脉搏 | 覆盖写入 |
| 实体表 | 未实现（见文末） | — |
| 退出 | 排空保存队列，做最后一次保存 | 同步 |

保存动作在专门的保存线程中按固定顺序执行：**事件 → 状态 → 区块**（事件先落盘，状态里记录的"最新事件时间"才是新的）。保存请求用一个槽位排队：上一次还没做完就跳过本次（反正下一次还会保存）。

- 崩溃恢复：最多丢一个脉搏间隔（默认 5 秒）的尾部变化；其中未落盘的确定性区块可以重新生成。
- 保存过程不发布任何事件：存档是游戏世界外的元操作，不产生历史、不进因果图。

## 读档与回滚（进程模型）

菜单进程（只管理存档）和世界进程（进入世界后运行）分开：进入世界 / 回滚 = 前端停掉旧进程、以目标参数拉起新进程。网络先就绪（端口与密钥文件立即就绪，大陆生成期间前端可连接并接收进度）；前端经握手和 `world_initialized` 事件感知就绪。

读档流程：
1. 回滚时先把离开时刻的进度保留（当前记录原地刷新），再展开目标回退点。
2. 回退点展开为存档位目录。
3. 从介绍信息解出密钥，解锁并校验状态文件；失败则拒绝加载（防篡改）。
4. 直接用存档目录里的数据文件（不复制）。
5. 恢复时钟：取状态记录时间与事件记录最新时间的较大者，防止时间倒退。随后重建日历。
6. 按种子重建大陆整体地形（确定性生成，约 30 秒；缓存命中秒级），区块从存档恢复。
7. 恢复玩家位置（实体表全量恢复未实现，见文末；读档不发布诞生事件）。
8. 天气引擎按种子和时钟重建调度。
9. 发布世界就绪事件（含出生点）= 就绪信号；前端据此接入。

世界请求的处理程序只注册一次：一个进程只服务一种模式，中途不换世界。菜单进程只注册存档请求。

## 保存时机汇总

- **脉搏（每 5 秒）**：状态 + 事件 + 区块一起落盘。
- **被挤出时**：缓存淘汰的区块立即写回（不等待下一个脉搏）。
- **手动**：玩家主动保存 → 当前记录晋升为回退点（永久保留），随后开启新的当前记录。
- **回滚前**：离开时刻的当前记录原地冻结（保护最新分支）。
- **退出**：排空保存队列做最后一次保存。

## 回退点血缘（时间线分叉）

每个世界的 `lineage.json` 记录回退点的父子关系（时间线分叉元数据，世界级，不随回退点打包——回退点依赖世界内的血缘提供上下文）。文件为签名包装结构（与状态文件同密钥、同威胁级别：防直读/防误改，不防推导）：

```
{data: {live_origin: <回退点文件名 | "">,   # 当前文件来源（回滚目标 / "" = 世界初始）
        snapshots: {<回退点文件名>: {
            parent: <派生来源文件名 | "">,   # 创建时文件来源
            game_time: <游戏时间>, saved_at: <真实时刻>,
            seq: <单调递增序号>}}},          # 权威排序键（创建顺序，回滚后游戏时间倒退不受影响）
 sig: <签名>}
```

- `seq` 是排序的唯一依据：编号、时间线内串链、兄弟排序统一使用；`saved_at` / `game_time` 仅作展示；文件的修改时间不参与排序。
- **严格模式**：无有效签名的血缘一律视为损坏；血缘无法验签时不执行任何自动淘汰（宁可多留，不误删）。

### 回退点删除（单一原语）

删除统一走一个原语：调用方给出要删除的文件列表，原语负责血缘重接、当前来源回退、序号保留空洞、文件删除容忍缺失（磁盘可能已丢，血缘必须自洽）。

- **血缘重接**：被删节点的每个存活子节点，其来源上溯为最近的存活祖先；找不到则为世界初始。
- **当前来源可删**：当前来源指向被删节点时沿同一规则回退到最近存活祖先，不拒绝删除。
- **序号保留空洞**：不重编号——序号是创建顺序，重排会破坏其它会话的编号事实；前端编号为位置序号，对空洞免疫。
- **范围计算**：单点删除 = 节点本身（后代重接）；分支裁剪 = 节点 + 全部后代；保留策略淘汰 = 满足保留规则的最老集合。子树删除没有"重挂"语义。

### 前端交互

- 点击回退点节点 = 选中并弹出操作面板：「进入存档点」（回滚，直接执行）、「删除存档点」（单点，后代重接）、「删除分支」——仅当节点有后代时显示；再次点击同一节点或点击空白处关闭面板。
- 删除为危险操作：面板内删除项点击后弹出确认弹窗（说明删除影响），确认才执行，取消 / 点弹窗外 / 按 Esc 关闭；当前来源节点不可删除，点击直接进入世界。存档行（整个世界）的删除同样走确认弹窗（删除存档及其全部回退点）。
- 删除完成后刷新存档列表并保持时间线展开；仅当展开的世界行本身被删除时才收起。

## 界面请求（请求-响应通道）

```
save_list            列出所有世界与回退点（含血缘字段），存档选择页数据源
save_create          创建新世界存档位（名称、种子、生成参数；种子缺省在创建时随机定案；
                     生成参数为创建世界流程的调参产出：陆地比例、宽、高，
                     随档定案与种子同权重；名称全集合唯一，重名拒绝）
save_snapshot        手动创建回退点（当前记录晋升为保存节点），返回回退点文件名
save_snapshot_delete 删除回退点（单点 / 分支裁剪），返回已删列表
save_rename          重命名（名称全集合唯一；与自身同名允许）
save_delete          删除世界（连带回退点），需确认
save_export          复制世界为新的存档位（副本自动追加"副本"后缀保持名称唯一；
                     回退点逐个改绑副本编号——副本自包含，预览/回滚不依赖原世界；
                     任一回退点损坏即整体失败）
```

进入世界 / 回滚不走请求通道：前端停菜单进程、以 `run_server --world-id <编号> [--snapshot <文件>]` 拉起世界进程——`--world-id` 加载活目录；`--snapshot` 回滚（新进程启动时先保留离开时的进度再展开，保护语义不变）。

全部为世界外元操作：不产生历史、不进因果图。

## 与相邻工作项的关系

- **实体持久化（#25）**：未实现，被本设计阻塞。目录结构、实体文件格式、读档语义（不发布诞生事件）由本设计确定，实现在 #25 落地。
- **存档选择页（#14）**：`save_list` / `save_create` / `save_rename` / `save_delete` / `save_export` 为其接口。
- **开始游戏流程（#8）**：创建世界经多步调参（实时地形预览）→ `save_create`（种子 + 生成参数随档定案）→ 停菜单进程、以 `--world-id` 拉起世界进程 → 加载进度页（阶段广播驱动进度）→ 世界就绪进入主世界。存档选择页「新建游戏」同样进入该流程。

## 未实现的部分

- **实体表全量持久化（#25）**：实体文件只预留位置，尚未写入与读取；当前只有玩家位置随状态保存。
- **退出保存回退点**：`quit` 类型的保留策略已预留（保留最近 3 个），退出时创建退出回退点尚未接入（退出目前只做最后一次保存）。
- **SQLCipher**：若数据文件级真加密成为需求，替换明文数据文件（牺牲实时增量写兼容性）。
- **存档版本迁移**：若介绍信息格式需要变更，实现逐版本迁移（当前无版本号机制）。
- **用户密码派生**：如需强防读取（非防误改），改为用户密码派生密钥。
