# 存档系统 — 技术

实现记录。设计决策与语义见 [设计.md](设计.md)。

## 模块结构

```
ascend/save/
  __init__.py     # 导出公共 API
  crypto.py       # SaveKeys：加密 + HMAC 签名
  io.py           # atomic_write：原子写（唯一临时名 + fsync + rename）
  manifest.py     # Manifest：存档位元信息读写
  manager.py      # SaveManager：编排层（世界管理 + 实时状态 + 快照语义组合）
  snapshot.py     # SnapshotStore：快照文件原语（打包/增量 diff/物化/重基座）
  lineage.py      # LineageStore：血缘文件（lineage.json）读写与条目维护；
                  # SnapshotEntry 条目契约（parent/game_time/saved_at/seq，
                  # frozen dataclass + 容错解析）+ 血缘文档键常量
                  # （LIVE_ORIGIN_KEY 等，全库禁止魔法字符串）
  serializer.py   # collect_state / aligned_time / apply_clock / apply_player
```

职责划分：`SaveManager` 保留公开 API 与快照编排（晋升/冻结/
删除/保留策略的语义组合）；`SnapshotStore` 为快照文件低层原语（依赖血缘
存储做锚点解析与链式物化）；`LineageStore` 只读写世界血缘文件。依赖方向
`manager → snapshot → lineage` 单向无环。

## 磁盘布局

```
<SAVE_ROOT>/<world_id>/                   # 一个存档位 = 一个目录
    manifest.json          # 明文元信息 + 密钥混淆串 secrets_blob
    state.json.enc         # 加密 + HMAC
    entities.json.enc      # 预留（Issue #25，未实现）
    chunks.db              # SQLite WAL（ChunkStore 直接打开）
    events.db              # SQLite WAL（EventArchive 直接打开）
    continent.bin          # 大陆宏观场缓存（可再生）
    lineage.json           # 血缘（时间线分叉元数据，签名包装）
    snapshots/             # 回退点集合（回滚时保留自身）
        @<ts>-<uniq>-<suffix>.ascendsave
```

- `SAVE_ROOT` 由环境变量 `ASCEND_SAVE_ROOT` 指定（`config.py`），默认
  `~/.ascend/saves`；无设置界面入口。
- 快照是世界目录内的兄弟子目录：回滚替换活文件时快照先移出再放回，不受影响。
- 回滚换目录的墓碑/临时目录/挂起标记前缀（`.old-` / `.extract-` /
  `.extract-pending-`）：确定性命名，目录存在性即崩溃现场状态，
  `SaveManager` 构造期 `_recover_interrupted_extract()` 向前补全。

## 加密（crypto.py）

- 密钥：每存档自动生成 32B 加密密钥 + 32B 签名密钥，经 `protect()` 用
  world_id + seed 派生密钥加密后藏入 `manifest.json` 的 `secrets_blob`
  （混淆层：防直读/防手贱，不防推导——威胁模型见设计文档；随档分发→
  自动解锁，可移植）。
- 文件格式：`HMAC_SHA256(ciphertext) || ciphertext`，`ciphertext` 为
  Fernet token。`SaveKeys.decrypt` 先验 HMAC 再解密；任一失败抛
  `SaveCryptoError`。
- 快照 `.ascendsave`：首行明文 JSON 头（format/version/base/world_id/
  seed/secrets_blob）+ 会话密钥加密的 zip。会话密钥每次生成，经 protect
  混淆藏入头部 secrets_blob（与存档位同级：防直读/防手贱，不防推导）；
  zip 内文件用世界密钥（藏于 zip 内 manifest 的 secrets_blob）。
  增量链模型：`base=null` 全量（v1 兼容）；`base=<文件>` 增量——文件级
  条目只在变化时携带，SQLite 数据库以 `<库名>.pages` 页图携带。
  锚点规则：每个节点锚定其最近手动祖先（沿血缘 parent 上溯，跳过
  auto/quit；到 `""` 则 base=null）。物化 = 沿链合并（全量解包 + 逐级
  应用增量页覆盖）。`export_world` 以 `rebind_snapshot` 把快照整体改绑
  新世界 ID（头部与内嵌 manifest 同步换身份，钥匙不变）。
- 读档防篡改（设计文档承诺）：chunks.db / events.db 打开后执行
  `PRAGMA integrity_check`，结构性损坏拒绝加载（`ChunkStore.verify()` /
  `EventArchive.verify()`，GameEngine.start 存档模式下调用）。
- 保留策略：auto 环形保留最近 20 个（当前记录 live_origin 永不自动淘汰，
  实际同来源上限 = 21），quit 预留保留最近 3 个，manual 永久保留
  （`AUTO_SNAPSHOT_KEEP` / `QUIT_SNAPSHOT_KEEP`，snapshot.py）。

## SaveManager（manager.py）

编排层：世界管理 + 实时状态 + 快照语义组合。快照文件原语在
`SnapshotStore`（snapshot.py），血缘文件在 `LineageStore`（lineage.py）。

| 方法 | 说明 |
|---|---|
| `create_world(name, seed, world_id=None, gen_params=None)` | 建活目录 + 密钥 + 初版 manifest（seed=0 创建时随机定案；名称全集合唯一） |
| `get_manifest(world_id)` / `list_worlds()` | manifest 读取 / 摘要列表（损坏项跳过；含 snapshot_count / latest_snapshot_at / birth_chunk / gen_params） |
| `rename_world` / `delete_world` / `export_world` | 重命名 / 删除（含快照）/ 复制为新世界（快照改绑新 ID） |
| `write_state(world_id, state)` / `read_state(world_id)` | 加密原子写 / 解密读（篡改抛 `SaveCryptoError`） |
| `create_snapshot(world_id, suffix="manual")` | 保存语义：当前 auto 记录**晋升**为保存节点（内容刷新为当前活状态，parent/seq 保留，原 auto 文件删除）并在其下游开启新 auto 当前记录；suffix="auto" 为原语路径（创建/冻结当前记录本身） |
| `enter_snapshot(snapshot_path, world_id)` | 完整进入语义：冻结离开记录 → 展开目标 → 非 auto 目标在其下游开启新 auto 当前记录（分叉点）；auto 目标 = 继续，不新建节点 |
| `list_snapshots(world_id)` | 快照列表（file/saved_at/suffix/size） |
| `read_snapshot_state(snapshot_path)` | 快照内 state 预览（回滚确认用） |
| `extract_snapshot(snapshot_path)` | 解密 → 临时目录 → 原子替换活目录，返回 world_id；防 zip 路径穿越 |
| `remove_snapshots(world_id, files)` | **删除原语**：血缘重接（子节点上溯最近存活祖先）、live_origin 回退、seq 留空洞、文件删除容忍缺失；返回已删文件名列表 |
| `remove_snapshot_branch(world_id, filename)` | 分支裁剪：BFS 收集节点+后代后走原语 |
| `snapshot_lineage(world_id)` | 血缘读取（live_origin / 父子关系 / seq） |
| `world_dir` / `snapshot_dir` / `manifest_path` / `state_path` / `lineage_path` / `chunks_db_path` / `events_db_path` / `continent_path` | 路径助手 |

内部方法（下划线前缀，外部不直接调用）：`_set_live_origin`（回滚后记录活目录来源）、
`_refresh_snapshot`（auto 节点原地冻结）、`_prune_snapshots`（保留策略淘汰）、
`_create_plain_snapshot` / `_promote_auto_snapshot`（快照新建/晋升原语）。

## 状态序列化（serializer.py）

```json
state = {
  "clock": {"time": int, "speed": float, "paused": bool},
  "player": {"entity_id": str|null, "x": float, "y": float},
  "archive_max_timestamp": int
}
```

- `collect_state(clock, player_service, weather_engine, archive_max_timestamp)`：采集
  （weather_engine 为参位占位，天气不序列化——由 manifest.seed + 恢复后的时钟确定性重建）。
- `aligned_time(state)`：读档时钟 = `max(clock.time, archive_max_timestamp)`
  （防时间倒流）。
- `apply_clock(state, clock)` / `apply_player(state, player_service)`：
  恢复时钟 + 玩家（静默，不发布事件）。

## 恢复接口（各子系统）

- `WorldClock.restore(*, time, speed, paused)`（time/clock.py）：设置时钟状态，不触发回调。
- `EntityManager.restore(entity_id, type, cx, cy, tx, ty, *, layer_id, controller, data, born_at)`（entity/manager.py）：静默恢复，**不发布 entity_born**（Issue #20/#25 语义）；#25 全量实体表恢复复用。
- `PlayerService.restore(entity_id, x, y)`（entity/player.py）：绑定/静默重建玩家实体 + 位置校准。
- `WorldTree.configure(archive_path=...)`：路径变化时自动关闭旧归档并切换（读档切存档位）。
- `WorldTree.archive_pending()`：保存脉搏时归档全部内存缓冲并清空（flush-and-drop，事件单一事实源）。
- `WorldTree.archived_max_timestamp()`：归档最新事件时间戳（时钟对齐）。
- `ChunkStore.flush()`：已加载 chunk 全量落盘（dirty 或首次加载；已落盘跳过，重访不重写）。
- `WeatherEngine.seed`（property）：天气状态由 seed + 时钟确定性重建，无需额外序列化。

## GameEngine 集成（game.py）

- `load_world(world_id, snapshot=None, regen_continent=False)`：世界进程
  启动入口（run_server --world-id/--snapshot/--regen-continent）。回滚经
  `save_manager.enter_snapshot(snapshot, world_id=world_id)` 统一处理
  （冻结离开记录 → 展开 → 手动档开启新当前记录），再 `start(world_id)`；
  目标非当前加载世界时其 DB 未打开，直接打包活目录即为一致快照。
- `start(*, world_id=None)`：读档模式（seed/DB 路径/时钟/玩家全恢复）；
  state 文件缺失 = 新世界首次进入。网络层先行（端口先开、世界后生成，
  前端可连收 world_progress）。
- 保存脉搏：每 `SAVE_PULSE_INTERVAL`(5s)，tick 线程只入队
  （`_maybe_save_pulse`，单槽位防堆积、零 I/O 阻塞），专用保存线程串行
  执行 **事件 flush（archive_pending）→ state 写入 → chunk flush
  （ChunkStore.flush）**——三样数据同一点提交，顺序保证 state 的
  `archive_max_timestamp` 新鲜。单步失败记录日志不阻断其余步骤。
- 退出保存：`_cleanup_world()` 中 `world_tree.await_async()` 之后同步排空
  `_final_pulse()`（最终脉搏，等价最后一次完整落盘）。
- 快照强一致点：`snapshot_current()` 对当前加载世界先同步完整脉搏再
  `checkpoint()` 两库（WAL 强制写回），快照含近期事件。
- 进程模型（一进程一模式）：菜单进程（服务模式，仅存档管理）与 世界进程
  （--world-id 直启世界）分离；进入世界 / 回滚 = 前端停旧进程、以目标
  参数拉起新进程（Connection.restart_backend）。进程内不换世界。
  服务模式不启动保存线程。
- 无存档模式（`world_id=None`，测试/调试）：保存线程同样运行，事件按
  脉搏 flush 到 `{tmpdir}/ascend-dev/events.db`（`WT_ARCHIVE_PATH`）、
  chunk flush 到 `{tmpdir}/ascend-dev/chunks.db`（`CHUNK_STORE_DB_PATH`）
  ——调试数据根在系统临时目录，随 /tmp 清理；state 写入跳过（无存档位）。

## 网络协议（save_handler.py）

全部为状态通道 request-response，响应带 `request_type` 与 `seq`：

| 请求 | 载荷 | 响应 payload |
|---|---|---|
| `save_list` | — | `{worlds: [摘要], snapshots: [...], current_world_id}`：worlds 条目含 world_id/name/seed/birth_chunk/gen_params/game_time/play_duration_sec/created_at/last_played_at/snapshot_count/latest_snapshot_at/live_origin；snapshots 条目含 world_id/file/saved_at/suffix/size/parent/game_time/seq（血缘字段驱动时间线分叉视图） |
| `save_create` | `{name, seed?, gen_params?}` | `{world_id}` |
| `save_snapshot` | `{world_id}` | `{file}`（手动保存：当前 auto 记录晋升 + 新当前记录；引擎可用时走 snapshot_current 强一致路径） |
| `save_snapshot_delete` | `{world_id, snapshot, recursive?}` | `{deleted: [file]}`（recursive=false 单点删除后代重接；true 分支裁剪；快照不在血缘报错） |
| `save_rename` | `{world_id, name}` | `{world_id, name}` |
| `save_delete` | `{world_id}` | `{}` |
| `save_export` | `{world_id}` | `{world_id: 新ID}` |

进入世界 / 回滚不走请求通道：前端停菜单进程、以 `run_server --world-id
<id> [--snapshot <file>]` 拉起世界进程（进程模型）。

错误经 dispatcher 返回 `type=error`（未知 world_id、空名称等）。
