# 存档系统 — 技术

实现记录。设计决策与语义见 [设计.md](设计.md)。

## 模块结构

```
ascend/save/
  __init__.py     # 导出公共 API
  crypto.py       # SaveKeys：Fernet 加密 + HMAC 签名
  manifest.py     # Manifest：存档位元信息读写
  manager.py      # SaveManager：磁盘层全部操作
  serializer.py   # collect_state / apply_state / aligned_time
```

## 磁盘布局

```
<SAVE_ROOT>/<world_id>/                   # 一个存档位 = 一个目录
    manifest.json          # 明文元信息 + 密钥混淆串 secrets_blob
    state.json.enc         # 加密 + HMAC
    entities.json.enc      # 预留（Issue #25）
    chunks.db              # SQLite WAL（ChunkStore 直接打开）
    events.db              # SQLite WAL（EventArchive 直接打开）
    continent.bin          # 大陆宏观场缓存（可再生）
    snapshots/             # 回退点集合（回滚时保留自身）
        @<ts>-<uniq>-<suffix>.ascendsave
```

- `SAVE_ROOT` 默认 `~/.ascend/saves`（`config.py: SAVE_ROOT`，可在设置调整）。
- 快照是世界目录内的兄弟子目录：回滚替换活文件时快照先移出再放回，不受影响。

## 加密（crypto.py）

- 密钥：每存档自动生成 32B Fernet 密钥 + 32B 签名密钥，经 `protect()` 用
  world_id + seed 派生密钥加密后藏入 `manifest.json` 的 `secrets_blob`
  （混淆层：防直读/防手贱，不防推导——威胁模型见设计文档；随档分发→
  自动解锁，可移植）。
- 文件格式：`HMAC_SHA256(ciphertext) || ciphertext`，`ciphertext` 为 Fernet token。
- `SaveKeys.decrypt` 先验 HMAC 再 Fernet 解密；任一失败抛 `SaveCryptoError`。
- 快照 `.ascendsave`：首行明文 JSON 头 `{"format":"ascendsave","version":1,"fernet_key":...,"sign_key":...}` + 会话密钥加密的 zip。会话密钥每次生成（头部随档分发）；zip 内文件的加密仍用世界密钥（藏于 zip 内 manifest 的 secrets_blob）。
- 读档防篡改（设计文档承诺）：chunks.db / events.db 打开后执行
  `PRAGMA integrity_check`，结构性损坏拒绝加载（`ChunkStore.verify()` /
  `EventArchive.verify()`，GameEngine.start 存档模式下调用）。

## SaveManager（manager.py）

| 方法 | 说明 |
|---|---|
| `create_world(name, seed, world_id=None)` | 建活目录 + 密钥 + 初版 manifest |
| `get_manifest(world_id)` / `list_worlds()` | manifest 读取 / 摘要列表（损坏项跳过） |
| `rename_world` / `delete_world` / `export_world` | 重命名 / 删除（含快照）/ 复制为新世界 |
| `write_state(world_id, state)` / `read_state(world_id)` | 加密原子写 / 解密读（篡改抛 `SaveCryptoError`） |
| `create_snapshot(world_id, suffix="manual")` | 打包加密快照，返回文件名 |
| `list_snapshots(world_id)` | 快照列表（file/saved_at/suffix/size） |
| `read_snapshot_state(snapshot_path)` | 快照内 state 预览（回滚确认用） |
| `extract_snapshot(snapshot_path)` | 解密 → 临时目录 → 原子替换活目录，返回 world_id；防 zip 路径穿越 |
| `chunks_db_path` / `events_db_path` | 引擎直接以存档内路径打开 DB |

## 状态序列化（serializer.py）

```json
state = {
  "clock": {"time": int, "speed": float, "paused": bool},
  "player": {"entity_id": str|null, "x": float, "y": float},
  "weather": {"seed": int},
  "archive_max_timestamp": int
}
```

- `collect_state(clock, player_service, weather_engine, archive_max_timestamp)`：采集。
- `aligned_time(state)`：读档时钟 = `max(clock.time, archive_max_timestamp)`（防时间倒流）。
- `apply_state(state, clock, player_service)`：恢复时钟 + 玩家（静默，不发布事件）。

## 恢复接口（各子系统）

- `WorldClock.restore(*, time, speed, paused)`（time/clock.py）：设置时钟状态，不触发回调。
- `EntityManager.restore(entity_id, type, cx, cy, tx, ty, *, layer_id, controller, data, born_at)`（entity/manager.py）：静默恢复，**不发布 entity_born**（Issue #20/#25 语义）；#25 全量实体表恢复复用。
- `PlayerService.restore(entity_id, x, y)`（entity/player.py）：绑定/静默重建玩家实体 + 位置校准。
- `WorldTree.configure(archive_path=...)`：路径变化时自动关闭旧归档并切换（读档切存档位）。
- `WorldTree.archived_max_timestamp()`：归档最新事件时间戳（时钟对齐）。
- `ChunkStore.flush_dirty()`：仅写 dirty chunk（周期实时保存）。
- `WeatherEngine.seed`（property）：天气状态由 seed + 时钟确定性重建，无需额外序列化。

## GameEngine 集成（game.py）

- `load_world(world_id, snapshot=None)`：世界进程启动入口（run_server --world-id/--snapshot）。回滚时先 `create_snapshot("auto")` 保护活目录分支，再 `extract_snapshot`，最后 `start(world_id)`。
- `start(*, world_id=None)`：读档模式（seed/DB 路径/时钟/玩家全恢复）；state 文件缺失 = 新世界首次进入。网络层先行（端口先开、世界后生成，前端可连收 world_progress）。
- 周期保存：state 每 `SAVE_STATE_INTERVAL`(5s)、dirty chunk 每 `SAVE_CHUNK_FLUSH_INTERVAL`(30s)，在 tick 循环内执行（`_maybe_save_state`），失败记录日志不中断。
- 退出保存：`_cleanup()` 中 `_save_state_now()`（世界树 await 之后、子系统关闭前）。
- 进程模型（一进程一模式）：菜单进程（服务模式，仅存档管理）与 世界进程（--world-id 直启世界）分离；进入世界 / 回滚 = 前端停旧进程、以目标参数拉起新进程（Connection.restart_backend）。进程内不换世界，无同进程读档重建。
- 无存档模式（`world_id=None`，测试/调试）：行为与旧版一致（全局 DB 路径）。

## 网络协议（save_handler.py）

全部为状态通道 request-response，响应带 `request_type` 与 `seq`：

| 请求 | 载荷 | 响应 payload |
|---|---|---|
| `save_list` | — | `{worlds: [摘要], snapshots: [{world_id, file, saved_at, suffix, size}]}` |
| `save_create` | `{name, seed?}` | `{world_id}` |
| `save_snapshot` | `{world_id}` | `{file}` |
| `save_rename` | `{world_id, name}` | `{world_id, name}` |
| `save_delete` | `{world_id}` | `{}` |
| `save_export` | `{world_id}` | `{world_id: 新ID}` |

进入世界 / 回滚不走请求通道：前端停菜单进程、以 `run_server --world-id <id> [--snapshot <file>]` 拉起世界进程（进程模型重构）。

错误经 dispatcher 返回 `type=error`（未知 world_id、空名称等）。
