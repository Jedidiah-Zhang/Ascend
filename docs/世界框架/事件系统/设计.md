# 世界树 — 设计

世界树是连接所有模块的**中枢**——所有状态变化在此记录、路由与流转。

世界中的一切变化——从一场雨到一个文明兴衰——都作为事件在世界树上流动。气候系统不直接告诉 NPC 下雨了，生态变化不直接通知聚落，NPC 之间的互动也不走私有的通信管道。所有模块都向世界树发布事件，所有模块都从世界树订阅自己关心的事件。

## 事件与状态

世界中的变化分三类，处理方式不同：

- **事件**：离散的变化瞬间，具有因果/观测意义，进入事件记录并持久化。系统事件（下雨/停雨、日期变更）、实体事件（出生/死亡/移动）、玩家行动都属此类。
- **状态**：随时间累积的量，无法从种子重新算出，保存到地图区块/存档状态里（如湿润、覆雪、结冰这类需要积分的值——这部分未实现，见地形状态文档）。
- **解析量**：随时可以从其他数据推算出来的值，不保存，运行时现算（如当前温度）。

判定方式：需要跨会话追溯因果的变化 → 事件；可确定性重建的累积量 → 状态存储；纯派生 → 不落盘。

## 事件结构

每个事件包含：

- **发起方**：谁/什么触发了这个事件（系统、NPC、玩家）
- **受影响方**：谁/什么受到了影响（可以是实体集合、区域、整个世界）
- **事件数据**：发生了什么的具体内容
- **时间戳**：世界时间
- **位置**：事件发生的地点（所属区块、层、格点）
- **关系**：引用其他事件（引发它的原因、被谁观测等）

## 事件契约

每个模块发布什么内容，由该模块自己声明：一个事件契约类，字段就是事件数据的键，类型就是数据的类型，事件类型名由类属性声明。契约类放在发布代码所在的模块里，发布时实例化契约、取出数据即可，不需要重复写类型名。

新增一种事件 = 新增一个契约类 + 在发布处实例化 + 契约测试加一行。事件类型名全局唯一，由契约测试保证。发布路径不校验数据内容——数据形状由契约类在构造时强制。

## 三层存储

事件数据分三处存放：

- **活跃窗口（内存）**：近期事件的完整数据，提供按时间、按实体、按空间位置的快速查找。空间上按区块再细分的格子分桶，支持精确到格点附近的小范围查询。模块通过订阅实时接收事件。
- **历史归档（磁盘）**：每个保存脉搏（默认 5 秒）把内存中的全部事件写入磁盘记录并清空内存（flush-and-drop，见事件系统/技术.md）。查询时自动合并两处结果，对调用方透明，不重复不遗漏。事件量在单个脉搏内超过上限时，按权重分层清理作为兜底。
- **因果图（内存 + 磁盘）**：事件之间的关系边同时存在内存和磁盘记录中。重启时从磁盘边记录恢复最近的边，加速因果追溯；被清理掉的事件体仍可按需从磁盘补全。

## 事件关系

事件之间不是简单的线性链条，而是**有向图**。关系类型包括：

| 关系 | 含义 | 示例 |
| ------------------ | ---------------------- | ------------------------------ |
| `caused_by` | A 导致了 B | 暴雨 → 洪水冲毁粮仓 |
| `observes` | 观测事件引用被观测事件 | NPC 注意到下雨 → 引用下雨事件 |
| `co_participant` | 多方共同参与 | 婚礼中双方都是发起方 |
| `informed_by` | 从他人处获知 | 从邻居那里听说某件事 |

`informed_by` 尚未有系统使用（仅数据结构和图接口支持）。

## 按发起方分类

### 系统事件

非人格系统发起。气候（下雨、暴风）、物理法则范畴内的变化。这是当前实际存在的事件来源。

### NPC 事件

NPC 发起：行动、言语、观测、情感、决策。**未实现**——当前没有 NPC 系统，事件字段与图结构已支持（发起方类型 `npc`、观测引用 `observes`），实际由 NPC 产生的发布待心智系统落地。

### 玩家事件

玩家发起。与 NPC 事件结构相同，但发起方为玩家。当前已实现玩家传送（`player_teleported`）；其余玩家行动（建造、交互等）**未实现**。

## 观测的分层

观测事件不是"NPC 主观决定去注意"的结果。它有物理前提和认知加工两层：感知层（自动物理判定：距离、遮蔽、感官状态）和注意层（主观关注程度，影响记忆深度和是否触发反思）。**当前未实现**——感知判定、注意层、反思触发均无代码（`observes` 字段与图查询接口已就绪）。

## 共享事件

当一个事件有多个共同参与者时（如结婚、合作、冲突），每个参与者都将其记录在自己的时间线上。不是复制——是同一个事件，所有参与方的时间线都引用到它。**当前未实现**——`co_participants` 字段已存在，暂无系统发布多方参与事件。

## 事件与快进

快进期间，世界树持续记录系统产出的事件与 NPC 响应产生的事件，因果链逐步展开，行为层在因果分叉点推演（见 [心智系统 / AI原生NPC/设计.md](../../心智系统/AI原生NPC/设计.md)）。不是一次性跳过几十年然后生成摘要，而是事件链逐个推演。**当前未实现**——无快进游戏功能（时钟原语 `run_to` 存在但无调用方，见时间系统文档）。

## 事件的遗忘

NPC 的记忆有限，事件随时间衰减：日常琐事淡出活跃记忆，情感重大事件长期记住。重要性判定由注意层关注程度 + 事件本身的客观影响范围共同决定。**当前未实现**——NPC 时间线索引与记忆衰减均无代码（见事件系统/技术.md"待实现"部分）。

当前事件记录本身有对应的清理机制：清理按权重分层，普通事件最先清理，关键事件存活更久；事件体被清理后，因果边仍保留在磁盘记录中，因果链跨会话可追溯。

## 世界树上的各模块

所有模块通过世界树连接，发布和订阅事件：

- → **时间系统**：时间推进是世界树的主时钟，每个事件带上时间戳（日历事件实际发布：分钟/小时/日期变更）
- → **气候系统**：向世界树发布天气变化事件；不关心谁在听，只负责发布
- → **表现层**：订阅世界树，把事件转发给前端（实时广播）

以下为规划中的连接（**未实现**）：生态系统（种群波动、花期）、心智系统（订阅与 NPC 相关的事件、观测判定、注意层、反思触发）、群体社会（聚落事件、事件升级）、玩家行动（玩家事件、地形编辑）、表现层（视觉/音效/UI 通知）。
