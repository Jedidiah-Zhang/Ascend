# 地形状态 — 设计

地形状态是基底之上的动态叠加层。基底决定"这格是什么"，状态决定"这格现在怎么样"——游戏逻辑（寻路/碰撞/建造）以基底为骨架，状态为修正。状态不覆盖基底，只修正参数。

**状态 = 有玩法消费方的量**：无消费方的视觉变化（如"淋湿变深色"）是渲染层贴花，不进状态层。

## 两层模型

```
基底类型（TerrainType）      状态层（TileState）
─────────────────          ─────────────────
准静态，生成时确定          动态叠加，天气场驱动
见《地图生成/设计.md》       湿润 / 覆雪 / 结冰
```

## 状态集合

| 状态 | 字段 | 适用基底 | 主消费方 | 驱动 |
| --- | --- | --- | --- | --- |
| 湿润 | uint8 (0-100) | 土壤类、沙地 | 土壤→植物生长；沙地→行动 | 降水沉积 − 排水（坡度/渗水） − 蒸发 |
| 覆雪 | uint8 (cm) | 全部陆地基底 ∪ 冰面 | 行动（15/30/50cm 阶梯）、采集效率、视觉 | 降水（≤0°C）沉积 − 温度融雪 |
| 结冰 | uint8（厚度） | 仅水面 | 通行性（冬季步行过河）、视觉 | 温度 <0 累积 / >0 融化 |

雪档位 thresholds=(15, 30, 50) 是行为阈值事件触发点。

**不适用规则**：

- 岩石类（ROCK / GRAVEL / PERMAFROST）：无湿润——岩石不吸水
- 开放水面：无湿润（无意义）；无覆雪——水面先结冰，雪落冰上
- 沙地（SAND）：湿润初始不适用（沙漠语义，沙干得快）；预留（未来若需"湿沙影响行动"，消费方已声明）

### 状态-基底兼容矩阵

按**基底类别**声明（不逐型列举，加新地形不破矩阵）：

| 基底类别 | 湿润 | 覆雪 | 结冰 |
| --- | --- | --- | --- |
| 土壤类（FERTILE_SOIL / GRASSLAND / MARSH） | ✓ 生长 | ✓ | ✗ |
| 沙地（SAND） | ✗（预留） | ✓ | ✗ |
| 岩石类（ROCK / GRAVEL / PERMAFROST） | ✗ | ✓ | ✗ |
| 水面（WATER） | ✗ | ✓（仅冰面） | ✓ |

**叠加规则**：水面：湿润不适用 → 结冰 → 冰上覆雪；陆地：湿润 + 覆雪可共存。雪落水中不产生状态（水吸收），只有结冰后才有承载面。

### 通性例外

**结冰是唯一允许覆盖基底通行性的状态**——冰让不可通行的深水变成可通行（冬季过河捷径）。水面通行性按水深实时推导（`water_passability`，见地图生成），结冰覆盖该推导。

规则：状态默认只修正参数（移动速度/效率/产出）；覆盖通行性需显式声明 `overrides_passability`，当前仅结冰授权。

## 明确不做（决策记录）

- **积水**：设计意义不明确（暴雨→洼地积水的玩法消费方未立住），砍
- **薄冰**：现阶段无必要性（融冰期破冰风险玩法无场景），砍；`water_frozen` 保留为 chunk 级布尔聚合
- **冻土**：等有需要再说（冬季采集/基因扩展时立项）
- 冰上可建造性：待定（优先默认不可建造）

## 覆盖度（遮蔽）

建筑/树冠下方的地形不按常规沉积。**遮蔽是实体层的属性，不是 tile 状态**——存成状态就是派生数据的重复拷贝，建筑移除时会留下过期状态。

- 建筑 = 全遮蔽（雪沉积 ×0、湿润 ×0）；树冠 = 部分遮蔽（雪 ×0.3、湿润 ×0.8）；露天 = 无（×1）
- 覆盖度规格已定案（COVERAGE_SPECS），实现为 C 内核的每 tile 沉积倍率（tile_cover）
- **实体查询接入未实现**：`invalidate_coverage` 接口已声明，实体系统增删时失效 chunk 级缓存，接入后启用
- NPC 的"避雪/在室内"语义走事件系统感知层的既有"室内/室外"判定（事件系统/设计.md），不重复造

## 持久化原则

**解析量不存，积分量必存：**

- 统一天气场（seed + 时间可完全重算）→ 不存
- 覆雪/湿润/结冰（天气历史的非线性积分，无闭式解）→ **必存**

- 状态数组随 TileGrid 快照（与 elevation/slope 并列），每 tile 各 1B，200×200 chunk ≈ 40KB/状态
- **chunk 卸载/重载**：状态随 chunk 持久化，重载时恢复——绝不重新积分（流式加载下雪不会凭空消失）
- **settled_day**：状态是"日终态"，另存**状态已结算到的游戏日**，读档/LRU 重载按此续算缺口，防止重放已演化区间

## 解析结算器

状态演化是非线性积分（沉积需温度 <0、融化需正温、冰雪相互作用），无闭式解，需要统一的**大步长近似结算器**（每游戏日一档，按温度均值/降水总量批量推演）。

一个结算器，两个使用场景：

| 场景 | 用法 | 目的 |
| --- | --- | --- |
| 预热（出生前） | 从历史起点结算到出生时刻 | **校准起点**——出生即与季节自洽（极地冬季出生 → 初始就有雪有冰）；发生在加载画面，无跳变感知 |
| 快进（快速旅行/时间跳变） | 结算跳变区间 | **不错位**——快进结束雪与季节对得上，不逐 tick 推演 |

**预热 vs 运行的分工**：预热 = 结算器校准起点；运行期 = 事件驱动批量涂抹 + 前端渐进呈现（见下）。

## 事件三通道（防刷屏）

tile 状态更新**不走事件系统**——"持续状态不是事件，状态改变的瞬间才是事件"（事件系统/设计.md）。三万格同时变湿不是三万条事件，是数据写入：

1. **降水涂抹**（世界树，区域级一条）：降水起止事件（携带区域 chunks 列表）→ 对区域 chunk 即时沉积
2. **小时脉冲**（数据通道）：订阅小时变化，每注册 chunk 演化 1/24 日——实时天气驱动沉积与衰减
3. **日档快进**（世界树）：订阅日变化（跳变时）→ 结算器补缺口

**破阈值叙事事件**（世界树，区域级一条，涂抹的对账出口）：跨过行为阈值才发——**15cm**（采集/行动效率拐点）→ **30cm**（移动惩罚）→ **50cm**（封路/快速旅行受阻）。当前发 `StateThresholdCrossed`（chunk 级聚合，上下沿穿越都发）；消费方（叙事文案/寻路缓存失效）**未接入**。

规则：

- 事件收敛：任何路径的事件数与 tile 数量无关
- 持续状态不发重复事件（"暴雪第 3 天"是状态横幅，不是新事件）

### 寻路与状态

- **路径规划**：静态基底成本 + chunk 级状态聚合（平均雪深、`water_frozen` 布尔）——tile 级状态**不参与路径选择**
- **缓存失效**：仅视野内 chunk 在跨阈值（15/30/50）时失效寻路缓存（视野外 NPC 不模拟具体行为、无逐 tile 寻路，见《群体社会/世界模拟》）——**消费接入未实现**
- **tile 级状态只修正实际移动速度与产出效率**（路径确定后的执行语义）

## 前后端边界

- **后端 = 真值**：状态数组、事件驱动批量涂抹、解析结算器、存档持久化
- **前端 = 显示值追赶**：渲染层持有 `display_*` 缓存，向后端真值渐进收敛，视觉无跳变：
  - **逐帧随机抽样**：每帧随机抽 N 个 tile，被抽中的显示值 `+= step`——不同 tile 错开推进，雪"一片片铺开"，避免"整块同步变白"
  - 初雪/暴雪事件 → 临时提高抽样密度/step（快下快铺）
  - 追赶速率快于感知阈值（偏差有界，几秒到几十秒收敛）
  - **纯视觉缓存**：可真随机，不进存档、不参与逻辑
  - 结冰/湿润共用同一框架（冰面渐凝、色调渐深）
  - **未实现**：当前前端仅解码状态段存储，无渲染消费；详见《表现层/视觉风格/设计.md》

## 状态更新节拍

- **运行期**：后端事件驱动批量涂抹（小时级，绝不逐 tick 全图扫描）；前端逐帧抽样渐进呈现（未实现）
- **快进/预热**：解析结算器大步长
- **0→非0 的存在性翻转**：后端批量写同一值，同步错位由前端逐帧抽样保证（视觉渐进铺开）

## 与基因系统的接口（声明）

状态是基因价值的**展示面**——"世界变难了 → 该不该投资耐寒基因"：

- 耐寒基因：覆雪对移动的惩罚系数修正（覆雪 ≥30cm 无惩罚之类）
- 山地行走基因：坡度对移动成本修正（面内坡度派生属性，见地图生成）
- 两栖/耐涝基因：未来积水通行（若积水重新立项）

基因系统预留"对 tile 状态修正"的扩展点（属性修正维度）。

## 与生态系统的接口（声明）

生物分布已有季节修正（冬眠/迁徙，群系生态/设计.md）；雪深/结冰 → 生物活动密度修正的接口**声明**（后置实现）。

## 与其他模块的接口

- ← **季节气候**：统一天气场合成值 → 阈值判定 → 沉积/融化（见《季节气候/设计.md》"统一天气场"）；`get_day_summary` / `precip_type_for` 供结算器
- ← **地图生成**：基底类型（兼容矩阵输入）、海拔/坡度（排水模型、起伏度）
- ← **实体系统**：覆盖度查询（建筑/树冠）——接口已声明，实体接入后启用
- → **事件系统**：降水起止事件契约扩展（chunks 字段）；破阈值叙事事件 `StateThresholdCrossed`（chunk 级聚合，三通道对账出口）
- → **表现层**：状态数组经 chunk 数据通道下发（与海拔/坡度同列表），F3 面板逐格显示
- → **存档系统**：状态数组随 TileGrid 快照（积分量必存）+ settled_day 列（续算起点）
