# 地形状态 — 技术

## 模块结构

```
ascend/space/
├── state_defs.py       # 状态注册表（STATE_TYPES）+ 状态配置 + 遮蔽规格
├── terrain.py          # 地形注册表加载 + TerrainDef/AltitudeBand schema
│                       #   （内容在 data/terrain.json，见下）
├── tile_grid.py        # TileGrid v2：基底/高程/坡度 + 状态数组（BLOB 版本 2）
├── _state.c            # C 演化内核 state_evolve（结算/脉冲同公式）
├── tile_state.py       # ctypes 包装 + SettlementCalculator + TileStateEngine
├── chunk.py            # ChunkData.settled_day（状态结算日，随库持久化）
└── chunk_store.py      # chunk_tiles 表 + settled_day 列（ALTER 补列兼容旧库）
```

前端对应：`frontend/scripts/world/main_world.gd`（BLOB v2 解码）。

## 地形注册表（data/terrain.json，单一事实源）

`terrain.py` 从 `data/terrain.json` 构建 `TERRAIN_DEFS: dict[str, TerrainDef]`
——**加一个地形 = 数据文件加一项（value 追加）**，枚举（动态生成
IntEnum）、游戏性属性、状态参数、海拔带生成分类、陡坡重分类豁免全部
由它派生，算法代码零改动。注册表键为命名空间 id（`ascend:grassland`），
显示名存 `label_key`（文案在 `lang/*.json`）。

```
TerrainDef
├── ns_id / value       命名空间 id / 持久化值（BLOB 契约，不可改，只能追加）
├── label_key           显示名 i18n 键（文案在 lang/*.json）
├── passable / buildable / movement_cost / fertility
├── states             状态参数（None = 不适用）
├── water              水域标志（陡坡重分类豁免等水域语义）
├── altitude           海拔带 AltitudeBand（参与生成分类；None=不生成）
├── no_steep_reclass   陡坡重分类豁免
└── fallback           无带命中兜底（全表唯一，SAND）
```

- **海拔带**：`(lo, hi, priority)` 半开区间 `[lo, hi)`，priority 越大越优先
  （重叠时高者胜）；`lo_delta`/`hi_delta` 为 TerrainBias 字段名，生成时
  对边界加群系偏移——基准值引用 config 调参常量，加地形调带不碰生成算法
- 派生：`TerrainType` 枚举（value 升序）、`WATER_TYPES`（water 标志）、
  `get_terrain_def()`/`is_passable`/`is_buildable`/`movement_cost`/
  `fertility`/`state_params()`（原 state_defs.TERRAIN_STATE_PARAMS 矩阵并入）
- 完整性兜底：test_state_defs.py 矩阵测试遍历注册表 × 状态，漏声明即 fail

**增删状态** = `STATE_TYPES` 加/减一行 + bump TileGrid._TILEGRID_VERSION
+ 前端 STATE_KEYS 同步（仍走 state_defs 注册表，序列化/涂抹/结算零改动）。

## TileGrid v2 BLOB

4B 版本头（LE uint32）+ 80KB 地形（uint16 LE）+ 160KB 高程（float32 LE）+ 160KB 坡度（float32 LE）+ 状态段（按 `STATE_TYPES` 注册顺序，各 40KB uint8）。

```
TileGrid
├── 版本头       uint32 LE        4B
├── 地形         uint16 LE        80KB   TerrainType 枚举
├── 高程         float32 LE       160KB  tile 级连续高度 (m)
├── 坡度         float32 LE       160KB  tile 级局部梯度 (m/m)
└── 状态段       每状态 uint8×40KB       moisture / snow / ice（注册顺序）
```

- 增删状态 = `STATE_TYPES` 加/减一行 + bump `_TILEGRID_VERSION`；`_state_bytes()` 自动跟随注册表
- **无向后兼容**：v1 BLOB（无状态段）`from_bytes` 拒绝（`ValueError`），`chunk_store` 侧包装成明确中文提示
- 前端按版本头查 `_STATE_NAMES_BY_VERSION` 分段解码 + 长度校验，契约漂移时 `push_error` 并标记失败（不无限重试）

## 状态参数表

每个地形的 `states` 行定义在 `data/terrain.json`（单一事实源）：键 = 状态名
（`STATE_TYPES` 的键），值为 `StateParams` 系数对象或 `null`（不适用，恒 0）。
示例语义：

| 地形 | moisture | snow | ice |
| --- | --- | --- | --- |
| 草地/沃土 | deposit 1.6 / drain 0.10 / melt 0.02 | deposit 1.0 / melt 0.15 | — |
| 沙地 | 不适用 | deposit 1.0 / melt 0.15 | — |
| 岩石 | 不适用 | deposit 1.0 / melt 0.15 | — |
| 水面 | 不适用 | deposit 1.0 / melt 0.15 | freeze 1.5 / melt 0.8 |

MARSH 自定义行覆写 moisture drain=0.03（沼泽排水慢），`data/terrain.json` 中
逐型微调。C 内核公式见下。

**注册表驱动契约**：增删地形/状态只需改注册表，涂抹/结算代码零改动
（`_N_STATES`/`_KEY_INDEX`/`state_params()` 全部从注册表派生）。
模板常量定义在 terrain.py（StateParams 类型来自 state_defs.py）。

`COVERAGE_SPECS`：STRUCTURE（雪 ×0、湿润 ×0）、canopy（雪 ×0.3、湿润 ×0.8）、露天 ×1。**查询点占位**：`invalidate_coverage(cx, cy)` 接口已声明，实体系统接入后启用（当前 tile_cover 恒 NULL=1.0）。

## C 内核（_state.c）

```
state_evolve(states(uint8_t**, 行主序), terrain(uint16_t*), slope(float*),
  tile_cover(double*|NULL), n, n_states, n_steps, step_precip(n_states×n_steps),
  step_temp, dt, deposit/drain/melt/freeze(n_states×256), freeze_below/melt_above/state_max)
```

统一公式（**mm/日 标定**，delta × dt 缩放步长）：

```
delta = precip_mm × deposit[t]                  # 沉积（降水）
      + freeze[t] × max(0, freeze_below − temp) # 冻结
      − state × (melt[t]×max(0, temp−melt_above) + drain[t]×(1+slope))  # 衰减
```

- 不适用组合 = 参数表系数全 0 → delta 恒 0 天然空转（无需适用性分支）
- `freeze_below ≤ −9000` 哨兵表示无冻结项；`decay_only` 跳过全零 tile
- 舍入 `(uint8_t)(v + 0.5)`；确定性：无 `-ffast-math`、无 `-march=native`（同 seed 跨机器一致）
- 编译/加载走 `_cext.py`（源码+动态库双路）；打包脚本需显式编译（`build_backend.sh` 预编译 import、`build_backend_windows.sh` 交叉编译循环均含 `_state`）

## 结算器（SettlementCalculator）

- 每日 4 固定采样点（t0=(day−1)·GAME_DAY，步长 GAME_DAY/4），由 `weather_engine.get_day_summary` 提供
- `precip_type_for(round(T,1))` 分雨/雪；mm = intensity × 步长小时数
- `settle(chunk, grid, from_day, to_day)`：C 内核 `state_evolve(dt=1.0)`，一步一日
- 大步长近似（4 点采样日均温 vs 逐小时实时温度）与 24 次脉冲偏差 ≤40（同量级同方向）

## 状态引擎（TileStateEngine）

订阅 world_tree 事件（驱动来源走事件总线，**数据写状态数组**——不逐格发事件）：

| 通道 | 事件 | 动作 |
| --- | --- | --- |
| ① 降水涂抹 | precipitation_start（chunks 必填） | 区域 chunk 即时沉积 dt=1/24（intensity mm/h × 24 → 日速率标定） |
| ② 小时脉冲 | hour_change | 每注册 chunk 演化 dt=1/24；有雨时 `rainfall × 24` 沉积（与结算同标定） |
| ③ 日档快进 | day_change（skipped_days>0） | `settle(previous_day, day)` 补缺口 |

**阈值对账**（`_reconcile_thresholds`）：snow 档位 0/1/2/3（bisect_right on chunk max），穿越上下沿发 `StateThresholdCrossed`（chunk 级聚合事件，消费方：叙事/寻路缓存，后置接入）。穿越事件**锁内收集 → 锁外发布**：`_reconcile_thresholds` 只 append 到 `_pending_publish`；写通道统一走 `_locked_write()` 上下文（锁内写，`finally` 里 `_flush_pending` 锁外发布——发布含网络转发，不得在 `_lock` 内；异常路径同样兜底，不吞事件）。

**聚合**（`aggregates`）：`water_frozen`（水面任一 tile 结冰）/`mean_snow`/`mean_moisture`，懒计算 + 缓存，任何写入失效。

**settled_day 语义**：

- `on_tiles_ready`（tile 生成/恢复完成）：全新 chunk（0）从 epoch=day 1 结算；恢复 chunk 从持久化结算日续算——**不重放历史**
- 脉冲演化后 `_advance_settled_day` 推进到当前日（落盘语义"状态=当日态"成立；settle 路径各自显式管理，`_mark_written` 不得推进——防 settle_gap 虚标）
- 快进缺口起点取 `previous_day`（日历 `skipped = day − previous − 1`，用 previous_day 最可靠）

**线程模型**：写路径全部持 `threading.RLock`（tick 线程事件分发 vs 网络 handler 线程 register/on_tiles_ready/LRU 淘汰注销并发；C 循环毫秒级可接受）。动态生成 chunk：先 `register_chunk`（tile_grid=None）→ tile 生成完成 → `on_tiles_ready` 结算并**回写网格快照**（不回写则小时脉冲永久跳过该 chunk）。

**锁序约定**（防 ABBA 死锁）：`_lock` 内绝不请求 weather `_query_lock`——天气快照一律锁外预取（`_on_precip_start`/`_on_hour_change` 先遍历收集 pending 再进锁；`_on_day_change` 的 settle 已拆 `precompute` 锁外 + `settle_from_summaries` 锁内纯计算）。weather 持锁发布事件同步分发到本引擎处理器请求 `_lock` 是单向依赖（weather → tile_state），安全。

**直写契约**（`touch(cx, cy)`）：生态/基因系统若经 `state_raw()` 直写状态数组（绕过本引擎演化通道），写后必须 `touch`——清聚合缓存与阈值档位缓存，不演化、不推进结算日；本引擎自身写路径已内含失效，无需 touch。

## 事件契约（天气侧变更）

- `PrecipitationStart/Stop.chunks`：**必填**（tuple，序列化为 list）——区域越阈连通域由 region_tracker 计算，`_publish_region_event` 填充
- `RegionEvent.chunks` 字段新增

## 持久化

- 状态数组随 TileGrid BLOB 自动落库（积分量必存）
- `chunk_tiles` 表新增 `settled_day INTEGER NOT NULL DEFAULT 0`；旧库 `ALTER TABLE ADD COLUMN` 就地补列
- `ChunkData.settled_day` 字段；`_save_tiles(cx, cy, grid, settled_day)` / `_persist` 写该列
- `load_tiles_with_day(cx, cy) → (TileGrid, int) | None`（新增；`load_tiles` 签名不变，内部复用）
- 读档/LRU 重载路径（game `_build_tiles`、map_handler 恢复分支）统一走 `load_tiles_with_day` + `chunk.restore_tiles` + `chunk.settled_day = day`，随后 `on_tiles_ready` 续算缺口

## 装配（GameEngine）

- start() 5c：`TileStateEngine(clock, weather_engine, wt)` + `_world_stack` 清理（shutdown=取消订阅+注销全部）
- **chunk 生命周期注册器**（`space/chunk_services.py`）：`ChunkServiceRegistry` 统一广播 `register`/`on_tiles_ready`/`unregister`；`WeatherChunkService`（5 参 register_chunk 适配，on_tiles_ready 空实现——解析算无需追赶）、`TileStateChunkService`（方法名对齐）。game 5c 装配 `ChunkServiceRegistry([WeatherChunkService, TileStateChunkService])`——**新增引擎 = registry.add(service)，生命周期时序零改动**
- `_on_chunk_evicted`：LRU 淘汰时 `chunk_services.unregister(cx, cy)`（注册器统一广播）
- `make_map_handlers(..., chunk_services=None)`：恢复路径 register + 立即 on_tiles_ready；生成路径 register（无网格）→ 异步生成 → on_tiles_ready

## 前端解码

- `_TILE_BLOB_VERSION = 2`；`_STATE_NAMES_BY_VERSION = {2: ["moisture", "snow", "ice"]}`（状态段与版本强关联，防分段错位）
- expected 长度 = 头+地形+高程×2+状态段字节；解码后 `chunk["states"] = {moisture: PackedByteArray, snow: ..., ice: ...}`（各 40KB）
- 前端渲染消费（阶段 3 起）：`StateDisplayChaser` 显示值追赶真值（逐帧随机抽样收敛 + 天气事件加速），独立 States TileMapLayer 渲染，周期刷新换真值（见 表现层/视觉风格/技术.md）

## 性能

本机 24 核实测（`test_tile_state.py::test_c_kernel_performance`）：

| 场景 | 耗时 |
| --- | --- |
| 90 天×49 chunk（全图结算） | ≈ 0.70s |
| 1800 天×1 chunk（单格长快进） | ≈ 0.28s |
| 小时脉冲×49 chunk | ≈ 0.01s |

纯 Python 逐 tile 方案 360 天×1 chunk ≈ 1.04-1.42s——C 内核为必要决策。
