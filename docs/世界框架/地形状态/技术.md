# 地形状态 — 技术

## 模块结构

```
ascend/space/
├── state_defs.py       # 状态注册表（STATE_TYPES）+ 状态配置 + 遮蔽规格 + 内核参数表构建
├── terrain.py          # 地形注册表加载 + TerrainDef schema + water_passability
│                       #   （内容在 data/terrain.json，见下）
├── tile_grid.py        # TileGrid：基底/高程/坡度 + 状态数组（BLOB 版本 1）
├── _state.c            # C 演化内核 state_evolve（数组层直调入口，测试/内核对拍用）
├── tile_state.py       # ctypes 包装 + TileStateEngine（声明更新点的单一积分器）
├── chunk.py            # ChunkData.integrated_through（积分游标，随库持久化）
└── chunk_store.py      # chunk_tiles 表 + integrated_through 列（ALTER 补列兼容旧库）

ascend/world/modules/terrain/
├── module.py           # 地形演化 field 机制声明（方程 + 见证 + 实现摘要）
├── kernel.py           # 参考实现 evolve_reference 与 C 加速绑定（逐位一致）
└── core.py             # TerrainCore：声明程序适配（生产求值路径）
```

前端对应：`frontend/scripts/world/main_world.gd`（BLOB v1 解码）与
`state_display_chaser.gd` / `state_layer_manager.gd`（显示值追赶渲染）。

## 地形注册表（data/terrain.json，单一事实源）

`terrain.py` 从 `data/terrain.json` 构建 `TERRAIN_DEFS: dict[str, TerrainDef]`
——**加一个地形 = 数据文件加一项（value 追加）**，枚举（动态生成
IntEnum）、游戏性属性、状态参数全部由它派生，算法代码零改动。
注册表键为命名空间 id（`ascend:grassland`），显示名存 `label_key`
（文案在 `lang/*.json`）。

`TerrainType` 只表达**纯地表材质**（8 种），
地貌形态（山巅/陡坡）与水体深浅不进枚举——海拔/坡度/水深均为场，
从场推导（见 地图生成 技术）。

```
TerrainDef
├── ns_id / value       命名空间 id / 持久化值（BLOB 契约，不可改，只能追加）
├── label_key           显示名 i18n 键（文案在 lang/*.json）
├── passable / buildable / movement_cost / fertility
├── states             状态参数（None = 不适用）
└── water              水域标志（单一 WATER；结冰/岸边过渡等水域语义）
```

- 派生：`TerrainType` 枚举（value 升序）、`get_terrain_def()`/
  `is_passable`/`is_buildable`/`movement_cost`/`fertility`/`state_params()`
  （地形 × 状态参数矩阵由注册表派生）、
  `water_passability(terrain, elevation)`（水面通行按水深实时推导——
  浅水可涉水，深水不可；**消费方须走此函数，勿用 is_passable 基线**）
- 完整性兜底：test_state_defs.py 矩阵测试遍历注册表 × 状态，漏声明即 fail

**增删状态** = `STATE_TYPES` 加/减一行 + bump TileGrid.TILE_GRID_VERSION
+ 前端 `_STATE_NAMES_BY_VERSION` 同步（序列化/积分由 state_defs 注册表驱动，零改动）。

## TileGrid BLOB（版本 1）

4B 版本头（LE uint32）+ 80KB 地形（uint16 LE）+ 160KB 高程（float32 LE）+ 160KB 坡度（float32 LE）+ 状态段（按 `STATE_TYPES` 注册顺序，各 40KB uint8）。

```
TileGrid
├── 版本头       uint32 LE        4B
├── 地形         uint16 LE        80KB   TerrainType 枚举
├── 高程         float32 LE       160KB  tile 级连续高度 (m)
├── 坡度         float32 LE       160KB  tile 级局部梯度 (m/m)
└── 状态段       每状态 uint8×40KB       moisture / snow / ice（注册顺序）
```

- 增删状态 = `STATE_TYPES` 加/减一行 + bump `TILE_GRID_VERSION`；`_state_bytes()` 自动跟随注册表
- **无向后兼容**：版本不符（其他格式/未来产物）`from_bytes` 拒绝（`ValueError`），`chunk_store` 侧包装成明确中文提示
- 前端按版本头查 `_STATE_NAMES_BY_VERSION` 分段解码 + 长度校验，契约漂移时 `push_error` 并标记失败（不无限重试）

## 状态参数表

每个地形的 `states` 行定义在 `data/terrain.json`（单一事实源）：键 = 状态名
（`STATE_TYPES` 的键），值为 `StateParams` 系数对象或 `null`（不适用，恒 0）。
示例语义：

| 地形 | moisture | snow | ice |
| --- | --- | --- | --- |
| 草地/沃土 | deposit 1.6 / drain 0.10 / melt 0.02 | deposit 1.0 / melt 0.15 | — |
| 沼泽 | deposit 1.6 / drain 0.03 / melt 0.02 | deposit 1.0 / melt 0.15 | — |
| 沙地 | 不适用 | deposit 1.0 / melt 0.15 | — |
| 岩石/砾石/冻土 | 不适用 | deposit 1.0 / melt 0.15 | — |
| 水面 | 不适用 | deposit 1.0 / melt 0.15 | freeze 1.5 / melt 0.8 |

MARSH 自定义行覆写 moisture drain=0.03（沼泽排水慢），`data/terrain.json` 中
逐型微调。C 内核公式见下。状态适用性由注册表 `states` 行的 `null` 声明
（岩石/沙/砾石/冻土/水 的 moisture = 不适用），矩阵测试兜底。

**注册表驱动契约**：增删地形/状态只需改注册表，积分代码零改动
（`_N_STATES`/`_KEYS`/`state_params()` 全部从注册表派生）。
状态参数直接写在 `data/terrain.json` 每行的 `states`（`StateParams` 类型来自 state_defs.py）。

`COVERAGE_SPECS`：STRUCTURE（雪 ×0、湿润 ×0）、canopy（雪 ×0.3、湿润 ×0.8）、露天 ×1。
**实体查询接入未实现**：遮蔽倍率由 `coverage_for()` 按实体类型/标记给出，
C 内核接受每 tile 的 `tile_cover` 参数；当前引擎不传遮蔽（None = 露天 1.0），
实体系统接入后启用（见设计篇）。

## C 内核（_state.c）

```
state_evolve(states(uint8_t**, 行主序), terrain(uint16_t*), slope(float*),
  tile_cover(double*|NULL), n, n_states, n_steps, step_precip(n_states×n_steps),
  step_temp, dt, deposit/drain/melt/freeze(n_states×256), freeze_below/melt_above/state_max)
```

统一公式（**mm/日 标定**，delta × dt 缩放步长）：

```
delta = precip_mm × deposit[t]                  # 沉积（降水）
      + freeze[t] × max(0, freeze_below − temp) # 冻结
      − state × (melt[t]×max(0, temp−melt_above) + drain[t]×(1+slope))  # 衰减
```

- 不适用组合 = 参数表系数全 0 → delta 恒 0 天然空转（无需适用性分支）
- 每步按状态 clamp 到 `[0, state_max]`，`int(v + 0.5)` 量化回 uint8
- `freeze_below ≤ −9000` 哨兵表示无冻结项；无降水且无冻结时只处理非零 tile
- 确定性：无 `-ffast-math`、无 `-march=native`（同 seed 跨机器一致）
- 公式冻结契约：参考实现（`world/modules/terrain/kernel.py::evolve_reference`）
  与 C 加速逐位对拍，黄金向量存 `backend/tests/world/data/terrain_golden.json`
- 编译/加载走 `_cext.py`（源码+动态库双路）；打包脚本需显式编译（`build_backend.sh` / `build_backend_windows.sh` 预编译循环均含 `_state`）

生产路径：`tile_state.state_evolve` 把状态/地形/坡度数组交给声明式地形模块
（`TerrainCore`，field 机制求值），原地回写状态数组；数组层直调入口
`state_evolve_arrays`（`space/_state.c` 零拷贝包装）保留给内核测试对拍。

## 单一积分器（TileStateEngine）

状态演化只有一条路径：**声明更新点（每游戏小时）的单步积分**。

- 驱动：帧调度器把 `TileStateEngine.advance(now)` 绑定到 "hour" 更新点，由时钟
  推进信号调用（tick 线程）；不订阅世界事件，事件只作记录（阈值穿越），不驱动状态。
- 目标更新点 `target = (now // GAME_HOUR) * GAME_HOUR`；每 chunk 从
  `chunk.integrated_through` 逐步积分到 target，步长 `dt = 1/24` 日。
- 每步天气取解析场：`weather.get_weather(cx, cy, boundary)` 给该更新点的
  温度与雨强；雨强换算 `rainfall × 24` mm/日，按 `precip_type_for(温度)`
  分派到 moisture（雨）或 snow（雪）行，ice 行无降水沉积。
- **fail-closed**：任一步边界采样缺失（chunk 未注册到天气引擎）则整段不推进
  游标，待注册后重试；不回退、不部分应用。
- 帧事务（WC-7.6）：积分写状态数组的影子副本，帧边界整组替换提交；
  提交成功才推进游标、置脏（`chunk.mark_modified()`，含内容版本号）并发布阈值事件；
  帧回滚丢弃影子写入、游标不动。
- 注册契约：`register_chunk` 只登记（网格可晚就绪）；`on_tiles_ready`
  在 tile 生成/恢复完成后把状态从游标补齐到当前更新点（读档/LRU 重载续算缺口）；
  `unregister_chunk` 释放。
- 聚合（`aggregates`）：`water_frozen`（水面任一 tile 结冰）/`mean_snow`/`mean_moisture`，
  懒计算 + 缓存，任何提交失效；未注册返回 `{}`。

### 阈值事件（StateThresholdCrossed）

- 积分前后成对比较 chunk 级 max 的档位（`bisect_right` on 15/30/50cm）：
  净升档发 "up"、净降档发 "down"，无净变化不发事件。
- 事件为 chunk 级聚合（一条含 cx/cy/state/value/threshold/direction），
  在提交成功后发布；**只作记录，不反馈演化**。消费方（叙事文案、寻路缓存失效、
  生态/基因修正）待接入。

### 线程模型

- 注册/注销/聚合/提交同持一把 `threading.RLock`；C 循环毫秒级可接受。
- 天气采样在锁外完成（锁序：本引擎锁内不请求 weather 锁），提交前复核游标与网格身份，
  被其他调用抢先推进或网格已替换时跳过。
- 动态生成 chunk：`register_chunk`（网格未就绪）→ tile 生成完成 → `on_tiles_ready` 补齐。

## 事件契约

- 本引擎发布 `state_threshold_crossed`（`StateThresholdCrossed`，chunk 级聚合）——
  只作记录；引擎不订阅任何世界事件，状态演化只读解析天气场。
- 天气侧 `PrecipitationStart/Stop.chunks`（必填，tuple 序列化为 list）与
  `RegionEvent.chunks` 由 region_tracker 计算、`_publish_region_event` 填充，
  供前端区域渲染与叙事载荷消费。

## 持久化

- 状态数组随 TileGrid BLOB 自动落库（积分量必存）
- `chunk_tiles` 表 `integrated_through INTEGER NOT NULL DEFAULT 0`；旧库 `ALTER TABLE ADD COLUMN` 就地补列
- `ChunkData.integrated_through` 字段；`_save_tiles(cx, cy, grid, integrated_through)` / `_persist` 写该列
- `load_tiles_with_day(cx, cy) → (TileGrid, int) | None`（`load_tiles` 内部复用它）
- 读档/LRU 重载路径（game `_build_tiles`、map_handler 恢复分支）统一走
  `load_tiles_with_day` + `chunk.restore_tiles` + `chunk.integrated_through = 游标`，
  随后 `on_tiles_ready` 续算缺口

## 装配（GameEngine）

- start() 5c：`TileStateEngine(clock, weather_engine, wt, store)` 创建并入 `_world_stack`
- 5c'：帧调度器按世界声明程序（WorldProgram）的波次计划注册更新点——`"minute" → weather.advance`、
  `"hour" → tile_state_engine.advance`（`bind_periods`，执行权只来自声明）
- **chunk 生命周期注册器**（`space/chunk_services.py`）：`ChunkServiceRegistry` 统一广播 `register`/`on_tiles_ready`/`unregister`；`WeatherChunkService`（5 参 register_chunk 适配，on_tiles_ready 空实现——解析算无需追赶）、`TileStateChunkService`（方法名对齐）。game 5c 装配 `ChunkServiceRegistry([WeatherChunkService, TileStateChunkService])`——**新增引擎 = registry.add(service)，生命周期时序零改动**
- `_on_chunk_evicted`：LRU 淘汰时 `chunk_services.unregister(cx, cy)`（注册器统一广播）
- `make_map_handlers(..., chunk_services=None)`：恢复路径 register + 立即 on_tiles_ready；生成路径 register（无网格）→ 异步生成 → on_tiles_ready

## 前端解码与渲染

- `_TILE_BLOB_VERSION`（默认 `Config.TILE_BLOB_VERSION = 1`；握手时服务端在 `hello_ack` 下发 `blob_version` = 后端 `TILE_GRID_VERSION`，前端以其解码/校验）；`_STATE_NAMES_BY_VERSION = {1: ["moisture", "snow", "ice"]}`（状态段与版本强关联，防分段错位）
- expected 长度 = 头+地形+高程×2+状态段字节；解码后 `chunk["states"] = {moisture: PackedByteArray, snow: ..., ice: ...}`（各 40KB）
- 渲染：`StateDisplayChaser` 显示值追赶真值（逐帧随机抽样收敛 + 降水/风暴事件加速），
  独立 States TileMapLayer 渲染（`StateLayerManager` 管理层生命周期）；周期刷新换真值

## 性能

数值循环下沉 C 内核：本机实测单 chunk（200×200）逐小时积分约
0.15 ms/步（30 游戏天 = 720 步约 0.1s）。成本随「chunk 数 × 小时步数」线性增长，
因此大范围快进必须走 C 路径；纯 Python 参考实现只用于逐位对拍。

## 整合点

- 更新点：帧调度器 "hour"（时钟推进信号；不订阅世界事件）
- 天气输入：`WeatherEngine.get_weather(cx, cy, time)`（解析量，支持过去时刻）
- 网络装配：`make_map_handlers(chunk_services=...)`——ChunkServiceRegistry 统一广播 register/on_tiles_ready/unregister（恢复注册+立即就绪，生成注册→异步就绪）
- LRU 淘汰：`_on_chunk_evicted` → `chunk_services.unregister(cx, cy)`
- 打包：`build_backend.sh` / `build_backend_windows.sh` 编译 `_state` 扩展
- 前端：chunk 数据通道 BLOB v1 解码（`_STATE_NAMES_BY_VERSION`）
